Phase 1 · Lesson 2

The one-line update rule

How to learn a value from noisy rewards, using one line of code that you'll see in almost every RL algorithm.

🧰 You'll need (quick reminders)
  • Q(a) = our current estimate of an action's average reward (Lesson 1.1).
🎯 Hook

This line of code (or something very close to it) is inside Q-learning, TD learning, DQN, PPO's value function, and the LLM training methods in Phase 8:

Q = Q + alpha * (reward - Q)

By the end of this lesson you'll know exactly why it works.

The problem

In Lesson 1.1 you estimated each machine's value as the average of its rewards. The obvious way to do that is to store every reward and call sum(rewards) / len(rewards). But after a million pulls you'd be storing a million numbers and re-adding them every time. Can we update the average using only the old average and the new reward?

Math refresher Updating an average without storing everything

Say you've seen rewards 4 and 6. Average = 5. Now a new reward of 8 arrives.

Slow way(4 + 6 + 8) / 3 = 6
Fast way5 + 1⁄3 × (8 − 5) = 5 + 1 = 6 ✅

The fast way says: start from the old average, then move toward the new reward by 1/n of the gap.

Why does it work? The new average is (old_sum + R) / n, and old_sum = old_avg × (n−1). Three lines of algebra (check each with the numbers above: old = 5, R = 8, n = 3):

new = ( old·(n−1) + R ) / n(5·2 + 8) / 3 = 6
    = old − old/n + R/n5 − 5/3 + 8/3 = 6
    = old + (R − old)/n5 + 3/3 = 6 ✅

(Step 2 just splits old·(n−1)/n into old − old/n. Step 3 groups the two /n pieces.)

new_avg = old_avg + 1⁄n · ( R − old_avg ) One multiplication and one addition. No list needed.

Each new sample matters less as n grows: the 2nd reward moves the average by ½ of the gap, the 100th by only 1/100. That makes sense, because one new data point shouldn't change much once you already have 99.

The update rule

Q ← Q + α · ( R − Q ) "new estimate = old estimate + step size × (what I got − what I expected)"
estimate Qreward R (the target)step size α (alpha)

The part in brackets, R − Q, is the error, or surprise:

  • Positive → "better than I expected!" → raise the estimate.
  • Negative → "worse than I expected" → lower the estimate.
  • Zero → "exactly as expected" → no change. Nothing to learn.

Sutton & Barto write it in a general form that you'll see again and again:

NewEstimate ← OldEstimate + StepSize × ( Target − OldEstimate )
🎮 Playground · Watch one update

A machine pays rewards around 7 (with noise). Your estimate starts at 0. Each click draws a reward and moves the estimate α of the way toward it.

Click "Get a reward"

Try α = 1: the estimate jumps all the way to each new reward, so it only remembers the last one. Try α = 0.05: it barely moves and takes ages to reach 7.

💡 Big idea Learning = nudging your guess toward what actually happened, by a fraction α of your surprise.
🧠 Analogy: updating your opinion of a café

You think a café's coffee is a 5/10. Today it's an 8. You don't jump straight to 8 (could be a lucky day), and you don't ignore it either. You move your opinion part of the way: maybe to 6.5. α is "how far you move": big α = you change your mind fast; small α = you need lots of evidence.

✏️ Worked example: three updates by hand

Start with Q = 5.

  • α = 0.5, reward 8: Q = 5 + 0.5 × (8 − 5) = 6.5.
  • α = 0.5, next reward 4: Q = 6.5 + 0.5 × (4 − 6.5) = 5.25.
  • Same first reward with α = 0.1: Q = 5 + 0.1 × 3 = 5.3. Smaller α = smaller, steadier steps.

1/n or a fixed α?

If α = 1/n, you get the exact average of all rewards. But what if the machine changes over time? (Real worlds do. So does an LLM's behavior during training.)

🎮 Playground · When the world changes

Faint dots = noisy rewards. Dashed = the true value. Each ⚡ press redraws a fresh 400-pull run with one more sudden jump in the true value, at a random moment. Press it a few times. The 1/n average gets stuck in the past, while the fixed-α estimate keeps up.

How much does each past reward count (fixed α)?

With a fixed α, a reward from k steps ago has weight α(1−α)k. With α = 0.1: the latest reward counts 10%, the one before 9%, then 8.1%… each older one × 0.9. Recent rewards count most and old ones fade away (an "exponential moving average", the same fade-out shape as discounting in Lesson 0.3). Change α and watch the bars.

Step sizeGood atBad at
α = 1/nExact average, smooth, ideal if the world never changesGoes stale when the world changes; later rewards barely count
Big fixed α (0.5)Reacts fast to changeNoisy; jumps around with every lucky or unlucky reward
Small fixed α (0.01)SmoothSlow to learn and slow to adapt

Why a fixed α never settles exactly: every new reward still moves Q by α × its surprise, and with noisy rewards the surprise is almost never zero. So Q keeps jiggling around the true value forever (in the playground, with α = 0.1, by about ±0.34). Only a shrinking step size like 1/n calms down to a single number.

This trade-off between speed and stability is the same one you face when choosing a learning rate for a neural network, and that's not a coincidence. Our update is exactly one step of gradient descent ("take a small step downhill on the error") on the squared error ½(R − Q)², with α as the learning rate: the downhill direction for Q is +(R − Q). Phase 4 does the same thing for millions of Q's at once, inside a neural network.

🌍 Where it's used
A fixed α for a world that drifts 🏭 In production · 1988 RFC 6298: how TCP decides a packet is lost

How: estimate Q = the smoothed round-trip time · target R = each newly measured round trip · update Q ← Q + α(R − Q) with α = 1/8.

Why this method: network delay changes as traffic comes and goes, so an all-time average would go stale. A fixed α tracks recent delays with one stored number per connection.

Target − estimate = surprise 🏭 In production · 1970 FIDE chess ratings (the Elo system)

How: estimate Q = your expected score against this opponent, from the two ratings · target R = the actual result (1, ½ or 0) · step size = K.

Why this method: your rating moves by K × (actual − expected): beat a stronger player, big surprise, big jump. K = 40 for new players, 10 once you reach 2400: big steps while unsure.

🤯 Fun fact · your brain runs this update

In the 1990s, neuroscientist Wolfram Schultz recorded dopamine neurons in monkeys getting juice. Dopamine fired when juice arrived unexpectedly. Once a light reliably predicted the juice, dopamine fired at the light and not at the juice. And if the juice didn't come when expected, dopamine dipped below normal.

That's R − Q: positive when surprised, zero when predicted, negative when disappointed. A 1997 paper (Schultz, Dayan & Montague) showed that dopamine behaves like an RL reward prediction error. (Lesson 6.8 explores this in depth, including a playground that recreates the experiment.)

🌉 LLM bridge · "better than expected?"

"How much better than expected was this?" is the most important question in modern RL. It has different names:

  • TD error (Phase 3): the same "reality − expectation" trick, applied to future rewards.
  • Advantage (Phase 5): how much better this action was than average
  • GRPO (Phase 8, used for DeepSeek-R1): sample ~8–64 answers to the same prompt, and an answer's advantage = its reward − the group's average reward. Answers better than their siblings get pushed up, worse ones pushed down.

It's all the same target − expectation idea from this lesson.

Check yourself ✅

1. Q = 4, you receive R = 10, α = 0.5. What's the new Q?
4 + 0.5 × (10 − 4) = 4 + 3 = 7. Halfway from 4 to 10.
2. If R − Q = 0, what happens?
No surprise means nothing to learn. Like the dopamine neurons once the juice was fully predicted.
3. Your environment slowly changes over time. Which step size should you use?
A fixed α weights recent rewards more, so it keeps tracking. 1/n treats a reward from long ago the same as yesterday's, so it gets stuck in the past.
📝 TL;DR
  • Q ← Q + α(R − Q): nudge your estimate toward the target by a fraction of the surprise.
  • α = 1/n → exact average. Fixed α → recent rewards count more (good when things change).
  • Target − estimate = the "surprise" signal behind TD learning, advantages, GRPO, and dopamine.
