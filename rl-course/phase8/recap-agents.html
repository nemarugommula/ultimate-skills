🧾 Cheat sheet

Multi-turn RL (8.10)

Episode = many turns of think → tool call → observation, then an outcome reward. Mask environment tokens from the loss. It's a POMDP: the context window (plus notes) is the agent's belief state. Long-horizon credit assignment is the core difficulty.

Infrastructure (8.11)

Rollouts dominate wall-clock time. Inference engine + reward services + trainer + weight sync. Async = throughput + staleness. Training–inference mismatch → truncated importance sampling (TIS), an FP32 LM head, or FP16.

Scaling curves (8.12)

Reward vs compute follows an S-curve with a ceiling A. Curves can cross, so compare ceilings, not snapshots. A trick that shifts the curve left made training faster, not better.

Coding agents (8.13)

Containers per repo → task factories (SWE-smith breaks code, R2E-Gym reverses commits, SWE-RL learns from history) → RL on hidden fail-to-pass and pass-to-pass tests → pick the best of many attempts (tests + judge: 34% → 51% in R2E-Gym).

Scaling agentic RL (8.14)

Bottlenecks: environments (20,000 in parallel), horizons (context limits → trained self-summarization), realism (real-time RL from users; watch for hacks). METR time horizons: ~4-month doubling since 2023, ~12 h by Feb 2026.

Search agents (8.15)

Reward = correct final answer; mask retrieved text. The key is data: multi-hop, obfuscated questions that are hard to find and easy to check. Warm up on successful trajectories, then agentic RL.

🗂️ Case files: five real problems, one phase later

The same five problems follow you through the course (meet them). Here's what this phase changes for each.

🌡️ The cooling plant

Now: still not the main tool: the control loop doesn't need a language model, and the Phase 6 approach (safe, constrained, learned from logged data) stays. The one echo is 8.14's real-time loop: deploy, measure, update, and watch for hacks, which is how a live plant would be tuned too.

Still breaks: you still can't show that a saving is real rather than a cooler week, because one run with no baseline proves nothing.

📱 The feed

Now: Cursor Tab (8.14) is a feed problem solved with online RL: show something or nothing, reward = accepted or rejected, a new checkpoint every couple of hours. A feed can run the same loop, with the same warning that hacks surface live.

Still breaks: separating a true improvement from noise, novelty and seasonal swings needs carefully designed comparisons with error bars.

🦾 The robot hand

Now: the agent loop (observe → think → act) is reaching robots: models like Google DeepMind's RT-2 (2023) turn a camera image + an instruction into motor actions written as tokens, learned mostly from demonstrations rather than RL.

Still breaks: real-world episodes are slow and can't be reset or copied, so you can't run 10,000 parallel environments the way coding agents do.

♟️ The board game

Now: nothing new: the game is a perfect, free environment with a checkable outcome, exactly the kind of environment agent builders now work hard to recreate for other tasks (8.14).

✅ Where it stands: solved for perfect-information games since AlphaZero; what's left is measuring strength fairly over many games.

🧑‍💻 The coding agent

Now: the full recipe: a container per repo, task factories, multi-turn RL with hidden fail-to-pass tests, masked tool output, async rollouts, then pick the best of several attempts (8.10–8.13).

✅ Where it stands: this is how today's coding agents are trained. What's left is measuring them honestly, since public benchmarks leak into training data and single runs are noisy.

🧩 Frame it yourself

🧩 New problem

An IT helpdesk gets thousands of tickets a day: “VPN won't connect”, “install the data-science toolkit on my laptop”, “my account is locked”. You want an agent that resolves them itself using tools: the ticket system, a user-directory API, a knowledge-base search, and a remote shell on the employee's machine. Wrong actions (deleting files, unlocking the wrong account) are costly.

Before you open the answer, write down: the state, the action, the reward, episodic or continuing (and γ), and which method from this phase (or earlier) you'd try first.

Reveal One good framing + the classic mistakes

State: the ticket + everything seen so far (tool results, user replies). The agent can't see the whole machine, so this is a POMDP and the context is its belief state (8.10). Action: think, call one tool, ask the user a question, or finish. Reward: at the end, a checker on a sandboxed copy of the machine: does the VPN test pass, is the toolkit importable, is the right account unlocked? 1 if yes, a large penalty for any forbidden action, 0 otherwise. Episodic? Yes, one ticket per episode; γ slightly below 1 (or a small per-step cost) to prefer short fixes, like Kimi-Researcher.

Method: build the environments first, with a task factory in the spirit of SWE-smith: take a working virtual machine, break it on purpose (bad VPN config, missing package), and keep the checker hidden. Warm up on successful human resolutions, then multi-turn agentic RL with groups of attempts per ticket, tool output masked from the loss, async rollouts because some tickets take 3 steps and some 40 (8.10–8.13).

Classic mistakes: reward = “ticket closed” (the agent learns to close tickets unfixed); a judge that reads the agent's final message (“Fixed! Everything works” fools judges, as in R2E-Gym); training against real employee machines instead of sandboxes; letting the agent see the checker script; forgetting to mask tool output, so the policy is trained on text it didn't write; and no plan for tickets too long for the context window.

💻 Stretch lab (optional): make Lab 8 multi-turn

💡 What you'll build A one-tool agent on top of your Lab 8 code (labs/phase8_grpo.py, best on a free Colab GPU). There's no new lab file: this is a do-it-yourself extension, and a good portfolio piece.
  1. Add a calculator tool. When the model writes CALC(17*23), stop sampling, append = 391 as environment tokens, and let the model continue. Allow at most 3 tool calls.
  2. Mask the tool output. Build a 0/1 mask over the response and multiply it into the per-token loss, so only tokens the model wrote get a gradient (8.10).
  3. Same reward as Lab 8: the last number matches the answer. Use harder problems (3-digit multiplication) so the tool is worth using.
  4. Measure: accuracy with and without the tool, and how often the model calls it before and after training. Does RL teach it when to use the tool?

Boss quiz 👾

One agent episode: a 200-token prompt, then the model writes 300 tokens (thinking + a tool call), the tool returns 5,000 tokens of file contents, and the model writes 100 more. How many tokens get a policy-gradient update?
The prompt and the tool output weren't sampled from the policy, so pushing their probabilities up or down teaches nothing about the agent's choices. Mask them, and train on the 300 + 100 tokens the model actually chose (8.10).
In a synchronous RL run, 63 of 64 rollouts finish in 2 minutes, but one runs for 20. What's the standard fix, and its cost?
In a synchronous loop every GPU waits for the slowest rollout. Async pipelines keep training on finished rollouts while others continue, so some data comes from a policy a few updates old (8.11).
You're building training data for a search agent. Which question makes the better RL task?
The model already knows trivia, so it never needs to search, and an essay has no exact check. Good search tasks are hard to find but easy to check (8.15).
