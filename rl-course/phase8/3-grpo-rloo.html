GRPO & RLOO: dropping the critic

Sample several answers to the same question and compare them with each other. That comparison replaces the value network.

🧰 You'll need (quick reminders)
  • REINFORCE: push up answers in proportion to their reward (Lesson 5.2).
  • Baseline / advantage: compare with "what's typical" instead of using raw reward (Lesson 5.3).
  • PPO's clip: limit how much each update can change a token's probability (Lesson 5.6).
🎯 Hook

GRPO (Group Relative Policy Optimization) was introduced in DeepSeek's DeepSeekMath paper (Feb 2024), where a 7B model reached about 51.7% on the MATH benchmark. A year later it powered DeepSeek-R1, and it became the default starting point for open reasoning-RL research.

💡 Big idea For each prompt, sample a group of G answers and score them all. Each answer's advantage = how much better it did than its siblings. No critic network is needed: the group is the baseline (a Monte Carlo estimate of V(prompt), Lessons 3.1 and 5.3).
🧠 Analogy: grading on a curve

8 students take the same exam. Instead of asking "is 70 a good score?" (which needs an expert to know how hard the exam was: that's the critic), you just compare each student with the class average. Above average → praised, below → corrected. If everyone gets 100, nobody learns anything from the comparison. GRPO grades each answer on the curve of its own group.

Numbers first: 4 answers score [1, 0, 0, 1]. Class average = 0.5. Correct answers are +0.5 above average, wrong ones −0.5 below. GRPO then divides by the group's spread (std = 0.5 here) to get ±1.0. That's the whole formula:

GRPO: Âi = ( ri − mean(r) ) / std(r)    RLOO: Âi = ri − mean of the other G−1 Â ("A-hat") = estimated advantage of answer i: how much better than its siblings it did. GRPO then plugs Â into PPO's clipped update (5.6, the "don't change too much at once" rule), plus an optional KL leash to the original model (7.4). RLOO compares each answer with the average of the others and uses plain REINFORCE (5.2). When does the clip actually do anything? Only on the 2nd, 3rd… update from the same batch of rollouts (or on slightly stale data from an asynchronous pipeline, 8.11). With a single update on fresh samples, new and old probabilities are identical, the ratio is exactly 1, the clip never fires, and GRPO is just REINFORCE with a group-mean baseline. That's why RLOO can drop the clip without losing much.

Why divide by the std? Rewards might be 0/1 in one task and 0–10 in another. Dividing by the group's spread makes advantages scale-free: roughly "how many spreads above average", whatever the reward units. (Lesson 8.4 shows the side effect on nearly-solved prompts.) How big should G be? A bigger group gives a better average to compare with and a better chance that at least one sample succeeds on a hard prompt, but costs G× the generation. Common choices are 8 to 64.

The GRPO update

for step in range(N):
    prompts = sample_batch(dataset)
    groups  = [[policy.generate(p) for _ in range(G)] for p in prompts]    # G = 8…64
    rewards = [[verifier(p, y) for y in g] for p, g in zip(prompts, groups)]
    adv     = (rewards - rewards.mean(axis=1)) / (rewards.std(axis=1) + eps)      # one number per answer…
    loss    = ppo_clip_loss(new_logp, old_logp, adv_broadcast_to_every_token)  # …shared by all its tokens
    loss   += beta * kl(policy, reference)                                    # optional
    step(loss)

The weirdest part, in plain words: an answer gets one advantage, and every one of its tokens inherits that same number. If an 800-token answer was correct, all 800 tokens get nudged up, including the boring ones like "the". Over many answers, the tokens that consistently show up in winners are the ones that really climb. (Smarter credit for individual steps is Lesson 8.5.)

Math refresher Why the critic turned out to be optional

In classic RL the critic reduces variance for a randomly initialized agent facing long episodes. An LLM starts from a strong pretrained policy, the episode (one answer) is short, and we can afford several samples per prompt. A group mean is a good enough baseline, and it saves an entire LLM-sized network, roughly halving memory.

🌍 Where it's used
GRPO for a giant model 🏭 In production · 2024 DeepSeek-V3

How: state = prompt · action = a full response, G of them per prompt · reward = rule checks where answers are checkable, a learned reward model otherwise. Advantage = each reward vs. the group's scores.

Why this method: the policy has 671B parameters, and a critic is usually the same size. GRPO's group baseline replaces that second giant network for free.

GRPO on a small, hand-picked prompt set 🏭 In production · 2025 Qwen3 reasoning RL (Alibaba)

How: state = one of just 3,995 query–verifier pairs · action = a response, many per query · reward = the verifier's check.

Why this method: Qwen kept only queries that were hard but learnable for the model, so groups mix wins and losses. All-equal groups would give zero signal (this lesson's warning).

RLOO's leave-one-out baseline 🧪 Research · 2025 PRIME (Eurus-2-7B-PRIME)

How: K samples per math or code problem · reward = answer or tests check · each sample's baseline = the average reward of the other K − 1 samples.

Why this method: leaving yourself out keeps your own luck out of your baseline. The authors chose it because it reduced variance, with no critic to train.

🤯 Fun fact

RLOO's paper (Ahmadian et al., 2024, "Back to Basics") reported that PPO's clipping rarely activated in their RLHF runs, which led them to drop it and use plain REINFORCE with a leave-one-out baseline. Later work on long reasoning runs found the opposite: the details of clipping matter a lot (next lesson). Findings in this field depend heavily on the setting.

🌉 Connecting the dots

GRPO = REINFORCE (5.2) + group baseline (5.3) + PPO clipping (5.6) + KL to a reference (7.4), with the critic and GAE (5.4–5.5) removed. Every piece came from an earlier lesson.

📝 TL;DR
  • GRPO: G samples per prompt, advantage = group-normalized reward, PPO-clip + optional KL, no critic.
  • RLOO: leave-one-out mean baseline, plain REINFORCE.
  • All-equal groups give zero signal. The std division over-weights nearly-solved prompts.
  • Built from REINFORCE + baseline + PPO + KL.
