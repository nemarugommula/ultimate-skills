Phase 8A · Lesson 2

RLVR: rewards you can check

Replace the learned reward model with a program that checks the answer. It's simple, cheap and hard to fool, but only if the checker is written carefully.

🧰 You'll need (quick reminders)
  • Reward models are learned judges with blind spots that RL can exploit (Lessons 7.3–7.4).
🎯 Hook

AI2's Tülu 3 (Nov 2024) gave this a name: RLVR, Reinforcement Learning with Verifiable Rewards. Two months later DeepSeek-R1 showed how far it could go. The appeal is that a math checker can't be flattered and a unit test doesn't care how confident the answer sounds.

💡 Big idea Reward = 1 if a program verifies the response, else 0. Verifiers exist for math answers, code (run the tests), formatting constraints, puzzles, games and SQL queries. RLVR is RL where the reward is a check, not an opinion. It works exactly as well as the checker does.
🧠 Analogy: an answer key vs an opinion

A math exam with an answer key is graded the same way every time, and you can't charm the answer key. An essay graded by opinion depends on the grader's mood and tastes, and students learn to write what the grader likes. RLVR uses answer keys (programs that check), which is why it can be pushed much harder than RL on a learned reward model.

😈 Challenge: be the reward hacker

Type a wrong response (one whose real final answer isn't 1/2) that still gets reward 1.

  1. Fool the sloppy verifier.
  2. Harder: fool the careful verifier.

Try every preset. The naive verifier wrongly rejects correct answers written differently. A sloppy "contains 1/2 anywhere" check would reward the hedge that lists three answers, or the response that mentions 1/2 and then answers 3. During RL, the policy will find any such gap. Real pipelines use careful answer extraction, math-equivalence libraries, a penalty for multiple final answers, and audits of high-reward samples.

Why 0 or 1, and not partial credit?

✏️ Worked example: partial credit invites guessing

Rule A (binary): 1 if the answer is exactly right, else 0. Rule B (partial credit): 1 if exact, 0.5 if within 10% of the right answer. Two strategies a model could learn:

strategyexactcloseRule A averageRule B average
actually solve it30%20%0.300.30 + 0.20 × 0.5 = 0.40
guess a plausible round number0%80%00.80 × 0.5 = 0.40

Under partial credit, lazy guessing scores exactly as well as real work, so RL has no reason to prefer solving. Under 0/1, only real answers pay. Every extra way to earn reward is another target for the policy to aim at, which is why most RLVR recipes keep the main reward binary.

Math refresher False positives vs false negatives

False negative (correct marked wrong): wastes signal and teaches the model to avoid valid formats. False positive (wrong marked correct): far more dangerous in RL, because the policy will actively seek out whatever triggers it. That's reward hacking. A verifier with 99% precision can still be exploited if the 1% is easy to reach on purpose.

🌍 Where it's used
Verifiable rewards for math and instructions 🧪 Research · 2024 Tülu 3 (AI2)

How: state = a math problem, or an instruction with a constraint · action = the response · reward = 10 if a checker passes (extracted answer matches, or the constraint's check function says yes), else 0.

Why this method: AI2 picked three skills (GSM8K, MATH, IFEval) whose answers a short program can check, so there was no learned judge for PPO to flatter.

Unit tests as the reward 🧪 Research · 2025 DeepCoder-14B (Agentica + Together AI)

How: state = a programming problem · action = the program · reward = 1 only if it passes all sampled tests (the 15 hardest), else 0. Bad formatting also scores 0.

Why this method: the team deliberately gave no partial credit (k of n tests), because it invites printing the public tests' answers or passing only the easy edge cases.

The verifier is the spec 🧪 Inside · 2025 Hugging Face Math-Verify, used by Open-R1

How: the reward function parses the model's answer and the reference into math objects and compares their values, so {1,3} ∪ {2,4} counts as equal to {1,2,3,4}. Open-R1's accuracy reward calls it.

Why this method: plain string matching marks correct answers wrong, exactly like the naive verifier in the playground. A math-aware checker makes the 0/1 reward trustworthy.

🤯 Fun fact · "spurious rewards"

A 2025 study (Shao et al., "Spurious Rewards: Rethinking Training Signals in RLVR") found that RLVR on some Qwen2.5-Math models improved math scores even with random or deliberately incorrect rewards. The training seemed to mostly bring out behaviors the base model already had (such as writing small programs to solve math, a habit these models picked up in pretraining), rather than teach new math. The effect didn't transfer to other model families. Lesson: test your RL claims on more than one base model.

🌉 Why RLVR took over reasoning
  • Hard to hack compared with a learned reward model, so labs can train much longer and harder, often with a small or zero KL penalty (the leash that keeps the model close to where it started, Lesson 7.4). Why drop the leash? In RLHF its job was to stop the policy wandering into regions where the learned reward model is wrong and exploitable. A program that checks answers is much harder to exploit, so the leash mostly just slows learning. (Not impossible to exploit, though: Lesson 8.6.)
  • Cheap and infinite: no human labels, just problems with answers or tests.
  • Limits: only works where answers can be checked. Extending it to subjective domains is what rubrics (8.9) and agent environments (8.10) try to do.

Check yourself ✅

1. What makes a reward "verifiable"?
Verification is cheap, objective and repeatable, unlike learned preferences.
2. Which verifier error is more dangerous during RL?
RL optimizes toward whatever is rewarded. A reachable false positive becomes the strategy.
3. "Spurious rewards" results suggest you should…
Good experimental controls (Phase 9). Some gains come from eliciting what the base model already does.
📝 TL;DR
  • RLVR: reward = programmatic check (math answer, tests, constraints, format).
  • Hard to hack, cheap, scalable. Lets reasoning RL run long with little or no KL.
  • The verifier is the spec: guard against false positives, normalize answers, penalize hedging.
  • Use controls (random rewards, other base models) before claiming RL taught new skills.
