Phase 8B · Lesson 15

Search & deep-research agents

The other big agentic RL domain: models that search the web, read, cross-check and decide when they know enough.

🧰 You'll need (quick reminders)
  • Agentic RL and loss masking: train only on the agent's own tokens, not on tool outputs (Lesson 8.10).
  • RLVR: a checkable final answer as the reward (Lesson 8.2).
🎯 Hook

In 2025, OpenAI released BrowseComp, a benchmark of questions built to be hard to find but easy to check: the kind where you might search for hours, but once someone tells you the answer you can verify it in a minute. Open models were far behind closed "deep research" agents. Within months, open projects such as Alibaba's Tongyi DeepResearch (30.5B parameters, only 3.3B active per token) reported state-of-the-art results on BrowseComp and similar benchmarks, mostly thanks to clever training data and agentic RL.

💡 Big idea A search agent is the multi-turn agent from Lesson 8.10 with one main tool: search (plus "open page"). The reward is simple (is the final answer correct?). The hard part is getting questions that actually require searching: if the model can answer from memory, RL teaches it nothing about research.
🧠 Analogy: a detective, not a quiz contestant

A quiz contestant answers from memory. A detective follows clues: each finding points to the next lead, and vague clues ("a tall man with a limp") match many suspects until combined. To train detectives, you need cases with multiple linked clues and deliberately vague descriptions, not trivia questions.

What one episode looks like

Q: In which town stands the library designed by the engineer behind a timber footbridge that won a small regional design prize in 1998?
think: The bridge clue is vague. First find which bridge won that prize, then its engineer, then the library, then the town.
search("timber footbridge regional design prize 1998")
[results] … the 1998 Northfold Design Award went to the Lindqvist Footbridge …
search("Lindqvist Footbridge engineer")
[results] … designed by structural engineer Mara Ostrow …
search("Mara Ostrow library")
[results] … Ostrow's later work includes the Halden Seed Library …
search("Halden Seed Library location")
[results] … the Halden Seed Library, on the main square of Tarrow …
answer: Tarrow

The names are invented for this demo, and that's the point: the answer can't come from memory, so the agent has to search, one hop at a time (4 searches: 1 to decode the vague clue + 3 hops). Solid boxes = the agent's tokens (trained). Dashed boxes = search results (masked out of the loss, exactly like tool outputs in 8.10). Search-R1 (2025) called this "retrieved token masking" and showed it's needed for stable training.

🎮 Playground · Make a question hard enough to need research

Data recipes like WebSailor's build questions from a chain of linked facts (a "knowledge graph"), then obfuscate them: replace exact names with vague descriptions. More hops = more searches; vaguer clues = more candidates to rule out. Try the combinations.

Math refresher Why vague clues make questions harder (multiplying candidates)

If clue 1 matches 20 possible things and clue 2 matches 20 for each of those, a naive search might check 20 × 20 = 400 combinations. Exact names collapse a clue to 1 candidate. Obfuscation keeps answers unique (only one thing satisfies all clues together) while making each clue alone ambiguous. That forces the agent to search, combine and verify, which is the skill being trained.

🌍 Where it's used
End-to-end RL for research 🏭 In production · 2025 OpenAI deep research

How: state = your question + pages and files read so far · action = search, open a page, run Python, or write the report · exact reward not public.

Why this method: trained end-to-end on hard browsing tasks, it learned to plan, backtrack and react to what it finds. A hand-written search workflow can't adapt like that.

A correct answer, discounted by length 🏭 In production · 2025 Kimi-Researcher (Moonshot AI)

How: action = think + search, browse or code call, or finish · reward = answer matches ground truth, and step i gets r × γT−i (T = total steps, γ < 1 is the discount factor).

Why this method: two correct runs earn the same at the end, but the shorter one's early steps earn more, so it learns to research efficiently. Its Humanity's Last Exam score rose from 8.6% to 26.9%.

🤯 Fun fact

"Hard to find, easy to check" is the same asymmetry as the puzzle in Lesson 0.4 (generating vs verifying). It's what makes these tasks good RL material: the reward is cheap and reliable even when finding the answer takes an agent dozens of searches.

🏁 Phase finale: open problems, where you could contribute

🎯

Credit assignment

Every token gets the same reward. Which tokens or steps actually mattered? PRMs, tree rollouts, turn-level credit (8.5, 8.10).

💸

Sample efficiency

Each rollout gives about one bit (right or wrong), and we need 8–64 per prompt. How do we learn more from failures?

🧗

Very hard problems

If no sample ever succeeds, there's no gradient. Exploration, curricula and teacher hints (6.5, 8.7, 8.8).

🌍

Beyond math & code

Subjective, long-horizon, multi-turn tasks: rubrics, judges, agent environments (8.9, 8.10).

🔬

Reliable science

Results often come from one model family and one budget. Which improvements survive across scale and models? (Phase 9)

🛡️

Safety

Reward hacking that generalizes (8.6); faithfulness (does the written reasoning reflect what the model really did?); scalable oversight (how do you check a model that's better than you at the task?).

🔁

Continual learning

Agents that keep learning from deployment experience without forgetting, which is RL's original promise (real-time RL, 8.14, is a first step).

🧭 How to keep up (this phase will go stale; you won't)

Once a month, skim:

  • Interconnects (Nathan Lambert): post-training and RL news with opinions from a practitioner.
  • Ahead of AI (Sebastian Raschka): careful explainers and paper round-ups.
  • The RLHF Book (Nathan Lambert): a free, updated reference for the whole post-training stack.
  • Lab tech reports on arXiv (DeepSeek, Qwen, Kimi, MiniMax and others publish detailed ones): read the RL section and its ablations.

For each new paper, ask:

  1. Which box of the loop map (8.1) does it change? Which component: advantage, normalization, clipping, aggregation or data?
  2. Does it improve speed or ceiling (8.12)? Was it run long enough to tell?
  3. Is pass@k reported, not just pass@1 (8.8)?
  4. How many base models and seeds? Only one model family is a warning sign (spurious rewards, 8.2; Phase 9).
🌉 Connecting the dots

Search agents combine RLVR (8.2: checkable final answers), agentic loss masking (8.10), long horizons (8.14) and data synthesis (8.13's "task factory" idea, for questions instead of bugs). The extra "agentic mid-training" stage is a newer recipe detail: shape agent behaviors with cheaper training before expensive RL.

Check yourself ✅

1. Why are trivia-style questions poor training data for search agents?
You reinforce what gets rewarded. If memory suffices, research behavior never gets reinforced.
2. What does "obfuscating" a question do?
Unique answer, ambiguous clues: the agent must combine evidence.
3. Why are search results masked out of the policy-gradient loss?
Same rule as tool outputs in 8.10: only train on the agent's own choices.
📝 TL;DR
  • Search agent = multi-turn agent with search tools; reward = correct final answer; mask retrieved text.
  • The key is data: multi-hop, obfuscated questions that require research (WebSailor-style synthesis).
  • Recipes: warm-up on successful trajectories, then agentic RL; Tongyi adds agentic mid-training.
  • "Hard to find, easy to check" tasks make cheap, reliable rewards.
  • Open problems: credit assignment, sample efficiency, hard problems, non-verifiable domains, reliable science, safety, continual learning. Keep up monthly, and triage each paper by which box of the loop it changes.
