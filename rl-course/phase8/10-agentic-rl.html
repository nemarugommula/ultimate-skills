Multi-turn RL: when the LLM acts in a world

From "write one answer" to "click, type, run, read, repeat until the job is done". RL for agents is RL in the full sense again: long episodes, a real environment, partial views and delayed rewards.

🧰 You'll need (quick reminders)
  • RLVR: reward = a program's check, e.g. tests pass (Lesson 8.2).
  • GRPO: compare a group of attempts at the same task (Lesson 8.3).
  • Partial observability: the agent can't see the whole state at once (Lesson 2.1).
🎯 Hook

In January 2025, OpenAI showed CUA (Computer-Using Agent): a model that looks at screenshots and moves a mouse and keyboard, built by combining GPT-4o's vision with reasoning trained through reinforcement learning. On OSWorld (real desktop tasks like "rename these files" or "make this spreadsheet chart") it succeeded 38.1% of the time. Humans manage 72.4%. The gap is what this lesson is about: acting in a world, step after step, is much harder than writing one good answer.

💡 Big idea An agent's episode is many turns: think → call a tool (run a command, edit a file, search) → read the result → think again… → finish. The environment is a real sandbox, and the reward usually arrives only at the end (tests pass, task done). This is the token MDP of 7.1 turned into a long, partially observable MDP (Lesson 2.1): the agent can't see the whole repository or machine at once, only what's in its context window.
🧠 Analogy: an intern with a laptop

You give an intern a bug ticket and a laptop. For an hour they look around, run commands, read error messages, try fixes and run the tests, then say "done". You only check whether the tests pass at the end. To get better, they must figure out which of their many actions made the difference. That's agentic RL.

🎮 Playground · Anatomy of one agent trajectory

  • Mask the environment's tokens. Tool outputs (file contents, error messages) weren't chosen by the model, so they aren't actions. Training on them would teach the model to "predict the terminal", not to act. Only the agent's own tokens get policy-gradient updates. Why is this new? In single-turn RL the task prompt also isn't trained, but it sits neatly before the answer, so "train only the response" handles it for free. In multi-turn RL the environment's text lands in the middle of the agent's turns, so it has to be masked out explicitly. It stays in the context (the agent still reads it); it just gets no gradient.
  • Credit assignment is brutal: one reward after 50 tool calls and maybe 30,000 tokens. Which call mattered? Turn-level checks (did the edit apply? did a new test start passing?) and checklist rewards (8.9) add denser signal, at the risk of being gamed.

Memory: the agent's belief state

An agent never sees the whole world: not the whole repository, not the whole website, not what's behind the next click. In Lesson 2.1's terms it lives in a POMDP (a partially observable MDP), and the right thing to act on is a belief state: its best summary of everything it has seen so far. For an LLM agent, the belief state is simply what's in its context window, plus any notes or memory files it chooses to write. When the context fills up, the agent must decide what to keep, and RL can train that decision too (self-summarization, Lesson 8.14).

What makes agentic RL hard

🐢

Slow, expensive rollouts

Each step runs real code in a container. One episode can take minutes. Infrastructure is half the work (8.11).

🏗️

Building environments

Thousands of reproducible tasks with reliable checks: code sandboxes, terminals, browsers, whole desktops. Building good "RL environments" became a big industry effort in 2025–26 (coding: 8.13, scaling: 8.14, search: 8.15).

🧠

Context limits

Long trajectories overflow the context window. Agents must summarize, take notes and manage memory, which is partial observability again.

🎣

Hacking

Editing tests, hard-coding outputs, finding leaked solutions (8.6). Environments must be hardened.

Math refresher Token-level vs turn-level advantages

GRPO-style training gives every agent token in a trajectory the same advantage (episode reward minus the group mean). Turn-level methods estimate an advantage per turn (each tool call is an "action"), using turn rewards or a value estimate per turn. That's GAE-style credit (5.5): each turn gets credit for how much it changed the odds of success, rather than every token getting the same score.

🌍 Where it's used
Tool use learned by RL 🏭 In production · 2025 OpenAI o3 and o4-mini

How: state = conversation + tool results so far · action = think, call a tool (search, Python, image tools) or answer · the reward design isn't public.

Why this method: OpenAI's stated aim was to teach when to use a tool, not just how. That's a decision with delayed payoff, exactly what RL learns and examples alone don't.

Masking the environment's tokens 🧪 Research · 2025 ReTool (ByteDance Seed)

How: state = math problem + reasoning + interpreter outputs · action = text or code run in a sandbox · reward = final answer correct. Interpreter output is masked from the loss.

Why this method: the policy didn't write those tokens, so they get no gradient. With the tool, the 32B model reached 67% on AIME in 400 steps vs 40% after 1,080 text-only steps.

A learned belief state 🧪 Research · 2025 MEM1 (MIT, NUS)

How: each turn the agent rewrites a short internal state (its notes) and older turns are deleted · reward = task answered correctly, with nothing rewarding memory size.

Why this method: memory stays constant however long the task runs. On a 16-question task, the 7B agent scored 3.5× higher with 3.7× less memory than a 14B model reading everything.

🤯 Fun fact

The think → act → observe loop in the playground has a name: ReAct (Yao et al., 2022). It started as a prompting trick, with no RL at all: just show the model one or two examples of interleaving thoughts with tool calls. On two interactive benchmarks (ALFWorld and WebShop) it beat imitation- and RL-trained agents of the time. Agentic RL takes that same loop and trains the model to run it well.

🌉 Close to home

The coding agent that built this course works the same way: read files, run commands, edit, test, repeat. Public evidence suggests agents like it improve substantially through RL in sandboxed software environments with test-based rewards: the techniques of this lesson, with the safeguards of 8.6. Check yourself ✅

1. Why mask tool-output tokens from the policy-gradient loss?
Only the agent's choices (its thoughts, tool calls and final answer) should be trained.
2. What's the typical reward for a SWE agent?
A verifiable outcome reward (RLVR) for a long, multi-turn episode.
3. Agentic RL compared with single-turn reasoning RL…
It's closer to classic RL (Phases 2–6), with an LLM as the policy.
📝 TL;DR
  • Agent episode = many turns of think → tool call → observation, ending with an outcome reward.
  • Mask environment tokens (they land mid-episode, unlike the prompt). Credit assignment over long horizons is the core difficulty.
  • It's a POMDP: the context window (plus notes) is the agent's belief state.
  • Building environments, slow rollouts, context limits and hacking are the practical challenges. Computer-use, coding and search agents are this same loop with different tools (8.13–8.15).
