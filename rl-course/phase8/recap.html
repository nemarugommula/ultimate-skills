🧾 Cheat sheet

o1 / R1

RL against correctness checks → long reasoning and reflection emerge. R1-Zero: AIME 15.6% → 71.0%. Test-time compute (voting, verifiers) amplifies the distribution; RL improves it.

RLVR

Reward = programmatic check (answer, tests, constraints). Hard to hack, so long training with little or no KL. Guard against false positives. Use controls (spurious rewards).

GRPO / RLOO

Group of G samples per prompt. GRPO: (r − mean)/std + PPO-clip + optional KL, no critic. RLOO: leave-one-out mean + REINFORCE. All-equal groups → zero signal. With one update per batch the ratio is 1 and the clip never fires.

Fixes (2025–26)

Must know: Dr. GRPO (no std, constant normalizer), DAPO (token-level, clip-higher 0.28, dynamic sampling, overlong shaping), CISPO (clip the weights, keep the gradient). Also: GSPO (sequence ratio), MaxRL (divide by success rate), DPPO (divergence-based trust region).

Process rewards

PRM = value of a reasoning prefix. Precise credit, but costly and hackable. Outcome rewards for training, PRMs and verifiers for search.

Reward hacking

Length, sycophancy, test special-casing, scoring tampering. KL, ensembles, hardened environments, CoT monitoring (don't optimize against it). Hacking can generalize.

Entropy & pass@k

RL sharpens: entropy ↓, pass@1 ↑, coverage may ↓. Clip-higher, forking tokens, covariance clipping. pass@k = 1 − C(n−c,k)/C(n,k). Agentic RL can expand capability.

Beyond verifiable

Generative judges and rubric rewards (weighted yes/no criteria, including negative items). Score each criterion, not a holistic 1–10.

🗂️ Case files: five real problems, one phase later

The same five problems follow you through the course (meet them). Here's what this phase changes for each.

🌡️ The cooling plant

Now: mostly not this phase's tool: setting fans and chillers doesn't need a language model. One lesson carries over: metered energy is already a “verifiable” reward, so hacking risk (8.6) hides in what you measure, e.g. a policy that cools only the spots where sensors sit.

Still breaks: a reported 10% saving might just be a milder month, and you can't yet prove the gain is real rather than weather or luck.

📱 The feed

Now: Lesson 8.6 is the feed's story: GPT-4o's thumbs-up flattery is clickbait in another costume. Treat watch time as a hackable proxy: keep the new policy close to the current one (KL), score with several signals, and audit the top-scoring items by hand.

Still breaks: none of that tells you whether people are actually better off; you'd need a careful live comparison against the old feed that separates a real gain from noise.

🦾 The robot hand

Now: not yet. “Try G times per task and compare” is cheap for text, but on a physical hand every attempt costs real minutes and wear, so it leans on simulation and logged data (Phase 6).

Still breaks: success often has to be judged from a camera (“is the cube solved?”), and that checker is itself a learned model that a policy can fool.

♟️ The board game

Now: nothing new needed. Influence runs the other way: a win or loss is the original verifiable reward, and a reasoning model that thinks longer is buying search at answer time, like AlphaZero running more simulations.

✅ Where it stands: solved for perfect-information games since AlphaZero; what's left is measuring strength fairly over many games.

🧑‍💻 The coding agent

Now: the reward becomes checkable: sample G patches per issue, reward = 1 if the hidden tests pass, group-normalized advantage, token-level loss, drop all-equal groups (8.2–8.4). DeepCoder trained exactly this way on coding problems.

Still breaks: real bug fixing isn't one answer: the agent must open files, run code and react over many turns, and every task needs its own runnable copy of the repo.

🧩 Frame it yourself

🧩 New problem

Your company's analysts ask questions in plain English (“Which 5 regions had the biggest drop in renewals last quarter?”) and wait days for someone to write the SQL. You have a 7B open model, the database schema, and 20,000 past questions, each with the SQL query an engineer wrote for it. You want the model to write correct queries itself.

Before you open the answer, write down: the state, the action, the reward, episodic or continuing (and γ), and which method from this phase (or earlier) you'd try first.

Reveal One good framing + the classic mistakes

State: the question + the schema (+ the query tokens written so far). Action: the next token; the whole query is one response. Reward: run the model's query and the engineer's query on a read-only copy of the database; 1 if they return the same rows, else 0 (plus a tiny penalty for unparseable SQL). Episodic? Yes, one query per episode, γ = 1.

Method: RLVR with GRPO (8.2–8.4): sample about 8 queries per question, group-normalized advantage, token-level loss, drop questions where all 8 agree, small or no KL. Execution match is a cheap, hard-to-flatter check, so no learned judge is needed. Report pass@1 from several samples and pass@k (8.8), and say which temperature you used.

Classic mistakes: rewarding an exact text match with the reference SQL (many correct queries look different: false negatives); rewarding “the query runs” (SELECT 1 runs: a hack); partial credit for overlapping rows (invites broad SELECT * guesses); test databases so small or empty that wrong queries return the same rows (false positives); letting queries write to the real database; and claiming new skills without checking another base model or a random-reward control (8.2).

💻 Lab 8: GRPO from scratch on a real LLM

💡 What you'll build A verifier (reward), group-relative advantages, per-token log-probs, and the clipped GRPO loss with token-level averaging, plugged into a training loop on SmolLM2-135M-Instruct for arithmetic problems.

File: labs/phase8_grpo.py. Best on a free Colab GPU: minutes (Runtime → Change runtime type → GPU). On a laptop CPU it takes 15–50 min depending on load. Needs transformers (see Lab 7).

  1. TODO 1: reward_fn: last-number match + small clean-format bonus. Checks include a hedging case.
  2. TODO 2: group_advantages: group normalization, with a zero-signal check.
  3. TODO 3: response_logprobs: per-token log π of the response.
  4. TODO 4: grpo_loss: clipped ratio × advantage, averaged over real tokens (DAPO-style). A check verifies the clipping gradient. With the default inner_epochs=1 the ratio is always 1, so training is REINFORCE with a group baseline; set inner_epochs=2 or more to see the clip fire (the loop then prints the clip fraction).
  5. Train: compare held-out accuracy, greedy and sampled, before and after.
⚠️ What the reference run showed (a real lesson, not a bug)

Sampled accuracy (temperature 1) rose from 0.28 → 0.59, but greedy accuracy stayed around 0.6 (0.64 → 0.58, within the ±0.06 noise of 64 test problems). The model's most likely answer was usually already right; GRPO sharpened the distribution so samples agree with it (Lessons 8.7–8.8). The clean-format bonus never triggered either: the model never sampled a bare number, so that reward was never seen, which is an exploration problem. Training accuracy also swings a lot from step to step, because each step uses only 4 prompts.

🔬 Mini research ideas (great portfolio seeds)
  • Dr. GRPO vs GRPO: drop the std division and use a constant normalizer. Do response lengths change?
  • Clip-higher: εhigh = 0.28. Track entropy of sampled tokens over training.
  • Reward hacking: make the verifier sloppy ("contains the number anywhere"). What does the model learn to do?
  • pass@k: estimate pass@1 and pass@16 before and after training with the unbiased estimator.
