DQN: replay buffer & target network

Q-learning + a neural network + two tricks = the algorithm that started the deep RL boom.

🧰 You'll need (quick reminders)
  • Q(s, a) = "how good is action a in state s", counting future rewards (Lesson 2.3).
  • Q-learning's target: reward + γ × the best Q-value of the next state, r + γ max Q(s', a') (Lesson 3.4).
  • A neural network = a big adjustable function; training nudges its weights a little "downhill" on a loss, the number measuring how wrong it is (Lesson 4.2).
🎯 Hook

In 2013, a small London startup called DeepMind posted a paper in which one algorithm learned to play seven Atari games from raw pixels and the score, with no game-specific code. The 2015 Nature version played 49 games with the same network and settings, reaching human level on many of them. Google had bought DeepMind in 2014 for a reported ~$500 million.

💡 Big idea DQN = Q-learning where a neural network replaces the Q-table: screen in → one Q-value per action out. The naive version is unstable, so DQN adds two tricks: a replay buffer (learn from random old experiences) and a target network (a frozen copy that provides the targets).

Why 4 frames? One frame is a photo: you can see the ball, but not which way it's moving. Four frames in a row show motion and speed, so the "state" really describes the situation.

🧠 Analogy: studying with flashcards

The network is a student learning "how good is each move here?". Replay buffer = a big box of flashcards from past games, shuffled, instead of re-reading only the last page you studied (which makes you over-fit to one moment). Target network = an answer key that's updated once a week, not every minute; if the answer key changed every time you studied, you'd never settle on anything.

✏️ Worked example: one DQN update in Pong

The network looks at the screen and outputs one score per joystick action: Q(up) = 0.8, Q(down) = 0.3, Q(stay) = 0.5. It presses up (the biggest). Reward this step: 0. On the next screen, the target network says the best action is worth 0.9.

Target = reward + γ × best next value = 0 + 0.99 × 0.9 = 0.891. The network said 0.8, so it was 0.091 too low. Training nudges the weights so that, for screens like this one, Q(up) moves a little toward 0.891. Repeat millions of times on shuffled flashcards and the scores become accurate.

In symbols, that "how wrong was I" is the squared TD error from Lesson 3.4, now used as the network's loss:

L(θ) = ( r + γ maxa' Q(s', a'; θ−) − Q(s, a; θ) )² θ = the network's weights. θ− (read "theta minus") = the frozen target network, copied from θ every few thousand steps.

The labs swap the square for the Huber loss (smooth_l1_loss): squared for small errors, but only growing in a straight line for big ones, so one wild target can't yank the weights. The 2015 DQN got the same effect by clipping the error to ±1.

Why naive "Q-learning + neural net" falls apart

Sutton & Barto call it the deadly triad. When these three are combined, learning can diverge, with values blowing up to infinity:

🧠

1. Function approximation

Updating one state changes others (generalization cuts both ways).

🔁

2. Bootstrapping

Targets are built from the network's own guesses.

🔀

3. Off-policy data

Training on a mix of states that doesn't match the policy being learned.

🎮 Playground · Watch the deadly triad blow up (a famous 2-state example)

Picture two situations that one shared dial w controls: B's score is forced to be exactly double A's. (State A has feature 1, state B has feature 2, so v̂(A) = w, v̂(B) = 2w.) A → B with reward 0, and B → B forever with reward 0, so the true values are all 0. We do semi-gradient TD updates (α = 0.1) starting from w = 1.

Training only on A: each update makes w bigger whenever γ > 0.5. A's target 2γw grows along with w, so it keeps chasing its own tail. With numbers (γ = 0.9, w = 1): A's target is 0.9 × 2 × 1 = 1.8, so w climbs toward 1.8; then the target becomes 3.24, then 5.8, and so on forever. Tick the box and add the states the policy really visits: it converges to 0. That's the deadly triad in two states, and it's why stability tricks matter.

Now untick it and tick 🧊 instead. With γ = 0.9, w reaches about 150 after 120 updates instead of about 10,000: the frozen copy slows the feedback loop, but it still grows. Keep that in mind for the rest of the lesson: DQN doesn't remove the deadly triad. Replay keeps the data mix stable and the target network slows the feedback loop. That's damage control, not a cure.

Trick 1: the replay buffer

Store every transition (s, a, r, s', done) in a big buffer (DQN: the last 1 million). Train on random minibatches from it.

🎮 Playground · Consecutive vs random samples

Each square is a stored transition, colored by which part of the game it came from (consecutive moments look alike). Outlined squares = the training minibatch.

  • Breaks correlations: 8 consecutive frames are nearly identical, so the gradient keeps pushing the same way (like studying one page of a textbook over and over). Random samples are diverse.
  • Reuses data: each experience can be learned from many times. That's possible because Q-learning is off-policy (Lesson 3.4).
🎬 Animation · The DQN data pipeline

Each tick, the agent takes one step in the game and stores the experience (colored by when in the game it happened). Training then grabs a random minibatch of 4 from the buffer (outlined), so consecutive, look-alike moments are rarely trained on together. Every 10 ticks, the frozen target network is refreshed with a copy of the online network.

Trick 2: the target network

Keep a frozen copy θ− of the network to compute targets, and refresh it only every C steps (DQN: 10,000). Between refreshes the targets stand still, so the network chases a fixed target for a while, like supervised learning, instead of one that moves on every step.

for step in range(total_steps):
    a = epsilon_greedy(q_net(s), eps)                  # ε decays from 1.0 to ~0.05
    s2, r, done = env.step(a); buffer.add(s, a, r, s2, done)
    s = s2                                              # (reset s when the episode ends)
    s_b, a_b, r_b, s2_b, d_b = buffer.sample(32)       # trick 1: a random batch of OLD moments
    target = r_b + gamma * (1 - d_b) * target_net(s2_b).max(1)   # trick 2 (no gradient)
    loss = mean((q_net(s_b)[a_b] - target) ** 2); gradient_step(loss)
    if step % C == 0: target_net = copy(q_net)

Note that the update uses the batch variables (s_b, r_b…), not the step the agent just took. That's the whole point of trick 1.

Honest note: these tricks make DQN work well in practice, but they don't guarantee stability. Even with a target network, the 2-state example above can still diverge (tick 🧊 above). Deep RL theory is still catching up with deep RL practice.

⚠️ What happens without the target network (Lab 4)

In Lab 4's ablation (CartPole, 3 seeds), DQN with a target network scored 109–141 out of 500. With the target network removed, it scored 9 on every seed, worse than pressing random buttons (about 22). Chasing a target that moves on every step didn't just slow learning down; it broke it.

🌍 Where it's used
DQN trained on logged data 🏭 In production · 2018 Facebook (Horizon): should we send you this notification?

How: state = features of the person and the notification · action = send or drop · reward = later activity on Facebook, minus a penalty per notification sent. Send when Q(send) beats Q(drop) by enough.

Why this method: a click predictor misses long-term effects; Q-values count them. Being off-policy, it retrains daily on tens of millions of logged transitions, which act like a giant replay buffer.

Replay buffer + target networks on real robots 🧪 Research · 2018 Google QT-Opt: grasping objects it has never seen

How: state = a 472×472 camera image + whether the gripper is open · action = how to move the gripper, or close it · reward = 1 if an object is lifted, else 0. A Q-network scores each option.

Why this method: robot time is precious. A replay buffer reused 580,000 real grasp attempts from 7 robots, and lagged target networks kept targets steady: 96% success on unseen objects.

🤯 Fun fact

DQN famously discovered the tunnel trick in Breakout: dig a hole through the side of the brick wall and send the ball behind it to bounce around and break bricks automatically. Nobody programmed that strategy. DQN worked it out because it scored more.

The 2015 Nature DQN used one set of settings for all 49 games and clipped every reward to ±1 (so a 10-point and a 1,000-point event looked the same). Its score on Montezuma's Revenge, where you must cross several rooms before seeing any reward: 0. Random ε-greedy button presses almost never find that first reward. Fixing that takes curiosity (Lesson 6.5).

🌉 LLM bridge · frozen copies everywhere

RLHF keeps a frozen reference model, a copy of the starting LLM, and penalizes the policy for drifting away from it (the KL penalty, Phase 7). It's a different purpose from DQN's target network (staying close rather than giving stable targets), but the same instinct: anchor a moving learner to something that holds still. Replay-style reuse of old samples is also coming back in LLM RL, as big systems train on slightly stale rollouts to keep GPUs busy.

Check yourself ✅

1. What does the replay buffer fix?
Random minibatches from a large memory give diverse, roughly independent samples, and each one is reused many times.
2. Why use a separate target network?
Fixed targets turn each stretch of training into something closer to supervised regression, which is much more stable.
3. The "deadly triad" is…
Any two are usually fine. All three together can make value estimates diverge, and DQN has all three.
📝 TL;DR
  • DQN: neural net Q(s, ·; θ), trained on the squared TD error with targets from a frozen θ−.
  • Deadly triad (function approximation + bootstrapping + off-policy) → possible divergence.
  • Replay buffer: random, reusable, decorrelated minibatches. Target network: slow-moving targets.
  • Works very well in practice. Theory still has no guarantee.
