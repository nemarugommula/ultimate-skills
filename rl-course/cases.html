🌡️ The cooling plant

A data centre runs thousands of servers that turn electricity into heat. Fans, pumps, chillers and cooling towers remove it. Every few minutes someone (or something) has to choose their settings: too little cooling and machines overheat, too much and you waste energy.

🏭 In production · 2016–2018 DeepMind's system cut the energy Google used for cooling by up to 40%, first as recommendations to operators and later in direct control, saving about 30% on average, with safety limits and a human override that always wins.

Framing: state = sensor readings (temperatures, load, weather) · action = the settings · reward = minus the energy used, with hard safety limits · it never ends (a continuing task, so γ < 1).

PhaseWhat changes
0You can describe it: states, actions, a reward that is a cost, and a task that never ends.
1Try settings and keep the best one? It fails: the best setting depends on the weather and the load.
2With a perfect simulator of the building you could plan ahead. Nobody has one.
3Learn from experience without a model. But a table of every sensor combination is far too big.
4A neural network predicts how good each setting is from the sensor readings.
5Learn a policy that outputs smooth, continuous knob settings directly.
6Learn safely from years of logged data first, respect constraints, and model the building: the shape of the real system.
7–8BNot the main tool here: a cooling plant doesn't need an LLM. Knowing that is part of mastery.
9Prove the saving is real: baselines, weather-matched comparisons and error bars.

📱 The feed

A video app, a news site or a streaming service decides what to show you next, millions of times a second. You click, watch, skip or leave, and that's the only feedback.

🏭 In production · 2017–2019 Netflix chooses the artwork for each title with bandits, and YouTube trained a recommender with a policy-gradient method that corrects for learning from an older system's logs.

Framing: state = the user and their history · action = what to show · reward = a click or watch time, which is only a proxy for “the user is glad they came”.

PhaseWhat changes
0You can frame it, and spot the danger: the reward is a proxy.
1Pick the best thumbnail while still trying new ones: explore vs exploit. Many real systems stop here.
2–3What you show today changes what the user wants tomorrow, so long-term value matters, not just the next click.
4Too many users and items for tables: neural networks.
5A policy over a huge catalogue, learned from logs of an older system, with a correction for the mismatch.
6Estimate how a new policy would do from old logs before you ship it.
7–8AA learned reward for engagement can be hacked (clickbait): the same failure seen in LLM training.
9A/B tests with honest error bars decide what ships.

🦾 The robot hand

A robot arm with a camera has to pick up objects it has never seen, or a robot hand has to turn a Rubik's cube. Physics is messy, and every real attempt costs time and wear.

🧪 Research · 2018–2019 Google's QT-Opt learned from over 580,000 real grasp attempts and reached 96% grasp success on unseen objects. OpenAI trained a hand only in simulation, with heavily randomized physics, and it solved a Rubik's cube on the real robot.

Framing: state = camera image + joint angles · action = motor commands (continuous) · reward = success at the end, maybe small hints along the way.

PhaseWhat changes
0You can frame it, and see why it's hard: rewards come late and every try is expensive.
1–3Not yet: no usable model of physics, and continuous states don't fit in a table.
4Neural networks can read camera images, but picking the best of infinitely many motor commands is awkward.
5A policy that outputs motor commands directly, trained in simulation.
6Continuous-control methods, sim-to-real, learning from logged robot data and from human demonstrations: how real robot learning works.
9Test over many objects and seeds before claiming it works.

♟️ The board game

Go has more possible positions than there are atoms in the observable universe. You only learn whether you won at the very end.

📜 History · 1992–2017 TD-Gammon learned backgammon by playing itself (Lesson 3.2). AlphaZero learned chess, shogi and Go from the rules alone and, within 24 hours of training, beat a world-champion program in each.

Framing: state = the board · action = a legal move · reward = +1 win, −1 loss, at the end only · episodic, γ = 1.

PhaseWhat changes
0You can frame it, and name the core difficulty: which of 200 moves deserves credit for the win?
2The rules are known, so planning works in principle, but there are far too many positions.
3Learn by playing yourself, updating guesses from later guesses: TD-Gammon's recipe.
4–5Neural networks judge positions and propose moves.
6Search plus self-play: AlphaZero. ✅ Solved for perfect-information games.
8AThe same idea, think before you move, returns in reasoning models.

🧑‍💻 The coding agent

Give an LLM a real repository and a bug report. It reads files, runs commands, edits code, and is done when the tests pass.

🏭 In production · 2024–2026 SWE-bench collected 2,294 real GitHub issues from 12 Python projects. In 2023 the best model solved about 2% of them; today's RL-trained coding agents solve most of the verified subset (Lesson 8.13).

Framing: state = the repository + the conversation so far · action = the next token, or a tool call · reward = do the hidden tests pass?

PhaseWhat changes
0You can frame an LLM as an agent, and spot the risk: it might edit the tests instead of the code.
1–3The same ideas apply, one token at a time.
4–5The policy is a huge neural network, trained by policy gradients on text.
6First imitate human code, then improve by RL.
7Human preferences teach it to be helpful and clear.
8AA reward you can check, “the tests pass”, makes long RL training possible.
8BMany turns of tool use in sandboxed repositories with hidden tests. ✅ How today's coding agents are trained.
9Benchmarks, contamination and error bars: how to tell real progress from noise.
