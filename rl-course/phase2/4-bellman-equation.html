The Bellman equation

The most important equation in RL. It says each state's value can be worked out from the values of its neighbors.

🧰 You'll need (quick reminders)
  • V(s) = how much return to expect from state s (last lesson).
  • The return trick: G = reward now + γ × the return from the next step (Lesson 0.3).
🎯 Hook

If RL had an E = mc², this would be it. Q-learning, DQN, actor-critic, PPO's value model: all of them are, at heart, ways of solving the Bellman equation. (AlphaZero's value network is a cousin: it learns from final game results, Monte Carlo style, rather than from this one-step equation.) Understand this lesson and the rest of RL becomes variations on one theme.

Start from something you already know

In Lesson 0.3 you learned the recursive return:

Gt = rt+1 + γ · Gt+1 "my return = the reward I get now + γ × the return from the next step"

Value is the expected return. Take the average of both sides, and "the return from the next step" becomes "the value of the next state". Why exactly V(s')? The Markov property (Lesson 2.1): once you land in s', the future doesn't care how you got there, so the return from there on averages out to the same number as if you had started in s', which is V(s').

V(s) = 𝔼[ r + γ · V(s') ] "the value of here = the average of (reward now + γ × value of wherever I land next)"
💡 Big idea You don't need to imagine the whole future. Just look one step ahead: value here = reward for the step + γ × value of where you land, averaged over what might happen. Every state's value is tied to its neighbors' values.
🧸 Analogy · asking your neighbors

Want to know how long it takes to drive home from here? Don't plan the whole route. Ask the next intersection: "how long from you?" Add the time to drive there. Done. If every intersection does this, the whole city ends up with correct travel times, just from neighbors talking to neighbors.

✏️ Worked example: one state's value, by hand

Made-up numbers. My policy goes ↑ half the time and → half the time. Going ↑ lands me somewhere worth 4; going → lands somewhere worth 8. Each step costs −1 and γ = 0.9.

  • Dry floor: V(here) = 0.5 × (−1 + 0.9 × 4) + 0.5 × (−1 + 0.9 × 8) = 0.5 × 2.6 + 0.5 × 6.2 = 4.4.
  • Now → is slippery: it lands on the cell worth 8 with probability 0.9, but slides onto the cell worth 4 with 0.1. Average over the two landings: 0.9 × (−1 + 0.9 × 8) + 0.1 × (−1 + 0.9 × 4) = 0.9 × 6.2 + 0.1 × 2.6 = 5.58 + 0.26 = 5.84.
  • Then V(here) = 0.5 × 2.6 + 0.5 × 5.84 = 4.22. Slipping costs a little value.

Each landing brings its own reward: if a slip could drop you onto the 💎, that branch would use r = +10 while the others use −1.

The big equation below is exactly this arithmetic with letters: an average over my actions (the 0.5s), and inside it an average over where the world might send me (the 0.9 and 0.1). The r inside the brackets is the reward for that particular landing.

Vπ(s) = Σa π(a|s) Σs' P(s'|s,a) [ r + γ Vπ(s') ] "average over my actions, then average over where the world sends me, of (reward + discounted value of landing spot)"

It looks scary, but it's just two nested for-loops:

def bellman_value(s, V, policy, P, gamma):
    v = 0
    for a, prob_a in enumerate(policy[s]):            # Σ over actions, weighted by π(a|s)
        for p, s_next, r, done in P[s][a]:            # Σ over outcomes, weighted by P(s'|s,a)
            v += prob_a * p * (r + gamma * (0 if done else V[s_next]))
    return v
Math refresher Weighted averages, recursion, and max

Weighted average: Σ p · x

Your exam is 70% final + 30% homework. Final 80, homework 100 → 0.7·80 + 0.3·100 = 86. The Bellman equation does this twice: weights from the policy, then weights from the world.

An equation that refers to itself

V appears on both sides. That's like a recursive function, e.g. fib(n) = fib(n-1) + fib(n-2). It isn't circular nonsense, it's a consistency rule (like a spreadsheet where cells reference each other: the solver keeps recalculating until every cell agrees): the true values are the numbers that make every state agree with its neighbors at the same time. (Next lesson: how to find those numbers.)

max instead of average

Average = "what happens if I act according to my policy". max = "what happens if I always pick the best action". Swapping one for the other is the only difference between the two versions below.

The optimal version

What's the value of a state if you act perfectly? (The star in V* and Q* means "optimal".) Replace "average over my policy's actions" with "take the best action". Why does the max sit outside the sum over s'? Because you choose the action, so you take the best one, but you don't choose where you slip, so you still average over the landing spots.

V*(s) = maxa Σs' P(s'|s,a) [ r + γ V*(s') ] The Bellman optimality equation: "the value of here, if I play perfectly from now on"
Q*(s,a) = Σs' P(s'|s,a) [ r + γ maxa' Q*(s',a') ] Same idea for Q. Remember this one: it's exactly what Q-learning (Phase 3) and DQN (Phase 4) learn.

Once you have V* or Q*, the optimal policy is simply: in every state, pick the action with the best one-step lookahead.

🌍 Where it's used
Bellman optimality, no dice 🏭 In production · 1988 RIP, an internet routing protocol (RFC 1058)

How: state = the router a packet is at · action = which neighbor gets it · each router's distance D = min over neighbors of [link cost + neighbor's D]. Costs, so min replaces max.

Why this method: each router only needs its neighbors' numbers, so best routes emerge from local swaps with no central map. The RFC says it's “based on Bellman's equation”.

Bellman optimality with chance 📜 History · 1979 Cox–Ross–Rubinstein tree for American options

How: state = (stock price, date) on a tree of up/down moves · action = cash in now or wait · value = max(payoff now, discounted average of the two next nodes' values).

Why this method: an option you may use on any day is a stop-or-continue decision. One Bellman max per node, backed up from expiry, prices it; finance libraries still ship this.

🤯 Fun fact · the principle of optimality

Bellman's key insight: any piece of an optimal path is itself optimal. If the fastest Delhi → Mumbai route goes through Jaipur, then its Jaipur → Mumbai part must be the fastest Jaipur → Mumbai route. Otherwise you could swap in a faster one and beat the "fastest" route. The Bellman optimality equation is this principle written in math.

🌉 LLM bridge · the value of a half-written answer

For a math problem with reward 1 (correct) or 0 (wrong) and γ = 1, V(prompt + partial solution) = the probability this half-written solution ends up correct.

Bellman says: V(partial) = the average over possible next tokens of V(partial + token). A solution that's on track has high value, and one that just made an algebra mistake has its value drop sharply. Process reward models and value-guided search for reasoning models (Phase 8) are attempts to learn this function, so a model can tell mid-solution whether it's going wrong.

Check yourself ✅

1. Deterministic world, γ = 0.9. From s, action → gives r = −1 and lands in s' with V(s') = 10. Under a policy that always goes →, what's V(s)?
−1 + 0.9 × 10 = −1 + 9 = 8.
2. Slippery: action → lands in s'₁ (V = 10) with 0.9, or s'₂ (V = 0) with 0.1. Every step gives r = −1, γ = 1. What's Q(s, →)?
0.9 × (−1 + 10) + 0.1 × (−1 + 0) = 8.1 − 0.1 = 8.
3. What's the only difference between the Bellman expectation and optimality equations?
Expectation: "how good is it to follow π?" (average). Optimality: "how good is it to play perfectly?" (max). The world's randomness is averaged in both.
📝 TL;DR
  • Bellman: V(s) = average of [ r + γV(s') ]. Value here = reward now + discounted value of where you land.
  • Expectation version (follow π: average over actions) vs. optimality version (max over actions).
  • It's a consistency rule: the true values make every state agree with its neighbors.
  • Q*(s,a) = Σ P [r + γ max Q*(s',a')]: the target behind Q-learning and DQN.
