Phase 2 · Lesson 5

Policy evaluation & policy iteration

How to actually solve the Bellman equation: guess, fix the guess, repeat. Then use the values to build a better policy.

🧰 You'll need (quick reminders)
  • Bellman equation: value here = reward + γ × value of where you land, averaged (Lesson 2.4).
  • Acting greedily = in each state, pick the action that looks best ("argmax").
🎯 Hook

Grab a calculator, set it to radians, type any number, and press cos over and over. Whatever you start with, the display settles on 0.739085…, the number where cos(x) = x.

Solving the Bellman equation works the same way: keep applying it, and the values settle on the true answer.

Math refresher Fixed points: repeat until nothing changes

A fixed point of a function f is a value x where f(x) = x: applying f doesn't change it. Some functions pull every starting point toward their fixed point, so you just apply them again and again.

The Bellman update is such a function. Why does it converge? Each update multiplies the errors from neighbors by γ < 1. With γ = 0.9 the error shrinks to at most 90% each sweep: after 10 sweeps ≤ 35% (0.9 multiplied by itself 10 times ≈ 0.35), after 50 sweeps ≤ 0.5%. (Mathematicians call this a contraction.) This needs γ < 1, or a policy that is guaranteed to reach the end. With γ = 1 and a policy that bumps into a wall forever, the values slide off toward −∞ and never settle.

Step 1: Policy evaluation

💡 Big idea To find Vπ: start with all values = 0, then sweep over every state, replacing its value with the Bellman one-step lookahead using the current guesses. Repeat until the values stop changing.
🧠 Analogy: improving your commute

First, measure how long your current route takes from every intersection (evaluate). Then, at each intersection, ask: "given those times, is there a better turn here?" and switch where there is (improve). Measure the new route, improve again. After a few rounds nothing changes: you've found the best route.

V = {s: 0 for s in states}
while True:
    new_V = {s: bellman_value(s, V, policy, P, gamma) for s in states}   # one sweep
    delta = max(abs(new_V[s] - V[s]) for s in states)
    V = new_V
    if delta < 1e-6: break                                         # stopped changing (by less than 0.000001) → done

Unlike Monte Carlo (Lesson 2.3), there's no randomness and no sampling. We use the model P to average over every outcome exactly. Each sweep, information spreads one step further from the rewards.

Step 2: Policy improvement

Now that we know Vπ, look one step ahead from every state and switch to the best action:

πnew(s) = argmaxa Σs' P(s'|s,a) [ r + γ Vπ(s') ] "in each state, pick the action with the highest Q-value under the old policy". This is called acting greedily with respect to V.

The policy improvement theorem (in plain English): the new greedy policy is never worse than the old one, in any state. Why? Picture switching only the first move: in state s, take the greedy action once, then go back to the old π. That's worth Qπ(s, greedy action) ("take this action, then follow π"), which is at least Vπ(s), because the greedy action won the one-step lookahead and the old action was one of the candidates. Now make the same switch in the next state you reach, and the next: each switch can only help, so following the new policy everywhere is at least as good. If it isn't strictly better anywhere, you've already found the optimal policy.

✏️ Worked example: an improvement that flips an action

A row of cells: [wall] A, B, 💎. Each step costs −1, stepping onto 💎 gives +10 instead, γ = 0.9. A silly starting policy: in A go ← (bump the wall), in B go →.

  • Evaluate. V(B) = +10 (straight onto the gem; the gem itself is worth 0). A bumps the wall and stays in A forever: V(A) = −1 + 0.9 × V(A). Solve: 0.1 × V(A) = −1, so V(A) = −10 (the same as −1 − 0.9 − 0.81 − … forever).
  • Improve A. ← : −1 + 0.9 × (−10) = −10. → : −1 + 0.9 × V(B) = −1 + 9 = 8. Switch A to →! (That 8 is the theorem in action: change only A's first move, keep the old policy after it, and you already beat −10.)
  • Improve B. → : 10. ← : −1 + 0.9 × (−10) = −10. Keep →.
  • Evaluate again. V(B) = 10, V(A) = −1 + 0.9 × 10 = 8. Improve again: in A, → 8 beats ← (−1 + 0.9 × 8 = 6.2); in B, → 10 beats ← (6.2). Nothing changes → optimal, after 2 rounds.
💻 Dev aha: a fixed policy's Bellman equation is a linear system

Look at A above: V(A) = −1 + 0.9 × V(A) is one equation with one unknown, solved by algebra, no sweeps. With N states you get N equations in N unknowns, all linear (no max, because the policy is fixed). So numpy can solve them in one call:

V = np.linalg.solve(np.eye(N) - gamma * P_pi, r_pi)
# P_pi[i][j] = chance of going from state i to j under π (columns for 💎/🔥 left out: they're worth 0)
# r_pi[i]    = average reward of one step from state i under π

That's instant for our 20 non-terminal cells, but the cost grows like N3. Each sweep only touches every state once, so when states number in the millions, sweeps win.

Step 3: Repeat → policy iteration

Why can't it go round in circles? Each round either changes nothing (then you stop) or makes some state strictly better and none worse. So once you leave a policy, you can never come back to it. There are only finitely many policies (420 here), so the loop must end. (One detail: when two actions tie, always break the tie the same way, or the policy could flip between equally good choices forever.)

🔬 Generalized Policy Iteration (GPI)

Sutton & Barto point out that almost every RL algorithm is this same loop in disguise. Some part of the system estimates values, another part improves the policy using them, and the two chase each other until they agree. You don't even need to evaluate fully before improving: one sweep is enough (that's the next lesson). Keep this picture in mind for the rest of the course.

🌍 Where it's used
Policy evaluation 📜 History · 1993 Sonnenberg & Beck: Markov models in medical decision making

How: state = Well, Disabled or Dead, one hop per cycle · policy = a fixed treatment plan · reward = life-years (often quality-adjusted) · output = V of each plan.

Why this method: doctors usually compare a handful of fixed strategies. Evaluating each one, then picking the best, is enough: no search over every possible policy needed.

Policy improvement 📜 History · 1996 Tesauro & Galperin: backgammon rollouts

How: for each legal action, simulate many games that then follow a base policy, average the results (≈ Q), and play the best one: one greedy improvement step.

Why this method: improvement is never worse, so it upgrades any player. It cut the error rate of base players, from random up to TD-Gammon, by as much as 5× or more.

Policy iteration (GPI) 🧪 Research · 2017 DeepMind AlphaGo Zero

How: a lookahead search picks better moves than the network alone (improve), self-play games score them (evaluate), the network learns the improved policy and V, repeat.

Why this method: exact sweeps over Go's states are impossible, but the evaluate ↔ improve loop still works. The paper calls its search “a powerful policy improvement operator” inside “a policy iteration procedure”.

🤯 Fun fact

Policy iteration was introduced by Ronald Howard in his 1960 book Dynamic Programming and Markov Processes, based on his MIT doctoral work. Howard went on to found the field of decision analysis at Stanford, which helps businesses and governments make big decisions under uncertainty.

🌉 LLM bridge · evaluate-and-improve loops everywhere
  • Actor-critic (Phase 5) and PPO for RLHF (Phase 7) are GPI with neural networks: the critic evaluates (learns V), the actor improves (the LLM policy), and they alternate on every batch.
  • Self-improvement loops for LLMs, like STaR and rejection-sampling fine-tuning (Phase 7), look a lot like policy iteration: generate many answers (current policy), evaluate them with a checker, train on the best ones (improve), and repeat.

Check yourself ✅

1. Policy evaluation starts with V = 0 everywhere. Why does it still reach the right answer?
The Bellman update is a contraction, like pressing cos on a calculator: the start doesn't matter, it always settles on the same fixed point.
2. What does "policy improvement" do?
Greedy with respect to Vπ. The policy improvement theorem guarantees the result is at least as good everywhere.
3. When does policy iteration stop?
If the greedy policy equals the current policy, the values satisfy the Bellman optimality equation, so you're done. With finitely many policies, this is guaranteed to happen.
📝 TL;DR
  • Policy evaluation: repeat Bellman sweeps from V = 0 until the values stop changing → Vπ.
  • Policy improvement: act greedily on the lookahead. Never worse, usually better.
  • Policy iteration: alternate the two until the policy stops changing → optimal policy, usually in a few rounds.
  • This evaluate ↔ improve loop (GPI) is the skeleton of actor-critic, PPO and LLM self-improvement.
