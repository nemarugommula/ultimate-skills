Value functions: "how good is it to be here?"

If you know how much future reward each state is worth, picking good actions becomes easy.

🧰 You'll need (quick reminders)
  • Return G = total (discounted) reward from now until the end (Lesson 0.3).
  • Policy π = the agent's rule for picking actions (Lesson 0.2).
  • Expected value = the long-run average over all the ways things could turn out (Lesson 1.1).
🎯 Hook

Watch any online chess broadcast and you'll see a bar next to the board, "+1.5" or "−3.2". That's a chess engine's evaluation: how good this position is for White, in pawns.

+1.5 White
Black

That bar is a value function. AlphaGo had one too: a "value network" trained on 30 million positions to predict who would win from any board.

💡 Big idea The value of a state is the return you can expect from here on, if you keep following your policy. It sums up all possible futures as one number: "how good is it to be here?"
🧸 Analogy · Google Maps' ETA

At every intersection your GPS knows the time remaining to your destination. That's a value function (with a minus sign: less time = better). To choose a turn, you look at where each turn takes you and pick the one with the best remaining time. Values make decisions simple.

Two kinds of value

Two reminders first: Gt = "total discounted reward from now on" (Lesson 0.3), and 𝔼 = "average over all the ways the future could go". The superscript π just says "while following policy π". So the first line literally says: the average return if I start in s.

Vπ(s) = 𝔼π[ Gt | St = s ] "state value: the expected return if I start in s and follow policy π"
Qπ(s, a) = 𝔼π[ Gt | St = s, At = a ] "action value: the expected return if I take action a in s, then follow π afterwards"
📍

V(s): "how good is this place?"

One number per state. Chess evaluation bar. GPS time-to-go.

🕹️

Q(s,a): "how good is this move here?"

One number per (state, action). The best action is simply argmaxa Q(s,a) ("the a that makes Q biggest": the tallest bar). You saw Q in bandits!

The two are linked: V is the policy-weighted average of the Q's:

Vπ(s) = Σa π(a|s) · Qπ(s,a) If I go ↑ half the time (Q=4) and → half the time (Q=8), my state is worth 0.5·4 + 0.5·8 = 6.
Math refresher Expected value over branching futures

From any state, the future branches: your random actions and a random world can lead to many different episodes, each with its own return G.

𝔼[G] = the average return over all those possible futures, weighted by how likely each one is. Same idea as the die's 3.5 in Phase 1.

How do we compute it? The simplest way, called Monte Carlo (named after the casino): play the future out many times and average. By the Law of Large Numbers, the average approaches the true value. That's exactly what the playground below does.

def estimate_V(s, policy, n=200):
    returns = [play_episode_from(s, policy) for _ in range(n)]
    return sum(returns) / n        # average return = value estimate
✏️ Worked example: a value by hand, two ways

1. Monte Carlo. Play the future out 3 times from a cell. The returns are −3, +5 and −8. Average: (−3 + 5 − 8) / 3 = −6 / 3 = −2. That's your estimate of V(s). (Three rollouts is far too few; the playground uses 200.)

2. From Q to V. Take the cell just left of the 💎, (0,3), under the random policy (γ = 0.9). Its four Q-values (from the exact solver):

  • ↑ bumps the top edge and stays put: Q = −3.45
  • → steps onto the 💎: Q = +10
  • ↓ steps into the 🔥: Q = −10
  • ← wanders back left: Q = −7.44

The random policy picks each with probability 0.25, so V = 0.25 × (−3.45 + 10 − 10 − 7.44) = 0.25 × (−10.89) ≈ −2.72. One great move and one terrible one, averaged with two mediocre ones.

Why are 💎 and 🔥 themselves worth 0? Look at Q(→) = +10 exactly. The +10 is paid for stepping onto the gem, and then the episode is over: from the gem itself no more reward can ever come, so V(💎) = 0. The gem's reward shows up in its neighbour's value, not its own.

🌍 Where it's used
State value V: “how good is this board?” 🧪 Research · 2016 DeepMind AlphaGo: the value network

How: state = a Go board · reward = win or lose at the end · V(s) = a neural network's estimate of the expected outcome from this position.

Why this method: Go has far too many possible games to play each one out. A good V lets the search judge a position on the spot, without playing to the end.

Action value Q: “how good is this move?” 🧪 Research · 1993 Boyan & Littman: Q-routing for network packets

How: state = (this router, packet's destination) · action = which neighbor to pass it to · Q = estimated delivery time via that neighbor (a cost, so lower is better).

Why this method: Q scores each move directly, so a router just picks the neighbor with the best Q, using only messages from its neighbors. It beat fixed shortest-path routing under heavy load.

🤯 Fun fact

TD-Gammon (1992) never learned a policy directly. It only learned a value function: "how likely am I to win from this board?" To move, it simply tried each legal move, looked at the resulting board, and picked the one with the highest value. A good value function was enough to play at expert level.

🌉 LLM bridge · the critic, and why GRPO dropped it

In RLHF with PPO (Phase 7), alongside the LLM there's a second network called the value model or critic. It reads a prompt plus a partly written answer and predicts V: "how much reward will this answer end up getting?" It's usually about as big as the LLM itself, so it costs a lot of memory and compute.

GRPO (DeepSeek, Phase 8) threw it away. Instead, it samples a group of answers to the same prompt and uses their average reward as the value estimate. That's exactly Monte Carlo estimation of V(prompt), the method in this lesson's playground, just with 8–64 rollouts instead of 200.

Check yourself ✅

1. What does Vπ(s) measure?
Value = expected return (all future rewards), not just the immediate reward. And it depends on the policy you follow afterwards.
2. You have Q(s, a) for every action. How do you act well?
Q already includes the long-term consequences, so the greedy choice on Q is a far-sighted choice. That's why Q-learning (Phase 3) and DQN (Phase 4) learn Q.
3. π picks ↑ with 0.25 (Q=−2), → with 0.75 (Q=6). What's V(s)?
0.25 × (−2) + 0.75 × 6 = −0.5 + 4.5 = 4. V is the policy-weighted average of Q.
📝 TL;DR
  • Vπ(s) = expected return from state s under π: "how good is this place?"
  • Qπ(s,a) = expected return after taking a in s, then following π: "how good is this move?"
  • V = Σ π · Q. Best action = argmax Q.
  • Monte Carlo estimates values by averaging many played-out futures. It works but it's slow and noisy. GRPO's group average is the same idea.
