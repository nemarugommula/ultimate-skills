Phase 2 · Lesson 6

Value iteration

A shortcut: skip the full evaluation and go straight for the optimal values, one sweep at a time.

🧰 You'll need (quick reminders)
  • Bellman optimality equation: value = best action's (reward + γ × value of landing spot) (Lesson 2.4).
  • Policy iteration: evaluate fully, then improve, repeat (last lesson).
🎯 Hook

In 1958, Bellman published a shortest-path algorithm now called Bellman–Ford. The early ARPANET, the ancestor of the internet, routed messages with a distributed version of it: every router repeatedly asked its neighbors "how far are you from destination X?" and kept the best answer plus one hop. Its descendant RIP (the Routing Information Protocol, still found in small networks) runs the same distance-vector idea: dynamic programming on a graph of routers.

That's value iteration. You'll watch it happen in the playground below.

💡 Big idea Use the Bellman optimality equation directly as an update: in every sweep, set each state's value to the best one-step lookahead. Values spread out from the rewards like ripples in a pond, and settle on V*.
🧠 Analogy: news spreading through a village

Only the house next to the treasure knows it's there. Each day, every house asks its neighbors "how close are you to the treasure?" and updates its own answer. On day 1 only the treasure's neighbor knows; on day 2 its neighbors know; and so on. After enough days, every house knows the best way there. Each "day" is one sweep of value iteration.

Vk+1(s) ← maxa Σs' P(s'|s,a) [ r + γ Vk(s') ] "new value = the best action's (reward + discounted old value of where it lands)" 
V = {s: 0 for s in states}
while True:
    new_V = {s: max(q_values(s, V)) for s in states}     # max instead of policy-average
    if max(abs(new_V[s] - V[s]) for s in states) < 1e-6: break
    V = new_V
policy = {s: argmax(q_values(s, V)) for s in states}  # read off the optimal policy at the end

Compared with policy iteration, the only change is max instead of the policy's average. There's no separate policy to evaluate. Improvement happens inside every single sweep.

Experiments (use the preset buttons)

  1. 🌊 Ripple: press "1 sweep" slowly. After sweep 1, every cell only knows "a step costs −1", except the cells right next to 💎/🔥. Each sweep, news of the gem spreads one cell further. Watch V(start): it drops for 7 sweeps (−1, −1.9, −2.7, …) because all it knows about is step costs. At sweep 8 it jumps to −0.43, because the gem is 8 steps away.
  2. 🧊 Very slippery (slip 0.3, γ = 0.99): on a dry floor, "up first" and "right first" tie at the start. Now the robot commits to right along the bottom row, then up the right edge. Along an edge, a slip into the wall just costs a step. It can't dodge the lava completely: both of the gem's neighbours touch 🔥, so every route ends with a risky last step. Risk changes the best plan.
  3. 😱 Desperate robot (every step costs −11): the robot walks straight into the lava! Reaching the gem takes 8 steps (7 × −11 + 10 = −67), while lava takes 6 (5 × −11 − 10 = −65). With a step cost worse than −10, ending it early is "optimal".
  4. 😴 Lazy robot (step reward +2, γ = 0.9): it refuses to finish. Bumping into a wall forever earns 2 + 2·0.9 + 2·0.9² + … = 2/(1−0.9) = 20, more than the gem's 10. Run the robot and watch it dodge the 💎.
  5. 🙈 Short-sighted (γ = 0.5): the gem's value fades fast with distance. Far-away cells have values near −2 and barely "feel" the gem: 10 × 0.57 ≈ 0.08.
⚠️ The lesson behind experiments 3 and 4

The algorithm did nothing wrong. It found the truly optimal policy for the rewards it was given. The rewards were badly designed. This is reward hacking from Lesson 0.3 again: getting rewards right is often harder than the algorithm itself.

✏️ Worked example: watch the news spread

A row: A → B → C → 💎. Each step −1, stepping onto 💎 +10, γ = 0.9. All values start at 0; each sweep uses the previous sweep's values.

The gem's "news" travels one cell per sweep. Before it arrives, A only knows that steps cost −1, so its value drops at first (just like the start cell in the playground).

Why does it converge? After k sweeps, Vk(s) is exactly the best return you can collect within k steps from s. That's why the start cell only "sees" the gem at sweep 8. As k grows, the steps beyond k matter less and less (they're discounted by γk, or the episode has already ended), so Vk closes in on V*.

Also notice: the greedy arrows stop changing long before the numbers do. On the 🧊 preset the arrows settle after about 11 sweeps, while the values need about 31 to stop moving. That's why policy iteration needs so few rounds: it only has to get the arrows right.

The catch: why we can't stop here

📖

1. It needs the rulebook

Dynamic programming needs the model P and R. A real robot, a game opponent or a human user doesn't hand you a transition table. → Phase 3: learn from experience instead.

💥

2. It sweeps every state

22 cells is fine. Backgammon has ~1020 states, Go ~10170, an LLM ~105000. → Phase 4: neural networks that generalize between similar states.

🌍 Where it's used
Value iteration, backwards in time 🏭 In production · 2017 Real-time bidding for display ads

How: state = (auctions left, budget left, this ad request) · action = the bid price · reward = a click · V(auctions left, budget left) filled in by dynamic-programming sweeps.

Why this method: a bid now spends budget you may need later, so judging each auction alone overspends. The system was deployed on a commercial ad platform and A/B-tested online.

The curse of dimensionality 🏭 In production · 2010 Schneider National: planning 6,000+ truck drivers

How: state = where every driver and load is · action = which driver takes which load · V = an approximate value for each type of driver (by home base), not a full table.

Why this method: an exact table over thousands of drivers is hopeless; approximate values still let decisions look ahead like an expert dispatcher. Schneider used it for real calls (better driver bases: ~$5M/year).

🤯 Fun fact

Bellman coined the phrase "the curse of dimensionality" for problem #2: every extra variable in the state multiplies the number of states. A robot arm with 7 joints, each with 100 possible angles, has 1007 = 100 trillion configurations. Sweeping them all is hopeless, and that problem shaped decades of RL research.

And the name "dynamic programming"? By his own account, Bellman chose it to hide that he was doing mathematical research: the Secretary of Defense, Charles Wilson, had "a pathological fear and hatred of the word, research". "Programming" then meant planning, as in "linear programming", and "dynamic" was hard to object to.

🌉 LLM bridge · planning at test time

For an LLM we do have a perfect model (append a token), but sweeping 105000 states is impossible. So we plan only locally, from the current state:

  • AlphaGo/AlphaZero run tree search a few moves ahead from the current board, using a learned value network at the leaves. It's a Bellman backup on a small tree instead of the whole game.
  • Reasoning models do something similar inside their chain of thought: try an approach, judge if it's promising, and back up. Research systems make this explicit with tree search over reasoning steps, guided by value or reward models (Phase 8).

Check yourself ✅

1. What's the key difference between a value iteration sweep and a policy evaluation sweep?
Same one-step lookahead, different aggregation: max (optimality) vs. π-weighted average (expectation).
2. Starting from V = 0, the start cell's value drops for 7 sweeps, then suddenly jumps up at sweep 8. Why?
Each sweep extends the lookahead by one step. After k sweeps, Vk(s) is the best return achievable within k steps. Within 7 steps the gem is out of reach, so all the start cell sees is −1 per step.
3. Value iteration says the best move is to jump into the lava. What's most likely wrong?
DP finds the optimal policy for the rewards you gave it. If that policy looks crazy, check the rewards first.
📝 TL;DR
  • Value iteration: repeat V(s) ← maxa Σ P [r + γV(s')] until it converges → V* → greedy policy is optimal.
  • Values ripple outward from rewards one step per sweep.
  • Optimal for the given rewards. Badly designed rewards give "optimal" but crazy behavior.
  • DP needs a model and sweeps every state. Fixing those two problems is what Phases 3 and 4 are about.
