🧾 Cheat sheet

Why policies

Learn πθ(a|s) directly: continuous and huge action spaces, stochastic optimal policies, smoother learning. Softmax(scores / T) → probabilities. An LLM is one of these.

Policy gradient (REINFORCE)

∇J = 𝔼[G · ∇log πθ(a|s)] via the log-derivative trick. Loss = −Σ Gt log π(at|st) = reward-weighted supervised learning on your own samples.

Baselines & advantage

Use A = G − b(s). No bias (𝔼[b∇log π] = 0), much less variance. b ≈ V(s) (critic), group mean (GRPO), leave-one-out (RLOO).

Actor-critic

Critic learns V by TD. Actor uses δ = r + γV(s') − V(s) as its advantage. A2C/A3C: parallel environments for decorrelated on-policy data.

GAE(λ)

Ât = Σ (γλ)l δt+l = δt + γλÂt+1. λ = 0 TD (biased, low variance), λ = 1 MC (unbiased, noisy). Typical λ = 0.95.

PPO

ρ = πnew/πold. L = 𝔼[min(ρÂ, clip(ρ, 1±ε)Â)] + value loss − entropy bonus. Several epochs per batch. TRPO = the KL-constrained version.

LLM links

RLHF = PPO + KL(π ‖ πref) penalty, 4 models (actor, critic, reward, reference). GRPO = PPO-clip with group-mean advantages and no critic. DAPO = asymmetric clip.

🗂️ Case files: five real problems, one phase later

The same five problems follow you through the course (meet them). Here's what this phase changes for each.

🌡️ The cooling plant

Now: a bell-curve policy outputs every fan speed and setpoint directly as continuous numbers, and a critic predicts the energy cost. You could train it with PPO in a simulator of the building.

Still breaks: these methods learn from fresh trial and error, which a real data centre can't afford, and nothing in them guarantees the safety limits hold.

📱 The feed

Now: a softmax policy over millions of videos, trained with REINFORCE on logs and corrected for the older system that chose them: what YouTube shipped (Lesson 5.2).

Still breaks: before launching a new policy you can only guess how it will do; you need a trustworthy estimate from old logs alone.

🦾 The robot hand

Now: PPO in simulation with randomized physics. OpenAI's Rubik's Cube hand trained this way on about 13 thousand years of simulated experience (Lesson 5.6).

Still breaks: PPO throws its data away after a few passes: fine in a simulator, far too wasteful for learning on a real robot.

♟️ The board game

Now: a policy network gives every legal move a probability, trained first on expert games and then by self-play, as in AlphaGo (Lesson 5.1).

Still breaks: one pass of a network doesn't look ahead; the strongest players combine the network with a search over future moves.

🧑‍💻 The coding agent

Now: the LLM is a softmax policy: sample a patch, reward = the tests pass, update with PPO plus a KL leash to the starting model (how InstructGPT was tuned for helpfulness).

Still breaks: from scratch it would never stumble on a passing patch; it first has to learn to write code from examples, and many tasks have no tests to reward it.

🧩 Frame it yourself

🧩 New problem

A family has rooftop solar panels and a home battery. Electricity prices change every 15 minutes, and they can sell power back to the grid. Every 15 minutes the controller chooses how fast to charge or discharge the battery. The goal: the lowest bill without wearing the battery out.

Before you open the answer, write down: the state, the action, the reward, episodic or continuing (and γ), and which method from this phase (or earlier) you'd try first.

Reveal One good framing + the classic mistakes

State: battery charge, time of day, current and forecast prices, forecast solar output, the house's demand. Action: charge or discharge power in kW, any number between −max and +max. Reward: −(money spent − money earned) each step, minus a small wear cost per kWh moved. Episodic? Continuing (every day follows the last), γ ≈ 0.99 per 15-minute step, so roughly a day of look-ahead.

Method: PPO with a bell-curve (Gaussian) policy and GAE, trained in a simulator replaying a year of the home's prices, sunshine and demand. The action is continuous, so a policy that outputs the number beats DQN, which would have to chop it into a few coarse levels.

Classic mistakes: leaving time of day or prices out of the state (3 a.m. and 6 p.m. look identical: not Markov); no wear cost (it cycles the battery to death for pennies); not enforcing the battery's charge limits; testing on the same days you trained on.

🔬 Implementation details that matter (look for them in the code)
  • Advantage normalization per minibatch (mean 0, std 1).
  • Gradient clipping (max norm 0.5).
  • Time-limit handling: when CartPole truncates at 500 steps, PPO bootstraps from the critic instead of pretending the episode ended.
  • Entropy bonus (0.01) to keep exploring.

Try removing one at a time and see what breaks. That's how you build intuition, and it's how the "37 implementation details" post was written.

Boss quiz 👾

Rewards [0, 0, 1], critic V = [0.5, 0.5, 0.5, 0] (last = terminal), γ = 1, λ = 0. What are the advantages?
λ = 0 → Â = δ. δ0 = 0 + 0.5 − 0.5 = 0, δ1 = 0 + 0.5 − 0.5 = 0, δ2 = 1 + 0 − 0.5 = 0.5.
A bad action (Â = −1) now has ratio ρ = 1.5 (an update accidentally made it more likely). Does PPO clip its gradient?
The min() is pessimistic: it only clips when moving further would look better, never when it would fix a mistake.
Which piece of PPO does GRPO remove?
GRPO replaces V(s) with the mean reward of a group of sampled answers to the same prompt, saving a whole LLM-sized network.
🚀 What's next: Phase 6

🏁 Milestone: you've built PPO from scratch, the same core algorithm that trained OpenAI Five and ChatGPT's RLHF. Bandits → MDPs → TD → deep RL → policy gradients: that's the core of RL.

Phase 6 fixes PPO's remaining weak spots, one lesson each: continuous control that reuses old data (DDPG, TD3, SAC: actor-critics with a replay buffer), learning a model of the world to plan with (MuZero, Dreamer), learning from a fixed dataset with no new interaction (offline RL), exploring when rewards are rare (curiosity, the Montezuma's Revenge fix), self-play, and imitation.
