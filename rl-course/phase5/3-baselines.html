Phase 5 · Lesson 3

Baselines & the advantage

Don't ask "was this good?". Ask "was this better than usual?". One subtraction cuts the noise a lot.

🧰 You'll need (quick reminders)
  • REINFORCE: push up each action in proportion to its return G (last lesson).
  • V(s) = the return you'd typically get from state s (Lesson 2.3).
🎯 Hook

A student who usually scores 95% gets 90% on a test. A student who usually scores 40% gets 70%. Who deserves praise? Raw scores say the first one. Compared to their usual, it's clearly the second. REINFORCE as written praises the 90%. This lesson fixes that.

The problem: all-positive rewards

In CartPole every step gives +1, so every return is positive. Plain REINFORCE then pushes every action up after every episode, just some more than others. The useful signal ("this was better than that") is buried under a huge shared push. Here's the mechanism: probabilities add up to 1, so pushing the sampled action up pushes the others down. If every G is positive, whichever action you happened to sample wins, and the direction of learning comes from sampling luck, not from which action is better. In the playground below, with every reward shifted up by 10, about 1 run in 3 ends up over 90% sure of a wrong arm (over half at +20). With a baseline: none.

💡 Big idea Subtract a baseline b(s), a guess of the typical return from this state. Use the advantage A = G − b(s) instead of G. Better than usual → push up. Worse than usual → push down. And it doesn't bias the gradient at all.
🧠 Analogy: judging a salesperson

A salesperson who usually sells 100 units sells 90 this month. Is that good? Not for them: it's below their normal. Another who usually sells 20 sells 40: great month. Judging against the usual (the baseline) tells you what to reinforce. Judging by raw numbers would praise both.

∇θ J = 𝔼[ ( G − b(s) ) · ∇ log πθ(a|s) ] The best common choice: b(s) ≈ V(s), the expected return from s. Then G − V(s) estimates the advantage A(s,a) = Q(s,a) − V(s).
🎮 Playground · Same bandit, everything shifted up

The 3-armed bandit from 5.2 (true means −1, 0, +1) plus a constant offset added to every reward. The offset changes nothing about which arm is best. We compare REINFORCE with and without a baseline (a running average of rewards), averaged over 50 runs.

With offset 0, both do fine. Crank the offset to 10–20: without a baseline every pull gets a big positive push, so the policy locks onto whichever arm got lucky early. With a baseline the offset cancels out, and the result looks the same as with no offset.

Math refresher Why subtracting a baseline adds no bias

The whole proof in words: probabilities must add up to 1, whatever the weights θ are. Something that never changes has a slope of zero. The baseline term is just b × (the slope of that always-1 sum), so on average it adds exactly nothing. It never pushes the wrong way; it only cancels shared noise.

In symbols, for the curious: 𝔼[ b · ∇log π(a) ] = b · Σa π(a) ∇log π(a) = b · Σa ∇π(a) = b · ∇(Σa π(a)) = b · ∇(1) = 0. (The second step uses π·∇log π = ∇π from Lesson 5.2.)

The probabilities always sum to 1, so the gradient of that sum is zero. On average the baseline contributes nothing, but it cancels a lot of the noise in each individual update. Lower variance, same expected direction. (The only rule: b must not depend on the action taken.)

✏️ Worked example: all-positive returns

CartPole gives +1 per step, so returns are always positive. Three episodes return 20, 25 and 30.

  • Without a baseline: all three push their actions up (by 20, 25, 30). The difference between good and bad is buried in a huge shared push.
  • With baseline 25 (the average): advantages are −5, 0, +5. The bad episode's actions get pushed down, the average one isn't touched, the good one gets pushed up. Same direction on average, far less noise.

🌍 Where it's used
Baseline = the model's own greedy answer 🧪 Inside · 2017 IBM: self-critical training for image captions

How: state = the image + words so far · action = the next word · reward = how well the finished caption matches human ones. Advantage = sampled caption's score − the greedy caption's score.

Why this method: no critic to train: the baseline is what the model would say at test time anyway, so only captions that beat it get pushed up. It raised the best MSCOCO score from 104.9 to 114.7.

Baseline = a frozen copy's greedy route 🧪 Inside · 2019 Kool et al.: learning delivery routes

How: state = the stops left to visit · action = the next stop · reward = −tour length. Advantage = how much shorter this tour is than the greedy tour of the best model so far.

Why this method: the authors found this simple baseline more efficient than learning a value function. With the same settings it learned strong heuristics for travelling-salesman and vehicle-routing problems up to 100 stops.

Baseline = the group mean 🧪 Inside · 2025 DeepSeek-R1 (trained with GRPO)

How: state = a math or coding problem · action = a whole written answer · reward = rule-checked: is the final answer correct, and is the reasoning inside the required tags?

Why this method: a critic as big as the LLM costs a lot of memory. Scoring several answers to the same prompt and subtracting their mean gives a baseline for free (worked numbers in the LLM bridge below).

🤯 Fun fact

Williams' 1992 REINFORCE paper already included the baseline. It's the "Offset Reinforcement" in the name: the reward minus a reinforcement baseline. It took the field years to appreciate how much that offset matters in practice.

🌉 LLM bridge · GRPO's advantage, in one line

GRPO samples a group of, say, 8 answers to one math problem and checks each: rewards [1, 0, 0, 1, 0, 0, 0, 1]. The baseline is the group mean, 0.375. Correct answers get advantage +0.625 (push up), wrong ones −0.375 (push down). GRPO also divides by the group's spread (standard deviation), so advantages are measured in "how unusual was this answer for its group" units. And if all 8 are correct (or all wrong), every advantage is 0, so that prompt teaches nothing. That's why recent methods filter such prompts out (Phase 8).

📝 TL;DR
  • Use the advantage A = G − b(s) instead of the raw return G.
  • A baseline adds no bias (𝔼[b∇log π] = 0) and greatly reduces variance.
  • Best baseline ≈ V(s), learned by a critic. GRPO uses the group mean, RLOO the leave-one-out mean.
