GAE: Generalized Advantage Estimation

The λ dial from Lesson 3.5, applied to advantages. It's how PPO decides how much credit each action gets.

🧰 You'll need (quick reminders)
  • TD error δ = r + γV(next) − V(now): one step's surprise (Lesson 3.2).
  • λ: the dial between 1-step TD and full Monte Carlo (Lesson 3.5).
  • Advantage = how much better an action was than usual (Lesson 5.3).
🎯 Hook

In 2015, John Schulman and colleagues used GAE to teach simulated 3D robots to walk and run from scratch, with no hand-coded gait, just reward for moving forward. GAE then became the default advantage estimator inside PPO, and later inside the RLHF that trained ChatGPT.

💡 Big idea How much credit should an early action get for a reward ten steps later? Two extreme answers exist for the advantage (Â, read "A-hat": our estimate of how much better an action was than usual): δt (one TD step: low variance, but biased if the critic is wrong) and Gt − V(st) (Monte Carlo: unbiased, but noisy). GAE blends all the in-between options with a single knob λ.
🧠 Analogy: credit for a goal in football

A team scores. The final shot gets the most credit, the pass before it a good share, the pass before that a bit less, and so on back. λ decides how quickly credit fades as you go back in time: λ near 0 = only the last touch matters; λ near 1 = the whole build-up shares the credit.

Ât = δt + (γλ) δt+1 + (γλ)2 δt+2 + … ,   δt = rt + γV(st+1) − V(st) "add up the critic's surprises from now on, fading by γλ per step"

Bias vs variance, in plain words: bias = trusting a critic that might be wrong; variance = trusting noisy real rewards. λ picks which risk you'd rather take. λ = 0 trusts the critic after one step; λ = 1 trusts only real rewards.

It's computed with the same backward loop as discounted returns in Lesson 0.3:

adv = 0
for t in reversed(range(T)):
    delta = r[t] + gamma * V[t + 1] * (1 - done[t]) - V[t]
    adv   = delta + gamma * lam * (1 - done[t]) * adv     # Â_t = δ_t + γλ·Â_{t+1}
    A[t]  = adv
value_targets = A + V[:-1]                                 # the critic's new homework: V + measured advantage

Why A + V? Â is "how much better things went than the critic expected". Add the critic's own guess back and you get "how well things actually went": the λ-blended return (real rewards for a while, then the critic's later predictions). If the critic said 0.8 and Â = +0.2, the new target is 1.0. That's what the critic trains toward next.

✏️ Worked example: GAE over 3 steps

The critic's surprises at steps 0, 1, 2: δ = 0.2, −0.1, 1.0. With γ = 0.9 and λ = 0.95, each step back fades by γλ = 0.855. Work backwards:

  • Â₂ = 1.0
  • Â₁ = −0.1 + 0.855 × 1.0 = 0.755
  • Â₀ = 0.2 + 0.855 × 0.755 ≈ 0.85

Step 1 had a small negative surprise of its own, but it led to the big positive surprise at step 2, so it ends up with clearly positive credit.

🎮 Playground · Watch GAE assign credit

A 6-step episode where the only reward (+1) arrives at the very end, γ = 1. The critic's predictions V(st) are shown. Choose an accurate critic or a badly wrong one, then move λ.

  • Untrained critic, λ = 0: only the last step gets any credit (δ5 = 1). Earlier steps get nothing, so credit can't flow back through a critic that knows nothing.
  • Untrained critic, λ = 1: every step gets +1, the plain Monte Carlo answer. No critic needed, but in a noisy world those returns would vary a lot.
  • Wrong critic, λ = 0: the bad prediction at step 3 creates fake big advantages around it. That's bias. Raise λ and the errors largely cancel out along the chain.
  • Accurate critic, noisy rewards: tick the box and press 🎲 a few times. At λ = 1 the early bars jump around (each adds up to 6 noisy rewards). At λ = 0 each bar sees only one, so they move much less. That's variance.
Math refresher Why critic errors cancel when λ = 1 (telescoping)

With γ = λ = 1: Ât = δt + δt+1 + … = (rt + Vt+1 − Vt) + (rt+1 + Vt+2 − Vt+1) + … Every middle V appears once with + and once with −, so they cancel like a collapsing telescope, leaving Σ r − V(st) = Gt − V(st). The critic only acts as a baseline, which (Lesson 5.3) adds no bias.

🌍 Where it's used
GAE 🧪 Inside · 2019 OpenAI's Rubik's Cube robot hand

How: state = fingertip and cube positions · action = 20 joints, 11 settings each · reward = progress toward the goal, +5 per goal reached, −20 per drop. Advantages: GAE with γ = 0.998, λ = 0.95.

Why this method: rewards arrive many steps after the finger moves that earned them, and the critic is imperfect. GAE blends several steps of real reward with the critic's guess: less noise, without trusting the critic fully.

GAE 🧪 Inside · 2021 ETH Zurich: 4,096 simulated ANYmal robots learn to walk

How: state = body motion, joint angles and 108 terrain heights around the robot · action = target joint positions · reward = following the commanded speed and heading, plus smaller terms. GAE with γ = 0.99, λ = 0.95.

Why this method: GAE needs several real rewards in a row. The authors found learning failed when each robot contributed fewer than about 25 consecutive steps (0.5 s of simulated time).

🤯 Fun fact

John Schulman, first author of GAE (2015), TRPO (2015) and PPO (2017), went on to co-lead the team at OpenAI that built ChatGPT's RL fine-tuning. Much of the core math of modern LLM post-training traces back to a few of his papers.

🌉 LLM bridge · per-token credit

In PPO-based RLHF, the reward model's score lands on the last token (plus a small per-token KL penalty, a "don't drift from the original model" cost; next lesson and 7.4), and GAE with γ = 1, λ ≈ 0.95 spreads credit back over the tokens using the critic's predictions. GRPO skips all this and gives every token the same advantage (effectively λ = 1 with a group-mean baseline). For long reasoning and agent tasks, some 2025 work (for example ByteDance's VAPO) brought the critic and GAE back with tweaks such as a length-adaptive λ. Per-token credit assignment is still an open research question.

High λ relies more on real rewards and less on the critic's (bad) predictions, at the cost of more variance.
