🧾 Cheat sheet

LLM = policy

How it writes: text → token IDs → one pass scores every next token at every position → sample from the last position, append, repeat. Generating 500 tokens = 500 passes; scoring an existing answer = 1 pass. State = prompt + tokens so far. Action = next token (~100k). Deterministic transitions, reward at the end, γ = 1. log π(y|x) = Σ token log-probs (response tokens only). Sample at T ≈ 1 for RL.

Pipeline

Pretrain → (mid-train) → SFT (behavior cloning) → preference / RL stages → rejection sampling / distillation, often repeated. InstructGPT, Llama 3, Tülu 3, DeepSeek-R1.

Reward models

Bradley–Terry: P(A ≻ B) = σ(rA − rB). LLM + scalar head, loss −log σ(rc − rr). Learns labeler biases (length). ~73% human agreement.

RLHF (PPO)

max 𝔼[rφ] − β·KL(π ‖ πref). Optimum π* ∝ πref·exp(r/β). Per-token KL penalty + reward-model score at the end, GAE, 4 models. Over-optimization: proxy ↑, gold ↑ then ↓.

DPO family

r = β log(π/πref) + const → L = −log σ(β[Δc − Δr]). Offline, simple. IPO, KTO, SimPO, ORPO, online/iterative DPO. Quirk: likelihood displacement.

RLAIF / Constitutional AI

AI judges label preferences using written principles. Self-critique → revise (SFT) → AI preferences → RL. Judge biases: position, verbosity, self-preference.

Best-of-N & self-improvement

BoN KL ≤ log N − (N−1)/N. Winner's curse with noisy reward models. Rejection sampling + SFT, repeated = STaR / ReST / expert iteration (≈ policy iteration). Distillation: SFT on a teacher's outputs (off-policy), or the teacher grades each of the student's own tokens (on-policy, dense signal).

🗂️ Case files: five real problems, one phase later

The same five problems follow you through the course (meet them). Here's what this phase changes for each.

🌡️ The cooling plant

Now: not the main tool. Energy and temperatures are measured by meters, so there's no need to learn a reward from human preferences.

Still breaks: proving a saving is real, and not just a cooler month, needs careful comparison against a baseline.

📱 The feed

Now: a learned model of ‘what this user will like’ is a reward model, and the KL leash becomes ‘stay close to today's recommender’ so one update can't change everything at once.

Still breaks: the policy finds what the scorer overrates (clickbait, outrage), and a leash only slows that down; you need ways to spot and resist the hack.

🦾 The robot hand

Now: learning rewards from comparisons started with robots: Christiano et al. (2017) trained simulated robots from people comparing short clips, using about an hour of human time. RT-2 writes robot actions as text tokens, so ‘LLM as policy’ carries over.

Still breaks: human comparisons are far too slow for the thousands of tries a real hand needs; it needs rewards it can check for itself.

♟️ The board game

Now: nothing to add: win or loss is a perfect reward, so there are no preferences to learn. But Best-of-N and expert iteration are its loop in text form: search for good moves, then train on what the search found.

✅ Where it stands: solved for perfect-information games by search plus self-play (Phase 6).

🧑‍💻 The coding agent

Now: SFT on human code, then RLHF or DPO: reviewers compare two fixes, a reward model learns their taste, and a KL leash keeps the code fluent.

Still breaks: ‘looks right to a reviewer’ isn't ‘passes the tests’. Confident, plausible code fools the reward model, so it needs a reward that actually runs the code.

🧩 Frame it yourself

🧩 New problem

A help desk wants an LLM to draft replies to customer tickets. For each ticket, a support agent sees two drafts side by side and clicks the one they'd rather send. There's no single correct reply, and tone matters as much as facts. You have months of these clicks, plus the replies agents actually sent.

Before you open the answer, write down: the state, the action, the reward, episodic or continuing (and γ), and which method from this phase (or earlier) you'd try first.

Reveal One good framing + the classic mistakes

State: the ticket, the earlier messages in the thread, product details, and the reply so far. Action: the next token (or, bandit-style, the whole reply). Reward: a Bradley–Terry reward model trained on the agents' A-vs-B clicks, scored once at the end. Episodic? Yes: one reply per episode, γ = 1.

Method: SFT on the replies agents actually sent, then DPO on the click pairs: offline, cheap, no reward model or sampling loop. Keep Best-of-N with a reward model as the baseline to beat. If you move to PPO later, keep a KL leash to the SFT model.

Classic mistakes: reward = ‘ticket closed fast’ (the policy learns to brush customers off or declare things resolved); ignoring length bias (longer drafts look thorough and win clicks); no leash (flattering filler the reward model overrates); an AI judge without swapping draft order (position bias); testing on the same agents' clicks you trained on.

🔬 Experiments to try
  • Increase the learning rate 10×. Does the model start producing odd text? (That's over-optimization without a strong enough anchor.)
  • Track the policy's log-prob of the chosen answers during training. Does it go down even as the margin grows? (Likelihood displacement.)
  • Change β from 0.1 to 0.5. What happens to how far the model moves?

Boss quiz 👾

Policy vs reference log-ratios: chosen +1.0, rejected −1.0, β = 0.1. DPO loss?
Margin = 0.1 × (1 − (−1)) = 0.2. σ(0.2) ≈ 0.55 → −log 0.55 ≈ 0.598. Slightly below the starting value log 2.
Your RLHF run's reward-model score keeps rising, but human raters say answers got worse. First suspect?
Goodhart's law: the policy is exploiting the reward model's errors.
