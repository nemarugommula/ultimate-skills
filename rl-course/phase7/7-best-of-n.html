Phase 7 · Lesson 7

Best-of-N, rejection sampling & STaR

The simplest way to get better answers: generate many, keep the best. Then train on the winners and repeat.

🧰 You'll need (quick reminders)
  • Reward model: scores answers, with some errors (Lesson 7.3).
  • KL = how far a model's behavior has drifted from the original (Lesson 7.4).
🎯 Hook

Best-of-N, "sample N answers and keep the one the reward model likes most", sounds too simple to matter. Yet in OpenAI's 2021 math work (Cobbe et al., which introduced the GSM8K benchmark), a 6B model that sampled 100 solutions and let a trained verifier pick one slightly outperformed a fine-tuned 175B model, about the same boost as a 30× bigger model. Since then, Meta has made rejection sampling a core stage of Llama 2 and Llama 3, and "sample many, verify, pick" is one of the main ways to spend extra compute at test time.

💡 Big idea Best-of-N (BoN): sample N responses, return the highest-scoring one. Rejection sampling fine-tuning: do BoN on many prompts, then SFT on the winners, so the model learns to produce them directly. Repeat and you get a self-improvement loop (expert iteration), which looks a lot like policy iteration.
🧠 Analogy: write 10 drafts, send the best

Before an important email, you write several drafts and send the best one: that's Best-of-N. Now imagine studying your best drafts so your first draft gets that good next time: that's rejection-sampling fine-tuning. Do it again and again and you steadily improve: that's expert iteration (STaR).

🎮 Playground · Best-of-N with a noisy reward model

Each sampled answer has a true quality (gold) drawn from a bell curve. The reward model sees gold + noise. BoN picks the answer with the highest reward model score. How good is the winner really?

  • The reward model's score for the winner (orange) keeps climbing with N: it's increasingly picking answers it overrates (the winner's curse, Lesson 4.4).
  • The winner's true quality (green) improves too, but more slowly and with diminishing returns. The noisier the reward model, the bigger the gap.
  • With σ = 0 (a perfect verifier, like unit tests), the two curves match. That's why verifiable rewards are so valuable.
Math refresher How far does BoN move from the original model?

A neat formula from the RLHF literature: Best-of-N's KL divergence from the base policy is at most

KL(πBoN ‖ π) ≤ log N − (N − 1)/N N = 4 → ≈ 0.64 · N = 16 → ≈ 1.83 · N = 256 → ≈ 4.55. It grows only logarithmically.

Why so small? BoN never invents anything: it only re-weights the base model's own samples, favoring the ones it picks. So it can't put probability anywhere the base model wouldn't have gone; it can only shift weight among answers the base model already writes.

What this buys you: BoN barely drifts from the original model, the gentlest possible improvement. That's its strength (it's safe) and its weakness (it can't go far). BoN is a cheap, strong baseline for "how much reward can I get at a given KL budget?". Good RL methods should beat it.

✏️ Worked example: how much does sampling more help?

A model solves a problem 30% of the time per attempt, and we have a perfect checker. With N attempts, the chance that at least one is right is 1 − 0.7N:

  • N = 1: 30%
  • N = 4: 1 − 0.7⁴ ≈ 76%
  • N = 16: 1 − 0.7¹⁶ ≈ 99.7%

With a noisy reward model instead of a perfect checker, the gains are smaller, and very large N starts picking answers the reward model overrates (the playground above).

⭐

STaR (2022)

Self-Taught Reasoner: generate step-by-step rationales, keep the ones reaching the right answer, fine-tune, repeat. For failures, give the answer as a hint and ask the model to explain it ("rationalization").

🔁

ReST / RFT / expert iteration

The same loop under different names: grow a dataset from your own filtered samples, improve on it. Simple, stable, and surprisingly strong for math and code.

⚖️

vs. real RL

The loop learns only from successes (positive examples). Policy-gradient RL also pushes down failures using negative advantages, which often makes it more sample-efficient. Both are now used together.

Distillation: copying a teacher instead of RL

If a stronger model already exists, a small model can skip most of the trial and error and copy it. There are two ways to copy:

📼

Off-policy distillation

The teacher writes the answers; the student does plain SFT on them (rejection sampling, with someone else's samples). DeepSeek-R1's report compared both routes on the same 32B base model: large-scale RL scored 47.0% on AIME 2024, while SFT on R1's outputs scored 72.6%. The catch: the student only sees the teacher's paths, never its own mistakes (exposure bias, Lesson 6.7).

🎙️

On-policy distillation

The student writes the answer; the teacher scores every token of it with its own log-probs. The per-token penalty is log πstudent(token) − log πteacher(token), the per-token reverse KL ("reverse" = measured on the student's own samples). RL's learning on your own attempts, but with a dense signal instead of ~1 number per episode.

✏️ Worked example: what each token learns

The student writes a 3-token answer. Its probabilities for the tokens it chose: 0.95, 0.6, 0.9. The teacher's probabilities for the same tokens: 0.9, 0.5, 0.3. Per-token penalties ln(student/teacher):

  • token 1: ln(0.95/0.9) ≈ 0.05 (teacher agrees)
  • token 2: ln(0.6/0.5) ≈ 0.18 (minor)
  • token 3: ln(0.9/0.3) ≈ 1.10 (the teacher thinks this token was a mistake)

The student learns which token went wrong. RL would only have said "this answer scored 0" for all three. The Qwen3 team reported (and Thinking Machines' Oct 2025 write-up highlights) that on-policy distillation reached 74.4% on AIME 2024 with about 1,800 GPU hours, against 67.6% for RL with about 17,920: better, at roughly a tenth of the cost.

🌍 Where it's used
Best-of-N with a verifier 🧪 Research · 2021 OpenAI: Training Verifiers (GSM8K)

How: the policy samples many solutions to a school maths word problem, a trained verifier scores each one, and the top-scored solution is returned.

Why this method: choosing among many tries gave about the same boost as a 30× bigger model, without changing the policy at all.

Rejection sampling fine-tuning 🏭 In production · 2023 Meta: Llama 2-Chat

How: for each prompt, sample several replies, keep the one the reward model scores highest, and fine-tune on those. Until the fourth RLHF round this was the only RL-style step; then PPO was added on top.

Why this method: fine-tuning on the model's own best outputs is plain supervised learning, so it's stable, and sampling many replies per prompt explores widely.

Expert iteration (ReST-EM) 🧪 Research · 2023 Google DeepMind: Beyond Human Data

How: generate answers to maths and coding problems, keep only those a checker marks correct (reward 1 or 0), fine-tune on them, and repeat a few times.

Why this method: when correctness can be checked, the model's own filtered work beat fine-tuning only on human-written solutions, and the gain grew with model size.

On-policy distillation 🏭 In production · 2025 Qwen3 Technical Report

How: the small student writes its own answers. The big teacher's probabilities for each token of those answers are the training target, token by token.

Why this method: for Qwen3-8B it beat RL on the reported maths and coding benchmarks with about a tenth of the GPU hours.

🤯 Fun fact

The STaR loop is policy iteration in disguise: generate with the current policy (evaluate by checking answers), then train on what worked (improve). It's generalized policy iteration from Lesson 2.5 (alternate "evaluate honestly" and "keep what worked"), now with an LLM.

🌉 Where this shows up today
  • Test-time compute: sample many answers and pick by majority vote or a verifier (Phase 8).
  • DeepSeek-R1's rejection-sampling stage: generate with the RL model, keep the correct, readable answers, and SFT on ~800k of them (Lesson 7.2).
  • Distillation (section above): copying a stronger teacher, from its samples or token by token. It often beats doing RL directly on a small model.

1. As N grows in Best-of-N with a noisy reward model, the winner's reward-model score…
Picking the max of noisy scores selects for positive noise: the winner's curse.
2. What does rejection-sampling fine-tuning do?
It distills Best-of-N into the policy itself.
3. What can policy-gradient RL learn from that STaR-style filtering can't?
Filtering keeps only positives. RL uses both what worked and what didn't.
📝 TL;DR
  • Best-of-N: sample N, keep the best. KL ≤ log N − (N−1)/N. A strong baseline.
  • Noisy reward models → winner's curse. Verifiers avoid it.
  • Rejection sampling + SFT, repeated = STaR / ReST / expert iteration (≈ policy iteration).
  • RL adds learning from failures. Distillation spreads the gains: off-policy (SFT on teacher outputs) or on-policy (teacher grades each of the student's tokens).
