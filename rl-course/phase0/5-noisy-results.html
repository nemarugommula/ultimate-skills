Phase 0 · Lesson 5

One run lies: mean, spread & error bars

RL results are noisy. Three small numbers tell luck apart from a real improvement, and you'll use them in every lab from here on.

🧰 You'll need (quick reminders)
  • Return = the total (discounted) reward of one episode; Σ = “add them all up” (Lesson 0.3).
  • Slippery floor: 20% of the time the robot moves in a random direction instead of the one it chose (Lesson 0.2).
🎯 Hook

In 2017, researchers trained the same algorithm with the same settings 10 times, changing only the random seed. They split the 10 runs into two groups of 5 and averaged each group. A standard statistics test called the two curves “significantly different”. If you'd seen them in a paper, you'd believe one method beat the other. The only difference was luck. (Henderson et al., “Deep RL that Matters”, Figure 5.)

Why one run lies

Run the same policy twice and you can get completely different returns: on the slippery floor one episode reaches the 💎 (+3) and the next slips into the 🔥 (−14). A single episode tells you about luck, not about the policy. So we run many episodes and describe the whole pile of results with two numbers:

🎯

Mean: “what's typical?”

Where the results are centered. It's our estimate of the policy's expected return: the average you'd get if you could run it forever.

↔️

Standard deviation: “how much does it vary?”

How far a typical result lands from the mean. Small = consistent and predictable. Large = it depends heavily on luck.

💡 Big idea One run is luck. Run many and report three numbers: the mean (what's typical), the standard deviation (how much single runs vary) and the standard error (how much the mean itself would wobble if you redid the whole experiment).
🧠 Analogy: judging a restaurant

One bad dinner doesn't make a bad restaurant. You read the average rating (mean). Then you check whether reviews agree: a place that always gets 4★ is safer than one that gets 1★ or 5★ with the same average (standard deviation). And you trust an average of 500 reviews more than an average of 3 (standard error). RL results work the same way.

✏️ Worked example: mean and std of 8 episodes, by hand

Say 8 episodes gave these returns: 2, 4, 4, 4, 5, 5, 7, 9.

Mean = add them up, divide by how many: (2+4+4+4+5+5+7+9) / 8 = 40 / 8 = 5.

Standard deviation, in 4 steps:

return24445579
1. distance from mean (x − 5)−3−1−1−100+2+4
2. square it911100416

3. Average the squares: (9+1+1+1+0+0+4+16) / 8 = 32 / 8 = 4. This is called the variance.
4. Square root: √4 = 2. That's the standard deviation (std, written σ, “sigma”).

In words: the typical distance of a result from the mean. As a formula (Σ = add up, √ = square root, n = number of episodes):

σ = √( Σ (x − mean)² / n ) “square each distance from the mean, average them, take the square root”
Math refresher Why square, then square-root? (and the n − 1 small print)

Why square? If you just averaged the distances, the −3 and +2 and +4 would partly cancel out. Squaring makes every distance positive (and makes big misses count more). The square root at the end puts the answer back into the same units as the returns.

Small print: Python's statistics.stdev (used in Lab 0) divides by n − 1 instead of n, giving 2.14 here. That small correction matters for tiny samples and barely matters for 1,000 episodes.

import statistics
returns = [2, 4, 4, 4, 5, 5, 7, 9]
statistics.mean(returns)     # 5
statistics.pstdev(returns)   # 2.0   (divide by n)
statistics.stdev(returns)    # 2.14  (divide by n-1)

Rule of thumb: for bell-shaped results (most results near the middle, fewer far out, like the histogram in the playground below), about 68% land within 1 std of the mean and about 95% within 2 std.

How precise is the mean? The standard error

⚖️

1. Is the difference real?

Policy A averages 5, policy B averages 6. If each run swings by ±10, that gap could easily be luck. The std tells you how noisy the comparison is.

🛡️

2. Risk

Two policies with the same mean: one always gets 5, the other gets −20 or +30. For a self-driving car or a medical robot you want the consistent one.

📏

3. How precise is the mean?

The standard error says how much the mean itself would wobble if you repeated the experiment. More episodes → smaller standard error → a more trustworthy mean.

Numbers first: with σ ≈ 8.6 and n = 1,000 episodes, √1000 ≈ 31.6, so the standard error ≈ 8.6 / 31.6 ≈ 0.27. A 1,000-episode mean usually lands within about two standard errors (±0.55) of the true mean. In words: divide the spread of single runs by the square root of how many runs you averaged.

standard error = σ / √n In plain words: more episodes → the mean wobbles less. The wobble shrinks with the square root of n: 4× more episodes halves it. (σ = the std; √n = square root of the number of episodes.)

Real example: Lab 0 printed −2.79, but the true mean is −2.14. That gap of 0.65 is about 2.4 standard errors, an unlucky batch: a miss that big (in either direction) happens roughly 1 time in 60. That's why researchers report error bars: so a reader can tell luck apart from a real difference.

Notice the 1/√n, and bookmark it: it comes back in Phase 1 as the exploration bonus of the UCB algorithm. In Lab 1 you'll draw it as error bands around each curve.

🌍 Where it's used
Is the gap bigger than luck? 🏭 In production · 2021 Netflix: reading A/B test results

How: action = which version of the app a member sees (old or new) · reward = a score per member, such as satisfaction · compare the two groups' means.

Why this method: a gap can be pure luck: 55 heads in 100 flips is no proof a coin is rigged. Netflix only trusts gaps too big for luck, accepting being fooled about 5% of the time.

Standard error = σ/√n: why trials are huge 📜 History · 2020 RECOVERY trial: dexamethasone for COVID-19

How: action = dexamethasone or usual care, chosen at random · reward = surviving 28 days · result: 22.9% vs 25.7% died, across 6,425 patients.

Why this method: a 3-point gap is small. By this lesson's formula, 200 patients per group gives an error bar (2 standard errors) of about ±9 points; the real trial's was about ±2.3, so the gap was clear.

🤯 Fun fact · error bars won an award

A 2021 paper on how to report RL results with only a few runs, “Deep RL at the Edge of the Statistical Precipice”, won an Outstanding Paper Award at NeurIPS, one of the field's biggest conferences. Its message is this lesson's: a single number without its uncertainty can make a method look better than it is. You'll use its tools (confidence intervals, the interquartile mean) in Phase 9.

🔬 Researcher habit #1

Never trust a single run. RL is noisy, so always average over many episodes (and, later, many random seeds). The labs make you report a mean and a spread. Papers that skip this are a known problem in the field (the Henderson et al. paper in the hook).

🌉 LLM bridge

Reasoning models are often compared on AIME, a math contest with only 30 problems a year, so each problem is worth 3.3 points. A yes/no score at 50% has a std of 0.5 per problem (every result is exactly 0.5 from the mean), so the standard error is 0.5 / √30 ≈ 0.09: about ±9 points. A “5-point jump” on AIME can be pure luck in which problems were set.

LLMs also sample their answers at random, so the same model can score differently on the same test twice. That's why careful reports average several samples per problem and show error bars. Anthropic's statistical approach to model evals is a readable guide; Lessons 8.8 and 9.3 come back to it.

Check yourself ✅

Policy A: mean 10, std 1. Policy B: mean 10, std 15. What's different?
Same center, different spread. A nearly always scores 9–11. B swings wildly. Which one you prefer depends on how much you care about risk.
You run 4× more episodes of the same policy. What happens to the std and the standard error?
The std describes the policy's own randomness, which more runs don't change. The standard error describes how precisely you know the mean: σ/√(4n) = half of σ/√n.
On a 30-problem test, model A solves 15 (50%) and model B solves 17 (56.7%). What should you conclude?
0.5 / √30 ≈ 0.09, so each score wobbles by about ±9 points just from which problems were set. To tell them apart you'd need more problems, several samples per problem, or both.
📝 TL;DR
  • One run is luck. Run many and report a mean (typical result) and a std (spread of single runs).
  • Standard error = σ / √n: how much the mean wobbles. 4× more runs halves it; the std stays the same.
  • A gap smaller than about 2 standard errors could be luck. Remember the 1/√n: it returns in Phase 1.
