Phase 0 · Lesson 3

Rewards, returns & discounting

An agent doesn't chase the next reward. It chases all the rewards still to come, and values the near ones a bit more.

🧰 You'll need (quick reminders)
  • Reward = the number you get after each action; episode = one complete run from start to finish (Lesson 0.2).
🎯 Hook

Would you take ₹100 today or ₹110 in a year? Most people take the ₹100. Your brain automatically counts future rewards as worth a bit less. RL agents do the same thing, and it's controlled by a single number called γ (gamma).

Reward ≠ goal. The return is the goal.

Imagine a chess game that pays +1 for every piece you capture. Refusing an easy capture costs you a point now, but it can set up checkmate (a much bigger prize) 5 moves later. A smart agent shouldn't grab the biggest reward right now. It should maximize the total reward over the whole future. That total is called the return, written G.

💡 Big idea The agent's goal is to maximize the return: the sum of all future rewards, with rewards further in the future shrunk by γ.
🧠 Analogy: an arcade game that might shut off

You're playing an arcade game, and after every move there's a 10% chance the power cuts out and the game is over. A coin one move away you'll collect 90% of the time. A coin two moves away needs you to survive twice: 0.9 × 0.9 = 81%. Three moves away: 73%. That's exactly what γ = 0.9 does: it weights each future reward by the chance you're still around to collect it. With γ = 1 the power never cuts out; with γ = 0 only the very next move is safe.

Math refresher Σ is a for-loop, and powers of 0.9 shrink

Σ (sigma) = "add them all up"

The big Greek Σ just means sum. If you can write a for-loop, you can read Σ.

An episode of T steps gives rewards r1, r2, …, rT (rewards start at r1, Lesson 0.2). Adding them all up:

G = Σk=1T rk "G = the sum of r_k for k from 1 to T"
G = 0
for k in range(1, T + 1):   # Σ from k=1 to T
    G += r[k]

Multiplying by a number less than 1 again and again shrinks things

γk means γ multiplied by itself k times. With γ = 0.9:

0.9k10.90.810.590.350.120.005

So a reward 50 steps away counts for only half a percent. It has basically faded out. (Anything to the power 0 is 1, so the very next reward counts in full.)

The discounted return

Gt = rt+1 + γ rt+2 + γ2 rt+3 + γ3 rt+4 + … "return from time t = next reward + a little less of the one after + even less of the one after that…"

Effective horizon ≈ 10 steps (≈ 1/(1−γ): how far ahead it "sees")
  • γ = 0: a short-sighted agent. Only the very next reward matters, like a toddler with a marshmallow.
  • γ = 0.9: looks roughly 10 steps ahead.
  • γ = 0.99: looks roughly 100 steps ahead.
  • γ = 1: no discounting at all. Fine when episodes always end, a problem if they could go on forever: +1 per step forever adds up to infinity, and "infinity" can't tell the agent which path is better.

Rule of thumb: the agent "sees" about 1 / (1 − γ) steps into the future. (Below you'll see where that comes from.)

Why discount at all?

♾️

1. It keeps sums finite

Get +1 every step forever with γ = 0.9: 1 + 0.9 + 0.81 + 0.73 + … adds up to 10, not infinity. In general 1 + γ + γ² + … = 1/(1−γ). That's the rule of thumb: γ = 0.9 is worth about 10 full steps, γ = 0.99 about 100.

🔌

2. It's a chance the game ends

γ = 0.9 behaves like a 10% chance, each step, that the episode stops (the arcade analogy above). Rewards far away are less likely to ever arrive.

🪞

3. It looks the same from every step

Why not just count the next 10 steps? Then the best action depends on how many steps are left: with 2 left, a gem 5 steps away is worth nothing; with 20 left, you'd walk to it. You'd need a different policy for every step count. Discounting by γ, γ², … looks identical wherever you stand, so one policy works everywhere.

Reason 3 is the deep one: "the future looks the same from every step" is exactly what makes the trick below work, and what keeps the Bellman equation (Phase 2) simple.

The most important trick in this lesson

Look at the return formula again. Everything after the first reward is just γ times the return from the next step:

Gt = rt+1 + γ · Gt+1 "my return = the reward I get now + γ × the return from the next step"

This recursive form looks like a small observation, but it's the seed of the Bellman equation, which you'll meet in Phase 2 and which appears in nearly every RL algorithm. It also gives a neat coding trick: compute all returns in one backward pass.

def discounted_returns(rewards, gamma):
    G, out = 0.0, []
    for r in reversed(rewards):   # walk backwards from the end
        G = r + gamma * G           # G_t = r_{t+1} + γ·G_{t+1}
        out.append(G)
    return out[::-1]

discounted_returns([0, 0, 10], 0.9)   # → [8.1, 9.0, 10.0]

You'll find this exact loop in the source code of REINFORCE, PPO and LLM RL libraries.

✏️ Worked example: computing a return by hand

An episode gives rewards −1, −1, +10 (two steps, then the gem). With γ = 0.9:

G = −1 + 0.9 × (−1) + 0.9² × 10 = −1 − 0.9 + 8.1 = 6.2. (With γ = 1 it would be −1 − 1 + 10 = 8.)

The backward trick gives the same answer with less work: start at the end. G after the last step = 10. One step earlier: −1 + 0.9 × 10 = 8. One more: −1 + 0.9 × 8 = 6.2 ✓. That's the loop every RL library uses.

Careful what you reward 🧞

The agent will maximize exactly what you reward, not what you meant. This is called reward hacking (or specification gaming).

🌍 Where it's used
γ sets the horizon 🧪 Research · 2019 OpenAI Five plays Dota 2

How: state = the game as each hero sees it, every 0.133 s · action = move, attack or use an ability · reward = winning, plus smaller signals like heroes dying and gathering resources.

Why this method: a game is about 45 minutes, roughly 20,000 steps. γ = 0.9993 per step looks about 3 minutes ahead (0.133 s × 1/(1−γ)). Stretching that toward 6 minutes made it play better.

Maximize the return, not the next reward 🏭 In production · 2023 Spotify: podcast picks for the long term

How: state = a listener and their history with each show · action = which podcast to recommend · reward = listening that keeps coming back over the following weeks, not just one play.

Why this method: the shows you're most likely to try once are often not the ones you'll stick with. Aiming at the long-run total changed the picks and did much better in A/B tests.

Careful what you reward 🧪 Research · 2017 DeepMind: a robot arm stacking Lego bricks

How: state = the arm's joints and the bricks' positions · action = how to move each joint · reward = points for reaching, grasping and stacking, added together.

Why this method: rewarding small steps made learning possible, but the pieces backfired: it flipped bricks (the grasp reward used the wrong reference point) and wouldn't stack, because letting go ended its grasp reward.

🤯 Fun fact · the boat that refused to finish

In 2016, OpenAI trained an agent on the boat-racing game CoastRunners. The reward was points from hitting targets along the course. The agent found a small lagoon where 3 targets respawned. It spun in circles forever, crashing into walls and catching fire, and never finished the race. It still scored about 20% higher than human players. It did what the reward asked for, which wasn't what the designers wanted.

🔬 The reward hypothesis

Richard Sutton (one of the founders of RL) made a bold claim. In normal words: any goal can be described as "maximize the total reward". In his own, more intimidating words: "All of what we mean by goals and purposes can be well thought of as the maximization of the expected value of the cumulative sum of a received scalar signal (reward)." In other words, any goal can be written as a reward to maximize. It's a bold claim, and researchers still debate it.

🌉 LLM bridge

Discounting: In LLM training, γ is usually set to 1 (no discount). A response always ends, and the reward usually comes only at the end ("was the answer right?"), so every token shares the credit equally. Tasks that may never end (a robot that's always on, a plasma controller) need γ < 1 to keep the return finite.

Reward hacking is very real in LLMs: models trained against learned reward models have learned to write longer answers (because longer answers looked better to the reward model), to flatter the user, and coding models have been caught special-casing or editing unit tests so they pass instead of fixing the code. Fighting reward hacking is an active research area (Phase 8).

Check yourself ✅

1. Rewards are [0, 0, 10] and γ = 0.5. What is the return from the start, G0?
G = 0 + 0.5·0 + 0.5²·10 = 0.25 × 10 = 2.5. Backwards: G2=10, G1=0+0.5·10=5, G0=0+0.5·5=2.5.
2. An agent with γ = 0.99 compared with one with γ = 0.5 is…
Horizon ≈ 1/(1−γ): 100 steps versus 2 steps. γ changes what counts as best, not just how fast the agent learns.
3. You reward a cleaning robot +1 for each piece of dirt it picks up. What could go wrong?
Classic reward hacking: the reward says "pick up dirt", not "keep the room clean". Rewarding the outcome you want (a clean floor) is safer.
📝 TL;DR
  • Return G = r1 + γr2 + γ²r3 + …. The agent maximizes this, not the next reward.
  • γ sets how far ahead the agent looks: horizon ≈ 1/(1−γ).
  • Recursive form: Gt = rt+1 + γGt+1. This is the seed of Bellman. Compute returns backwards.
  • Agents optimize exactly what you reward. Reward hacking is a real problem in LLMs today.
