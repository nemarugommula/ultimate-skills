🧾 Cheat sheet

The loop

Agent sees st → picks at ~ π(·|st) → environment returns rt+1, st+1 → repeat until the episode ends.

The 6 words

Agent (learner) · Environment (world) · State (snapshot) · Action (choice) · Reward (score number) · Policy (state → action rule; what RL learns)

Return

Gt = rt+1 + γrt+2 + γ²rt+3 + …
Recursive: Gt = rt+1 + γGt+1

Discount γ

0 = only the next reward matters. 0.99 = looks ~100 steps ahead. Horizon ≈ 1/(1−γ). LLM RL usually uses γ = 1.

Why RL is hard

Rewards are vague (a score, not an answer), late (credit assignment), and you only see results for actions you try (exploration).

RL ↔ LLMs

State = prompt + tokens so far. Action = next token. Policy = the LLM. Episode = one response. Reward = reward model score or a correctness check.

Noisy results (0.5)

One run is luck. Report the mean (typical) and std (spread). Standard error = σ/√n: how much the mean wobbles; 4× more runs halves it.

🗣️ Teach it back (60 seconds)

Say it out loud, as if to a friend

"RL is when an agent learns by trial and error. At each step it sees a ___, takes an ___, and gets a ___. It wants to maximize the ___, which is the sum of future rewards discounted by ___. The thing it learns is called a ___. For ChatGPT, an action is a ___."

🗂️ Case files: five real problems, one phase later

The same five problems follow you through the course (meet them). Here's what this phase changes for each.

🌡️ The cooling plant

Now: you can frame it. State = sensor readings (temperatures, power, outside weather), action = settings for fans, pumps and chillers, reward = −energy used, with a big penalty for breaking a temperature limit. It never ends, so it's a continuing task that needs γ < 1.

Still breaks: you can write the problem down, but you have no way yet to find good settings except guessing.

📱 The feed

Now: state = the user and what they've watched so far, action = which item to show next, reward = a click? watch time? Each is only a stand-in for “glad they came”, and the agent will chase exactly the one you pick (Lesson 0.3).

Still breaks: a click reward invites clickbait, and you have no method yet for choosing items.

🦾 The robot hand

Now: state = camera images plus joint angles, action = motor commands many times a second, reward = +1 when the object is lifted. Each attempt is one episode.

Still breaks: real-robot attempts are slow and wear out hardware, and a reward that only comes on success gives almost no signal at first.

♟️ The board game

Now: state = the board, action = a legal move, reward = +1 for a win, −1 for a loss, only at the end. Games always end, so γ = 1 is fine.

Still breaks: credit assignment: one reward at the end of a whole game, and no way yet to tell which moves earned it.

🧑‍💻 The coding agent

Now: state = the repository plus the conversation so far, action = the next token or tool call, reward = +1 if the hidden tests pass, at the end. Episodic, γ = 1.

Still breaks: one reward after thousands of actions, and an agent can learn to edit the tests instead of fixing the bug.

🧩 Frame it yourself

🧩 New problem

A city wants a smarter traffic light at one busy crossroads. Right now it switches on a fixed timer: 40 seconds north–south, 40 seconds east–west. Cameras can count the cars queuing in each direction. The goal: less time wasted waiting at the junction.

Before you open the answer, write down: the state, the action, the reward, episodic or continuing (and γ), and which method from this phase (or earlier) you'd try first.

Reveal One good framing + the classic mistakes

State: the queue length in each direction, which light is green, and how long it has been green. Action: every few seconds, keep the light or switch it. Reward: −(number of cars waiting) at each step, so the return is minus the total waiting. Episodic? No: traffic never stops, so it's continuing, and you need γ < 1 (for example 0.95: a horizon of about 20 decisions).

Method: with Phase 0 you can't learn a policy yet, but you can measure one. Simulate many days with random traffic and compare the fixed timer against a simple hand-written rule (“switch when the other queue is twice as long”), reporting the mean ± standard error of the return (Lesson 0.5), because one day of traffic is luck.

Classic mistakes: rewarding “cars that got through” only, so the light keeps the busy road green forever and side-street drivers wait without end; a state with only the light colour (not Markov: it can't see the queues); γ = 1 on a task that never ends (the return adds up to −∞); and declaring a winner after one simulated day.

Boss quiz 👾

Rewards [1, 1, 1, …] forever, γ = 0.9. What's the return?
1 + 0.9 + 0.81 + … = 1/(1−0.9) = 10. That's where the "horizon ≈ 1/(1−γ)" rule comes from: getting 1 forever with discounting is worth the same as getting 1 for about 10 steps with no discounting.
A coding agent is rewarded +1 when the unit tests pass. What's the biggest risk?
Reward hacking. Real RL training setups lock test files, hide some tests, and monitor for this.
