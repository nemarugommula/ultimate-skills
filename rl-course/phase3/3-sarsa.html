SARSA: on-policy control

TD learning for Q-values, so the agent can improve its behavior while it learns.

🧰 You'll need (quick reminders)
  • TD update: move a value toward reward + γ × the next value, after every step (Lesson 3.2).
  • Q(s,a) = how good action a is in state s (Lesson 2.3); ε-greedy = mostly best action, sometimes random (Lesson 1.3).
🎯 Hook

Imagine walking along a cliff edge, but you're a bit clumsy: 1 step in 10 goes in a random direction. Would you walk right at the edge (shortest), or a few steps back (safer)? A SARSA agent works out the sensible answer by itself.

💡 Big idea SARSA applies the TD update to Q(s,a), using the action the agent actually takes next, exploration included. So it learns the value of how it really behaves, clumsiness and all. In plain words: SARSA judges the route you'd actually take, including the clumsy random steps, not the route a perfect robot would take. That's what on-policy means.
🧠 Analogy: a nervous learner driver

A learner driver who still wobbles a bit should avoid the narrow cliff road, even though it's shorter. Not because the road is bad for an expert, but because it's bad for a driver who wobbles. SARSA learns exactly that: the value of routes for the agent as it really behaves, random mistakes included.

Q(s,a) ← Q(s,a) + α [ r + γ Q(s',a') − Q(s,a) ] The name is the five things each update uses: State, Action, Reward, next State, next Action 
a = epsilon_greedy(Q, s)
while not done:
    s2, r, done = env.step(a)
    a2 = epsilon_greedy(Q, s2)                       # choose the NEXT action first…
    Q[s][a] += alpha * (r + gamma * Q[s2][a2] - Q[s][a])   # …and learn from it
    s, a = s2, a2

Where did the "improve" step go? There's no separate one. Every action comes from ε-greedy on the latest Q, so the moment an update changes Q, behavior changes with it. Evaluate a little, improve a little, every single step: generalized policy iteration (Lesson 2.5's evaluate ↔ improve loop) in its tightest form.

Why choose a′ before updating? The target is supposed to describe what you'll really do next. So you pick the next action first (exploration and all), put its Q into the target, and then actually take that same action on the next step.

✏️ Worked example: one SARSA update near the cliff

α = 0.5, γ = 1. Currently Q(here, →) = −5. The agent moves → and gets r = −1. In the new cell, ε-greedy happens to pick a random action, ↓ toward the cliff, with Q(new, ↓) = −20.

SARSA uses that next action: target = −1 + (−20) = −21. Update: Q(here, →) = −5 + 0.5 × (−21 − (−5)) = −13. Moving along the edge just got a lot less attractive, because clumsy next steps there are expensive. (Next lesson: Q-learning would use the best next action instead.)

After a couple of hundred episodes, SARSA's path goes up and around, away from the edge: usually 17 steps (sometimes 19) instead of the shortest 13 (the path can still wobble near the cliff until Q settles). If the path length still says "not yet", run more episodes; the greedy path hasn't settled. Since its own random 10% steps would sometimes knock it off the edge, it learned that the edge isn't worth it for an agent that behaves like this. Switch ε to 0.01 and train 300+ episodes: a less clumsy agent dares to walk closer to the edge (in our tests, 15 steps about half the time, otherwise 17).

Math refresher On-policy, and Expected SARSA

On-policy: the policy you learn about = the policy you act with (here ε-greedy). The learned Q includes the cost of your exploration mistakes. With a fixed ε, SARSA converges to the best ε-greedy policy (the best you can do while still taking 10% random steps), not the best policy overall. Decay ε slowly toward 0 and it approaches the truly optimal one (quiz 3 below).

Expected SARSA replaces the random next action Q(s',a') with its average under the policy: Σa' π(a'|s') Q(s',a'). Same target on average, less noise. A small change that often works better.

🌍 Where it's used
SARSA on a soccer field 🧪 Research · 2005 Stone, Sutton & Kuhlmann: RoboCup keepaway

How: state = distances and angles to teammates and opponents · action = hold the ball or pass to a teammate · reward = time steps the team keeps the ball.

Why this method: learning the value of the actual behavior was steadier with an approximate Q. The best-next-action variant (next lesson) needed 40–50 hours vs SARSA's 15–20, and varied more between runs.

On-policy at scale: keep the data fresh 🧪 Research · 2019 OpenAI Five (Dota 2)

How: state = what the five heroes can see · action = each hero's next command · reward = winning, plus signals like heroes dying and collecting resources · learns from games of its current policy.

Why this method: on-policy data describes the policy that played it. Data about 8 versions old slowed learning a lot, so workers fetched fresh parameters about once a minute.

🤯 Fun fact

The algorithm was introduced in 1994 by Rummery and Niranjan under the clunky name "modified connectionist Q-learning". Richard Sutton suggested the catchier name SARSA, and that's the one that stuck.

🌉 LLM bridge · on-policy LLM training

PPO and GRPO for LLMs are on-policy: the model learns from answers it just generated itself, mistakes included, like SARSA. Methods like DPO learn from a fixed dataset written by other models or by people, which is off-policy (next lesson). Large training systems that generate answers while training (Phase 8) end up slightly off-policy, because data comes from a model a few updates old, and they need corrections for it.

Check yourself ✅

1. What does SARSA use as the next-state value in its target?
That's what makes it on-policy: it evaluates the behavior it really follows.
2. Why does SARSA avoid the cliff edge with ε = 0.1?
For an agent that slips 10% of the time, the edge path really is worse on average. SARSA learns the best policy given that it keeps exploring.
3. If ε slowly decayed to 0, what would SARSA's path become?
With no exploration, there's no risk of slipping, so the edge path becomes best, and SARSA converges to the optimal policy.
📝 TL;DR
  • SARSA: Q(s,a) ← Q(s,a) + α[r + γQ(s',a') − Q(s,a)], with a' = the action actually taken next.
  • On-policy: learns the value of how it really behaves, exploration included, so it plays safe.
  • Expected SARSA averages over a' for less noise.
