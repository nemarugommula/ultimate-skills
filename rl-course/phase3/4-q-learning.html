Phase 3 · Lesson 4

Q-learning: off-policy control

One tiny change to SARSA: learn about the best policy while behaving like an explorer.

🧰 You'll need (quick reminders)
  • SARSA: TD update for Q using the action you actually take next (last lesson).
  • Q* = the Q-values of the best possible policy; Bellman's optimality equation uses "max" over next actions (Lesson 2.4).
🎯 Hook

Q-learning was introduced in Chris Watkins' 1989 PhD thesis. Watkins and Dayan proved in 1992 that it finds the optimal Q-values in any finite MDP, as long as every action keeps getting tried and the step size α shrinks over time in the right way. Twenty-one years later, the same idea with a neural network attached played Atari (Phase 4).

💡 Big idea Use the best next action in the target, maxa' Q(s',a'), no matter what you actually do next. It's learning while daydreaming: "whatever clumsy thing I do next, pretend my future self plays perfectly." You can explore all you like, and Q still learns the value of acting optimally. That's off-policy learning.
🧠 Analogy: the chess student who studies the best move

A student plays a game, sometimes trying odd moves on purpose. Afterwards, for each position, they ask "what would the best move have been from the next position?" and learn from that, not from the odd move they actually played. They learn how a strong player should play while still experimenting. That's Q-learning: explore freely, learn about the optimal policy.

Q(s,a) ← Q(s,a) + α [ r + γ maxa' Q(s',a') − Q(s,a) ] It's the Bellman optimality equation for Q* (Lesson 2.4) turned into a sampled update 
while not done:
    a = epsilon_greedy(Q, s)                          # behave: explore sometimes
    s2, r, done = env.step(a)
    Q[s][a] += alpha * (r + gamma * max(Q[s2]) - Q[s][a])   # learn: as if acting perfectly next
    s = s2

SARSA (on-policy)

"What happens if I keep acting like I do now, clumsy steps included?" → safe path.

🏎️

Q-learning (off-policy)

"What happens if I act perfectly from the next step on?" → optimal edge path, even though its own exploring sometimes falls off.

✏️ Worked example: same step as last lesson, done the Q-learning way

α = 0.5, γ = 1, Q(here, →) = −5, the agent moves → and gets r = −1. In the new cell: Q(new, ↓) = −20 (toward the cliff) and Q(new, →) = −3 (the good move).

Q-learning ignores whatever it does next and uses the best next value: target = −1 + max(−20, −3) = −4. Update: Q(here, →) = −5 + 0.5 × (−4 − (−5)) = −4.5.

Compare SARSA's −13 for the same step. Q-learning thinks the edge is fine (because a perfect player wouldn't fall), so it learns the short, risky path. SARSA learns the safe path. That's the whole cliff result.

Two results that look contradictory but aren't:

  • Q-learning's greedy path is better: the optimal 13 steps along the edge (our Lab 3: 40 out of 40 runs).
  • But while training, Q-learning earns less: about −49 per episode vs SARSA's −26 (Lab 3). Walking along the edge while exploring 10% of the time means falling off a lot.

Which is "better" depends on the question: do you care about the final policy (Q-learning), or about not falling off while you're still learning (SARSA)? For a real robot near a real cliff, it's the second one.

Math refresher Why off-policy is so useful

Off-policy means the data can come from any behavior: an old version of yourself, a human, random exploration, a replay of past experience. Q-learning still learns about the optimal policy. That's what lets DQN (Phase 4) store old experience in a replay buffer and learn from it over and over. On-policy methods have to throw data away once the policy changes.

Why can't SARSA reuse old data too? Its target contains a′, the next action an old policy happened to pick, so an old transition describes behavior you no longer follow. Q-learning's target never stores a′: it recomputes maxa′ Q(s′,a′) from the current table, so an old (s, a, r, s′) is as useful as a new one.

The catch: the max over noisy estimates tends to be too high (maximization bias: the biggest of several noisy guesses is probably an overestimate). Tiny example: two actions, both truly worth 0, but each estimate is randomly off by +1 or −1. Of the four equally likely cases, the max is +1 in three and −1 in one, so on average the max says +0.5 while the truth is 0. And off-policy learning with neural networks can become unstable. Phase 4 covers both.

🌍 Where it's used
Off-policy: learn from stored attempts 🧪 Research · 2018 Google QT-Opt: robot grasping

How: state = camera image + gripper open/closed + height · action = how to move the gripper, or stop · reward = 1 if it lifts the object, else 0 · Q scores each move.

Why this method: robot time is slow and costly. Off-policy learning reused 580,000 grasp attempts gathered over weeks on 7 robots, reaching 96% success on objects it had never seen.

Q-values that decide send or drop 🏭 In production · 2018 Facebook Horizon: push notifications

How: state = features of the person and the candidate notification · action = send or drop · reward = later interactions and activity, minus a penalty for each notification sent.

Why this method: the old click-prediction models missed long-term effects. Comparing Q(send) with Q(drop) captures them, and off-policy learning lets it retrain daily on logged data.

🤯 Fun fact

DeepMind's 2013 DQN paper, the one that started the deep RL boom, was essentially Q-learning from this lesson with the Q-table replaced by a neural network that looks at Atari screen pixels, plus one stabilizing trick: experience replay. The second trick, a target network, arrived in the 2015 Nature paper. That's the whole of Phase 4.

Where it has run: remember the elevators from Lesson 2.2's hook? Crites & Barto controlled them with a team of Q-learning agents, one per elevator car, with the Q-tables replaced by small neural networks. In Q-routing (Boyan & Littman, 1994), every router in a simulated network kept Q-values for "how long will a packet to X take if I pass it to this neighbor?", and it beat fixed shortest-path routing under heavy traffic.

🌉 LLM bridge · Q-values hiding in an LLM

Value-based methods like Q-learning are rare for LLMs. Not because of the max: a max over ~100,000 next tokens is one cheap pass over a vector. The hard part is learning 100,000 accurate Q-values per state from a single reward at the end of the answer. Policy-gradient methods (Phase 5) fit text generation more naturally. But the idea isn't gone. A 2024 paper by Rafailov et al. is titled "From r to Q*: Your Language Model is Secretly a Q-Function": the math behind RLHF (Phase 7) lets you reinterpret the scores an LLM gives each next token as Q-values. Off-policy learning also matters for LLMs whenever we learn from data the current model didn't generate.

Check yourself ✅

1. The only difference between the SARSA and Q-learning updates is…
One symbol: the actual next action (SARSA, on-policy) vs the best next action (Q-learning, off-policy).
2. Why can Q-learning learn the optimal policy while acting randomly 10% of the time?
Off-policy: behavior policy (ε-greedy) ≠ target policy (greedy). The max makes the target about the greedy one.
3. On the cliff, which earns more reward during training, and why?
Better final policy ≠ better performance while learning. A key distinction for real-world RL.
📝 TL;DR
  • Q-learning: Q(s,a) ← Q(s,a) + α[r + γ maxa' Q(s',a') − Q(s,a)].
  • Off-policy: learns the optimal Q* from any exploratory data. That enables replay buffers.
  • SARSA = safer while learning; Q-learning = optimal final policy.
  • Q-learning + neural network + 2 tricks = DQN (Phase 4).
