Phase 3 · Lesson 5

n-step returns & eligibility traces

TD looks 1 step ahead and Monte Carlo looks all the way to the end. The best is often in between.

🧰 You'll need (quick reminders)
  • TD(0): one real reward, then trust your guess (Lesson 3.2).
  • Monte Carlo: use all real rewards to the end, no guessing (Lesson 3.1).
🎯 Hook

In 1995, Wei Zhang and Tom Dietterich trained a neural network with TD(λ), the algorithm at the end of this lesson, to schedule NASA space-shuttle payload processing: the tasks needed to install and test cargo before a launch. Their learned scheduler beat the best existing method for the job, an iterative-repair system based on simulated annealing that was in regular use at Kennedy Space Center.

The same dial, λ, comes back almost unchanged in PPO as GAE(λ) (λ = 0.95 by default, the standard advantage estimator in RLHF). Learn it here with tables and you'll recognize it later.

💡 Big idea Use n real rewards, then bootstrap from your guess: the n-step return. n = 1 is TD, n = ∞ is Monte Carlo. Middle values often learn fastest, because they get some of TD's low variance and some of MC's low bias.
🧠 Analogy: judging a chess move

To judge a move, you can trust your gut immediately (TD: 1 step), or play the whole game out (Monte Carlo: all steps, slow and noisy). A strong player does something in between: think n moves ahead, then use their positional judgment. n is how far you look before trusting your estimate.

Gt:t+n = rt+1 + γrt+2 + … + γn−1rt+n + γn V(st+n) "n real rewards, then my guess for where I'll be after n steps"
🎮 Playground · What does an n-step target use?

✏️ Worked example: a 1-step vs a 2-step target

γ = 0.9. From state s you get r = −1, land in s₁ (V(s₁) = 4), then get r = −1 again and land in s₂ (V(s₂) = 6).

  • 1-step (TD) target: −1 + 0.9 × V(s₁) = −1 + 3.6 = 2.6. One real reward, then a guess.
  • 2-step target: −1 + 0.9 × (−1) + 0.9² × V(s₂) = −1 − 0.9 + 4.86 = 2.96. Two real rewards, then a guess further away.

More real rewards = less reliance on possibly-wrong guesses, but more randomness from the actual steps.

Does the middle really win?

Sutton & Barto test this on a longer random walk with 19 states (exit left = −1, exit right = +1). For each n we try several step sizes α and keep the best, then measure the average error over the first 10 episodes.

🎮 Playground · Which n learns fastest? (19-state random walk)

Our Python version of this experiment: n = 1 → 0.35, n = 2 → 0.28, n = 4 → 0.27, n = 8 → 0.28, n = 16 → 0.33. There's a sweet spot in the middle, as in the textbook.

Why does a bigger n help when reward is rare? Each update carries real reward n cells back instead of 1. With reward only at the exits, TD(0) needs many visits for the news to crawl back one cell at a time; a 4-step return moves it 4 cells in a single update. Push n too far, though, and Monte Carlo's noise comes back: hence the sweet spot.

λ: average all the n's at once

Picking one n is awkward. The λ-return averages all n-step returns, where each extra step of lookahead gets its weight multiplied by λ: short lookaheads get the most weight and longer ones fade away (the bar chart below shows it). In math: weight (1−λ)λn−1 for the n-step return.

🎮 Playground · The λ dial

Math refresher Eligibility traces: λ without waiting

Computing a λ-return seems to need the future. The trick: run it backwards. Think of a trail of footprints that slowly fades: when a surprise arrives, the freshest footprints get the most credit. Every state keeps an eligibility trace e(s): a "how recently was I here?" counter. Wipe the counters at the start of each episode, then do this every step:

e = {x: 0 for x in states}                   # start of each episode: no footprints yet
# ...then, at every step from s to s2 with reward r:
e[s] += 1                                  # I was just here
delta = r + gamma * V[s2] - V[s]             # the usual TD error
for every state x:
    V[x] += alpha * delta * e[x]             # credit recently visited states
    e[x] *= gamma * lam                      # memories fade

A surprise now (δ) is shared out to every recent state, in proportion to how recently it was visited. λ = 0 → only the current state (TD(0)). λ = 1 → everyone since the start (Monte Carlo-like). This is TD(λ), and it's one neat answer to the credit assignment problem from Lesson 0.1.

✏️ Worked example: footprints and λ-returns give the same answer

A 3-step corridor: s₀ → s₁ → s₂ → 🏁. Rewards 0, 0, then +1 for the last step. γ = 1, λ = 0.5, α = 0.5, all values start at 0.

Backward view (footprints). The first two TD errors are 0 (no reward, all values 0). The last is δ = 1 + 0 − 0 = 1. At that moment the footprints are e(s₂) = 1, e(s₁) = γλ = 0.5, e(s₀) = (γλ)² = 0.25. So V(s₂) += 0.5 × 1 × 1 = 0.5, V(s₁) += 0.5 × 0.5 = 0.25, V(s₀) += 0.5 × 0.25 = 0.125. The state k steps back gets α · δ · (γλ)k.

Forward view (λ-return) for s₀. Its 1-step return is 0 + V(s₁) = 0, its 2-step return is 0 + 0 + V(s₂) = 0, and its full return is 1. Weights: 1 − λ = 0.5 on the 1-step, (1 − λ)λ = 0.25 on the 2-step, and all the leftover weight, λ² = 0.25, on the full return (the episode ends there). λ-return = 0.5 × 0 + 0.25 × 0 + 0.25 × 1 = 0.25. Update: 0.5 × (0.25 − 0) = 0.125. The same number. (For s₁: 0.5 × 0 + 0.5 × 1 = 0.5, update 0.25. For s₂: 1, update 0.5.)

The (γλ)k footprint is exactly the share of the λ-return that reaches k steps ahead. Here the two views match exactly; in general they match exactly when updates wait until the episode ends, and very closely when they don't.

🎬 Animation · Footprints that fade

The robot walks a corridor toward 🏁 (reward +1). Every cell it leaves gets a footprint 👣 (its eligibility trace), and all footprints fade by γλ each step. When the reward arrives, every cell's value goes up in proportion to its footprint. Compare λ = 0 (only the last cell learns) with λ = 0.9 (the whole trail learns at once).

🌍 Where it's used
n-step returns, picked per domain 🧪 Research · 2019 DeepMind MuZero

How: in Atari, value target = 10 real rewards + γ10 × the search's value estimate (n = 10). In board games it uses the final result (n = ∞, Monte Carlo).

Why this method: Atari games are long with rewards along the way, so waiting for the end is noisy. Board games only score at the end, so it simply uses the result.

Multi-step targets in Atari agents 🧪 Research · 2017 DeepMind Rainbow

How: target = 3 real rewards + γ3 × the best Q three steps later, instead of 1 reward + one-step bootstrap.

Why this method: they tried n = 1, 3, 5: 3 and 5 both did well early, 3 was best by the end. Removing multi-step targets was one of the two biggest losses.

Eligibility traces: TD(λ) 📜 History · 1992 Tesauro: TD-Gammon

How: state = the board · reward = only at game end · V = expected outcome · each TD error also corrects earlier positions' estimates, fading exponentially at a rate set by λ.

Why this method: one win or loss at the end must credit dozens of earlier moves. Traces spread each surprise backwards online, without storing whole games.

🤯 Fun fact

Eligibility traces were inspired by biology. Harry Klopf in the 1970s and 80s proposed that neurons keep a short-lived "eligibility" for change after they fire, so a reward arriving a bit later can still strengthen them. Neuroscientists have since found evidence for synaptic eligibility traces in the brain.

🌉 LLM bridge · λ in RLHF

PPO's advantage estimator GAE(λ) (Phase 5) is this lesson's λ-return applied to advantages: Ât = Σ (γλ)l δt+l: "how much better than expected was this step, plus a fading share of all the surprises after it". Classic RLHF setups used γ = 1 and λ = 0.95. GRPO-style methods effectively use λ = 1 (pure Monte Carlo: final reward minus a group baseline), trading higher variance for not needing a value model at all.

📝 TL;DR
  • n-step return: n real rewards + γnV(st+n). n = 1 TD, n = ∞ MC. The middle is often best.
  • λ-return: weighted average of all n-step returns, weights (1−λ)λn−1.
  • Eligibility traces compute it online by fading "I was here" markers. That's TD(λ).
  • Same dial as PPO's GAE(λ). GRPO ≈ λ = 1.
