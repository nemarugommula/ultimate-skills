Phase 3 · Lesson 1

Monte Carlo: learn from complete episodes

No rulebook this time. Play whole episodes, see how they turn out, and average.

🧰 You'll need (quick reminders)
  • Return G = the total (discounted) reward from a moment until the episode ends (Lesson 0.3).
  • Value V(s) = the return you get on average starting from state s (Lesson 2.3).
  • The update rule: new guess = old guess + α × (target − old guess). α (alpha) = step size, e.g. 0.1 = "move 10% of the way" (Lesson 1.2).
🎯 Hook

In 1946, just after the war, the mathematician Stanislaw Ulam was recovering from an illness and playing a lot of solitaire. Instead of calculating his chances of winning with math, he wondered: why not just play many games and count? Back at Los Alamos, he and John von Neumann turned the idea into a way to simulate neutrons for nuclear-weapons research. Its code name, "Monte Carlo", referred to the casino in Monaco where Ulam's uncle liked to gamble.

The big change in Phase 3

📖

Phase 2: we had the rulebook

We knew P(s'|s,a) and R, so we could compute values with sweeps. That's planning.

👣

Phase 3: we don't

The agent can only act and see what happens, like a real robot, a game, or an LLM talking to users. That's learning from experience.

💡 Big idea Monte Carlo (MC): play a complete episode, compute the actual return G from each state you visited, and nudge that state's value toward it. Average enough episodes and you get the true value. No model needed.
V(s) ← V(s) + α [ Gt − V(s) ] "After the episode ends: move my estimate toward the return I actually got from s." It's the one-line update rule from Phase 1 (new guess = old guess + α × surprise), with the target = the real return. 
for episode in range(N):
    trajectory = play_one_episode(policy)        # [(s0, r1), (s1, r2), ...]
    G = 0
    for s, r in reversed(trajectory):           # walk backwards (Lesson 0.3!)
        G = r + gamma * G
        V[s] += alpha * (G - V[s])
✏️ Worked example: two episodes by hand

Tiny world, γ = 1, α = 0.5, all values start at 0.

Episode 1: A → B → 💎. Rewards: −1 (A to B), then +10 (onto 💎). Walk backwards: G(B) = +10, G(A) = −1 + 10 = +9. Update: V(B) = 0 + 0.5 × (10 − 0) = 5; V(A) = 0 + 0.5 × (9 − 0) = 4.5.

Episode 2: A → C → 🔥. Rewards: −1, then −10. G(C) = −10, G(A) = −11. Update: V(C) = −5; V(A) = 4.5 + 0.5 × (−11 − 4.5) = −3.25.

See the weakness? V(A) jumped from +4.5 to −3.25 because of one unlucky episode. Monte Carlo is correct on average, but each single episode is noisy. Many episodes (and a smaller α) are needed for V(A) to settle.

🧸 Analogy · learning your commute

You want to know how long your drive to work takes from each landmark. Monte Carlo way: drive to work, and only when you arrive, write down "from the petrol pump it took 22 min, from the bridge 15 min…". After a few weeks, average your notes. Simple and unbiased, but you can only update after arriving, and one traffic jam throws off a whole day's numbers.

Math refresher First-visit vs every-visit, and why MC is "unbiased but noisy"

If a state is visited twice in one episode, first-visit MC only uses the return from the first visit; every-visit MC uses both. Both converge to the true value.

Unbiased = on average the target G equals the true value exactly, since G is a real sample of the thing we want. High variance = any single G depends on every random step until the end, so it can be far off. (The mean/std ideas from the Phase 0 recap: same mean, big std.) This bias-vs-variance trade-off comes back again and again, all the way to PPO and GRPO.

From prediction to control

Here's a subtlety. V tells me how good a state is, but to pick an action I'd need to know where each action lands me, and that's the rulebook P, which we no longer have. So we learn Q(s,a) instead: "how good is this specific move here?" Then picking the best action is just "take the move with the biggest Q", no rulebook needed.

One more ingredient: to keep learning about every move, we must keep exploring (ε-greedy from Phase 1). So the loop is: estimate Q from real episodes, act mostly greedily with some exploration, repeat. That's policy iteration (Lesson 2.5) with experience instead of sweeps:

for episode in range(N):
    traj = play_one_episode(lambda s: epsilon_greedy(Q, s))   # behave using the LATEST Q
    G = 0
    for s, a, r in reversed(traj):                     # walk backwards, as before
        G = r + gamma * G
        Q[s][a] += alpha * (G - Q[s][a])                   # evaluate: nudge Q toward the real return

Where's the "improve" step? There isn't a separate one. Improvement is automatic: the next episode's ε-greedy reads the freshly updated Q, so better-looking moves get picked more often straight away.

Why a constant α (say 0.1) here instead of the 1/N average? Because the policy keeps changing. Returns collected early on were earned by an older, worse policy, so they go stale. A constant α keeps weighting recent episodes more and slowly forgets the old ones.

Vocabulary: estimating V or Q for a fixed policy is called prediction; finding a better policy is called control. Methods that don't need the rulebook P are model-free.

🌍 Where it's used
Monte Carlo value targets 🧪 Research · 2017 DeepMind AlphaZero (chess, shogi, Go)

How: state = a board position · reward = only at the end (−1 loss, 0 draw, +1 win) · V(s) of every position is trained toward that final result: the full return G.

Why this method: self-play games always end, and every move shares one result, so waiting for the real outcome is simple and unbiased. No need to trust estimates of later positions.

One score at the end, for every token 🏭 In production · 2025 DeepSeek-R1

How: state = prompt + answer so far · action = next token · reward = a rule-based check that the final answer is correct (plus a format check), given once at the end.

Why this method: math answers and code can be checked exactly. For the first model (R1-Zero) they skipped a learned scoring model because it “may suffer from reward hacking” at scale.

🤯 Fun fact

Monte Carlo rollouts powered computer Go years before AlphaGo: programs judged a move by playing thousands of random games from it and counting wins. AlphaGo kept rollouts, played out by a fast, simple linear policy, and added deep neural networks to guide the search toward promising moves and to judge positions directly.

🌉 LLM bridge · LLM RL is mostly Monte Carlo

In RL for LLMs (Phase 8), the model writes a complete answer (the episode), a verifier scores it at the end, and that one score is the return for every token. That's Monte Carlo: no bootstrapping, wait for the final outcome. GRPO's "average reward of a group of answers" is MC estimation of V(prompt). It works because answers are short episodes with a clear ending. For long agent tasks spanning hours, the high variance of MC becomes a real research problem.

Check yourself ✅

1. When can a Monte Carlo agent update its values?
Gt includes every reward until the end, so MC must wait. That's its main weakness. TD (next lesson) fixes it.
2. Why do model-free control methods learn Q(s,a) instead of V(s)?
V tells you how good states are, but without P you don't know which action leads where. Q bakes the action's consequence in.
3. MC targets are "unbiased but high variance". What does that mean?
G is a genuine sample of the return (so it's right on average), but it depends on every random step to the end, so it's noisy.
📝 TL;DR
  • Model-free: learn only from experience; no P, no R table.
  • MC: V(s) ← V(s) + α[G − V(s)] after each episode. Unbiased, high variance, must wait until the end.
  • For control, learn Q(s,a) + explore with ε-greedy.
  • LLM RL with a final verifier score is essentially Monte Carlo.
