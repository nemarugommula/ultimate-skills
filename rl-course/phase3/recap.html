🧾 Cheat sheet

The pattern behind everything

estimate ← estimate + α(target − estimate). Methods differ only in the target.

Monte Carlo

Target = Gt (real return). Wait until the episode ends. Unbiased, high variance.

TD(0)

Target = r + γV(s'). Update every step, bootstraps. Some bias, low variance, often faster.

SARSA (on-policy)

Target = r + γQ(s',a'), with a' the action actually taken next. Learns the value of how you really behave → safe.

Q-learning (off-policy)

Target = r + γ maxa' Q(s',a'). Learns Q* from any data → optimal policy; enables replay buffers.

n-step & λ

n real rewards + bootstrap. λ-return averages all n (weights (1−λ)λn−1). λ = 0 TD, λ = 1 MC. Eligibility traces do it online.

Prediction vs control

Prediction = estimate Vπ. Control = find a good policy: learn Q, act ε-greedily, improve (GPI).

LLM links

LLM RL with a final reward ≈ Monte Carlo. PPO's critic uses TD targets, and GAE(λ) mixes them. On-policy (PPO/GRPO) vs off-policy (DPO on fixed data).

🗂️ Case files: five real problems, one phase later

The same five problems follow you through the course (meet them). Here's what this phase changes for each.

🌡️ The cooling plant

Now: no simulator needed: Q-learning can learn from the plant's own logged operation (it's off-policy), with sensor readings chopped into buckets as the state and settings as actions. Reward = −energy each step, so TD updates every few minutes instead of waiting for an “end”.

Still breaks: with hundreds of sensors the table has astronomically many cells, most never visited, and it can't guess that two similar readings deserve similar settings.

📱 The feed

Now: TD learning on logged sessions: after each item shown, nudge V(user state) toward reward + γV(next user state), learning long-term value from data you already have.

Still breaks: millions of users and items don't fit in a table, and a table learns nothing about a new video until it has been shown many times.

🦾 The robot hand

Now: not yet. Model-free learning removes the need for a physics model, but these methods still need a table with a row per state, and camera images and joint angles can't be listed in rows.

Still breaks: it needs something that reads raw camera pixels and handles continuous motor commands.

♟️ The board game

Now: self-play + TD: after every move, nudge V(board) toward V(next board), and the final win or loss is the only reward. That's how TD-Gammon learned backgammon (Lesson 3.2), with λ-traces spreading credit back over the game.

Still breaks: a table can't hold 1020 backgammon positions; TD-Gammon worked only because something that generalizes between similar boards replaced the table.

🧑‍💻 The coding agent

Now: Monte Carlo fits naturally: run the agent to the end, the tests pass or fail, and that one return credits every token and tool call. TD or n-step returns could give earlier credit, if you had a V(partial attempt).

Still breaks: the states are texts that never repeat exactly, so a table never sees the same state twice.

🧩 New problem

A city wants a smarter traffic light at one busy four-way junction. Sensors in the road count cars waiting in each direction, and every few seconds the controller can keep the current green or switch to the other road (after a fixed yellow). Nobody has a formula for how traffic arrives, but the city has a good traffic simulator and months of logs from the old fixed-timer light.

Before you open the answer, write down: the state, the action, the reward, episodic or continuing (and γ), and which method from this phase (or earlier) you'd try first.

Reveal One good framing + the classic mistakes

State: waiting cars per direction, bucketed (0, 1–3, 4–8, 9+), + which road is green + time since the last switch. Action: keep or switch. Reward: −(number of cars waiting) each step. Episodic? Continuing (traffic never ends), with γ ≈ 0.95–0.99.

Method: Q-learning in the simulator, with ε-greedy exploration. There's no transition table (so not DP), rewards come every step (so TD beats waiting for an end), and being off-policy means the old light's logs can be replayed too. If it must keep learning on the real street, SARSA's caution while exploring is worth it.

Classic mistakes: reward = cars that got through (it learns to keep the busy road green forever and starves the side street: count waiting cars instead); leaving “time since switch” out of the state (not Markov, and it may flicker the lights); exploring randomly on a real junction; and exact car counts in a table, which explodes the states.

Boss quiz 👾

Q(s,a) = 2, r = −1, γ = 1, α = 0.5. Next state s' has Q-values [4, 6] and the agent's ε-greedy policy actually picks the action worth 4. What are the SARSA and Q-learning updates?
SARSA target = −1 + 4 = 3 → 2 + 0.5 × (3 − 2) = 2.5. Q-learning target = −1 + max(4, 6) = 5 → 2 + 0.5 × (5 − 2) = 3.5.
You want to reuse a big log of old experience collected by a different policy. Which method fits?
Off-policy methods can learn about the optimal policy from data generated by any behavior. This is the basis of replay buffers and offline RL (Phase 6).

🚀 What's next: Phase 4

🏁 Phase 3 done: you can now learn values and good policies from experience alone (MC, TD, SARSA, Q-learning, n-step and λ), with no rulebook. Next payoff: the same updates on problems far too big for a table.

Tables don't scale: Atari screens, robot sensors and text have astronomically many states. Phase 4 replaces the table with a neural network, and adds the two tricks that made DQN play Atari from pixels: a replay buffer (the 2013 paper) and a target network (added in the 2015 Nature version).
