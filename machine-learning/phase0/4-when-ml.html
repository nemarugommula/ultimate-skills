Phase 0 · Lesson 4

When to use ML: rules vs classical ML vs deep learning

ML is a tool with running costs, not a badge. This lesson gives you a decision recipe: when a few lines of code beat any model, when trees on a table are the right call, when images, audio and text call for deep learning, and when the honest answer is “not yet”.

🧰 You'll need (quick reminders)
  • A tuned rule can match a model when patterns are few and stable; models win when patterns are many or moving (Lesson 0.1).
  • Always compare with a baseline, and remember most of an ML system's cost is outside the model (Lesson 0.2).
🎯 Hook: Google's first rule of ML is “don't”

Google runs some of the largest ML systems on Earth. Its public guide, Rules of Machine Learning by Martin Zinkevich, has 43 rules. Rule #1 is not about models at all:

“Don't be afraid to launch a product without machine learning.”

Two rules later comes the other side: Rule #3, “Choose machine learning over a complex heuristic.” So when does a team that has every ML tool in the world reach for a plain rule, and when does the rule have to go?

🔮 Predict first

Why would Google tell its engineers to launch without ML first?

The guide says it plainly: ML is cool, but it requires data, and borrowing data from another problem will likely underperform basic heuristics. Launch with a simple rule, measure, collect the data, then replace the rule when it gets complicated (Rule #3: a simple heuristic gets you out the door; a complex one is unmaintainable).

Numbers first: what kind of data, how much of it

💡 Big idea Ask three questions in order. 1. Can a simple rule do it? If the logic is known, stable, exact (tax, eligibility, thresholds), write code. 2. Is it a table? Rows and columns with meaningful features → classical ML, usually gradient-boosted trees, with a linear model as a check. 3. Is it raw perception? Pixels, waveforms, free text → deep learning, usually starting from a pre-trained model. And at every step: is the expected value bigger than the cost of building and running it?
🧠 Analogy: calculator, spreadsheet analyst, eyes and ears

To add VAT (sales tax) you use a calculator (a rule): exact, instant, no judgment. To guess which invoices will be paid late, you hire an analyst with a spreadsheet (classical ML): they find patterns in the columns. To read the handwritten invoices that come in by fax, you need eyes (deep learning): the useful “columns” aren't written down anywhere; they have to be learned from the pixels. Nobody hires an analyst to add VAT, and nobody builds eyes to read a spreadsheet.

🤔 Why this? Why not always use the most powerful model?
  1. The problem before. “Use AI” gets attached to problems a rule would solve, and teams spend months building a model nobody needed, or pick a deep network for a spreadsheet problem where trees would be better, cheaper and faster.
  2. What people tried. Always reaching for the newest, most flexible model. Flexible models need more data to beat simpler ones: below, with 8 examples a human rule scores 83%, a straight line 75% and a flexible model only 70%; the flexible model takes the lead only from about 30 examples.
  3. Why this works. Matching the tool to the data shape and size wins: rules need zero data, linear models a little, trees a lot of rows, deep networks a lot of raw examples (or someone else's pre-trained model). The cost check is simple arithmetic: decisions per month × cost per error × error rate saved, minus running costs.
  4. What it costs, when it fails. Every model adds data pipelines, monitoring, retraining and explanations (Lesson 0.2). Rules fail when they grow into a tangle of exceptions; ML fails when there's little data, when errors must be exactly zero, or when nobody can act on its output.
  5. What came next. Pre-trained foundation models made deep learning cheap to use (call an API or fine-tune) for text and images, which shifted the line again; the sibling AI Engineer course covers when not to use a large language model (LLM). In this course, Lesson 4.6 revisits trees vs deep learning on tables.

How much data do you have?

Data size decides more than taste does. Here's a two-feature problem (the interlocking moons again). A domain expert knows one fact: “class ■ sits lower”. That's a rule with no training. A straight line (logistic regression) learns from data but can only draw lines. A flexible model (k-nearest neighbours, a stand-in for any flexible learner) can follow any shape but needs examples to do it.

🔮 Predict first

With only 8 labelled examples, which approach scores best on new data?

The rule: 83%, against 75% for the line and 70% for the flexible model (averaged over 5 random samples of 8). The rule carries knowledge the models must extract from data, and 8 points isn't enough data. With 30 examples the flexible model jumps to 94%; with 800 it reaches 96%, while the line stalls at about 84%, no better than the rule, because the true boundary isn't straight.

✏️ Worked example: the defaults, by hand
  • Rules: 20,000 × 12% = 2,400 wrong calls × $5 = $12,000, + $500 upkeep = $12,500 a month.
  • ML: 20,000 × 8% = 1,600 wrong calls × $5 = $8,000, + $1,500 running = $9,500 a month.
  • Saving: $3,000 a month. Build: 6 weeks × $4,000 = $24,000. Payback: 24,000 ÷ 3,000 = 8 months. After 3 years: 36 × 3,000 − 24,000 = $84,000.
  • Now cut volume to 5,000 decisions a month: the error saving is 5,000 × 4% × $5 = $1,000, but ML costs $1,000 more to run than the rules: the saving is zero and it never pays back. Same model, same accuracy; the answer flipped on volume.

🧰 Tools you'll actually use

The cheapest way to answer “do we need ML?” is to measure it. scikit-learn's cross_val_score (Lesson 5.1) scores several candidates on the same splits: a do-nothing baseline, a one-question rule learned by a depth-1 tree, a linear model and boosted trees.

from sklearn.datasets import load_breast_cancer
from sklearn.dummy import DummyClassifier
from sklearn.ensemble import HistGradientBoostingClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.tree import DecisionTreeClassifier

X, y = load_breast_cancer(return_X_y=True, as_frame=True)   # 569 tumours, 30 numeric columns

candidates = {
    "baseline (majority class)": DummyClassifier(strategy="most_frequent"),
    "one-question rule (depth-1 tree)": DecisionTreeClassifier(max_depth=1, random_state=0),
    "logistic regression": make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000)),
    "gradient-boosted trees": HistGradientBoostingClassifier(random_state=0),
}
for name, model in candidates.items():
    scores = cross_val_score(model, X, y, cv=5)              # 5 train/test splits (Lesson 5.1)
    print(f"{name:34s} {scores.mean():.3f}")
# baseline 0.627 · rule 0.900 · logistic 0.981 · boosted trees ≈ 0.965

rule = DecisionTreeClassifier(max_depth=1).fit(X, y)
print("the learned rule:", X.columns[rule.tree_.feature[0]], "<=", round(rule.tree_.threshold[0], 2))  # worst radius <= 16.8

Read the ladder: one question already gets 90%, so a rule is a serious option; a linear model adds 8 points; here the boosted trees don't beat it (569 clean numeric rows is small and nearly linear). If the 10% the rule misses are cheap mistakes, ship the rule. If they're missed cancers, you need the model, and a doctor in the loop.

🚀 Startup vs big tech

Week one

Ship rules, log everything, and write down the metric. When the rule file passes a few dozen exceptions, or a month of logs gives you thousands of labelled rows, train gradient-boosted trees. For images or text, call a pre-trained model or an API instead of training your own.

At scale

Large volumes make small error rates expensive, so a 1% improvement can justify a team. Expect a stack: rules for hard constraints and safety, boosted trees for tabular scoring, deep models for perception and language, with cost-per-prediction tracked like any other infrastructure bill.

🎤 Interview angle

“Would you use machine learning for this?” (Product scenario.) A strong answer:

  • Asks what decision it drives, how many decisions, the cost of each kind of error, and whether labels exist.
  • Proposes a rule or baseline first, with logging, and names the metric that would justify replacing it.
  • Picks the model family from the data: tables → gradient-boosted trees (with a linear check); images/audio/text → pre-trained deep models.
  • Mentions running costs: monitoring, retraining, latency, explainability and who acts on the output.
🏭 In the real world
Rules of Machine Learning 🏢 Google Zinkevich: Rules of ML

How: Rule #1 launch without ML if you must; #3 move to ML once heuristics get complex; #4 keep the first model simple; #14 start with an interpretable model.

Why this method: distilled from many Google products: the first model's value comes from the data and pipeline it forces you to build, and heuristics are worth keeping as features later.

Deep learning takes images 🧪 Research · 2012 Krizhevsky, Sutskever, Hinton: ImageNet Classification with Deep CNNs

How: a 60-million-parameter convolutional network trained on 1.2 million labelled images, for five to six days on two GPUs.

Why this method: features learned from raw pixels beat the best hand-designed features by a wide margin (15.3% vs 26.2% top-5 error), which is why perception tasks start from deep models today.

Trees still rule tables 🧪 Research · 2022 Grinsztajn et al.: Why do tree-based models still outperform deep learning on tabular data?

How: 45 tabular datasets, equal hyperparameter-search budgets for tree ensembles and deep tabular models.

Why this method: trees stayed best on medium-sized tables, being robust to uninformative columns and good at irregular patterns. Lesson 4.6 covers when that's changing.

Rules and models together 🏢 Google · 2019 Gmail spam: new ML protections

How: new learned models complement Gmail's existing ML and rules-based protections.

Why this method: rules handle what's known and must always hold; models catch the shifting, fuzzy rest. “Rules vs ML” is usually “rules and ML”.

🤯 Fun fact · the network was split across two GPUs because of memory

AlexNet's authors spread their network over two GPUs, with the halves talking only at certain layers, for a mundane reason: a single GTX 580 had only 3 GB of memory, too little for the network they wanted. Training took five to six days. Today the same job is a small exercise on one consumer GPU; tables of customer data, meanwhile, are still usually best served by trees that train on a laptop in seconds.

Check yourself

1. 10,000 decisions a month; a model would cut errors from 10% to 7%; each error costs $2; the model costs $800 a month to run (the rule costs nothing). Does it pay?
10,000 × (10% − 7%) = 300 fewer errors × $2 = $600 saved, minus $800 running = −$200 a month. At this volume and error cost, keep the rule. At 100,000 decisions it would save $6,000 − $800 = $5,200 a month.
2. A bank wants to predict loan default from 40 columns (income, debts, history) with 200,000 past loans. A colleague proposes a large neural network. Your first proposal?
This is a medium-sized table: tree ensembles are the strong default (Grinsztajn et al., 2022) and logistic regression gives an explainable reference, which credit decisions often require. A neural net can be tried later; it must beat the trees on held-out data to earn its cost.
3. Which request is the best fit for a plain rule instead of ML?
The age check is exact, stable and legally defined: a two-line rule, 100% right, fully auditable. House prices are fuzzy patterns in a table (classical ML); transcription is raw audio (deep learning, pre-trained).
📝 TL;DR
  • Ask in order: can a rule do it? Is it a table? Is it raw perception? Then check the cost arithmetic.
  • Rules win when logic is exact, stable or there's no data yet (Rules of ML #1); replace them when they become a tangle (#3).
  • Tables → gradient-boosted trees (plus a linear check). Images, audio, text → pre-trained deep learning (AlexNet: 15.3% vs 26.2% error).
  • Flexible models need data: with 8 examples the expert rule beat both models; from about 30 the flexible model led.
  • Value = decisions × error-rate saved × cost per error − running costs. Volume often flips the answer.
