SHAP: fair credit for every feature

“Why did the model say that, for this customer?” SHAP answers with a number per feature that adds up exactly to the prediction, borrowing a 1953 idea from game theory about splitting a prize fairly. It's the most used explanation method for tabular models today.

🧰 You'll need (quick reminders)
  • Global vs local explanations, and the correlated-features trap of permutation importance (Lesson 8.1).
  • Gradient boosting adds up many small trees; a prediction is a sum of leaf values (Lesson 4.3).
  • An expected value is a probability-weighted average (Math 4.4).
🎯 Hook: twice as many warnings in the operating room

During surgery under general anaesthesia, a patient's blood oxygen can drop dangerously low (hypoxaemia). Anaesthesiologists watch dozens of signals at once and still rarely see it coming. In 2018 Scott Lundberg and colleagues at the University of Washington trained a gradient-boosted model on minute-by-minute records from over fifty thousand surgeries to predict the risk in real time.

A bare risk number wasn't enough: a doctor won't act on “risk 0.31” without knowing why. So each prediction came with the features pushing the risk up or down (this patient's weight, the current tidal volume, a recent drop in oxygen…). In the paper's tests, doctors anticipating 15% of hypoxaemia events on their own would anticipate 30% with the system's help.

Those per-feature pushes are SHAP values. How do you split one prediction fairly between features that interact? That's this lesson.

🔮 Predict first

A house-price model: being big adds $60k, a good location adds $100k, and being big and well located adds an extra $40k on top (big houses in good areas are rare). For a big house in a good location, who should get the extra $40k?

Split equally. The bonus exists only when both are present, and neither feature is more responsible for it. That's what the Shapley value does: average over every order of adding features. You'll compute it by hand in Playground 1.

Numbers first: one house, $120k to explain

The toy model: price = 200 + 60·big + 100·good location + 40·big·location + 20·pool (in $k; each feature is yes = 1 or no = 0, and half the houses on the market have each). The average house is predicted $300k. Our house has all three, and is predicted $420k. Something has to explain the +$120k.

MethodbiglocationpoolAdds up to
Remove one feature at a time (“leave one out”)+50+70+10+130 ✘ (counts the $40k bonus too often)

The two obvious methods disagree with each other and with the total, because of the interaction. The Shapley value gives each feature its main effect plus half of the shared bonus (60·½ + 20 = 45 and 100·½ + 20 = 65), and the pieces add up to the prediction, always.

💡 Big idea Treat the features as players in a team and the prediction minus the average prediction as the prize. A feature's SHAP value is its average marginal contribution: add the features one by one in a random order, note how much the prediction moves when this feature joins, and average over all orders. The result is the only way to split the prize that is additive (base value + all SHAP values = prediction), symmetric, and gives zero to a feature that never changes anything.
🧠 Analogy: splitting a taxi bill

Three friends share a taxi. Alone, Ana's ride would cost $20, Ben's $30; together they cost $35, because they live on the same street. Who saved what? If Ana got in first she “cost” $20 and Ben added $15; if Ben got in first he cost $30 and Ana added $5. Neither order is the true one, so average them: Ana pays $12.50, Ben $22.50, and together it's exactly $35.

That's Lloyd Shapley's 1953 rule, and it's exactly what SHAP does with features: the “ride” is the prediction, and getting in the taxi is a feature being revealed to the model.

🤔 Why this? Why SHAP?
  1. The problem before. Global tools (Lesson 8.1) say what matters on average, but a declined loan applicant, a doctor or a regulator asks about one prediction. For a linear model the answer is easy: weight × (value − average). For a forest or boosted model with interactions there was no principled answer.
  2. What people tried. Leave one out (remove a feature, see the change) double-counts interactions: in our house it sums to +130 instead of +120. LIME (2016) fits a small linear model around the point using perturbed samples, but its answer depends on how you sample and weigh the neighbours, and can change between runs. Tree “path” attributions (summing changes along the decision path) favour features near the top of the tree.
  3. Why this works. Averaging a feature's marginal contribution over every order is the unique split with additivity, symmetry and “no effect, no credit” (Shapley's theorem). With 3 features there are 3! = 6 orders: big contributes +40, +40, +50, +50, +40, +50 in them, average +45. Lundberg and Lee (2017) showed that several earlier methods, LIME included, are approximations of this one quantity, and named it SHAP (SHapley Additive exPlanations).
  4. What it costs, when it fails. Exact Shapley values need the model's answer for all 2M feature subsets: 230 ≈ 1 billion for 30 features. And “a feature is missing” must be simulated by filling in values from background data, which creates unrealistic rows when features are correlated, and splits credit between near-copies. SHAP explains the model, not the world: a big SHAP value is not a cause.
  5. What came next. TreeSHAP (Lundberg et al., 2020) computes exact SHAP values for tree ensembles in polynomial time, O(T·L·D²), which made it practical for every boosted model. KernelSHAP approximates it for any model. For causal questions (“what if we change this?”) you need experiments and causal methods (Lesson 8.4).

Step 1: compute Shapley values by hand

To ask “what does the model say if it only knows big?”, we fix big = yes and average the model over the unknown features, using how common they are in the background data. That gives a value v(S) for every subset S of known features. v(nothing) is the base value; v(everything) is the prediction.

✏️ Worked example: one order, by hand

Order location → big → pool, for our house (all three yes), with half the market big, well located and with a pool:

  • Nothing known: average over all houses = 200 + 30 + 50 + 10 + 10 = 300.
  • Reveal location = yes: 200 + 30 (big still unknown: half of 60) + 100 + 20 (half of the 40 bonus) + 10 = 360 → location contributed +60.
  • Reveal big = yes: 200 + 60 + 100 + 40 + 10 = 410 → big contributed +50 (its 60, minus the 30 already expected, plus the remaining 20 of the bonus).
  • Reveal pool = yes: 420 → pool contributed +10. Total 60 + 50 + 10 = 120 ✔ (every single order adds up; only the split differs).

Average big's contribution over all 6 orders and you get 45. That's the whole algorithm; everything else is making it fast.

Step 2: why TreeSHAP made SHAP practical

Brute force is fine for 4 features. Each extra feature doubles the number of subsets: 20 features is a million, 40 is a trillion, per prediction. Lundberg's team found that for trees you don't have to enumerate subsets at all: by walking each tree once and tracking what share of subsets reaches each leaf, you get the exact answer in time proportional to trees × leaves × depth², independent of 2M.

🎮 Playground 3 · How expensive is “exact”?

Work per explained row, counted as tree-node visits. Brute force needs T·L·M·2M (the paper's bound for exact Shapley on trees); TreeSHAP needs T·L·D², with L = 2D leaves per tree. Times assume about a billion node visits per second, a rough figure for one CPU core.

Pitfalls: what SHAP does not tell you

🔮 Predict first

A credit model uses income and tax paid, which are 99% correlated. For a high earner, income gets a SHAP value of +0.05 and tax paid +0.30. What's the right conclusion?

Near-twins share credit in whatever way the trees happened to split; retrain with a new seed and the split can flip. Sum SHAP values over groups of correlated features (the sum is stable), and never read a SHAP value as “if we raised tax paid, approval would rise”: that's a causal claim the model can't make (Lesson 8.4).
  • Explaining the model ≠ explaining the world. The pneumonia model of Lesson 8.1 would give asthma a large negative SHAP value, perfectly faithful to the model and dangerously wrong as medicine.
  • “Missing” is a modelling choice. Filling unknown features from background data (interventional) vs following the tree's own paths (TreeSHAP's default without background data) can give different numbers; the background set changes the base value too.
  • Output scale. For classifiers, TreeSHAP explains the log-odds by default (“raw” output), not the probability, so values add up in log-odds.
  • Explanations can be gamed. Slack et al. (2020) built models that behave in a biased way on real inputs but look innocent to LIME and SHAP, because those methods probe the model with unrealistic perturbed rows.
🧰 Tools you'll actually use

shap (0.54.1 as of late 2026): shap.TreeExplainer for trees (XGBoost, LightGBM, CatBoost, scikit-learn forests and boosting), shap.Explainer picks a method for any model, and shap.plots.waterfall / beeswarm / bar / force / scatter draw the plots. XGBoost and LightGBM can also compute TreeSHAP natively (pred_contribs=True, pred_contrib=True).

import shap
from sklearn.datasets import load_diabetes
from sklearn.ensemble import RandomForestRegressor

X, y = load_diabetes(return_X_y=True, as_frame=True)
model = RandomForestRegressor(n_estimators=200, random_state=0).fit(X, y)

explainer = shap.TreeExplainer(model)        # exact TreeSHAP: seconds, not centuries
sv = explainer(X)                             # an Explanation: .values, .base_values, .data

# additivity: base value + SHAP values = the model's prediction, row by row
print(sv.base_values[0] + sv.values[0].sum(), model.predict(X.iloc[[0]])[0])

shap.plots.waterfall(sv[0])   # why this patient's prediction
shap.plots.beeswarm(sv)       # every patient, every feature

# any model (slower, sampling-based): pass a prediction function and background data
explainer_any = shap.Explainer(model.predict, X.sample(100, random_state=0))

Checked against the shap documentation (we can't install shap on this course's laptop). For classifiers, add model_output="probability" with background data if you want explanations in probability units instead of log-odds.

🚀 Startup vs big tech

Week one

Run shap.TreeExplainer on your boosted model and look at the beeswarm with a domain expert. Ten minutes usually finds a leak, a feature with the wrong sign, or a proxy you didn't mean to use. Show waterfalls for your worst errors: they tell you which features misled the model.

At scale

Lenders turn SHAP values into reason codes for adverse-action notices (“declined mainly because of: high utilization, short history”), fraud and support teams see the top three drivers next to each score, and monitoring tracks mean |SHAP| per feature over time to catch drift (8.6). Explanations are computed in batch or cached; KernelSHAP is rarely fast enough for live traffic.

🎤 Interview angle

“Explain SHAP values to a product manager, then tell me when you wouldn't trust them.” A strong answer:

  • Plain words: each feature's fair share of the gap between this prediction and the average prediction; they add up exactly (base value + SHAP values = prediction).
  • Mechanics: the Shapley value from game theory, the average marginal contribution over all orders of adding features; exact for trees with TreeSHAP in O(T·L·D²).
  • Distrust when: features are strongly correlated (credit splits arbitrarily; group them), the background data is unrepresentative, someone reads it as causal, or the units are log-odds and they think in probabilities.
  • Compares with permutation importance (global, metric-based) and LIME (local, unstable), and knows a glass-box model can be the better answer when explanations are legally required.
🏭 In the real world
Hypoxaemia warnings in surgery 🧪 Research · 2018 Lundberg et al.: Explainable machine-learning predictions for the prevention of hypoxaemia during surgery (Nature Biomedical Engineering)

How: a gradient-boosted model on minute-by-minute anaesthesia records from over 50,000 surgeries predicts low blood oxygen, and shows the features driving each prediction.

Why this method: clinicians need the reason to act; with explanations, the expected share of events anticipated went from 15% to 30% in the study.

The unifying paper 🧪 Research · 2017 Lundberg & Lee: A Unified Approach to Interpreting Model Predictions (NeurIPS 2017)

How: defined additive feature attribution methods and showed a unique solution with local accuracy, missingness and consistency: Shapley values. Unified six earlier methods, LIME included.

Why this method: it replaced a zoo of incompatible heuristics with one quantity and a theorem.

TreeSHAP and global understanding 🧪 Research · 2020 Lundberg et al.: From local explanations to global understanding with explainable AI for trees (Nature Machine Intelligence)

How: the first polynomial-time algorithm for exact Shapley values of tree ensembles, interaction values, and global plots built from many local explanations; applied to mortality risk, kidney disease and monitoring a deployed hospital model.

Why this method: exponential to O(T·L·D²) is what made SHAP routine for XGBoost and LightGBM models.

The library 🧰 Open source shap on GitHub

How: TreeExplainer, KernelExplainer, DeepExplainer and friends behind one shap.Explainer interface, plus the plots.

Why this method: one consistent Explanation object for any model, and plots people already recognize.

Fooling the explainers 🧪 Research · 2020 Slack et al.: Fooling LIME and SHAP

How: a “scaffolded” model detects the off-distribution rows the explainers generate and answers those innocently, while using a sensitive feature on real inputs.

Why this method: a reminder that a clean explanation is evidence, not proof; audits need real data and outcome checks too (Lesson 8.3).

🤯 Fun fact · a Nobel prize hiding in your notebook

Lloyd Shapley published the value in 1953 in a paper about splitting the winnings of cooperative games. He shared the 2012 Nobel Memorial Prize in Economic Sciences with Alvin Roth “for the theory of stable allocations and the practice of market design”. Six decades later, the same averaging-over-orders idea explains why your model declined a loan.

Check yourself

1. A churn model's base value is 0.20 (average predicted churn). For one customer the SHAP values are +0.25 (support tickets), −0.05 (tenure) and +0.10 (price plan). What does the model predict for this customer?
Additivity: 0.20 + 0.25 − 0.05 + 0.10 = 0.50. That's the defining property of SHAP values (if the model explains probability; in log-odds units the same sum gives the log-odds).
2. Your model has 40 features. A teammate wants to compute exact Shapley values by enumerating feature subsets for each of 10,000 rows. What do you suggest?
Each feature doubles the subsets. TreeSHAP gives the exact answer in O(T·L·D²) for trees; for other models, KernelSHAP or permutation sampling approximate it. Leave-one-out isn't the same: it mishandles interactions and doesn't add up.
3. In a hiring model's beeswarm, “years since graduation” has a large spread and high values push the score down. HR asks: “So if a candidate had graduated more recently, would we hire them?” Best answer?
SHAP is faithful to the model, not to the world. A feature that encodes a protected attribute (age, here) is exactly what a fairness audit looks for (Lesson 8.3), and “would changing it change the outcome?” is a causal question (Lesson 8.4).
📝 TL;DR
  • A SHAP value is a feature's average marginal contribution over all orders of adding features: the Shapley value of game theory.
  • Additivity: base value (average prediction) + SHAP values = this prediction, exactly. Interactions are shared fairly.
  • Exact brute force costs 2M model calls per row; TreeSHAP does it exactly for trees in O(T·L·D²).
  • Waterfall = one row; beeswarm = all rows (spread = importance, colour vs side = direction).
  • Pitfalls: correlated features split credit arbitrarily, the background data matters, classifiers default to log-odds, and SHAP explains the model, not the world.
