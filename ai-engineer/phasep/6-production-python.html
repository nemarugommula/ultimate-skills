🎯 Hook

Open the docs of OpenAI's and Anthropic's official Python SDKs and you'll find the same two defaults: requests time out after 10 minutes, and failed or timed-out requests are retried 2 times with a short exponential backoff.

Those are sensible defaults for a script that generates a long report. In a chat API they mean one hung provider connection can hold your user (and one of your server's connections) for 3 attempts × 10 minutes = 30 minutes. Nothing is broken in the code; it's a configuration you didn't choose. This lesson is about choosing it.

Numbers first: where a chat request's time goes

Typical ranges; they vary a lot by model, prompt size and load. Measure yours (Lesson 8.2).

Two lessons fall out of this table. First, stream: the user sees words after ~1 s instead of a spinner for 15 s. Second, almost all the risk sits in one network call you don't control, so timeouts and retries are part of your design, not an afterthought.

1. A reproducible project with uv

A virtual environment (venv) is a folder with its own Python and installed packages, so this project's library versions don't clash with another's. A lockfile records the exact version of every package, including dependencies of dependencies, so your laptop, CI and the Docker image install the same thing. uv, from Astral (the makers of Ruff), does both: it manages Python versions, venvs, dependencies and a universal uv.lock, and its docs claim 10–100× faster installs than pip.

uv init rag-api && cd rag-api        # pyproject.toml, .python-version, README, .gitignore
uv add fastapi uvicorn pydantic-settings anthropic   # updates pyproject.toml + uv.lock + .venv
uv add --dev pytest ruff mypy         # dev-only tools
uv run pytest                         # runs inside the project venv, syncing it first
uv sync --locked                      # CI / Docker: install exactly the lockfile, fail if it's stale

Commit pyproject.toml and uv.lock; never commit .venv. The same pattern works with Poetry or pip-tools; the idea that matters is declared dependencies + a lockfile.

2. Validate at the boundary: FastAPI + Pydantic

FastAPI is a web framework where you describe each endpoint with type hints. Pydantic models (classes whose fields have types and constraints) define the request and response. FastAPI validates every incoming body against the request model; if it fails, the client gets 422 Unprocessable with a list of exactly which field is wrong, and your code never runs. The response model is your contract with the frontend: it's documented automatically (OpenAPI at /docs) and filtered on the way out.

class AskRequest(BaseModel):
    question: str = Field(min_length=1, max_length=2_000)   # caps prompt size (and cost)
    top_k: int = Field(default=3, ge=1, le=20)

# POST /ask {"question": ""} → 422:
# {"detail": [{"type": "string_too_short", "loc": ["body", "question"], ...}]}

Validating input is also cheap protection: a max_length on the question stops a 500,000-character paste from becoming a 125,000-token bill.

3. Stream tokens with Server-Sent Events

Server-Sent Events (SSE) is a simple HTTP format for pushing a stream of messages from server to client: the response stays open with type text/event-stream, and each message is a few lines like event: token / data: "Hello" followed by a blank line. Browsers read it natively with EventSource, and most LLM APIs stream this way. Since version 0.135, FastAPI supports it directly: return EventSourceResponse and yield events from an async generator. It also sends a keep-alive comment every 15 seconds and disables proxy buffering for you. (On older versions, use StreamingResponse with media_type="text/event-stream" and format the lines yourself.)

4. Timeouts and retries around the provider

  • Set a timeout you can explain. The HTTP library's read timeout is the longest wait for the next chunk of data, not for the whole response. When streaming, chunks arrive every few tens of milliseconds, so a 20 s read timeout catches a dead connection without killing a long answer. Without streaming, the whole answer is one chunk, and a 20 s timeout will cut off every long generation.
  • Retry only what can succeed next time: timeouts, connection errors, 429 and 5xx. Never retry a 400 (your request is wrong, and it'll be wrong three times). Back off exponentially with jitter (random spread) so a thousand clients don't retry in lockstep.
  • Know the worst case: attempts × timeout + backoff. Put a deadline on the whole request too.
  • Streams don't replay. The SDKs don't retry a stream once you've started consuming it, because that could duplicate output already delivered. If the connection dies mid-answer, tell the client and let it retry.
💡 Big idea An AI service is a thin, careful wrapper around a slow, expensive, occasionally failing network call. Production Python is mostly about the wrapper: validate before you spend, stream so users see progress, bound every wait, retry only the retryable, log what happened per request, and test it all with a fake model so tests are fast, free and deterministic.
🧠 Analogy: a restaurant kitchen with one star chef

The chef (the model) is brilliant, slow and occasionally doesn't answer. The host checks every order is complete before it reaches the kitchen (validation, 422). Waiters bring dishes out course by course instead of all at once (streaming). If the chef doesn't respond, the waiter waits a set time, then asks again, maybe twice, then apologizes (timeout, retries, error). Every order slip has a number (request ID) so complaints can be traced (logs). And the kitchen rehearses with a stand-in cook who follows a script (mocked LLM in tests).

5. Config, secrets and logs

  • Config from the environment (the twelve-factor habit): API keys, model IDs, timeouts and URLs come from environment variables, so the same image runs in dev, staging and prod. pydantic-settings turns them into a typed, validated Settings object, and SecretStr prints as ********** so keys don't leak into logs or tracebacks. Keep local values in a git-ignored .env; in production, use your platform's secret store.
  • Structured logs: one JSON line per event with fields (request_id, model, input_tokens, output_tokens, latency_ms, status) instead of prose. Then “p95 latency by model” or “cost per tenant” is a query, not a grep. Use the standard logging module or structlog, and don't log raw prompts or user data unless your privacy policy allows it (Lesson 8.5).

6. Background tasks vs a queue

FastAPI's BackgroundTasks runs a function after the response is sent, in the same process: perfect for small things like writing a feedback row or sending an email. But if the process restarts (a deploy, a crash, an autoscaler), the task is simply gone, and a heavy task competes with requests for CPU. For real work (re-embedding 50,000 documents, running a 500-case eval), FastAPI's own docs point to bigger tools like Celery with a message queue such as Redis or RabbitMQ: the job is stored, retried, and run by separate workers you scale independently.

7. Tests that don't call the model

pytest finds functions named test_* and runs them; a fixture is a function that sets something up for a test (a client, a fake model) and cleans up afterwards. The key move for AI services is dependency injection: the endpoint asks for an LLM via Depends(get_llm), and tests swap in a scripted fake with app.dependency_overrides. Three kinds of test, catching different bugs:

TestWhat it checksSpeed and cost
Unit, mocked LLMYour code: prompt assembly, parsing, retries, error handling, given scripted model output (including malformed output).Milliseconds, free, deterministic: run on every commit.
Contract / schemaThe API's shape: response matches the Pydantic model, status codes, the stream's event sequence ends with done.Milliseconds, free.
Golden evalQuality: a fixed set of real questions with expected answers, run against the real model and scored (Phase 5).Minutes and real money: on prompt or model changes, or nightly.

Add a type checker (mypy, Pyright, or Astral's newer ty) and Ruff (a very fast linter and formatter) in CI: they catch None passed where a str is expected and undefined names in rarely-run branches, before any test runs.

✏️ Worked example: choosing timeout and retries

Your product promise: an answer, or a clear error, within 60 s. Streaming is on; TTFT is under 2 s at p99; tokens arrive every ~40 ms.

  • SDK defaults: worst case = 3 attempts × 600 s = 1,800 s (30 min). Way over.
  • Read timeout 20 s, max_retries 2: 3 × 20 s + backoff (~0.5 + 1 s) ≈ 61.5 s. Just over.
  • Read timeout 15 s, max_retries 2: 3 × 15 + 1.5 ≈ 46.5 s. Under the promise, with room for retrieval.
  • Is 15 s safe for healthy requests? With streaming, the longest silent gap is the TTFT (≤ 2 s), so yes: 7× headroom. Without streaming, a 400-token answer at 25 tokens/s takes 16 s + TTFT, and 15 s would time out healthy requests.

Then add an overall deadline (for example asyncio.timeout(55) around the call, Python 3.11+) so no combination of retries can exceed the promise.

8. Ship it in a container

A Docker image packages the code, the Python version and the locked dependencies into one artifact that runs the same everywhere. uv's Docker guide recommends copying the uv binary from its official image (pinned to a version), installing only the dependencies (uv sync --frozen --no-install-project, with just the lockfile mounted) in a layer before copying your code, then uv sync --locked after it, so a code change doesn't reinstall every package, and keeping .venv out of the build with .dockerignore. Images, layers and caching are taught in depth in the System Design course: Docker: images, layers & containers.

A complete small service and its tests (tested with FastAPI 0.162 and pytest 9 on Python 3.13; fastapi.sse needs FastAPI ≥ 0.135):

# app.py
import json, logging, time, uuid
from collections.abc import AsyncIterable, AsyncIterator
from typing import Protocol

from fastapi import Depends, FastAPI
from fastapi.sse import EventSourceResponse, ServerSentEvent
from pydantic import BaseModel, Field, SecretStr
from pydantic_settings import BaseSettings, SettingsConfigDict


class Settings(BaseSettings):                  # reads APP_* env vars (or .env)
    model_config = SettingsConfigDict(env_prefix="APP_", env_file=".env")
    llm_api_key: SecretStr = SecretStr("")     # SecretStr never prints its value
    llm_model: str = "your-model-id"
    llm_timeout_s: float = 20.0                # not the 10-minute SDK default
    llm_max_retries: int = 2


class AskRequest(BaseModel):
    question: str = Field(min_length=1, max_length=2_000)
    top_k: int = Field(default=3, ge=1, le=20)


class AskResponse(BaseModel):
    answer: str
    sources: list[str]


class LLM(Protocol):
    def stream(self, prompt: str) -> AsyncIterator[str]: ...


class ProviderLLM:                             # the real thing (Anthropic SDK shown)
    def __init__(self, s: Settings):
        from anthropic import AsyncAnthropic
        self.model = s.llm_model
        self.client = AsyncAnthropic(api_key=s.llm_api_key.get_secret_value(),
                                     timeout=s.llm_timeout_s, max_retries=s.llm_max_retries)

    async def stream(self, prompt: str) -> AsyncIterator[str]:
        async with self.client.messages.stream(
            model=self.model, max_tokens=512,
            messages=[{"role": "user", "content": prompt}],
        ) as stream:
            async for text in stream.text_stream:
                yield text


DOCS = {"refunds": "Refunds are available within 30 days.",
        "shipping": "Standard shipping takes 3 to 5 business days."}
log = logging.getLogger("rag")
app = FastAPI()


def get_llm() -> LLM:                          # tests replace this dependency
    return ProviderLLM(Settings())


def build_prompt(question: str, k: int) -> tuple[str, list[str]]:
    ids = list(DOCS)[:k]                       # stand-in for real retrieval (Phase 3)
    context = "\n".join(f"[{i}] {DOCS[i]}" for i in ids)
    return f"Answer from the context only.\n<context>\n{context}\n</context>\nQ: {question}", ids


@app.post("/ask", response_model=AskResponse)
async def ask(req: AskRequest, llm: LLM = Depends(get_llm)) -> AskResponse:
    t0, rid = time.perf_counter(), uuid.uuid4().hex[:8]
    prompt, ids = build_prompt(req.question, req.top_k)
    answer = "".join([tok async for tok in llm.stream(prompt)])
    log.info(json.dumps({"event": "ask", "request_id": rid, "sources": ids,
                         "latency_ms": round(1000 * (time.perf_counter() - t0))}))
    return AskResponse(answer=answer, sources=ids)


@app.post("/ask/stream", response_class=EventSourceResponse)   # FastAPI >= 0.135
async def ask_stream(req: AskRequest, llm: LLM = Depends(get_llm)) -> AsyncIterable[ServerSentEvent]:
    prompt, ids = build_prompt(req.question, req.top_k)
    async for tok in llm.stream(prompt):
        yield ServerSentEvent(data=tok, event="token")
    yield ServerSentEvent(data={"sources": ids}, event="sources")
    yield ServerSentEvent(raw_data="[DONE]", event="done")
# test_app.py   (run: uv run pytest -q)
import pytest
from fastapi.testclient import TestClient

from app import AskResponse, app, get_llm


class FakeLLM:                                  # scripted stand-in: no network, no cost
    def __init__(self, tokens):
        self.tokens, self.prompts = tokens, []

    async def stream(self, prompt):
        self.prompts.append(prompt)
        for t in self.tokens:
            yield t


@pytest.fixture
def fake():
    llm = FakeLLM(["Refunds ", "take ", "30 days."])
    app.dependency_overrides[get_llm] = lambda: llm
    yield llm
    app.dependency_overrides.clear()


@pytest.fixture
def client():
    return TestClient(app)


def test_answer_matches_contract(client, fake):          # contract / schema test
    r = client.post("/ask", json={"question": "How long do refunds take?"})
    assert r.status_code == 200
    body = AskResponse.model_validate(r.json())
    assert body.answer == "Refunds take 30 days."


def test_prompt_contains_retrieved_context(client, fake):  # unit test, mocked LLM
    client.post("/ask", json={"question": "refunds?", "top_k": 1})
    assert "within 30 days" in fake.prompts[0]


def test_empty_question_is_rejected(client, fake):
    r = client.post("/ask", json={"question": ""})
    assert r.status_code == 422                            # Pydantic validation error


def test_stream_ends_with_done(client, fake):
    with client.stream("POST", "/ask/stream", json={"question": "refunds?"}) as r:
        body = "".join(r.iter_text())
    assert "event: token" in body
    assert body.rstrip().endswith("data: [DONE]")

🚀 Startup vs big tech

Week one

One FastAPI service: uv + lockfile, Pydantic models on every endpoint, SSE streaming, timeouts set explicitly, settings from env vars, JSON logs with a request ID, and a pytest suite with a fake LLM that runs in under 10 s. A 50-question golden eval you run by hand before changing the prompt.

At scale

A shared internal “LLM client” package with timeouts, retries, budgets and tracing built in (often behind an LLM gateway, Lesson 8.1), contract tests between teams, golden evals gating every prompt or model change in CI, queues for indexing and batch jobs, and images built from locked dependencies with provenance checks.

🎤 Interview angle

“Take this notebook that calls an LLM and turn it into a production API.” A senior answer covers:

  • Contract: Pydantic request/response models, input limits, 422s, versioned endpoints.
  • Latency: streaming over SSE, async I/O for the provider call (Lesson P.3), and what TTFT the product needs.
  • Failure: explicit read timeouts, retries only on 408/429/5xx/connection errors with jittered backoff, an overall deadline, and a fallback model or a clear error (Lesson 8.1).
  • Operations: env-based config with secrets in a store, structured logs with tokens and latency per request, a lockfile and a container image.
  • Testing: mocked-LLM unit tests and contract tests on every commit, a golden eval on prompt/model changes.
🏭 In the real world
Retries and timeouts built into the SDK 🧰 OpenAI Python SDK openai-python README

How: connection errors, 408, 409, 429 and ≥500 responses are retried 2 times with short exponential backoff; requests time out after 10 minutes by default; responses are Pydantic models. Stream consumption is not retried automatically.

Why this method: transient failures are common at LLM scale, and replaying a stream could duplicate output the app already received.

The same defaults, configurable per request 🧰 Anthropic Python SDK Claude SDK for Python docs

How: 2 automatic retries with exponential backoff, a 10-minute default timeout, both overridable on the client or per call with with_options(...); an async client and a streaming helper with text_stream.

Why this method: the docs recommend streaming for long requests, because idle connections can be dropped by networks before a long non-streamed answer arrives.

SSE as a first-class response 🧰 FastAPI · 0.135+ Server-Sent Events (SSE)

How: yield items or ServerSentEvents from a path operation with response_class=EventSourceResponse; works with POST (as MCP uses it).

Why this method: the docs name AI chat streaming as a main use; FastAPI adds a 15-second keep-alive ping, Cache-Control: no-cache and X-Accel-Buffering: no so proxies don't buffer or close the stream.

Locked, layered container builds 🧰 uv Using uv in Docker

How: pin the uv image version, uv sync --locked so builds fail if the lockfile is stale, install dependencies in an intermediate layer before copying the code, and keep .venv out of the image.

Why this method: reproducible images, and rebuilds after a code change reuse the cached dependency layer.

🤯 Fun fact · the error that tells you exactly what's wrong

That 422 isn't a generic “bad request”. Pydantic's error lists the type (string_too_short), the exact location (["body", "question"]), the bad input and the constraint (min_length: 1). That precision is why the same structured error is what you feed back to a model whose JSON failed validation, in the validate-and-retry loop for structured outputs (Lesson 1.3).

Check yourself

1. You set the SDK to timeout=30 and max_retries=2. The provider accepts the connection and then sends nothing, every time. Roughly how long until your user gets an error?
max_retries=2 means 3 attempts: 3 × 30 s = 90 s, plus short exponential backoff between attempts. With the 10-minute default it would be 30 minutes. Add an overall deadline if you need a hard cap.
2. A teammate renamed the response field answer to text. Unit tests and the golden eval are green, and the mobile app broke in production. Which test would have caught it?
Answer quality didn't change, so evals stay green; the shape did. Contract tests pin the API shape that other teams and apps rely on.
3. An admin endpoint re-embeds 50,000 documents using BackgroundTasks. Deploys happen several times a day, and some documents never get re-embedded. What's the right fix?
BackgroundTasks run in the web process after the response; a restart loses them. A queue (Celery, a cloud queue) stores the job, retries failures, and lets you scale workers separately from the API.
📝 TL;DR
  • uv + pyproject.toml + uv.lock: the same dependencies on every machine; uv sync --locked in CI and Docker.
  • Pydantic models at the boundary: 422 before you spend a token; the response model is your contract.
  • Stream with SSE (EventSourceResponse); pair it with a short read timeout.
  • Never ship SDK defaults blindly: worst case = attempts × timeout. Retry only 408/429/5xx/connection errors, with jitter.
  • Settings from env (SecretStr), JSON logs per request, queues for heavy jobs.
  • Test with a fake LLM via dependency overrides; contract tests for shape; golden evals for quality.
