How LLMs work: tokens, next-token prediction, transformers

Just enough of the inside to predict how a model will behave, why it makes things up, and which knobs you actually control.

🧰 You'll need (quick reminders)
  • An AI engineer builds products on models someone else trained (Lesson 0.1).
  • Probability: numbers between 0 and 1 for each possible outcome that add up to 1 (100%). That's all the math here.
🎯 Hook

In 2023, lawyers in a New York personal-injury case against the airline Avianca filed a brief citing court decisions that did not exist. ChatGPT had produced them: plausible case names, plausible quotes, plausible citations. The judge fined the lawyers $5,000 (Mata v. Avianca).

The model wasn't lying, and it wasn't broken. It was doing exactly what it was built to do: produce the most plausible next words. Plausible and true are different things. By the end of this lesson you'll know why, and what an AI engineer does about it.

Numbers first: one token at a time

Give a model the text The cat sat on the. It doesn't “look up” an answer. It outputs a probability for every token in its vocabulary (a token is a word or a piece of a word; Lesson 0.3), something like:

Probability (illustrative)41%18%9%7%25% spread thin
  • Modern vocabularies have on the order of 100,000 to 200,000 tokens (OpenAI's o200k_base encoding is named for its ~200k).
  • One pick, one token. Then the chosen token is appended and the model runs again. A 500-token answer = 500 runs of the model, one after another. That's why output is slow and expensive (Lesson 0.3).
  • GPT-3, the 2020 model that started this era, had 175 billion parameters (the learned numbers inside the model). Current frontier sizes are mostly not disclosed.
💡 Big idea An LLM (large language model) is a function: text so far → a probability for every possible next token. Chat, coding, reasoning and tool use are all built by running that function in a loop and choosing a token each time. Everything you control as an AI engineer is either what goes in (the context) or how a token gets chosen (sampling).
🧠 Analogy: autocomplete that read the internet, then went to finishing school

Your phone keyboard suggests the next word from what you've typed. An LLM is the same idea scaled up enormously: it read a large slice of the internet, books and code, so its suggestions capture grammar, facts, style and reasoning patterns. Then it went to “finishing school”: extra training on example conversations and human preferences so it acts like a helpful assistant instead of just continuing your text.

Choosing the token: sampling

The model gives scores called logits, one per token. Softmax turns scores into probabilities. Temperature (T) is a dial applied before the softmax:

pi = exp(zi / T) ÷ Σj exp(zj / T)
  • T → 0: always take the top token (greedy decoding). Repeatable, but can loop and sounds flat.
  • T = 1: sample from the model's own distribution.
  • T > 1: flattens the distribution; rare (often wrong) tokens get picked more.
  • Top-k: only consider the k most likely tokens. Top-p (nucleus sampling): keep the smallest set of top tokens whose probabilities add up to p (say 0.9), drop the long tail, renormalize.
✏️ Worked example: temperature and top-p by hand

Three candidate tokens with logits z = [2.0, 1.0, 0.1].

  • T = 1: e2 = 7.39, e1 = 2.72, e0.1 = 1.11; sum 11.21 → [0.659, 0.242, 0.099].
  • T = 0.5 (divide logits by 0.5 → [4, 2, 0.2]) → [0.864, 0.117, 0.019]. Sharper: the top token wins more.
  • T = 2 (→ [1, 0.5, 0.05]) → [0.502, 0.304, 0.194]. Flatter: the weak token is picked ~1 time in 5.
  • Top-p = 0.9 at T = 1: 0.659 + 0.242 = 0.901 ≥ 0.9, so keep two tokens and renormalize: [0.731, 0.269, 0]. The tail token can never be chosen.

Red tokens = word pairs never seen in training (low-probability picks). Uncertainty is the entropy of the distribution in bits: 0 = certain, higher = more spread. A real LLM uses a transformer over the whole context, not just the previous word, but samples the next token in exactly this way.

At temperature 2 it picks words that never followed each other in training. Top-p fixes the second by cutting the tail. Production systems usually use moderate settings, and many current models now fix the sampling settings for you (Lesson 0.5).

Inside the model: transformers and attention

A bigram model only sees the previous word. Real LLMs are transformers (from the 2017 paper “Attention Is All You Need”): they look at every earlier token when predicting the next one, through a step called attention.

  • Each token is turned into a vector (a list of numbers). For each token, attention asks: which earlier tokens matter for me right now? It scores every earlier token, turns the scores into weights with softmax, and mixes in information from them.
  • A model stacks dozens of these layers, each with many attention “heads” looking for different relationships (grammar, who “it” refers to, which function a variable belongs to…).
  • GPT-style models are decoders: a token can only attend to tokens before it (causal masking). That's what lets them generate left to right.
  • Cost: every token attends to every earlier token, so the work grows with context length (Lessons 0.3 and 7.4 cover the KV cache, the trick that avoids redoing it).

How a model becomes an assistant

StageDataWhat it learnsResult
1. PretrainingTrillions of tokens of web text, books, codePredict the next token. Grammar, facts, style, reasoning patternsA base model: continues any text, doesn't follow instructions well
2. Instruction tuning (SFT, supervised fine-tuning)Tens of thousands to millions of example conversationsThe format and habits of a helpful assistantAnswers questions instead of continuing them
3. Preference tuning (RLHF, DPO…)Humans (or AI judges) compare two answers and pick the better oneWhat people prefer: helpful, honest, harmless, well-formattedA chat model like the ones you call via API
4. Reasoning training (many current models)Problems with checkable answers (math, code)To “think” in hidden tokens before answeringReasoning models with an effort knob (Lessons 0.4, 1.2)

RLHF = reinforcement learning from human feedback; DPO = direct preference optimization, a simpler alternative. You don't need the math to use them; Lesson 7.2 and the RL course cover it. The headline result: in OpenAI's InstructGPT paper, people preferred answers from a 1.3-billion-parameter tuned model over the 175-billion GPT-3 base model. Tuning matters as much as size.

Why models make things up

  • It's a plausibility machine. The model generates what looks like a good continuation. A fake court citation looks exactly like a real one, token by token.
  • Training rewards guessing. OpenAI's 2025 analysis argues that most benchmarks score “I don't know” as zero, the same as a wrong answer, so models learn that a confident guess scores better on average.
  • Knowledge cut-off. A model knows nothing after its training data ends. As of October 2026, Anthropic lists a reliable knowledge cutoff of June 2026 for its current Claude models; OpenAI lists April 30, 2026 for GPT-6 Astra. Ask about anything later and the model can only guess (or use a search tool).
  • No private knowledge. It has never seen your company's docs, tickets or database.

The AI engineer's toolkit against this: put the facts in the context (RAG, Phase 3), give the model tools to look things up (Phase 6), ask for citations and allow “I don't know” (Lesson 3.5), and measure hallucination rates with evals (Phase 5).

🧰 Tools you'll actually use

Hosted APIs hide the probabilities, but a small open model lets you see them directly. Hugging Face Transformers runs one on a laptop CPU (the download is about a gigabyte or more; run it on your own machine).

import torch
from transformers import AutoTokenizer, AutoModelForCausalLM

name = "Qwen/Qwen3-0.6B"              # any small open causal LM works
tok = AutoTokenizer.from_pretrained(name)
model = AutoModelForCausalLM.from_pretrained(name)

ids = tok("The cat sat on the", return_tensors="pt").input_ids
with torch.no_grad():
    logits = model(ids).logits[0, -1]          # scores for the NEXT token only
probs = torch.softmax(logits / 0.8, dim=-1)   # temperature 0.8
top = torch.topk(probs, 5)
for p, i in zip(top.values, top.indices):
    print(f"{tok.decode(i)!r:12} {p:.1%}")

Some hosted APIs return log-probabilities of the chosen tokens on certain models (for example OpenAI's logprobs options), useful for confidence scores; check your model's docs, since reasoning models often don't support it.

🚀 Startup vs big tech

Startup

You treat the model as a black box: good prompts, retrieval for facts, and evals that check for invented details. Nobody trains anything; the provider's tuning is your tuning.

Big tech

Teams may run their own instruction and preference tuning on open models, study token probabilities to calibrate confidence, and measure hallucination rates per product surface. The mental model is the same; there are just more levers.

🎤 Interview angle

“Explain how an LLM generates text” and “Why do LLMs hallucinate, and what do you do about it?” A senior answer:

  • Next-token prediction: tokens in, probability distribution out, sample, append, repeat; output cost scales with tokens generated.
  • Transformers use attention over all earlier tokens; pretraining → instruction tuning → preference tuning turns a text predictor into an assistant.
  • Hallucination = plausible but unsupported continuation, made worse by training that rewards guessing and by knowledge cut-offs.
  • Mitigations at the system level: grounding (RAG, tools), citations, letting the model abstain, and evals that measure it.
🏭 In the real world
The transformer 🧪 Research · 2017 Attention Is All You Need

How: replaced recurrent networks with an architecture built only on attention, so every position can look at every other position in one step.

Why this method: much more parallel to train on GPUs, and better translation quality; it's the architecture under essentially every LLM you'll call.

Turning a predictor into an assistant 🧪 OpenAI · 2022 Training language models to follow instructions with human feedback

How: fine-tuned GPT-3 on labeller-written demonstrations, then trained it with human rankings of its answers (RLHF) to create InstructGPT.

Why this method: a 1.3B-parameter InstructGPT was preferred over the 175B GPT-3, despite having 100× fewer parameters. This recipe became the template for chat models.

Why hallucinations persist 🏢 OpenAI · 2025 Why language models hallucinate

How: analyzes hallucinations as a statistical consequence of training, and shows how accuracy-only benchmarks reward guessing over saying “I don't know”.

Why this method: it explains why abstaining has to be designed and rewarded explicitly, in training and in your own evals (Lesson 5.3).

Looking inside: does it plan ahead? 🏢 Anthropic · 2025 Tracing the thoughts of a large language model

How: interpretability tools traced internal features while Claude wrote rhyming poetry and did arithmetic.

Why this method: they found the model picks the rhyming word before writing the line that leads to it. “One token at a time” describes the output, not the limits of what's computed inside.

🤯 Fun fact · next-token prediction is older than computers in your pocket

In 1951, Claude Shannon measured how predictable English is by asking a person to guess a passage one letter at a time. In one experiment, 89 of 129 letters (69%) were guessed correctly on the first try. LLMs play the same game with tokens, trillions of times during training.

Check yourself

1. Two tokens have probabilities 0.70 and 0.20, and many tiny ones share the remaining 0.10. With top-p = 0.85, what's the chance of picking the 0.20 token?
0.70 alone is below 0.85, so keep the next token too: 0.70 + 0.20 = 0.90 ≥ 0.85. Everything else is dropped and the two are renormalized: 0.20 ÷ 0.90 ≈ 0.22.
2. Your legal-research assistant sometimes cites cases that don't exist. Which fix addresses the cause?
Greedy decoding just picks the single most plausible citation, which can still be fake; a bigger model hallucinates less but not never. Grounding the answer in retrieved sources and checking citations mechanically attacks the actual problem.
3. A user asks your assistant about a product your company launched last week. The model confidently describes the wrong features. Most likely why?
The model has never seen the launch. Without the facts in the prompt (RAG) or a search tool, a plausible guess is the best it can do. That's a context problem, not a sampling problem.
📝 TL;DR
  • An LLM maps the tokens so far to a probability for every next token; generation repeats that once per output token.
  • Temperature sharpens or flattens the distribution; top-p cuts the unlikely tail. Greedy loops, high temperature wanders.
  • Transformers use attention: each token weighs earlier tokens to decide what matters; decoders only look backwards.
  • Pretraining → instruction tuning → preference (and reasoning) tuning turns a text predictor into an assistant.
  • Hallucinations come from plausibility without grounding, guessing-friendly training and knowledge cut-offs: fix with context, tools, citations and evals.
