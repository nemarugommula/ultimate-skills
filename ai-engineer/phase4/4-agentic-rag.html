Phase 4 · Lesson 4

Agentic, self-correcting & adaptive RAG (Self-RAG, CRAG, routing)

Naive RAG always retrieves once, from one place, and trusts whatever comes back. Agentic RAG lets the model decide: whether to retrieve, from where, whether the results are good enough, and what to try next.

🧰 You'll need (quick reminders)
  • Function calling: the model can ask your code to run a tool (like search_docs(query)) and read the result (Lesson 1.3).
  • Query rewriting and decomposition (Lesson 4.1); multi-hop questions (Lesson 4.3).
  • Latency and token cost add up per LLM call (Lesson 0.3).
🎯 Hook

In June 2025 Anthropic described how Claude's Research feature works: a lead agent plans, then spins up subagents that search in parallel, each with its own context window, and the lead combines their findings. On Anthropic's internal research eval this multi-agent system beat a single agent by 90.2%.

The bill came with it: agents used about 4× the tokens of a chat interaction, and the multi-agent system about 15×. Token usage alone explained 80% of the performance differences on a browsing benchmark. Agentic retrieval works, and you pay for it in tokens and seconds.

Calls and latencies are typical orders of magnitude, not guarantees; they depend on your model and how many loops you allow.

Most questions in a real product are simple. Paying the agentic price on every “how much is Plus?” wastes money; refusing to pay it on “compare X and Y across these three policies” gives wrong answers. The skill is choosing per question.

💡 Big idea Turn retrieval from a fixed step into a decision. Four decisions, each a small LLM call or classifier: whether to retrieve (routing, adaptive RAG), where to retrieve from (vector store, web, SQL, graph), is it good enough (a relevance grader: CRAG, Self-RAG), and what next (rewrite, decompose, fall back, or stop). Each decision costs latency, so add them where your evals show failures.
🧠 Analogy: the intern and the senior researcher

Ask an intern a question and they search once, grab the top result and write it up, even if it's about something else. A senior researcher first asks “do I even need to look this up?”, picks the right source (the wiki, the database, the news), skims the results and says “this isn't it”, rephrases, tries another source, and stops when they have enough. Agentic RAG teaches the system the senior's habits, and like a senior, it bills more hours.

Notice the trained components: Self-RAG fine-tunes the generator, CRAG and Adaptive-RAG train small evaluators. In products, most teams approximate them with prompts to a small fast model, at the cost of a little more latency, and graduate to a trained classifier once they have logs to train on.

✏️ Worked example: what the grader costs, and what it saves

100,000 questions a day. Naive RAG: 1 generation call, ≈ 1.6 s. Adding an LLM grader adds ≈ 700 input tokens and ≈ 0.5 s to every question; suppose 15% of questions fail the grade and trigger a rewrite + second retrieval + second grade (≈ +0.9 s, +900 tokens).

  • Extra tokens per day: 100,000 × 700 + 15,000 × 900 = 70M + 13.5M = 83.5M tokens. At an illustrative $1 per million for a small model: ≈ $84 a day.
  • Average added latency: 0.5 + 0.15 × 0.9 = 0.64 s; the unlucky 15% wait 1.4 s longer.
  • If 10% of naive answers were wrong because retrieval missed, and the loop fixes even half of them, that's 5,000 fewer wrong answers a day for ≈ $84. Usually worth it; but measure it, and grade only when the retrieval scores are borderline if latency matters.

Adaptive RAG: spend effort where it's needed

Adaptive-RAG's insight is that a cheap classifier in front can send each question to the cheapest strategy that will answer it. Question types differ wildly: greetings and general knowledge need no retrieval; most help questions need one search; a few need several.

🧰 Tools you'll actually use

LangGraph (graphs of nodes and conditional edges, with an agentic RAG tutorial in its docs), LlamaIndex agents and workflows, provider tool calling (OpenAI, Anthropic, Gemini), plus web search APIs for fallback. The graph below follows LangGraph's agentic RAG tutorial: the model decides whether to call the retriever tool; a grader routes to an answer or a question rewrite.

from typing import Literal
from pydantic import BaseModel, Field
from langchain.chat_models import init_chat_model
from langgraph.graph import StateGraph, MessagesState, START, END
from langgraph.prebuilt import ToolNode

grader = init_chat_model("anthropic:claude-haiku-5-5", temperature=0)   # small, fast judge (as of 2026)

class Grade(BaseModel):
    binary_score: str = Field(description="'yes' if the documents are relevant to the question, else 'no'")

def grade_documents(state: MessagesState) -> Literal["generate_answer", "rewrite_question"]:
    question, docs = state["messages"][0].content, state["messages"][-1].content
    g = grader.with_structured_output(Grade).invoke(
        [{"role": "user", "content": f"Question: {question}\nDocuments: {docs}\nRelevant? yes or no."}])
    return "generate_answer" if g.binary_score == "yes" else "rewrite_question"

def route_on_tool_calls(state: MessagesState):
    return "tools" if getattr(state["messages"][-1], "tool_calls", None) else END

g = StateGraph(MessagesState)
g.add_node(generate_query_or_respond)            # LLM with the retriever tool bound: may answer directly
g.add_node("retrieve", ToolNode([retriever_tool]))
g.add_node(rewrite_question)
g.add_node(generate_answer)
g.add_edge(START, "generate_query_or_respond")
g.add_conditional_edges("generate_query_or_respond", route_on_tool_calls, {"tools": "retrieve", END: END})
g.add_conditional_edges("retrieve", grade_documents)
g.add_edge("rewrite_question", "generate_query_or_respond")   # the loop: cap it in production
g.add_edge("generate_answer", END)
graph = g.compile()

Always cap loops: count rewrites in the graph state, or set LangGraph's recursion limit, so a question that can't be answered ends in “I don't know” instead of an expensive spin.

🚀 Startup vs big tech

Week one

Start with a fixed pipeline plus one decision: a cheap router (“retrieve or not, docs or SQL”) or a grader with a single rewrite. Cap the loop, log every step, and only make it more agentic where evals show multi-hop failures. Anthropic's own advice is to find the simplest solution and add agentic complexity only when needed.

At scale

Trained small classifiers for routing and relevance (cheaper and faster than LLM calls), per-route latency budgets, parallel tool calls, step-level tracing and evals of whole trajectories (Lesson 5.5), and deep-research style multi-agent flows reserved for high-value questions.

🎤 Interview angle

“Our RAG answers confidently from irrelevant documents. And some questions need several lookups. Design a fix.” A senior answer:

  • Adds a relevance check after retrieval (LLM judge or trained evaluator), explaining why a similarity threshold isn't enough.
  • On failure: rewrite and retry (capped), then fall back to another source or abstain; web fallback only with sanitising and citations.
  • Adds a router so simple questions skip the loop and complex ones get decomposition or iterative retrieval (Adaptive-RAG).
  • Puts numbers on it: added calls, p50/p95 latency, cost per 1,000 questions, and the eval showing fewer wrong answers.
🏭 In the real world
Parallel research agents 🏢 Anthropic · 2025 How we built our multi-agent research system

How: a lead agent plans and spawns subagents that search in parallel with separate context windows, then synthesises their results.

Why this method: open-ended research needs many searches; it beat a single agent by 90.2% on an internal eval, at about 15× the tokens of a chat, so it's reserved for high-value tasks.

Grade, then correct 🧪 Research · 2024 Corrective RAG (CRAG)

How: a 0.77B-parameter evaluator scores retrieved documents; thresholds map to Correct (refine into key “knowledge strips”), Incorrect (web search) or Ambiguous (both).

Why this method: plug-and-play robustness when retrieval goes wrong; it significantly improved both standard RAG and Self-RAG across four datasets.

A model that critiques its own retrieval 🧪 Research · 2023 Self-RAG (University of Washington, AI2, IBM)

How: train the LM to emit reflection tokens deciding when to retrieve and whether passages are relevant, supported and useful.

Why this method: retrieving a fixed number of passages every time hurts versatility; Self-RAG 7B and 13B outperformed ChatGPT and retrieval-augmented Llama 2 chat on open-domain QA, reasoning and fact verification.

Route by complexity 🧪 Research · 2024 Adaptive-RAG (KAIST)

How: a T5-large classifier, trained on labels collected automatically from which strategy actually succeeded, picks no-retrieval, single-step or multi-step per query.

Why this method: one strategy for all queries is either wasteful on simple ones or inadequate on complex ones; routing improved both accuracy and efficiency over fixed and other adaptive baselines.

🤯 Fun fact · retrieval triggered by doubt

FLARE (2023) doesn't decide up front whether to retrieve. It drafts the next sentence, and if any token in it has low probability (the model is unsure), it uses that draft as a search query, retrieves, and rewrites the sentence. The model's own uncertainty becomes the retrieval trigger.

Check yourself

1. A router sends 60% of questions to A (0.8 s), 35% to B (1.8 s) and 5% to C (6.5 s), and itself adds 0.05 s. What's the average latency, versus 6.5 s for “always C”?
0.6 × 0.8 + 0.35 × 1.8 + 0.05 × 6.5 + 0.05 = 0.48 + 0.63 + 0.325 + 0.05 ≈ 1.49 s, over 4× faster than always running the multi-step strategy.
2. Your grader passes documents when cosine similarity ≥ 0.5. Logs show confident wrong answers to “is there a delivery delay because of the storm?” built from your generic shipping-times page. Why, and what fixes it?
The shipping page is on-topic, so it's similar, but it can't answer a question about a current event. Relevance judging (CRAG's evaluator, Self-RAG's IsRel, or an LLM grader) asks the right question: does this support an answer?
3. A team makes every question go through a 6-step agent with web search. Quality is slightly better, but p95 latency went from 2 s to 25 s and cost rose 6×. What's the senior move?
Agentic retrieval earns its cost on a minority of questions. Adaptive routing keeps the quality gain where it matters and the 2 s path for the rest; a step cap bounds the worst case.
📝 TL;DR
  • Agentic RAG makes retrieval a decision: whether, where, good enough?, what next.
  • Self-RAG (reflection tokens), CRAG (evaluator + web fallback) and Adaptive-RAG (complexity router) are the reference designs; products approximate them with small, fast LLM calls.
  • Similarity isn't relevance: grade with a judge, cap the loop, and abstain when nothing relevant is found.
  • Every decision costs latency and tokens: route so that only the questions that need the loop pay for it.
