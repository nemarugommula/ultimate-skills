Phase R · Lesson 3

Attacking agents & tools: exfiltration, tool misuse, MCP risks

An injected sentence is only words until an agent turns it into tool calls. Follow the chain from a poisoned page to a leaked file, see where each mitigation breaks it, and learn to read MCP tool descriptions like an attacker would.

🧰 You'll need (quick reminders)
  • The agent loop: the model picks a tool, reads its result, picks the next one (Lesson 6.1). MCP (Model Context Protocol) servers expose tools, with names and descriptions the model reads (Lesson 6.2).
  • Prompt injection (Lesson R.2): text in content the model reads can act as instructions, and no prompt-level defence is airtight.
  • Lethal trifecta (Lesson R.1): private data + untrusted content + a way out. Only test agents you own or are authorized to test.
🎯 Hook

In May 2025, Invariant Labs showed an attack on the official GitHub MCP server. The attacker needed only one thing: the ability to open an issue on the victim's public repository, which anyone can do. The victim then asked their agent something ordinary, like “have a look at the open issues in my public repo”.

The agent read the malicious issue, pulled data from the user's private repositories into context, and published it in a new pull request on the public repo, where the attacker could read it. In the demo the leak included private project names, relocation plans and a salary. The client asked for confirmation per tool call by default, but, as Invariant noted, many users switch to “always allow”. And the flaw wasn't in the model: it affects any agent using that server, whatever the model.

Numbers first: what a stuck agent costs

Not every agent attack steals data. Some just make it spin. Suppose a poisoned page convinces an agent the content “continues on the next page”, forever:

Value
Tool calls per minute in a tight loop50
Tokens processed per call (context + page)8,000
Tokens per hour: 50 × 8,000 × 6024 million
Cost at $3 per million input tokens$72 per hour, per stuck session
100 sessions hitting the same page$7,200 per hour

Prices illustrative; real loops cost more because context grows each step. OWASP calls this denial of wallet (part of LLM10 Unbounded Consumption); MITRE ATLAS lists it as Cost Harvesting (AML.T0034), with a sub-technique for agentic resource consumption.

A step cap of 25 calls per session turns the worst case into 25 × 8,000 = 200,000 tokens, about $0.60. That is the pattern of this whole lesson: you can't stop the agent being fooled, but you can cap what a fooled agent can do.

💡 Big idea An agent's blast radius is the union of everything its tools can touch, and an injection borrows all of it. So defend the chain, not the prompt: least privilege per task, allow-listed destinations, confirmation for side effects, sandboxes for code, budgets for loops, and provenance tracking so untrusted text can never choose an action. Any one broken link stops the attack.
🧠 Analogy: the valet key

Many cars come with a valet key: it starts the engine but won't open the boot or the glovebox. You hand it to a stranger because you assume they might misbehave. Give your agent a valet key for each task: the browsing task gets the browser, not your files; the reply task can email the thread, not the world. Then it matters much less whether someone talks the valet into a joyride.

Provenance tracking stops all three, and costs you something: the legitimate second page of a long article isn't fetched either.

MCP: the tool description is part of the prompt

When you connect an MCP server, its tool names, descriptions and parameter docs are put into the model's context. Invariant Labs showed in April 2025 that a description can carry hidden instructions (tool poisoning) that the model follows and the user never sees, because clients often show only a short name. They also described rug pulls (the description changes after you approved it) and shadowing (one server's description changes how the model uses another server's tools). In September 2025 Koi Security reported a fake postmark-mcp package on npm that copied a real email server; version 1.0.16 added one line that blind-copied every outgoing email to the attacker. It had 1,643 downloads before removal.

Pattern rules catch the obvious cases and are easy to evade with rewording. Real scanners add LLM-based review and track changes over time; the strongest control is still pinning what you reviewed and limiting what any server's tools can reach.

Only the pinned hash notices that what you reviewed has changed.

✏️ Worked example: sizing a budget that doesn't break real work

You log 1,000 real sessions of your research agent. Median 6 tool steps; 99th percentile 14; the longest legitimate session 19.

  • Set the step cap a little above the longest legitimate session: 25 steps. Fewer than 1 in 1,000 real sessions would hit it.
  • Worst-case cost per session: 25 × 8,000 tokens = 200,000 tokens ≈ $0.60 at $3 per million (illustrative), versus $72 per hour uncapped.
  • Add a per-user daily budget, so a script opening 1,000 sessions costs at most what you decided, and alert when a session hits its cap: that's often an attack or a bug.
🧰 Tools you'll actually use

Your own tool gateway (every call passes through policy code), MCP clients that show full descriptions and arguments, Snyk Agent Scan (formerly Invariant's mcp-scan) for scanning installed MCP servers and skills, container or microVM sandboxes for code tools, and AgentDojo (ETH Zurich) to benchmark an agent's injection robustness: 97 tasks and 629 security test cases.

import hashlib, json, re
from urllib.parse import urlparse

TASK_TOOLS = {"summarize_url": {"web_fetch"}, "reply": {"read_thread", "send_email"}}
ALLOWED_DOMAINS = {"corp.example"}
MAX_STEPS, MAX_TOKENS = 25, 200_000

class PolicyError(Exception): pass

def check_call(task, name, args, session):
    if name not in TASK_TOOLS[task]:                         # least privilege
        raise PolicyError(f"{name} not granted for {task}")
    if session.steps >= MAX_STEPS or session.tokens >= MAX_TOKENS:
        raise PolicyError("session budget exhausted")        # denial of wallet
    if name == "send_email":
        domain = args["to"].rsplit("@", 1)[-1].lower()
        if domain not in ALLOWED_DOMAINS:                     # egress allow-list
            raise PolicyError(f"recipient domain {domain} not allowed")
        if session.saw_untrusted:                             # provenance: ask a human
            require_approval(name, args)                       # show ALL arguments

MD_LINK = re.compile(r"!?\[[^\]]*\]\(([^)\s]+)[^)]*\)")
def strip_untrusted_links(markdown):                          # close the image/link channel
    def keep(m):
        host = (urlparse(m.group(1)).hostname or "").lower()
        return m.group(0) if host in ALLOWED_DOMAINS else "[link removed]"
    return MD_LINK.sub(keep, markdown)

def fingerprint(tools):                                     # pin what you reviewed (rug pulls)
    return {t["name"]: hashlib.sha256(json.dumps(t, sort_keys=True).encode()).hexdigest()
            for t in tools}

🚀 Startup vs big tech

Week one

One tool gateway in code with per-task grants, recipient and domain allow-lists, a step and token budget, and approval for anything outbound or destructive, showing full arguments. Only first-party or reviewed MCP servers, pinned by version and description hash. Code tools run in a throwaway container with no network.

At scale

An internal MCP registry with security review and continuous scanning, scoped short-lived credentials per session, network policy on every tool host, provenance-tracking runtimes for agents near private data, AgentDojo-style regression suites per release, and anomaly alerts on tool-call patterns (new recipients, unusual volume, cap hits).

🎤 Interview angle

“Our coding agent can read issues, read all the user's repos and open pull requests. What could go wrong, and what would you change?” A senior answer:

  • Names the chain: untrusted issue text → private repo reads → publishing to a public place. It's the GitHub MCP incident pattern and a lethal trifecta.
  • Calls out the confused deputy: the agent's token is broader than the request. Fix: per-session tokens scoped to the repo the user named.
  • Adds gates where they actually help: approval for publishing with the full diff shown, and no blanket “always allow” for write actions.
  • Covers the tooling supply chain: pinned and scanned MCP servers, re-approval on description changes.
  • Says how they'd test it: injected-issue scenarios in an AgentDojo-style suite, run repeatedly, tracking both attack success and task success.
🏭 In the real world
A public issue hijacks a repo agent 🏢 Invariant Labs · 2025 GitHub MCP Exploited

How: a malicious issue in a public repo made an agent using the GitHub MCP server read private repositories and leak them in a public pull request; found with an automated analyzer for “toxic agent flows”.

Why this method: shows that the vulnerability is in the flow of permissions, not the model, so the fix is scoping and gating, not a better prompt.

Hidden instructions in tool descriptions 🏢 Invariant Labs · 2025 MCP Security Notification: Tool Poisoning Attacks

How: demonstrated tool poisoning, rug pulls and cross-server shadowing against popular MCP clients, and released a scanner (mcp-scan, now Snyk Agent Scan).

Why this method: the model sees the full description while the user sees a short name, so descriptions must be reviewed and pinned like code.

A malicious MCP server in the wild 🏢 Koi Security · 2025 First Malicious MCP Server Found (The Hacker News)

How: an npm package impersonating a real Postmark MCP server added a single line in version 1.0.16 that BCC'd every email sent through it to the attacker.

Why this method: a classic supply-chain attack, aimed at the new tool layer; pinning versions and limiting a server's network egress would have contained it.

Benchmarking agents under attack 🧪 ETH Zurich · 2024 AgentDojo

How: an extensible environment of realistic tasks (email, banking, travel) with injected tool outputs, measuring both task success and attack success for each defence.

Why this method: security without utility is easy; AgentDojo reports both, which is how CaMeL's 77% vs 84% result (Lesson R.2) was measured.

The protocol's own threat list 🧰 MCP specification MCP Security Best Practices

How: documents attacks on MCP implementations (confused deputy, token passthrough, server-side request forgery, session hijacking, local server compromise) with mitigations and scope minimization.

Why this method: many agent attacks are classic web-security bugs in new clothes; the spec names them so server authors can avoid them.

🤯 Fun fact · one line of code

The malicious postmark-mcp package was a copy of a legitimate open-source server with a single added line: a BCC to the attacker's address on every email. Koi Security's CTO put it as “The postmark-mcp backdoor isn't sophisticated – it's embarrassingly simple.” The agent never had to be fooled at all: the tool itself was the attacker.

Check yourself

1. A poisoned page traps an agent in a loop: 30 tool calls per minute, 10,000 tokens each, at $3 per million tokens. Nobody notices for 2 hours. Roughly what does it cost?
30 × 10,000 × 120 minutes = 36 million tokens; × $3 per million = $108, for one session. A 25-step cap would have stopped it at 250,000 tokens, about $0.75, and the cap hit itself is a useful alert.
2. Your repo agent has a token for all of a user's repositories. A public issue tricks it into copying private code into a public pull request. Which fix removes the problem at its root?
It's a confused deputy: the agent's privileges were broader than the request. Scoping the token removes the private data from reach; approval gates the exit. A classifier only lowers the odds (Lesson R.2), and model choice doesn't change the permissions.
3. You reviewed a third-party MCP server's tool descriptions last month and they were fine. What protects you if the server quietly changes them?
That's a rug pull: approval at install time says nothing about later versions. Fingerprinting what you reviewed turns a silent change into a visible event. Also limit what the server can reach, in case its code (not just its text) changes.
📝 TL;DR
  • An injection borrows the agent's whole blast radius: tools, tokens, data. Shrink it per task.
  • Exits are tool arguments, public destinations, rendered URLs and executed code; allow-list them and confirm side effects with full arguments.
  • MCP tool descriptions are prompt text: watch for poisoning, shadowing, rug pulls and malicious servers; review, pin and scan them.
  • Sandbox code, budget loops (denial of wallet), track provenance, and test with AgentDojo-style suites that measure attack and task success.
