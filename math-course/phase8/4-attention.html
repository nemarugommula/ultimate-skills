Attention & transformers: softmax(QKᵀ/√d)V

Every word asks a question, every word offers an answer, and dot products decide who listens to whom. This one formula is the engine of GPT, BERT, vision transformers and nearly every modern AI model.

🧰 You'll need (quick reminders)
  • Dot product: big when two vectors point the same way, 0 when unrelated (Lesson 1.3).
  • Matrix multiplication: XW multiplies every row of X (every token) by the same W in one go (Lesson 2.2).
  • Softmax: scores → positive weights that add up to 1 (Lesson 8.2).
🎯 Hook

“The cat sat on the mat because it was tired.” You instantly know “it” is the cat, not the mat. A model reading one word at a time has to work that out too. In a transformer, the vector for “it” literally looks back over every earlier word, scores each one with a dot product, and pulls in a blend that is mostly “cat”.

That's attention. It's about 5 lines of NumPy, and by the end of this lesson you'll have done it by hand.

Numbers first: one word looks around

Three tokens, “the cat sat”, each already turned into small vectors. The word “sat” wants to know who sat. It has a query (what I'm looking for), and every word has a key (what I contain) and a value (what I'll hand over if you pick me).

✏️ Worked example: attention for “sat”, by hand (d = 2)
  • Query of “sat”: q = [1, 2]. Keys: the [0, 1], cat [2, 1], sat [1, 0].
  • Score = q · k: the → 0 + 2 = 2, cat → 2 + 2 = 4, sat → 1 + 0 = 1.
  • Scale by √d = √2 ≈ 1.414: [1.41, 2.83, 0.71].
  • Softmax: e1.41 = 4.11, e2.83 = 16.92, e0.71 = 2.03, total 23.06 → weights [0.18, 0.73, 0.09].
  • Mix the values: the [0, 0], cat [1, 0], sat [0, 1] → 0.18·[0, 0] + 0.73·[1, 0] + 0.09·[0, 1] = [0.73, 0.09].

The new vector for “sat” is 73% “cat”. It has gathered the information “a cat did this” from its neighbour. Nothing was hard-coded: the dot products chose.

Where do queries, keys and values come from?

Each token starts as an embedding vector (Lesson 1.5). Stack the n tokens as rows of a matrix X (n × d). Three learned weight matrices turn every token into its query, key and value, all at once:

Q = XWQ    K = XWK    V = XWV “Q is X times W-Q”, and so on. Same tokens, three different learned “lenses”: one for asking, one for being found, one for what to share.

Then every query is dotted with every key at once (that's QKᵀ, an n × n table of scores), scaled, softmaxed row by row, and used to mix the values:

Attention(Q, K, V) = softmax( QKᵀ / √dk ) V “Softmax of Q times K-transpose over root d, times V.” Row i of QKᵀ holds token i's scores against every token. Divide by √dk (dk = the length of each key). Softmax each row into weights that add to 1. Multiply by V: each output row is a weighted average of value rows.
💡 Big idea Attention is a soft lookup table. A normal dictionary returns the one value whose key matches exactly. Attention compares the query with every key (dot products), turns the matches into weights (softmax), and returns a blend of all the values.
🧠 Analogy: asking a room of experts

You walk into a room with a question (query). Every person wears a badge describing their expertise (key). You listen to each person in proportion to how well their badge matches your question, and you leave with a blend of their answers (values). Next sentence, new question, different people get your attention.

The causal mask: no peeking

GPT-style models are trained to predict the next token. If “it” could attend to the words after it, it could just read the answer. So before the softmax, every score where the key comes after the query is set to −∞ (minus infinity). e−∞ = 0, so those words get exactly zero weight. The attention matrix becomes lower-triangular, as in the heatmap. BERT-style models, which fill in blanks instead, skip the mask and look both ways.

Why divide by √d?

A dot product adds up d products. If each entry of q and k is a random number with average 0 and spread 1, the transformer paper notes that q · k has average 0 and variance d, so its typical size is √d. With d = 64 that's about 8; with d = 1,024 about 32. Feed scores like 30, −25, 12 into softmax and one key gets ~100% of the weight, the rest ~0% (the 12 gets about 0.0000015%). Nudging any score barely changes that, so the gradient is tiny and learning gets almost no signal (the paper's words: “extremely small gradients”). Dividing by √d brings typical scores back to about 1.

Multi-head attention and the transformer block

One attention pattern can only ask one kind of question. So a transformer runs several heads side by side, each with its own WQ, WK, WV. The original Transformer used d = 512 split into 8 heads of 64. One head might track “which noun does this pronoun mean?”, another “what was the previous word?”. Their outputs are glued together and mixed by one more matrix WO.

A full transformer layer is: attention (tokens share information), then the MLP from Lesson 8.3 (each token thinks on its own), each wrapped with a skip connection (add the block's input back onto its output: the “1 +” highway from Lesson 3.2) and normalization (Lesson 5.1's layer norm: subtract the vector's mean, divide by its std; LLaMA uses the simpler RMSNorm from Lesson 1.4). Stack the layer dozens of times, put Lesson 8.2's softmax over the vocabulary on top, and you have an LLM.

Word order: attention can't see it on its own

Shuffle the worked example to “cat the sat”. “sat” still scores the → 2, cat → 4, sat → 1: each score depends only on the two vectors, not on where they sit. Same weights [0.18, 0.73, 0.09] on the same words, same output [0.73, 0.09]. Shuffle the words and attention gives exactly the same answers. To attention alone, a sentence is a bag of words: ignoring the mask, “dog bites man” and “man bites dog” look the same.

So transformers add position information to each token. The original Transformer added fixed sine-and-cosine waves to every embedding, a different pattern for each position (“sinusoidal encodings”). Many modern LLMs, LLaMA among them, use RoPE instead: rotate each query and key by an angle that grows with its position (the rotation matrices of Lesson 2.1), so q · k depends on how far apart two words are.

The KV cache

When an LLM writes, it adds one token at a time. Thanks to the causal mask, old tokens never look at new ones, so their keys and values never change. Store them, and each new token only needs its own query, key and value plus one row of attention. That store is the KV cache, and it's big: for a 13-billion-parameter model, the vLLM paper computes 2 (key and value) × 5,120 numbers × 40 layers × 2 bytes ≈ 800 KB per token, up to 1.6 GB for one 2,048-token conversation.

🐍 In code 
import numpy as np
def attention(Q, K, V, causal=True):
    S = Q @ K.T / np.sqrt(K.shape[-1])               # every query · every key, scaled
    if causal: S[np.triu_indices(len(S), k=1)] = -np.inf  # no peeking at the future
    A = np.exp(S - S.max(axis=1, keepdims=True))
    A /= A.sum(axis=1, keepdims=True)                   # softmax, row by row
    return A @ V                                        # blend the values

X = np.random.randn(5, 16)                               # 5 tokens, 16 numbers each
Wq, Wk, Wv = (np.random.randn(16, 16) for _ in range(3))
out = attention(X @ Wq, X @ Wk, X @ Wv)                   # shape (5, 16)
# PyTorch: torch.nn.functional.scaled_dot_product_attention(q, k, v, is_causal=True)

🌍 Where it's used
Scaled dot-product attention 🧠 LLMs · 2017 Vaswani et al., Attention Is All You Need

How: the paper defines Attention(Q, K, V) = softmax(QKᵀ/√dk)V, runs 8 heads of size 64 in parallel, and builds the whole model from attention plus MLP layers, with no recurrence. It was tested on English→German and English→French translation.

Why this method: all positions are processed at once with matrix multiplications instead of one word after another, so the abstract reports it is “more parallelizable” and needs “significantly less time to train” than the older models.

Causal (masked) attention in GPT 🧠 LLMs · 2020 GPT-3: Language Models are Few-Shot Learners

How: a decoder-only transformer with the causal mask: each token attends only to itself and earlier tokens, then predicts the next one. GPT-3 stacks 96 such layers with 96 heads of size 128.

Why this method: with the mask, one pass over a text trains every position's next-token prediction at once, and at generation time past keys and values can be cached.

Attention over image patches 🖼️ Deep learning · 2020 ViT: An Image is Worth 16x16 Words

How: cut the image into patches, turn each patch into a vector, and treat the patches as tokens. The same attention formula lets every patch look at every other patch (no mask: the whole image is visible).

Why this method: the paper shows a pure transformer on patches can match strong convolutional networks when pre-trained on lots of data, while needing substantially fewer computational resources to train.

Managing the KV cache in LLM serving 🏭 In production · 2023 vLLM / PagedAttention

How: servers keep each conversation's keys and values in GPU memory. vLLM stores this KV cache in small fixed-size blocks, like an operating system's memory pages, so nothing is wasted and requests can share blocks.

Why this method: the KV cache is huge and grows with every token (800 KB per token in their 13B example). Wasted cache space means fewer users per GPU; the paper reports 2–4× higher throughput.

🤯 Fun fact · built to translate

The Transformer was invented for machine translation. Its 2017 paper reported a new best score on English→German translation (28.4 BLEU, over 2 points above previous results, including ensembles). The same block, almost unchanged, now writes code, chats, and (as ViT showed) looks at pictures.

🌉 AI bridge · the transformer is the policy

RL: when RL trains a chatbot, the policy π(next token | text so far) is a causal transformer: attention + MLP layers + a softmax over the vocabulary. See RL course 7.1: the LLM as a policy, and Lesson 8.6 for the math RL then applies to it.

Numerics: those QKᵀ scores and their softmax are computed in 16-bit numbers on GPUs, with the subtract-the-max trick to avoid overflow. Lesson 8.5 shows why that matters.

Check yourself

1. A query has raw scores [4, 0] against two keys, and dk = 4. What are the attention weights?
Divide by √4 = 2: [2, 0]. Softmax: e² / (e² + 1) = 7.39 / 8.39 ≈ 0.88, and 0.12 for the other. Without the scaling you'd get [0.98, 0.02].
2. Why does the transformer divide the scores by √dk?
Softmax already makes the weights add up to 1. The √d only controls the typical size of the scores, so softmax stays in its sensitive range where learning works (the √d playground).
3. Why can an LLM reuse (cache) the keys and values of earlier tokens while it generates?
Each token's key and value depend only on itself and what came before it. New tokens can't change them, so computing them once and storing them (the KV cache) saves a huge amount of repeated work.
📝 TL;DR
  • Q = XWQ, K = XWK, V = XWV: three learned views of the same tokens.
  • Attention = softmax(QKᵀ/√dk)V: dot-product scores, row-wise softmax, weighted average of values.
  • Causal mask: future scores → −∞ → weight 0. It makes next-token training and the KV cache possible.
  • √d keeps scores around size 1 so softmax doesn't saturate. Multi-head = several attentions in parallel.
  • Used in every LLM, in vision transformers, and its cache is a big part of LLM serving cost.
