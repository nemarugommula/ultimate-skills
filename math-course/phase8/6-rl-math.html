Phase 8 · Lesson 6

The math of RL: expected return, Bellman, policy gradients

An expected value, a recursion and one calculus trick. With them, agents learn Atari and Go, and chatbots learn from feedback.

🧰 You'll need (quick reminders)
  • Expectation 𝔼[X] (read “the expected value of X”): the probability-weighted average of the outcomes (Lesson 4.4).
  • Derivative of a log: the slope of log f is (slope of f) / f, by the chain rule (Lessons 3.2 and 0.3).
  • Softmax gradient: for p = softmax(z), the slope of log pa with respect to z is one-hot(a) − p (Lesson 8.2).
🎯 Hook

AlphaGo improving by playing itself. DQN learning Atari from pixels. ChatGPT-style models being tuned with human feedback. DeepSeek's models learning to reason with GRPO. Four very different systems, and underneath almost all of them sit two equations: the Bellman equation (how good is this situation?) and the policy gradient (how do I make good actions more likely?).

You already know every piece. This lesson snaps them together, and the RL course takes it from there.

Numbers first: the return

A robot vacuum gets reward 0, 0, then +1 when it reaches its charger on step 3. Rewards that come later count a bit less, by a factor γ (“gamma”) per step, say γ = 0.9:

G = 0 + 0.9 × 0 + 0.9² × 1 = 0 + 0 + 0.81
G = r₁ + γr₂ + γ²r₃ + … = Σt≥1 γt−1 rt “The return G is the first reward, plus gamma times the second, plus gamma squared times the third, and so on.” γ between 0 and 1: near 0 = short-sighted, near 1 = patient. (RL course 0.3 builds this up slowly.)

Chance in the world: Markov chains

The world is random, so the return is random too. RL models the world as a Markov chain: the next state depends only on the current one (plus the action), with fixed probabilities. A two-state example, focused 🎯 and distracted 📱: from 🎯 you stay focused 90% of the time; from 📱 you come back 50% of the time.

start 🎯: after 1 step [🎯 0.9, 📱 0.1] → after 2: [0.9×0.9 + 0.1×0.5, 0.9×0.1 + 0.1×0.5] = [0.86, 0.14]

Each step is a vector times a matrix of probabilities (Lesson 2.2). Because only the present matters, we can talk about “the value of being here” without remembering how we got here.

Value is an expectation

The value of a state is the return you expect, on average, if you start there:

V(s) = 𝔼[ G | start in s ] “V of s is the expected return given that you start in state s.” The bar | reads “given”.

Example: from some state, a coin flip decides your path. Heads (50%): +1 right away, G = 1. Tails (50%): +1 two steps later, G = 0.81. So V = 0.5 × 1 + 0.5 × 0.81 = 0.905.

The Bellman equation: value as a recursion

Here's the key trick. The return from now = the next reward + γ × the return from the next state. Take the average of both sides and the second part becomes the value of the next state:

V(s) = 𝔼[ r + γ V(s′) ]     V*(s) = maxa 𝔼[ r + γ V*(s′) ] “The value here is the average of (reward now + gamma × value of wherever I land, s-prime).” The starred version, for the best possible behaviour, takes the best action a instead of averaging. Values are defined by other values, so you can compute them by repeating the equation until nothing changes.
💡 Big idea RL math is two moves. Bellman: value here = reward + γ × value next, so values can be computed by looking one step ahead, again and again. Policy gradient: to make good outcomes more likely, push up log π(action) in proportion to how good the outcome was.
🧠 Analogy: a chain of road signs

A road sign saying “Home: 3 km” doesn't need a map of the whole country. Its painter just read the next sign along the road (“Home: 2 km”) and added the 1 km between them. If every sign is painted that way, correct distances spread out from home across the whole road network. That's what repeated Bellman updates do, with γ as “each extra kilometre makes the trip a bit less attractive”.

✏️ Worked example: values ripple back from the goal

A corridor A → B → C → 🏁. Reaching 🏁 gives +1 and ends the episode (its value is 0). Every other step gives 0. γ = 0.9.

  • V(C) = 1 + 0.9 × V(🏁) = 1 + 0 = 1.
  • V(B) = 0 + 0.9 × V(C) = 0.9.
  • V(A) = 0 + 0.9 × V(B) = 0.81, the same 0.81 as the return at the top of the page.

Starting from all zeros, the first sweep gets C right, the second gets B, the third gets A. The playground does this on a 5 × 5 grid.

Notice two things. With γ = 0.9 the values fade by 10% per step away from 🏆: that's the discount. And the best-action arrows steer around 🔥 even though the shortest path passes next to it. This loop is value iteration; Q-learning and DQN learn the same fixed point from experience instead of from a known map.

From a map to experience: Q-values and the TD error

Without a map, an agent learns a value for each action. Q(s, a) is the expected return if you take action a in situation s and act well afterwards. The best you can do from s is to pick the best action, so V*(s) = maxa Q(s, a): the best Q.

Numbers first, in the corridor above. The agent's current guess is Q(B, right) = 0.5. It steps right, gets r = 0 and lands in C, where its best guess is max Q(C, ·) = 1. So Bellman says Q(B, right) should be 0 + 0.9 × 1 = 0.9. The gap 0.9 − 0.5 = 0.4 is the TD error (“temporal difference”): what happened (plus your next guess) minus what you predicted. With step size α = 0.1, the guess moves 0.1 × 0.4 = 0.04, to 0.54.

Q(s, a) ← Q(s, a) + α [ r + γ maxa′ Q(s′, a′) − Q(s, a) ] “Nudge the guess toward (reward + gamma × the best guess at the next state).” The bracket is the TD error. α (“alpha”) is the step size: the same job as this course's η, under the RL course's letter. This is Q-learning; see RL course 3.2: TD learning and 3.4: Q-learning.

The policy gradient: learning to act directly

Now the other half. A policy πθ(a) (read “pi-theta of a”: the probability that the policy with weights θ picks action a) is often a softmax over action scores (Lesson 8.2). We want to raise the expected reward J(θ) = Σa πθ(a) R(a). The problem: we can't list every action (an LLM has ~100,000 per step). We can only sample.

The log-derivative trick fixes it. From the chain rule, ∇ log π = ∇π / π, so ∇π = π · ∇ log π. Substitute:

∇θJ = Σa π(a) · ∇θ log π(a) · R(a) = 𝔼a~π[ ∇θ log πθ(a) · G ] “The gradient of the expected reward is the average, over actions sampled from the policy (a~π reads “a drawn from π”), of (the direction that makes that action more likely) × (how good the outcome was).” A sum weighted by π became an average over samples: just play, and average.

Check it on numbers. Two actions, π(A) = σ(θ) with θ = 0, so 50/50. R(A) = 1, R(B) = 0. The true gradient of J = σ(θ) is σ(1 − σ) = 0.25. The trick: picking A gives ∇log σ(θ) = 1 − σ = 0.5, times R = 1 → 0.5. Picking B gives (−0.5) × 0 = 0. Average: 0.5 × 0.5 + 0.5 × 0 = 0.25 ✓.

For a softmax policy, ∇z log π(a) = one-hot(a) − π: it's Lesson 8.2's p − y with the sign flipped. So the whole update is one line: scores += α × G × (one-hot(a) − π). That's REINFORCE (RL course 5.2).

✏️ Worked example: two REINFORCE updates by hand

3 actions A, B, C, all scores 0, so π = [⅓, ⅓, ⅓]. Step size α = 0.3.

  • Pull 1: picked C, G = +1. one-hot − π = [−⅓, −⅓, +⅔]. Δscores = 0.3 × 1 × that = [−0.1, −0.1, +0.2]. New π = [0.30, 0.30, 0.40].
  • Pull 2: picked A, G = −1. one-hot − π = [0.70, −0.30, −0.40]. Δscores = 0.3 × (−1) × that = [−0.21, +0.09, +0.12]. Scores [−0.31, −0.01, +0.32], π = [0.24, 0.32, 0.44].

The good action gained, the bad one lost. Subtracting a baseline (the usual reward) from G before the update keeps the direction but cuts the noise: that's the advantage A = G − b (RL 5.3), and GRPO's “compare with the group average” (RL 8.3).

🐍 In code 
import numpy as np
# Bellman: value iteration on the corridor A -> B -> C -> goal (+1)
V, gamma = np.zeros(4), 0.9                       # V[3] is the goal (terminal, stays 0)
for sweep in range(3):
    V[:3] = [(1 if s == 2 else 0) + gamma * V[s + 1] for s in range(3)]
# V[:3] == [0.81, 0.9, 1.0]

# Policy gradient (REINFORCE) on a softmax bandit
z, alpha, b = np.zeros(3), 0.1, 0.0
pi = np.exp(z) / np.exp(z).sum()
a = np.random.choice(3, p=pi); G = np.random.rand() < [0.2, 0.5, 0.8][a]
z += alpha * (G - b) * (np.eye(3)[a] - pi)        # grad of log softmax = one-hot - pi
# PyTorch: loss = -(advantage * log_prob).mean(); loss.backward()

🌍 Where it's used
The Bellman equation as a training target 🎮 RL · 2013 DQN: Playing Atari with Deep RL

How: a network outputs Q(s, a) for every action (Lesson 8.3). It's trained, “with a variant of Q-learning”, to make Q(s, a) match r + γ maxa′ Q(s′, a′): the Bellman optimality equation, used as a regression target.

Why this method: nobody knows the true values, but Bellman says what they must be consistent with, one step at a time. The paper's agent beat all previous approaches on six of seven games.

Policy gradients from self-play 🎮 RL · 2016 AlphaGo (Silver et al., Nature)

How: the policy network (a softmax over board moves) was first trained to imitate human games, then improved by reinforcement learning from games against itself: moves from won games pushed up, from lost games pushed down. A value network learned V(position) = the expected game result.

Why this method: imitation can only copy humans. The policy gradient optimizes what you actually care about, winning, and self-play supplies unlimited practice games.

RLHF: policy gradients on a language model 🧠 LLMs · 2022 InstructGPT (Ouyang et al.)

How: the LLM is the policy, each answer is an episode, and a reward model trained on human rankings gives the reward. PPO, a careful policy-gradient method, pushes up the log-probabilities of well-rated answers. See RL course 7.4.

Why this method: “helpful” has no formula to differentiate, but people can rank answers. With this, the paper reports that labelers preferred the 1.3B-parameter InstructGPT over the 175B GPT-3.

A group average as the baseline 🧠 LLMs · 2024 DeepSeekMath: GRPO

How: sample a group of answers to one math problem, score each, and use (reward − group mean) / group spread as the advantage in the policy gradient. No value network needed. See RL course 8.3.

Why this method: the paper introduces GRPO as a PPO variant that saves memory (no critic), and credits it as one of two keys to its 7B model reaching 51.7% on the competition-level MATH benchmark.

🤯 Fun fact · the first Markov chain was a poem

In 1913, Andrey Markov studied the first 20,000 letters of Pushkin's verse novel Eugene Onegin, sorting each letter into vowel or consonant and counting how often each kind followed the other. He showed that chains of dependent events could be modelled with transition probabilities: the idea every RL environment, and every “predict the next letter” model, is built on.

Check yourself

1. Rewards [1, 0, 2] with γ = 0.5. What is the return G?
G = 1 + 0.5 × 0 + 0.5² × 2 = 1 + 0 + 0.5 = 1.5. The reward of 2 is two steps away, so it's shrunk by γ² = 0.25.
2. From state s: 50% chance of reward 0 and landing in s′ with V(s′) = 10; 50% chance of reward 2 and the episode ends. γ = 0.9. What is V(s)?
Bellman: average of (r + γV(next)). 0.5 × (0 + 0.9 × 10) + 0.5 × (2 + 0) = 4.5 + 1 = 5.5. An ended episode contributes no future value.
3. Why do policy-gradient methods (REINFORCE, PPO, GRPO) use ∇ log π(a) · G instead of differentiating the reward directly?
∇J = 𝔼[∇log π · G] only needs the gradient of our own policy, which autograd can compute, and the rewards we observed. A game result, a reward model's score or “is the math answer right?” all work.
📝 TL;DR
  • Return G = Σ γt−1 rt; value V(s) = 𝔼[G | start in s].
  • Bellman: V(s) = 𝔼[r + γV(s′)] (max over actions for the optimal V*). Repeat it and values ripple out from rewards.
  • Policy gradient: ∇J = 𝔼[∇ log π(a) · G], from ∇π = π ∇log π. For softmax: scores += α · G · (one-hot − π).
  • Baselines (G − b) cut the noise; GRPO uses the group average.
  • Used in DQN, AlphaGo, RLHF (InstructGPT) and GRPO (DeepSeekMath).
