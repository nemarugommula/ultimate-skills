Convolution: how networks see images

Slide a small grid of weights across a picture and take a dot product at every spot. That one move read bank cheques in the 1990s, powers ResNets and diffusion models, and cuts photos into tokens for vision transformers.

🧰 You'll need (quick reminders)
  • Dot product: multiply matching entries and add, [1, 2, 3] · [1, 0, −1] = 1 + 0 − 3 = −2 (Lesson 1.3).
  • A dense layer Wx + b connects every input to every output: din × dout weights (Lessons 2.2 and 8.3).
  • A batch of images is a tensor of shape (N, C, H, W): batch, channels (red/green/blue), height, width (Lesson 2.3).
🎯 Hook

A 224 × 224 colour photo is 224 × 224 × 3 = 150,528 numbers. A dense layer with just 1,000 neurons on top of it needs 150,528 × 1,000 ≈ 150 million weights, for the first layer alone.

AlexNet, the network that won the 2012 ImageNet challenge by a mile, did something else. Its first layer has 96 small filters of 11 × 11 × 3 numbers: 34,848 weights, over 4,000 times fewer. And it saw better. The trick is to reuse the same few weights at every position in the image. That's a convolution.

Lay the filter over the top-left 3 × 3 patch of the image. Multiply each pixel by the weight on top of it and add up all nine products: that's Lesson 1.3's dot product, with the patch and the filter flattened into lists of 9. Write the answer down, slide the filter one pixel right, and repeat. Then the next row. The grid of answers is the feature map.

out[i, j] = Σa Σb x[i + a, j + b] · w[a, b] + b “The output at row i, column j is: for every row a and column b of the filter (Σ Σ means add over both), the pixel it sits on times its weight, all added up, plus a bias b.” With a 3 × 3 filter, a and b each run over 0, 1, 2: nine products per output.
x: image pixelsw: filter weights (learned)out: the feature map
✏️ Worked example: an edge detector and a blur

Top-left patch (columns 1–3): every pixel is 0, so the sum is 0. One step right (columns 2–4): each row reads [0, 0, 9], times [−1, 0, 1] gives 0 + 0 + 9 = 9; three rows: 27. Columns 3–5: [0, 9, 9] → 0 + 0 + 9 = 9 per row: 27. Columns 4–6: [9, 9, 9] → −9 + 0 + 9 = 0: 0.

every row of the feature map = [0, 27, 27, 0]  →  a 4 × 4 map that lights up only where dark meets bright

The filter computes “right side minus left side”. On flat areas the two cancel; on a vertical edge they don't. It's a vertical-edge detector.

Swap in the blur filter, nine weights of 1/9 each (the patch's average): the rows become [0, 3, 6, 9]. The hard 0→9 jump turned into a soft ramp.

💡 Big idea A convolution layer is one small dot product, reused at every position. The filter's weights are the same everywhere (weight sharing), so the layer needs very few of them, and it finds its pattern wherever it appears in the image. In a CNN (convolutional neural network) nobody picks the numbers: they are weights learned by backpropagation, like any other layer (Lesson 8.3).
🧠 Analogy: the stencil hunt

You're looking for a tiny shape in a huge poster. You cut it out of cardboard, place the stencil in the top-left corner, and score how well the poster matches it there. Slide it along, score again, row after row. You end up with a map of match scores: bright wherever the shape is. One stencil, used everywhere. A CNN layer carries dozens of stencils at once, and learns their shapes from data.

Math refresher Why mathematicians would call this “cross-correlation”

In maths and signal processing, a convolution first flips the filter (left↔right and top↔bottom), then slides it. Deep-learning libraries such as PyTorch's Conv2d skip the flip; strictly that's cross-correlation. Since the weights are learned anyway, the network simply learns the flipped filter, so everyone just says “convolution”. (Flip [−1, 0, 1] and you get [1, 0, −1]: the same edge detector with the opposite sign.)

Output size, padding and stride

A 3 × 3 filter fits in a 6-wide image at 4 positions: 6 − 3 + 1 = 4. The map shrinks a little at every layer. Two knobs control the size:

  • Padding p: add a border of p zeros around the image first. With p = 1, a 3 × 3 filter keeps the size the same (“same” padding).
  • Stride s: jump s pixels at each slide instead of 1. Stride 2 roughly halves the width and height.
out = ⌊ (n + 2p − k) / s ⌋ + 1 “The output width is: the input width n, plus twice the padding, minus the filter size k, divided by the stride s and rounded down (⌊ ⌋ means round down), plus one.” n = 6, k = 3, p = 0, s = 1: 3 + 1 = 4. With p = 1 and s = 2: ⌊4/2⌋ + 1 = 3.

Channels: colour in, many feature maps out

A colour image has 3 channels (red, green, blue), so its tensor is (3, H, W). A filter then has to cover all three: it's 3 × 3 × 3 = 27 weights, and one dot product of 27 products gives one output number. One filter makes one feature map. A layer with 64 filters makes 64 feature maps, a (64, H, W) tensor, and the next layer's filters are 3 × 3 × 64.

parameters = Cout × ( k · k · Cin + 1 ) “The number of learned numbers is: the number of filters (output channels), times the weights in each filter (k by k by the input channels), plus one bias each.” 3 × 3 filters, 3 → 64 channels: 64 × (27 + 1) = 1,792.

Compare a dense layer doing the same job on a small 32 × 32 colour image: 32·32·3 = 3,072 inputs to 32·32·64 = 65,536 outputs is 3,072 × 65,536 ≈ 201 million weights. The convolution: 1,792. Two assumptions buy that saving. Locality: each output looks only at a small neighbourhood. Weight sharing: the same filter is used at every position. Both are true of images: nearby pixels belong together, and an edge is an edge wherever it is.

Stacking layers: seeing more of the picture

One 3 × 3 filter sees a 3 × 3 patch: its receptive field. Stack a second 3 × 3 layer on top: each of its outputs combines 3 × 3 outputs of layer 1, which together cover 5 × 5 pixels. Three layers: 7 × 7. With stride-1 layers it grows by k − 1 per layer.

receptive field = 1 + L · (k − 1) “After L stacked layers with k × k filters and stride 1, each output sees a square of 1 + L × (k − 1) pixels on a side.” L = 3, k = 3: 1 + 3 × 2 = 7.

So early layers find edges and colour blobs, middle layers combine edges into textures and parts (an eye, a wheel), and deep layers see whole objects. AlexNet's authors found their first-layer filters had learned exactly such edge-like and colour-blob patterns on their own. To grow the view faster, networks use stride 2, or pooling: a 2 × 2 max pool keeps only the biggest of every four numbers ([[1, 3], [2, 8]] → 8), halving the width and height with no weights at all. ResNet (2015) stacked up to 152 layers, “mostly 3 × 3 filters”, by adding a shortcut around every pair or trio of layers, and won ImageNet with 3.57% top-5 error.

1D convolution: audio and text

The same idea works along time. Slide a filter of, say, 2 weights along a sound wave or a sequence of word vectors (Lesson 1.5) and take a dot product at every step. For raw audio, a receptive field of a few samples is useless: speech has 16,000 samples per second. Dilated convolutions skip inputs: layer 1 combines neighbours, layer 2 inputs 2 apart, layer 3 inputs 4 apart, and so on. With dilations 1, 2, 4, …, 512 and filters of size 2, ten layers see 1 + (1 + 2 + … + 512) = 1,024 samples: 64 ms of audio. Without dilation, ten such layers would see just 11.

🐍 In code 
import numpy as np, torch, torch.nn as nn
img = np.zeros((6, 6)); img[:, 3:] = 9           # dark left half, bright right half
K = np.array([[-1, 0, 1]] * 3)                   # vertical-edge filter
out = np.array([[(img[i:i+3, j:j+3] * K).sum()    # dot product of window and filter
                 for j in range(4)] for i in range(4)])
out[0]                                           # array([ 0., 27., 27.,  0.])

conv = nn.Conv2d(in_channels=3, out_channels=64, kernel_size=3, padding=1)
sum(p.numel() for p in conv.parameters())       # 1792 = 64 × (3·3·3 + 1)
conv(torch.randn(8, 3, 32, 32)).shape            # torch.Size([8, 64, 32, 32]): (N, C, H, W)
patch = nn.Conv2d(3, 768, kernel_size=16, stride=16)  # ViT-B/16's patch embedding
patch(torch.randn(1, 3, 224, 224)).shape        # torch.Size([1, 768, 14, 14]) → 196 tokens

🌍 Where it's used
Weight sharing reads cheques 📜 History · 1998 LeCun et al.: Gradient-based learning applied to document recognition (LeNet-5)

How: a 32 × 32 digit image goes through 5 × 5 convolutions, subsampling (pooling) and more convolutions, then small dense layers that output the digit. The paper's cheque-reading system built on it was “deployed commercially and reads several million checks per day”.

Why this method: the paper argues that a fully connected network on raw pixels has too many weights, “no built-in invariance” to shifts, and ignores the image's layout entirely; shared local filters fix all three.

Pixels in, Q-values out 🎮 RL · 2013 Mnih et al.: Playing Atari with Deep RL (DQN)

How: the last 4 game frames, 84 × 84 each, are stacked as 4 input channels. Conv layer 1: 16 filters of 8 × 8, stride 4 (→ 20 × 20 × 16); layer 2: 32 filters of 4 × 4, stride 2; then dense layers give one Q-value per joystick action.

Why this method: stacking frames as channels means every first-layer filter spans 4 moments in time, so it can respond to motion, and convolutions let the same network play many games from raw pixels with no hand-made features.

Dilated 1D convolutions for speech 🖼️ Deep learning · 2016 van den Oord et al.: WaveNet

How: a stack of 1D causal convolutions (each output sees only the past) with dilations 1, 2, 4, …, 512, repeated several times, predicts the next audio sample, at least 16,000 per second.

Why this method: the paper notes that each 1, 2, …, 512 block has a receptive field of 1,024 and is a more efficient, non-linear counterpart of one huge 1 × 1024 convolution. Human listeners rated its speech more natural than the best existing systems.

The U-Net inside diffusion models 🖼️ Deep learning · 2020 Ronneberger et al.: U-Net · Ho et al.: DDPM

How: U-Net (2015, built for segmenting cells in microscope images) shrinks the image with convolutions and pooling, then grows it back, with shortcuts that copy the sharp early feature maps across. DDPM uses “a U-Net backbone” to predict the noise in an image at every denoising step; Stable Diffusion runs a U-Net on a compressed latent image (Lesson 8.4b).

Why this method: denoising needs an output exactly the size of the input, and both the big picture (what object is this?) and pixel detail. The down-up path gives the first, the shortcuts the second.

Patch embedding = a stride-16 convolution 🖼️ Deep learning · 2020 Dosovitskiy et al.: An Image is Worth 16x16 Words (ViT)

How: the paper cuts the image into 16 × 16 patches, flattens each and applies one learned linear map. That is exactly a convolution with a 16 × 16 filter and stride 16 (no overlap), and the official code implements it as one Conv layer. The resulting vectors are the transformer's tokens (Lesson 8.4).

Why this method: attention over 50,176 single pixels would be hopelessly expensive (every token is compared with every other); 196 patch tokens make it affordable. The 2022 ConvNeXt paper borrowed the idea back: a 4 × 4, stride-4 “patchify” layer at the start of a pure ConvNet.

🤯 Fun fact · 122,304 connections, 156 numbers

LeNet-5's first layer has 6 filters of 5 × 5 on a 32 × 32 image, giving six 28 × 28 maps. Count every pixel-to-output wire and you get 122,304 connections, but only 156 trainable parameters (6 × (25 + 1)). The whole network, the 1998 paper notes, has 345,308 connections but only about 60,000 free parameters, “because of the weight sharing”.

🌉 AI bridge · convolutions everywhere

LLMs & transformers: vision transformers start with a convolution (stride = patch size) and then hand the patch tokens to attention (Lesson 8.4). Attention lets every patch look at every other one from layer 1, while a CNN's receptive field grows layer by layer. ConvNeXt (2022) showed a modernized pure ConvNet, with bigger 7 × 7 filters, can still compete with them, reaching 87.8% ImageNet top-1 accuracy.

Generative models: the denoiser inside most image diffusion models is a convolutional U-Net (Lesson 8.4b).

RL: DQN's conv layers turn Atari screens into Q-values: RL Lesson 4.3: DQN. Each 84 × 84 × 4 stack of frames is one (C, H, W) = (4, 84, 84) input.

Classic ML: on spreadsheet-like data there's no “neighbouring pixel”, so convolution's assumptions don't apply, and tree models often win (Lesson 8.1b).

Check yourself

1. LeNet's first layer applies 5 × 5 filters to a 32 × 32 image, with no padding and stride 1. How wide is each feature map?
(n + 2p − k) / s + 1 = (32 + 0 − 5) / 1 + 1 = 28. A 5-wide window fits in 32 positions minus 4. To keep 32 you'd pad with p = 2.
2. WaveNet doubles the dilation at every layer (1, 2, 4, …, 512). Why not just stack ordinary 1D convolutions?
Each layer still has only 2-wide filters, so no extra weights. Ordinary stacking grows the view by 1 per layer (1 + 10 = 11 samples); doubling dilations add 1 + 2 + 4 + … + 512 = 1,023, so the view is 1,024 samples (64 ms) after just 10 layers.
3. A conv layer has 3 × 3 filters, 16 input channels and 32 output channels, with a bias per filter. How many parameters does it have?
Each filter is 3 × 3 × 16 = 144 weights + 1 bias = 145. Times 32 filters: 32 × 145 = 4,640. (4,608 forgets the biases; 288 forgets that each filter spans all 16 input channels.) The image size doesn't appear at all: that's weight sharing.
📝 TL;DR
  • A convolution slides a small filter of weights over the input and takes a dot product at every position; the grid of results is a feature map.
  • Output size ⌊(n + 2p − k)/s⌋ + 1; filters span all input channels; parameters = Cout(k²Cin + 1), independent of image size.
  • Weight sharing + locality: thousands of times fewer weights than a dense layer, and translation equivariance (shift in → shift out).
  • Stacking layers, stride, pooling and dilation grow the receptive field: edges → parts → objects; 1D versions handle audio and text.
  • Used in LeNet, AlexNet, ResNet, DQN, WaveNet, the U-Nets of diffusion models and the patch embedding of vision transformers.
