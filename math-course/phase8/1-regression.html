Phase 8 · Lesson 1

Linear & logistic regression from the math up

A dot product, a loss and gradient descent: the smallest complete machine-learning model. It still predicts ad clicks, trauma survival and what is hidden inside neural networks.

🧰 You'll need (quick reminders)
  • Dot product: multiply matching entries and add, [2, −1] · [3, 4] = 6 − 4 = 2 (Lesson 1.3).
  • Gradient descent: step each knob a little against its slope, knob ← knob − η × slope (Lesson 3.4).
  • Cross-entropy: the loss −log p, where p is the probability you gave the right answer (Lesson 6.3).
🎯 Hook

Every time you search, Google decides which ads to show by predicting the probability you'll click each one. Its 2013 paper on that system says it makes predictions “many billions of times per day”, and calls regularized logistic regression “a natural fit” for the job.

Not a giant neural network. A dot product pushed through an S-shaped curve. This lesson builds it from scratch, and you'll train one live with your mouse.

Numbers first: fit a line to three points

Three houses. Size (in 100 m²) x = [1, 2, 3], price (in $100k) y = [2, 3, 5]. We want a rule “price ≈ w × size + b”. Start with a lazy guess, w = 0, b = 0: predict 0 for everything.

errors ŷ − y = [0−2, 0−3, 0−5] = [−2, −3, −5]  →  squared: [4, 9, 25]  →  average = 38 / 3 = 12.67

That average of squared errors is the loss. Big loss = bad line. Our job is to turn the two knobs w and b until the loss is as small as it can be.

ŷ = wx + b      L = (1/n) Σi (ŷi − yi)² “y-hat (the prediction) is w times x plus b. The loss L is the mean squared error: for each of the n examples, square the gap between prediction and truth, add them up (Σ), divide by n.”

With many inputs (size, bedrooms, age…) the same rule becomes a dot product: ŷ = w · x + b. That's linear regression.

💡 Big idea Almost every model in this phase is the same four-step recipe: score = dot product, maybe squash it, measure a loss, nudge the weights by gradient descent. Linear regression is the recipe with nothing extra.

Which way to turn the knobs?

The gradient (Lesson 3.3) tells us. For mean squared error it comes out short and readable:

∂L/∂w = (2/n) Σi (ŷi − yi) · xi     ∂L/∂b = (2/n) Σi (ŷi − yi) “The slope of the loss with respect to w (∂ is read “partial”) is twice the average of error × input. For b it's twice the average error.” Too-low predictions give negative errors, so the gradient is negative and the step pushes w and b up.
✏️ Worked example: one step of gradient descent, then the exact answer
  • Errors at w = b = 0 were [−2, −3, −5]. So ∂L/∂w = (2/3)(−2·1 − 3·2 − 5·3) = (2/3)(−23) = −15.33, and ∂L/∂b = (2/3)(−10) = −6.67.
  • Step with learning rate η = 0.05: w = 0 − 0.05 × (−15.33) = 0.767, b = 0 − 0.05 × (−6.67) = 0.333.
  • New loss: 2.57 (down from 12.67). Repeat a few hundred times and it settles.
  • Where it settles has a formula: slope = Σ(x − x̄)(y − ȳ) / Σ(x − x̄)². Averages x̄ = 2, ȳ = 3.33. Top: (−1)(−1.33) + 0 + (1)(1.67) = 3. Bottom: 1 + 0 + 1 = 2. So w = 1.5, and b = ȳ − w x̄ = 3.33 − 3 = 0.33. Loss there: 0.056, the best any straight line can do.

Math refresher The closed form (no gradient descent at all)

For squared error you can jump straight to the bottom. Stack the inputs as rows of a matrix X (with a column of 1s for b). The best weights are

w = (XᵀX)⁻¹ Xᵀ y “w equals the inverse of X-transpose-X, times X-transpose, times y.” ᵀ is the transpose (flip rows and columns) and ⁻¹ the inverse matrix (Lesson 2.4).

With one input it shrinks to the slope formula from the worked example. Why bother with gradient descent then? The inverse costs about d³ operations for d inputs, and it only exists for squared error. Gradient descent works for any loss, including the next one.

From prices to yes/no: logistic regression

Now predict a probability: will this person click the ad? A dot product can give any number, like 7 or −3. We need something between 0 and 1. Squash the score with the sigmoid curve σ (“sigma”):

z = w · x + b     p = σ(z) = 1 / (1 + e−z) “The score z is w dot x plus b. The probability p is sigma of z: one over one plus e to the minus z.” e ≈ 2.718 (Lesson 0.4). Big positive score → p near 1. Big negative → near 0. Score 0 → exactly 0.5.

🧠 Analogy: a judge's scorecard

A talent-show judge adds up points: +2 for singing, +1 for stage presence, −3 for forgetting the words. That total is the dot product. Then they turn it into confidence: “a total of +4? I'm 98% sure they go through. 0? Coin flip.” The sigmoid is that last step, turning “points” into “how sure”.

The loss is cross-entropy (Lesson 6.3): −log p if the truth was 1 (“clicked”), −log(1 − p) if it was 0. And here's the surprise. Its gradient has exactly the same shape as linear regression's:

∂L/∂w = (p − y) · x     ∂L/∂b = p − y “For one example: (predicted probability minus the true label) times the input.” Said 0.9 and it was 1? Small push. Said 0.1 and it was 1? Big push. No sigmoid derivative left over: it cancels out.

Why the sigmoid's slope cancels out

Numbers first, using the worked example below (score z = 1.5, so p = 0.818). Nudge the score to 1.51: σ goes from 0.81757 to 0.81906, up by 0.00149, which is 0.01 × 0.149. And 0.149 is exactly p × (1 − p) = 0.818 × 0.182. That's the sigmoid's slope, as promised in Lesson 3.2:

dp/dz = σ(z) (1 − σ(z)) = p(1 − p) “The slope of the sigmoid is p times one minus p.” It's largest, 0.25, at p = 0.5, and nearly 0 when p is close to 0 or 1.

Now the log. How fast does the loss change as p changes? It works out to (p − y) / (p(1 − p)). Here y = 1, so that's (0.818 − 1) / 0.149 ≈ −1.222 (the same as −1/p). The chain rule (Lesson 3.2) multiplies the two slopes:

∂L/∂z = (p − y) / (p(1 − p)) × p(1 − p) = p − y    check: −1.222 × 0.149 ≈ −0.182 = 0.818 − 1 ✔

The p(1 − p) from the sigmoid cancels the 1/(p(1 − p)) from the log, leaving p − y. That's lucky: when the model is confidently wrong (p ≈ 0 but y = 1), the sigmoid's slope alone would be almost 0 and learning would stall. After the cancellation the push is a healthy p − y ≈ −1.

✏️ Worked example: one click prediction, one update
  • Features x = [2, 1] (ad matches the query twice, user is on a phone), weights w = [1.5, −1], b = −0.5.
  • Score: z = 2 × 1.5 + 1 × (−1) − 0.5 = 1.5. Probability: σ(1.5) = 1 / (1 + e−1.5) = 0.818.
  • They clicked (y = 1). Loss = −log 0.818 = 0.201. Gradient: (0.818 − 1) × [2, 1] = [−0.365, −0.182], and −0.182 for b.
  • Step with η = 0.5: w = [1.5 + 0.182, −1 + 0.091] = [1.682, −0.909], b = −0.409. New p = 0.886. More confident, as it should be.

The decision boundary is a straight line

Where does the model switch from “no” to “yes”? At p = 0.5, which is where z = 0. In 2D that's w₁x₁ + w₂x₂ + b = 0: the equation of a straight line. The weight vector w points across it, toward the “yes” side, and a bigger ‖w‖ makes the switch sharper.

🐍 In code 
import numpy as np
X = np.array([[2, 1], [0, 3], [3, 0]]); y = np.array([1, 0, 1])
w, b, lr = np.zeros(2), 0.0, 0.5
for step in range(200):
    p = 1 / (1 + np.exp(-(X @ w + b)))   # sigmoid of the dot products
    w -= lr * X.T @ (p - y) / len(y)      # gradient = average of (p - y) * x
    b -= lr * np.mean(p - y)

# The same thing, ready-made (also does regularization for you):
from sklearn.linear_model import LogisticRegression
LogisticRegression().fit(X, y).predict_proba([[2, 1]])

🌍 Where it's used
Logistic regression for click prediction 🏭 In production · 2013 McMahan et al., Ad Click Prediction: a View from the Trenches (Google)

How: each (query, ad) pair becomes a huge, mostly-zero feature vector x. The click probability is σ(w · x), and w is updated online, one example at a time, with an algorithm called FTRL-Proximal.

Why this method: the paper describes billions of coefficients and billions of predictions a day. A dot product over the few non-zero features is about as cheap as prediction gets, and the output is a probability the auction can use directly.

Logistic regression in medicine 📊 Data science · 1987 Boyd et al., the TRISS method

How: the Trauma and Injury Severity Score predicts whether an injured patient survives from a few measurements (injury severity, vital signs, age). It was built with logistic regression: a weighted sum of those numbers, then the sigmoid.

Why this method: doctors can read every weight (“how much does age count?”), and the output is a survival probability, not just a yes/no.

Linear probes: what does a network know? 🖼️ Deep learning · 2016 Alain & Bengio, linear classifier probes

How: freeze a trained network, read the activations of one layer, and train a plain linear classifier on them. High accuracy means the information is sitting there, readable by a single dot product. They found this linear separability increases with depth.

Why this method: a linear model is too weak to do the work itself, so if it succeeds, the credit belongs to the layer it's reading. The same trick is used today to look for concepts inside LLMs.

Straight lines on log-log plots: scaling laws 🧠 LLMs · 2020 Kaplan et al., Scaling Laws for Neural Language Models

How: they found that an LLM's loss follows a power law in model size, data and compute. Take logs of both axes and a power law becomes a straight line, so fitting it is linear regression on the logs.

Why this method: a fitted line can be extended. The paper uses these trends to work out how to split a fixed compute budget between model size and data, before spending it.

🤯 Fun fact · least squares found a lost asteroid

In 1801 the astronomer Piazzi discovered the asteroid Ceres, tracked it for 40 days, then lost it in the Sun's glare. The predictions that let astronomers find it again came from the 24-year-old Gauss, using least squares: minimizing the sum of squared errors, exactly the loss in the playground above. Legendre published the method first, in 1805.

🌉 AI bridge · the one-neuron network

Deep learning: logistic regression is a neural network with one neuron. Lesson 8.2 gives it one output per class (softmax), and Lesson 8.3 stacks layers of them so the boundary can bend.

RL: the simplest value function is a linear regression: predicted value = weights · features, trained to match observed returns. That's RL course Lesson 4.1: function approximation.

LLMs: “(p − y) × input” will come back in every lesson of this phase. It's the gradient of the LLM output layer (8.2) and, with a twist, of policy gradients in RL (8.6).

Check yourself

1. Weights w = [1, 2], b = −1, input x = [3, −1]. What does logistic regression output?
z = 1·3 + 2·(−1) − 1 = 0, and σ(0) = 1 / (1 + 1) = 0.5. A score of 0 means the point sits exactly on the decision boundary: a coin flip.
2. The model said p = 0.9 that a user would click, and they didn't (y = 0). For the input x = [1, 2], what is the gradient for w?
(p − y) · x = (0.9 − 0) × [1, 2] = [0.9, 1.8]. Gradient descent subtracts it, so both weights go down and the next prediction for this user drops. A confident wrong answer gets a big push.
3. Why did Google's ad system use logistic regression instead of a big neural network for click prediction?
At that scale every microsecond counts. A sparse dot product plus a sigmoid is tiny, can be updated after every click, and gives a calibrated probability. (Neural networks can output probabilities too: Lesson 8.2.)
📝 TL;DR
  • Linear regression: ŷ = w · x + b, loss = mean squared error, solved by gradient descent or a closed form.
  • Logistic regression: p = σ(w · x + b), loss = cross-entropy.
  • Both gradients have the same shape: (prediction − truth) × input.
  • The decision boundary (p = 0.5, z = 0) is a straight line, so curvy problems need hidden layers (8.3).
  • Used for ad clicks, medical risk scores, probing neural networks and fitting scaling laws.
