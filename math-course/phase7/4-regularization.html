Phase 7 · Lesson 4

Regularization: weight decay, dropout, early stopping

Tricks that stop a model from memorizing its training data: keep weights small, randomly switch neurons off, stop at the right moment, invent more data. Every large model uses several of them at once.

🧰 You'll need (quick reminders)
  • Overfitting: great on training data, bad on new data. We spot it with a held-out test (or validation) set (Lesson 5.6).
  • L1 norm = sum of absolute values; L2 norm squared = sum of squares. For [3, −1, 2]: L1 = 6, L2² = 14 (Lesson 1.4).
  • One training step: w ← w − η∇L; AdamW is Adam plus “weight decay” (Lesson 7.3).
🎯 Hook

In 2012, AlexNet won the ImageNet challenge and kicked off the deep learning boom. It had 60 million parameters. Its authors wrote that without one trick, dropout, the network “exhibits substantial overfitting”. They also blew the training set up by a factor of 2,048 with random crops and mirror images.

Big models can memorize almost anything. Regularization is the set of tricks that makes them learn the pattern instead.

Numbers first: two models, same training error

Two models fit the same training points equally well. Model A has weights [0.5, 1.2]. Model B has weights [40, −38]: two huge numbers that almost cancel. Which would you trust on a new input?

Model A. Model B's giant weights mean a tiny change in the input can swing its output wildly. So add a penalty for big weights to the loss. With penalty strength λ = 0.1:

A: 0.1 × (0.5² + 1.2²) = 0.1 × 1.69 = 0.169   ·   B: 0.1 × (40² + 38²) = 0.1 × 3,044 = 304.4

Same data fit, but B now pays a huge extra cost. Training will prefer A.

Ltotal = Ldata + λ Σ w² Read: total loss = how badly we fit the data, plus λ (“lambda”) times the sum of all squared weights. λ is a knob: 0 means “don't care about weight size”, big means “keep weights tiny even if the fit suffers”.

This is L2 regularization (called ridge regression for linear models). Swap the squares for absolute values, λ Σ |w|, and you get L1 regularization (the lasso).

At λ = 0 the curve threads every training point (tiny train error) and swings wildly between them (big test error): textbook overfitting, with weights in the hundreds. A little λ calms it down and the test error drops by a factor of 5 or so. Too much λ flattens everything (underfitting). With L1, most bars snap to exactly zero: the lasso picks a few features and drops the rest.

💡 Big idea Regularization trades a little training accuracy for a lot of reliability on new data. The cheapest version: add λ × (size of the weights) to the loss, so the model only uses big weights when the data really demands them.

Why it's called weight decay

The slope of λw² is 2λw. Plug it into a gradient step:

w ← w − η(∇Ldata + 2λw) = (1 − 2ηλ) w − η∇Ldata Read: before the usual step, every weight is multiplied by a number slightly below 1. With η = 0.1 and λ = 0.05 that's 1 − 0.01 = 0.99: each step, every weight shrinks (“decays”) by 1%, unless the data pushes back.

For plain SGD, “add λw² to the loss” and “shrink every weight a bit each step” are the same thing. For Adam they're not: Adam divides gradients by their typical size (Lesson 7.3), which also distorts the penalty's gradient. AdamW (“Adam with decoupled Weight decay”) skips the loss and shrinks the weights directly: w ← w − ηλw each step. LLMs use AdamW with λ = 0.1.

Mind the factor of 2. The loss penalty λw² has slope 2λw, so it shrinks weights by 2ηλ per step. PyTorch's weight_decay=λ applies λw directly, shrinking by ηλ. So weight_decay=0.1 pulls as hard as a loss penalty of 0.05·w² would under plain SGD.

L1 vs L2: why L1 makes exact zeros

✏️ Worked example: how hard does each penalty push?

Take λ = 0.1. The L2 push on a weight is its slope, 2λw; the L1 push (slope of λ|w|) is always λ, whatever the weight's size.

  • Big weight w = 3: L2 push = 2 × 0.1 × 3 = 0.6. L1 push = 0.1.
  • Small weight w = 0.03: L2 push = 2 × 0.1 × 0.03 = 0.006. L1 push = still 0.1.

L2's push fades as a weight gets small, so weights become small but rarely exactly 0. L1 keeps pushing just as hard all the way down, so a weight the data doesn't really need gets shoved to exactly 0. That's sparsity: a model that uses only a few inputs.

Dropout: randomly switch neurons off

A completely different trick. During training, each step, every neuron in a layer is switched off with probability p (PyTorch's default is 0.5). The survivors are multiplied by 1/(1 − p) so the layer's total output stays the same on average. At test time, nobody is switched off.

Why would sabotage help? No neuron can rely on one specific partner being there, so each must learn something useful on its own. It's like training a huge family of thinned-out networks that share weights, and averaging them at test time.

🧠 Analogy: a team where anyone might call in sick

If a team always works with the same people, a few stars carry everything and the others coast. If any member might be absent on any given day, everyone has to understand the whole job. Dropout makes every neuron a reliable team player. Weight decay is the team's budget: nobody gets to make extreme bets. Early stopping is going home before you start overthinking.

Early stopping and data augmentation

Early stopping: keep an eye on the loss on a held-out validation set. Training loss keeps falling forever; validation loss falls, bottoms out, then rises as the model starts memorizing. Stop near the bottom. Since validation curves are noisy, we wait a few epochs (the patience) before deciding it really stopped improving, then keep the best checkpoint.

🎮 Mini playground · When to stop

Data augmentation: make more training data out of the data you have. Flip a cat photo left–right: still a cat. Crop it a little, change the brightness: still a cat. The model sees new-looking examples every epoch, so memorizing exact pixels stops paying off.

import numpy as np, torch, torch.nn as nn
from sklearn.linear_model import Ridge, Lasso
w = np.array([3.0, -1.0, 2.0]); lam = 0.1
lam * (w**2).sum(), lam * np.abs(w).sum()     # L2 penalty 1.4, L1 penalty 0.6
Ridge(alpha=1.0).fit(X, y); Lasso(alpha=0.1).fit(X, y).coef_   # lasso: many coefs exactly 0

layer = nn.Sequential(nn.Linear(512, 512), nn.ReLU(), nn.Dropout(p=0.1))  # Transformer-style rate
model.train(); model.eval()        # dropout is ON in train mode, OFF in eval mode
opt = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)  # decoupled decay

🌍 Where it's used
Weight decay in LLM training 🧠 LLMs · 2020 GPT-3 (training details, Appendix B)

How: every GPT-3 model was trained with a weight decay of 0.1, which the paper describes as a small amount of regularization. LLaMA (2023) used the same 0.1 with AdamW, following Loshchilov & Hutter's decoupled weight decay.

Why this method: one number, almost free to compute, and it keeps billions of weights from drifting to extreme values. The AdamW paper showed that with Adam, L2-in-the-loss and true weight decay are not equivalent, and the decoupled form is the one that behaves as intended.

Dropout 🖼️ Deep learning · 2014 Srivastava et al., Dropout (JMLR)

How: the paper's networks kept each hidden unit with probability 0.5 and each input with 0.8 (note: there p means “keep”, in PyTorch it means “drop”). The original Transformer used a dropout rate of 0.1.

Why this method: training one network with dropout approximates averaging an enormous number of thinned networks, without the cost of training them separately.

Data augmentation + dropout in AlexNet 🖼️ Deep learning · 2012 Krizhevsky, Sutskever & Hinton

How: random 224 × 224 crops of the 256 × 256 images plus their mirror images, which the authors say increases the training set by a factor of 2,048; dropout in the first two fully connected layers.

Why this method: a 60-million-parameter model on 1.2 million images would memorize. Flips and crops are free, label-preserving new data.

Lasso for feature selection 📊 Data science · 1996 scikit-learn Lasso

How: fit a linear model on hundreds of candidate features with an L1 penalty; most coefficients come out exactly 0, and the survivors are your selected features. Popularized by Robert Tibshirani in 1996.

Why this method: unlike ridge, which only shrinks, the lasso gives a short, readable list of what matters, and a cheaper model to run.

Early stopping 🤖 Machine learning · 2016 Deep Learning Book §7.8 · Keras EarlyStopping

How: watch a metric on held-out data (usually validation loss) and stop once it hasn't improved for patience epochs, then restore the best weights. Libraries like Keras ship it as a one-line callback.

Why this method: it needs no change to the model or loss, and it also saves compute: you stop paying for epochs that only make the model worse.

🤯 Fun fact · dropout was inspired by sex

The dropout paper says a motivation came from a theory of the role of sex in evolution: genes get mixed with random partners every generation, so a gene can't rely on one exact set of companions and has to be useful in many combinations. Neurons under dropout face the same pressure.

Check yourself

1. Weights [3, −1, 2], λ = 0.1. What is the L2 penalty λ Σ w²?
0.1 × (9 + 1 + 4) = 0.1 × 14 = 1.4. The L1 penalty would be 0.1 × (3 + 1 + 2) = 0.6.
2. Why does L1 (lasso) set many weights to exactly zero, while L2 (ridge) only makes them small?
The slope of λ|w| is ±λ everywhere, so an unneeded weight gets driven all the way to 0. The slope of λw² is 2λw, which is almost nothing for a weight that's already small.
3. You trained with nn.Dropout(p=0.1). What happens when you call model.eval() to serve the model?
Dropout is a training-only trick. PyTorch scales the survivors up by 1/(1 − p) while training, so the average output already matches the full network, and at test time it does nothing.
📝 TL;DR
  • L2 / weight decay: add λΣw², i.e. shrink every weight by a factor (1 − 2ηλ) each step. AdamW decouples it and shrinks by ηλ (no 2); LLMs use λ = 0.1.
  • L1 / lasso: add λΣ|w|; constant push → many weights exactly 0 (feature selection).
  • Dropout: randomly zero neurons with probability p in training, scale survivors by 1/(1 − p); off at test time.
  • Early stopping: stop when validation loss stops improving (with patience). Augmentation: flips, crops, noise = free extra data.
