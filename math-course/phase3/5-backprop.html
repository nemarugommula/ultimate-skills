Backpropagation: the chain rule on a graph

Run the model forward to get the loss, then walk backwards multiplying local slopes. You get the gradient for every weight at once, for about the price of two more forward passes. It's what loss.backward() does.

🧰 You'll need (quick reminders)
  • Chain rule: along a chain, local slopes multiply, like gear ratios (Lesson 3.2).
  • The gradient = one slope per weight; gradient descent steps against it (Lessons 3.3–3.4).
🎯 Hook

To train GPT-3 you need 175 billion slopes, one per weight, at every step. The nudge method from Lesson 3.1 would need one extra run of the whole model per weight: 175 billion runs for a single step.

Backpropagation gets all 175 billion slopes for roughly the cost of two extra runs. Without that trick there would be no deep learning. And the trick is just the chain rule, done in a clever order.

Numbers first: a model as a little graph

Take a one-neuron model and its loss: L = (w·x + b − y)². Break it into baby steps, each one a single operation. That's a computation graph. With w = 2, x = 3, b = 1, y = 5:

p = w·x = 6  →  z = p + b = 7  →  e = z − y = 2  →  L = e² = 4

That's the forward pass: inputs flow left to right and every box remembers its value. Now the backward pass asks, box by box from the right: “how much does L change if this value changes?”. Each box only needs its own local slope, times the answer it receives from its right.

  • Square e²: local slope 2e = 4. So ∂L/∂e = 4.
  • Subtract z − y: slope 1 for z. So ∂L/∂z = 4 × 1 = 4.
  • Add p + b: slope 1 for both. So ∂L/∂p = 4 and ∂L/∂b = 4.
  • Multiply w·x: the slope for w is x (= 3), for x it's w (= 2). So ∂L/∂w = 4 × 3 = 12 and ∂L/∂x = 4 × 2 = 8.

Check ∂L/∂w with a nudge: w = 2.001 gives L = (6.003 + 1 − 5)² = 4.012009, so the slope ≈ 0.012009 / 0.001 = 12.009 ✓.

gradient into an input = gradient arriving from the right × local slope Every box does the same thing on the way back: take the gradient handed to it, multiply by its own slope for each input, and pass the results further left. That's the chain rule, one link at a time.
💡 Big idea Forward pass: compute and remember every intermediate value. Backward pass: start with ∂L/∂L = 1 and walk right to left, multiplying by local slopes. Because each gradient is reused by everything to its left, every slope in the network comes out of one backward sweep.

🧠 Analogy: passing blame down a kitchen line

A dish comes back from a customer: “too salty, 4 points off”. The head chef passes the complaint back to each cook in proportion to how much they affected the saltiness. A cook who added salt directly gets a big share; one who only plated gets none. Each cook passes their share on to their own suppliers the same way. Nobody needs the whole picture: each station only knows its own local effect, and the blame flows back step by step.

✏️ Worked example: what the gradients tell you

From the graph: ∂L/∂w = 12, ∂L/∂b = 4. Both positive, so lowering w and b lowers the loss. One gradient-descent step with η = 0.01 (Lesson 3.4):

  • w ← 2 − 0.01 × 12 = 1.88; b ← 1 − 0.01 × 4 = 0.96.
  • New loss: (1.88 × 3 + 0.96 − 5)² = (1.60)² = 2.56, down from 4.

w got the bigger push because its input x = 3 is big: the multiply box hands w the gradient times x. Inputs that are large give their weights big gradients.

Forward, backward, step: a whole training loop

Now repeat that for a little dataset: three points on the line y = 2x + 1. Each training step runs forward and backward for every point, averages the gradients, and takes one step. This is a tiny micrograd.

🎮 Playground · Train a line with backprop

Press “Train 1 step” and read the table: each row is one forward + backward pass. Then run 300 steps and watch w → 2 and b → 1 (b is the slow one). Try a bigger η to make it blow up.

🐍 In code 
import torch
w = torch.tensor(2.0, requires_grad=True); b = torch.tensor(1.0, requires_grad=True)
x, y = 3.0, 5.0
L = (w * x + b - y) ** 2          # forward pass: PyTorch records the graph as it goes
L.backward()                        # backward pass: chain rule, right to left
print(L.item(), w.grad, b.grad)     # 4.0  tensor(12.)  tensor(4.)

with torch.no_grad():                # one gradient-descent step (Lesson 3.4)
    w -= 0.01 * w.grad; b -= 0.01 * b.grad   # w = 1.88, b = 0.96

🌍 Where it's used
loss.backward(): autograd 🏭 In production · 2016 PyTorch autograd mechanics

How: as your code runs forward, PyTorch records every operation as a box in a graph. loss.backward() walks that graph from the loss backwards, exactly like the playground, and stores each weight's slope in .grad.

Why this method: you write only the forward pass; the backward pass is generated automatically and can't get the chain rule wrong. JAX and TensorFlow do the same.

The paper that made it famous 📜 History · 1986 Rumelhart, Hinton & Williams, Nature

How: “Learning representations by back-propagating errors” applied the backward pass to networks with hidden layers and showed that the hidden units learn useful internal features on their own.

Why this method: earlier learning rules could only train a single layer. Backprop gives a slope to every weight, however deep it sits.

Why training costs about 3× a forward pass 🧠 LLMs · 2020 Kaplan et al.: Scaling Laws for Neural Language Models

How: a forward pass of a model with N weights costs about 2N operations per token, and the backward pass about twice that, so training costs about 6N per token. Scaling-law work uses C ≈ 6N × tokens to estimate the compute a training run needs.

Why this method: the alternative, nudging each weight, would cost N extra forward passes. Reverse-mode differentiation's cost is a small constant multiple of the forward pass (the autodiff survey by Baydin et al. puts it under 6, typically 2–3).

An autograd engine in about 100 lines 🤖 Machine learning · 2020 Karpathy's micrograd

How: every number is a Value that remembers its inputs and its local slope. backward() sorts the boxes and applies “gradient × local slope” from the loss back. Enough to train a small neural network.

Why this method: scalar-by-scalar it's slow, but it shows that PyTorch's core idea fits on a page. Real libraries do the same with whole matrices (Phase 2) on GPUs.

🤯 Fun fact · invented for rounding errors

The backward-sweep algorithm (“reverse-mode automatic differentiation”) was first published by Seppo Linnainmaa in his 1970 master's thesis in Helsinki, about how rounding errors pile up inside long computations. Neural nets weren't on his mind. And Ronald Williams, the third author of the famous 1986 paper, went on to invent REINFORCE in 1992: backprop and policy gradients share a parent.

🌉 AI bridge · backward through everything

LLMs: one training step of a transformer is a forward pass through every block, the cross-entropy loss (Lesson 6.3), one backward() and one optimizer step. Lesson 8.3 does a whole network by hand.

RL: deep RL backpropagates through value networks (RL Lesson 4.2) and through log-probabilities of actions (RL Lesson 5.2). Same loss.backward(), different loss.

Check yourself

1. A multiply box computes a · b with a = 3 and b = −2. The gradient arriving from the right is 5. What gradient does it pass to a?
For a multiply box, a's local slope is the other input, b. So a gets 5 × (−2) = −10. (And b gets 5 × 3 = 15.)
2. An add box z = p + b receives the gradient 4. What do p and b get?
The slope of p + b is 1 with respect to each input, so the add box copies the gradient to both. It's a distributor, not a splitter.
3. Why is backprop used to train big networks instead of nudging each weight?
For N weights, nudging costs about N forward passes; backprop costs about 2 more (Kaplan et al.'s 6N vs 2N). With billions of weights that's the difference between possible and impossible. Nudging is still great for checking (Lesson 3.1).
📝 TL;DR
  • A model is a computation graph of small boxes (multiply, add, square, ReLU…).
  • Forward pass: compute and remember values. Backward pass: from ∂L/∂L = 1, each box multiplies the incoming gradient by its local slope and passes it left.
  • Add copies the gradient; multiply swaps in the other input; ReLU gates it.
  • All slopes for ≈ 2× a forward pass's cost. It's loss.backward() in PyTorch, since Rumelhart, Hinton & Williams (1986).
