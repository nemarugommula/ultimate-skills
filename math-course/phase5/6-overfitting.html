Phase 5 · Lesson 6

Overfitting, bias–variance & train/test splits

A model that aces its training data can still fail on new data. How to measure that honestly (train/validation/test splits, cross-validation) and why it matters for every model from a polynomial to an LLM benchmark.

🧰 You'll need (quick reminders)
  • Least squares: fit a model by making the squared errors as small as possible (it's maximum likelihood with bell-shaped noise, Lesson 5.3).
  • A polynomial like 1 + 2x − x³ is a function machine with a few knobs (its coefficients) (Lesson 0.2).
  • Any number measured on a sample wobbles; the standard error says by how much (Lesson 5.5).
🎯 Hook

GSM8k is a famous benchmark of grade-school math problems, and LLMs score very high on it. In 2024, researchers wrote 1,000 brand-new problems in the same style and difficulty (GSM1k) and tested the same models. Some models' accuracy dropped by up to 8%, and the models most likely to reproduce GSM8k's own examples tended to show the biggest drops.

Those models had partly learned the test instead of the skill. That's overfitting, and the cure is a habit: always measure on data the model has never seen.

Numbers first: a line versus a curve that hits every point

Four training points: (1, 2.5), (2, 3.5), (3, 6.5), (4, 7.5). The truth behind them is roughly y = 2x plus noise. Two models:

  • A straight line (2 knobs). Least squares gives ŷ = 0.5 + 1.8x. It misses every point a little.
  • A cubic (4 knobs). With 4 knobs and 4 points it can pass through every point exactly.

Score both with the mean squared error: the average of (actual − predicted)².

MSE = (1/n) Σi (yi − ŷi)² “M-S-E is the average squared gap between the true values y and the model's predictions y-hat.” Computed on the training points it's the training error; on fresh points it's the test error.
✏️ Worked example: training error lies
  • Line, training: predictions 2.3, 4.1, 5.9, 7.7 → errors 0.2, −0.6, 0.6, −0.2 → MSE = (0.04 + 0.36 + 0.36 + 0.04) ÷ 4 = 0.20.
  • Cubic, training: it hits every point → MSE = 0. It looks perfect.
  • New points (1.5, 3), (2.5, 5), (3.5, 7). Line predicts 3.2, 5.0, 6.8 → test MSE = (0.04 + 0 + 0.04) ÷ 3 ≈ 0.027. Cubic predicts 2.5, 5.0, 7.5 → test MSE = (0.25 + 0 + 0.25) ÷ 3 ≈ 0.17, six times worse.
  • Ask both about x = 5 (true value about 10). Line: 9.5. Cubic: 2.5. It bent itself around the noise and now points the wrong way.
💡 Big idea Overfitting: the model learns the noise in its training data, so training error is low but test error is high. Underfitting: the model is too simple to capture the real pattern, so both are high. The only honest score is on data the model never trained on.
🎮 Playground · The polynomial fitter

Training error (teal) only goes down as the degree grows. Test error (green) falls, bottoms out, then shoots up: the famous U-curve.

Bias and variance: two ways to be wrong

The “20 fits” button retrains the same model on 20 different noisy samples. Two failure modes show up:

  • High bias (degree 0–1): all 20 fits agree with each other, and they're all wrong in the same way. The model is too rigid to follow the curve. Their average is still off.
  • High variance (degree 9–11): every fit is wildly different. Each one chases its own sample's noise. Their average is close to the truth, but any single fit is far from it.
expected test error ≈ bias² + variance + noise “Test error is roughly bias squared (how wrong the average fit is), plus variance (how much fits jump from sample to sample), plus the noise nobody can remove.” Simple models have high bias; flexible models have high variance; the best is in between.
🧠 Analogy: studying for an exam

Student A memorizes last year's answers word for word: 100% on the practice paper, lost on the real exam (overfitting, high variance). Student B learned one rule of thumb for everything: mediocre on both (underfitting, high bias). Student C learned the ideas: slightly imperfect on practice, good on the real thing. The real exam is the test set, and it only works if nobody has seen it in advance.

Train, validation, test, and cross-validation

Standard practice splits the data three ways. The training set sets the weights. The validation set chooses between models and settings (the degree, the learning rate). The test set is used once, at the very end, for the number you report. If you pick the degree by looking at test error, the test set has quietly become a validation set and your reported score is optimistic.

With little data, a single validation split is noisy. k-fold cross-validation splits the training data into k groups (“folds”), trains k times, each time holding out a different fold for validation, and averages the k scores. Every point gets to be validation data exactly once.

🎮 Playground · k-fold cross-validation picks the degree

The same 12 training points. Each row is one round: orange cells are held out for validation, blue cells are used for training. Run CV for the current degree, then for every degree, and see which one it picks, without ever touching the test points.

Cross-validation usually picks a degree close to the one with the lowest test error, using training data only. That's the point: you get an honest estimate for choosing models, and the test set stays clean for the final report.

Data leakage: when the test sneaks into training

Leakage is any way information from the test data reaches the model during training. It makes results look better than they are. Classic examples:

  • Standardizing features (Lesson 5.1) with the mean and std of the whole dataset before splitting. Fit the scaler on training data only.
  • The same patient, user or near-duplicate document in both training and test sets.
  • A feature that is only known after the outcome (predicting a loan default from “number of collection calls”).
  • For LLMs: benchmark questions that appear in the web data used for pretraining (contamination), as in the hook.
Plot twist Double descent: when huge models break the U-curve

Modern neural networks often have far more knobs than training examples, enough to fit the training data perfectly. The classic U-curve says they should overfit terribly. Yet they often generalize well.

Belkin and colleagues (2018) showed that if you keep increasing model size past the point where training error first hits zero, test error can go down again: a “double descent” curve. Among all the many ways to fit the data perfectly, training tends to find smooth ones. The U-curve is still the right picture for small models like our polynomials, and it's why validation sets remain essential for big ones.

🐍 In code 
import numpy as np
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import PolynomialFeatures, StandardScaler
from sklearn.linear_model import LinearRegression
X = np.random.uniform(-1, 1, (60, 1)); y = np.sin(3 * X[:, 0]) + 0.3 * np.random.randn(60)
X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25)   # lock the test set away
for d in [1, 3, 10]:
    model = make_pipeline(PolynomialFeatures(d), StandardScaler(), LinearRegression())  # scaler fit inside each fold: no leakage
    cv = cross_val_score(model, X_tr, y_tr, cv=5, scoring="neg_mean_squared_error")
    print(d, -cv.mean())                     # pick d with the lowest CV error; use X_te once at the end

🌍 Where it's used
Public vs private leaderboards 🏭 In production · 2015 Blum & Hardt: The Ladder (Kaggle leaderboards)

How: Kaggle splits a competition's hidden test set in two. One part scores the public leaderboard during the contest; the other, the private leaderboard, decides the final ranking after it ends.

Why this method: teams submit again and again and start to overfit the public part; the paper notes forum reports of public scores inflated compared with final ones. A never-seen private split keeps the final ranking honest.

Benchmark contamination in LLMs 🧠 LLMs · 2024 Zhang et al.: GSM1k

How: build a fresh test set matched to the old one (difficulty, number of steps, answer size), then compare scores. A big drop on the fresh set signals the model overfit the old one.

Why this method: you can't easily check whether test questions leaked into trillions of training tokens, but a brand-new test set can't have leaked. The paper also found many frontier models showed little sign of overfitting.

Leakage in published science 📊 Data science · 2022 Kapoor & Narayanan: Leakage and the Reproducibility Crisis

How: a survey found leakage errors in 17 fields, affecting 329 papers. In a deep dive on civil-war prediction, every paper claiming complex ML beat logistic regression failed to reproduce once leakage was fixed.

Why this method: a careful split (by time, by patient, scaler fit on training data only) is cheap; a leaked result can be wildly overoptimistic and mislead a whole field.

Double descent 🖼️ Deep learning · 2018 Belkin et al.: Reconciling modern ML practice and the bias–variance trade-off

How: plot test error against model size well past the point where the model fits the training data exactly: after the classic U, error falls a second time.

Why this method: it explains why giant networks trained to near-zero training error can still generalize, while keeping the classical U-curve as the small-model special case.

k-fold cross-validation 🤖 Machine learning · 2011 scikit-learn: cross-validation

How: cross_val_score(model, X, y, cv=5) trains 5 times on 4/5 of the data and scores on the remaining 1/5, for choosing models and hyperparameters.

Why this method: a single validation split wastes data and gives a noisy score; k folds use every example for both training and validation, and the spread of the k scores shows how much to trust the average.

🤯 Fun fact · fitting an elephant

In 1953 a young Freeman Dyson showed Enrico Fermi a theory that matched Fermi's data. Fermi asked how many free parameters it had. Four, said Dyson. Fermi quoted John von Neumann: “With four parameters I can fit an elephant, and with five I can make him wiggle his trunk.” In 2010, physicists actually drew an elephant using four (complex) parameters. Flexible models can fit anything, which is exactly why fitting the data proves nothing on its own.

🌉 AI bridge · overfitting everywhere

Deep learning: the standard cure kit is in Lesson 7.4: early stopping (stop training when validation error starts rising, the right side of the U), weight decay (the Gaussian prior of Lesson 5.4) and dropout.

RL & RLHF: a policy optimized hard against a learned reward model “overfits” the reward model's mistakes: the reward keeps rising while true quality falls. That's Goodhart's law, covered in RL Lesson 8.6: reward hacking & over-optimization.

LLMs: held-out evals, fresh benchmarks and contamination checks are this lesson applied at scale.

Check yourself

1. A model's errors on three test points are 1, −1 and 2. What is its test MSE?
Square each error: 1, 1, 4. Average: 6 ÷ 3 = 2. (0.67 is the plain average of the errors, where the −1 cancels a +1. Squaring stops that.)
2. You standardize all features using the mean and std of the full dataset, then split into train and test. What's wrong?
The mean and std contain information from the test rows. Fit the scaler on training data only, then apply it to test data (a scikit-learn Pipeline does this automatically, even inside each cross-validation fold).
3. Why do Kaggle competitions rank the final results on a private split that nobody sees during the contest?
Every resubmission is a peek at the public test data, so public scores drift upward. The private split plays the role of the true test set: used once, at the end.
📝 TL;DR
  • Overfitting: low training error, high test error (learned the noise). Underfitting: both high (too simple).
  • Test error ≈ bias² (too rigid) + variance (too jumpy) + noise; the best complexity is in the middle of the U-curve.
  • Split train / validation / test; use k-fold cross-validation to choose models; touch the test set once.
  • Beware leakage and benchmark contamination. Huge networks can show double descent, but validation still rules.
