Entropy: average surprise

One number for “how unpredictable is this?”. It sets the limit of compression, picks the questions in a decision tree, and keeps RL agents exploring.

🧰 You'll need (quick reminders)
  • Surprise of an outcome with probability p is −log₂ p bits: 1 bit for a coin flip (Lesson 6.1).
  • A distribution is a list of probabilities, one per outcome, adding up to 1 (Lesson 4.3).
  • An average weighted by probability is an expected value, 𝔼 (Lesson 4.4).
🎯 Hook

Ask a chatbot “Who wrote this obscure 1920s novel?” ten times. If it says the same author every time, it probably knows. If it names six different people, it's probably making things up.

A 2024 Nature paper turned that hunch into a hallucination detector by computing one number over the answers: their entropy. By the end of this lesson you'll compute it by hand.

Numbers first: two weather forecasts

In London, say, it's sunny half the days and rainy half the days. Every morning the forecast is a coin flip: 1 bit of news, every day.

In a desert, it's sunny 99% of days. Most mornings the forecast “sunny” is boring: −log₂ 0.99 ≈ 0.014 bits. Once in 100 days, “rain!” is a shock: −log₂ 0.01 ≈ 6.64 bits. On average?

0.99 × 0.014  +  0.01 × 6.64  ≈  0.014 + 0.066  =  0.08 bits per day

The desert's weather is much more predictable, so on average it tells you much less. That average surprise is called entropy.

H(p) = Σx p(x) · (−log₂ p(x)) = −Σx p(x) log₂ p(x) Read “H of p” (H for entropy). Σx means “add up over every outcome x”. For each outcome: how likely it is, times how surprising it is. Then add.
p(x): probability of outcome x−log₂ p(x): its surprise
💡 Big idea Entropy is the average surprise of a distribution, in bits. It's 0 when one outcome is certain and largest when all outcomes are equally likely: log₂ n bits for n outcomes. It measures how hard the next outcome is to guess.

🧠 Analogy: guessing a friend's order

One friend orders the same burger every single time: zero entropy, you can order for them. Another friend picks randomly from the whole menu: maximum entropy, no point guessing. Most people are in between: “usually pasta, sometimes pizza”. Entropy puts a number on where on that scale someone is.

✏️ Worked example: a four-letter alphabet

A message uses only A, B, C, D with probabilities ½, ¼, ⅛, ⅛. Surprises: 1, 2, 3, 3 bits.

H = ½·1 + ¼·2 + ⅛·3 + ⅛·3 = 0.5 + 0.5 + 0.375 + 0.375 = 1.75 bits per letter

Now a code: A = 0, B = 10, C = 110, D = 111. Each code is exactly as long as the letter's surprise. The average code length is ½·1 + ¼·2 + ⅛·3 + ⅛·3 = 1.75 bits, beating the obvious 2 bits per letter (00, 01, 10, 11). And no code can do better on average than the entropy. That's Shannon's source coding theorem.

Entropy is the floor for compression

A compressor gives common symbols short codes and rare symbols long ones, ideally about −log₂ p bits each. Then the average code length is about the entropy. Huffman coding builds such a code by repeatedly merging the two rarest symbols. Try it on your own text:

Huffman always lands at or just above the entropy, never below it. “aaaaaaab” has an entropy of only 0.54 bits per character; Huffman needs a whole 1 bit, because a code word can't be shorter than 1 bit. Eight different letters, each once, cost exactly 3 bits = log₂ 8: no pattern to exploit. Real compressors like ZIP beat this per-letter count by also using the context: a repeated word is replaced by a short pointer back to its first copy. The better you can predict each symbol from what came before, the lower its surprise. An LLM is, in that sense, a giant next-symbol predictor (Lesson 6.3).

Entropy picks the questions in a decision tree

A decision tree classifies by asking questions, like 20 questions. Which question should it ask first? The one that removes the most entropy from the labels.

10 emails: 5 spam, 5 not. Label entropy H = 1 bit. Split on “contains FREE”: one group has 4 spam + 1 normal, the other 1 spam + 4 normal. Each group has entropy H(0.8, 0.2) ≈ 0.722 bits. The drop, 1 − 0.722 = 0.278 bits, is the question's information gain. The tree tries every question and picks the biggest gain. (Lesson 6.5 shows this is the same as mutual information.) Lesson 8.1b grows whole trees this way, then boosts them.

Back to the hook: is the chatbot making it up?

Ask the novel question 10 times. If all 10 answers name the same author, the answer distribution is [1]: entropy 0 bits. Now suppose the 10 answers split 3 / 2 / 2 / 1 / 1 / 1 across six different names: probabilities 0.3, 0.2, 0.2, 0.1, 0.1, 0.1, surprises about 1.74, 2.32, 2.32, 3.32, 3.32, 3.32 bits.

H ≈ 0.3·1.74 + 2 × (0.2·2.32) + 3 × (0.1·3.32) ≈ 0.52 + 0.93 + 1.00 ≈ 2.45 bits

That's nearly as unpredictable as a fair 6-sided die (2.585 bits): a red flag. The Nature paper first groups answers that mean the same thing (“Twain” and “Mark Twain”), then takes the entropy over those groups, which it calls semantic entropy.

🐍 In code 
import numpy as np
def entropy(p):                  # in bits; skip zeros (0 · log 0 counts as 0)
    p = np.asarray(p, float); p = p[p > 0]
    return -(p * np.log2(p)).sum()
entropy([0.5, 0.5])                 # 1.0   a fair coin
entropy([1/6] * 6)                  # 2.585 a fair die = log2(6), the max
entropy([0.5, 0.25, 0.125, 0.125])  # 1.75  the worked example
# scipy.stats.entropy(p, base=2) does the same. A decision tree that splits by entropy:

🌍 Where it's used
Information gain picks each split 🤖 Machine learning · 1986 ID3 decision trees (Quinlan)

How: at each node, compute the label entropy before and after splitting on each feature, and split on the feature with the biggest drop (information gain). Its descendants C4.5 and today's criterion="entropy" option in scikit-learn use the same idea.

Why this method: plain “accuracy after the split” often can't tell two splits apart; entropy rewards any split that makes the groups purer, even a little, so the greedy tree-building has a smooth signal.

An entropy bonus keeps agents exploring 🎮 RL · 2016 A3C (Mnih et al.)

How: the policy's training objective gets + β · H(π), the entropy of its action probabilities (here β, “beta”, is just a small weight saying how much the bonus counts). The authors report that this improved exploration by discouraging early convergence to suboptimal, always-the-same policies. PPO and SAC use the same kind of bonus.

Why this method: without it, the policy quickly puts all its probability on whatever worked first (entropy → 0) and stops trying alternatives.

Semantic entropy flags hallucinations 🧠 LLMs · 2024 Farquhar et al., Nature (first version: Kuhn et al. 2023)

How: sample several answers to the same question, group the ones that mean the same thing, and compute the entropy of the group sizes. Many different meanings = high entropy = the model is probably making it up.

Why this method: plain token-level entropy is fooled by paraphrases (“Paris” vs “It's Paris”). Measuring entropy over meanings asks the real question: does the model keep changing its story?

The limit of lossless compression 📜 History · 1948 Shannon's source coding theorem

How: no lossless code can use fewer than H bits per symbol on average, and good codes (Huffman, arithmetic coding) get close. Every compressor, from ZIP to a neural-network-based one, lives above this floor.

Why this method: it tells engineers when to stop: if you're already near the entropy, no cleverness will shrink the file further.

🤯 Fun fact · a term paper beat the professor

In 1951, MIT students in Robert Fano's information theory class could skip the final exam by writing a term paper on finding the most efficient binary code. David Huffman, about to give up, hit on building the code tree from the two rarest symbols upward, and proved it optimal. It beat the method his professor had developed with Claude Shannon.

🌉 AI bridge · entropy as “how spread out”

RL: SAC adds α × entropy to the reward so the agent “succeeds while acting as randomly as possible”: RL course 6.2: Max-entropy RL (SAC). When RL fine-tunes an LLM, the policy's entropy often collapses and it stops exploring different solutions: RL course 8.7: Entropy collapse. Note that the RL course measures entropy in nats (with ln): a uniform choice over 6 options is ln 6 ≈ 1.79 nats = log₂ 6 ≈ 2.585 bits.

LLMs: the entropy of the next-token distribution is a live “how sure am I?” signal. Sampling temperature (Lesson 4.6) raises or lowers it.

Check yourself

1. A spinner lands on 4 colours, each with probability ¼. What is its entropy?
Each colour has surprise −log₂ ¼ = 2 bits, and the average of 2, 2, 2, 2 is 2. For n equally likely outcomes, H = log₂ n, and log₂ 4 = 2.
2. Which next-token distribution has the lowest entropy?
The model that's almost sure (97%) is the easiest to predict. Uniform over 4 gives the max, 2 bits; [0.5, 0.5, 0, 0] is a coin, 1 bit; [0.97, 0.01, 0.01, 0.01] is about 0.24 bits.
3. Why do RL algorithms like A3C, PPO and SAC add an entropy bonus to the policy's objective?
Rewarding entropy rewards spreading probability out. Without it, policy updates tend to pile everything on whatever worked first; with it, other actions keep getting tried and the agent can still discover something better.
📝 TL;DR
  • Entropy H(p) = −Σ p(x) log₂ p(x): the average surprise, in bits.
  • 0 when one outcome is certain; maximal (log₂ n) when all n outcomes are equally likely.
  • It's the floor for lossless compression: about H bits per symbol at best (Huffman gets close).
  • Used for decision-tree splits (information gain), exploration bonuses in RL, and LLM uncertainty (semantic entropy).
