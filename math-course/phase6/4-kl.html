Phase 6 · Lesson 4

KL divergence: distance between beliefs

How many extra bits does a wrong belief cost you? That one number is the leash in RLHF, the regularizer in VAEs, and the trust region in RL.

🧰 You'll need (quick reminders)
  • Entropy H(p) = average surprise if you know the true p; cross-entropy H(p, q) = average surprise if you believe q instead (Lessons 6.2, 6.3).
  • log(a / b) = log a − log b (Lesson 0.3).
  • A Gaussian is the bell curve, set by its centre μ (“mu”) and width σ (“sigma”) (Lesson 4.3).
🎯 Hook

When OpenAI trained InstructGPT with human feedback, the model was rewarded by a learned “judge” network. Optimized too hard, a model can learn to please the judge with text that humans find weird.

The fix was a leash: at every token, subtract 0.02 × “how differently do you now talk compared to the original model?”. That “how differently” is the KL divergence. It's one line of code, and it's in almost every RLHF recipe since.

Numbers first: the price of the wrong codebook

In Lesson 6.3 the letters came with p = ½, ¼, ⅛, ⅛, but we built our code for the wrong belief q = ⅛, ⅛, ¼, ½. We paid 2.625 bits per letter instead of the best possible 1.75 (the entropy). The waste:

H(p, q) − H(p) = 2.625 − 1.75 = 0.875 extra bits per letter

That waste is the Kullback–Leibler divergence. You can also compute it letter by letter: for each letter, log₂(p/q), weighted by how often it really appears.

½·log₂(½ ÷ ⅛) + ¼·log₂(¼ ÷ ⅛) + ⅛·log₂(⅛ ÷ ¼) + ⅛·log₂(⅛ ÷ ½) = ½·2 + ¼·1 + ⅛·(−1) + ⅛·(−2) = 0.875 ✔
DKL(p ‖ q) = Σx p(x) · log( p(x) / q(x) ) = H(p, q) − H(p) Read “the KL divergence from q to p”, or “KL of p relative to q”. The ‖ just separates the two; it is not the “given” bar | of Lesson 4.2. In words: the average extra surprise you suffer when reality is p but you believe q.
p: the reference / truthq: the approximation / model
💡 Big idea KL divergence measures how different two distributions are, in extra bits (or nats). It is never negative, it is 0 only when they're identical, and it is not symmetric: DKL(p ‖ q) and DKL(q ‖ p) are usually different numbers. So it's a “divergence”, not a true distance.

The “rules out” preset is the key danger: if q gives almost zero probability to something that p says happens, log(p/q) is huge, and DKL(p‖q) explodes. The other direction barely cares. Which direction you use changes what a model learns.

🧠 Analogy: packing for a trip

You pack for the weather you believe (q); the trip has the weather it has (p). Believe “it never rains” and get rain: miserable, and the misery is unbounded. Pack an umbrella for a place where it never rains: mildly wasteful. KL counts your average misery, and it's lopsided in exactly the same way: believing “impossible” about something that happens is the worst mistake.

✏️ Worked example: a lopsided coin, both ways

p = [0.9, 0.1] (a bent coin), q = [0.5, 0.5] (you think it's fair).

  • DKL(p‖q) = 0.9·log₂(0.9/0.5) + 0.1·log₂(0.1/0.5) ≈ 0.9·0.848 + 0.1·(−2.322) ≈ 0.763 − 0.232 = 0.531 bits.
  • DKL(q‖p) = 0.5·log₂(0.5/0.9) + 0.5·log₂(0.5/0.1) ≈ 0.5·(−0.848) + 0.5·2.322 = 0.737 bits.

Different numbers. Some terms are negative, but the total never is. In nats (using ln), the first one is 0.368.

Mode-seeking vs mass-covering

Here's where the asymmetry really matters. Suppose the truth p has two bumps (say, a model that can answer in two different styles), but your q is a single bell curve. Which single bell curve is “closest”? It depends on which KL you minimize:

  • DKL(p‖q) (“forward”): q is punished wherever p has mass and q doesn't. So q stretches to cover both bumps, even though that puts mass in the empty middle. This is what training with cross-entropy on data does.
  • DKL(q‖p) (“reverse”): q is punished wherever q has mass and p doesn't. So q hides inside one bump and ignores the other. Mode-seeking.

KL as a leash in RLHF

In RLHF the two distributions are the model being trained, π (“pi”, the policy), and the frozen original, πref. For one next-token choice with π = [0.7, 0.2, 0.1] and πref = [0.4, 0.4, 0.2]:

DKL(π‖πref) = 0.7·ln(0.7/0.4) + 0.2·ln(0.2/0.4) + 0.1·ln(0.1/0.2) ≈ 0.392 − 0.139 − 0.069 = 0.184 nats

The training reward becomes “reward-model score − β × KL”, where β (“beta”) is the price per nat of drift (0.02 in the hook), so drifting far from the original costs points. Note the order: the model sits first and the reference second, the opposite of the codebook example. That's the reverse KL from the bump game, so the penalty bites hardest when the policy puts probability on text the original model thought was nearly impossible: exactly the weird reward-hacking text.

🐍 In code 
import numpy as np
def kl(p, q):                                   # D_KL(p‖q) in nats
    p, q = np.asarray(p, float), np.asarray(q, float)
    m = p > 0                                     # terms with p = 0 contribute 0
    return (p[m] * np.log(p[m] / q[m])).sum()
kl([0.9, 0.1], [0.5, 0.5]), kl([0.5, 0.5], [0.9, 0.1])   # (0.368, 0.511): not symmetric

# RLHF-style per-token penalty (InstructGPT used beta = 0.02)
# logp_policy, logp_ref: log-probs of the tokens the policy actually sampled
# reward_per_token = -beta * (logp_policy - logp_ref)   # averages to -beta * KL(policy‖ref): a penalty

🌍 Where it's used
The KL leash in RLHF 🧠 LLMs · 2022 InstructGPT (Ouyang et al.)

How: PPO maximizes the reward model's score minus β · log(πRL(y|x) / πSFT(y|x)), a per-token KL penalty against the supervised model, with β = 0.02. The paper says the penalty is there to mitigate over-optimization of the reward model.

Why this method: the reward model is only trustworthy near the text it was trained on. Measuring drift with KL keeps the policy there, and keeps its fluency, without forbidding change outright.

The same KL objective, solved on paper 🧠 LLMs · 2023 DPO (Rafailov et al.)

How: DPO keeps RLHF's goal (high reward, small KL to the reference) but uses its closed-form solution, so the reward hides inside β · log(π/πref). Training becomes a simple classification-style loss on preference pairs.

Why this method: no separate reward model and no sampling from the model during training. The authors call it stable and lightweight, and report it matching or beating PPO-based RLHF on their tasks while being substantially simpler to implement.

Keeping a latent space tidy 🖼️ Deep learning · 2013 Variational autoencoders (Kingma & Welling)

How: the encoder maps each image to a small bell curve q(z|x) over a hidden code z. The loss is “reconstruction error + DKL(q(z|x) ‖ standard bell curve)”, and for two Gaussians that KL has a short closed-form formula.

Why this method: without the KL term every image could get its own isolated code; the KL pulls all codes toward one shared bell curve, so you can sample new images from it. Lesson 8.4b shows the μ + σ·ε sampling trick behind that.

A trust region measured in KL 🎮 RL · 2015 TRPO (Schulman et al.)

How: each policy update maximizes the improvement subject to “average KL between the old and new policy ≤ δ”, a small budget.

Why this method: a limit on parameter change (‖Δθ‖) says little about behaviour; a KL limit directly caps how much the action probabilities change, which keeps updates safe. PPO later approximated this with clipping.

🤯 Fun fact · born among codebreakers

Solomon Kullback and Richard Leibler introduced the divergence in 1951 as “the mean information for discrimination” between two hypotheses. Both were mathematicians and cryptanalysts who worked at the US National Security Agency.

Check yourself

1. Your cross-entropy H(p, q) is 2.3 bits and the entropy H(p) is 1.8 bits. What is DKL(p‖q)?
KL = cross-entropy − entropy = 2.3 − 1.8 = 0.5 extra bits per symbol. It can never be negative: no belief beats the truth.
2. Which statement about KL divergence is true?
KL ≥ 0, with 0 only for identical distributions. It's asymmetric (the bent-coin example gave 0.531 vs 0.737 bits), and the log(p/q) term blows up as q → 0 where p > 0.
3. Why does RLHF subtract β · KL(π ‖ πref) from the reward-model score?
The reward model is a learned judge with blind spots. The KL term is a leash: the policy may improve, but every bit of drift from the original model costs reward, so it stays where the judge is reliable. With β → ∞ it would copy πref; with β = 0 it would chase the judge's blind spots.
📝 TL;DR
  • DKL(p‖q) = Σ p log(p/q) = H(p, q) − H(p): the extra bits for believing q when the truth is p.
  • Always ≥ 0, = 0 only when identical, not symmetric, and infinite when q rules out something p allows.
  • Forward KL(p‖q) covers all of p's mass; reverse KL(q‖p) locks onto one mode.
  • Used as the RLHF leash (InstructGPT, β = 0.02), inside DPO, in VAEs and as TRPO's trust region.
