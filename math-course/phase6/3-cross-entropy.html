Phase 6 · Lesson 3

Cross-entropy & perplexity: the LLM loss

The price of believing the wrong probabilities. It's the loss every LLM and almost every classifier is trained on, and perplexity is how we report it.

🧰 You'll need (quick reminders)
  • Surprise = −log p; entropy H(p) = the average surprise (Lessons 6.1, 6.2).
  • Softmax turns any list of scores into probabilities that add up to 1 (Lesson 4.6).
  • ln = natural log; losses in code are in nats, and exp() undoes ln (Lesson 0.4).
🎯 Hook

Plot the training loss of a brand-new language model with a 50,000-token vocabulary, and the very first number is usually close to 10.8. Hours later it's around 2 or 3. Why 10.8, exactly?

Because a fresh model spreads its bets almost evenly over 50,000 tokens, and ln 50,000 ≈ 10.82. By the end of this lesson that number will feel obvious, and you'll know what a loss of 2 means in plain words.

Numbers first: the wrong codebook

Last lesson, letters A, B, C, D came with probabilities ½, ¼, ⅛, ⅛, and the best code (lengths 1, 2, 3, 3 bits) averaged 1.75 bits: the entropy.

Now suppose you built your code from the wrong belief. You thought the probabilities were ⅛, ⅛, ¼, ½, so you gave A and B the long codes (3 bits) and D the short one (1 bit). The real letters still arrive with ½, ¼, ⅛, ⅛:

½ × 3 + ¼ × 3 + ⅛ × 2 + ⅛ × 1 = 1.5 + 0.75 + 0.25 + 0.125 = 2.625 bits per letter

That's 0.875 bits per letter more than necessary. Cross-entropy is this number: the average surprise you actually suffer when the world follows p but you believe q.

H(p, q) = −Σx p(x) · log q(x) Read “the cross-entropy of q relative to p”, or just “H of p and q”. For each outcome: how often it really happens (p), times how surprised your belief q is by it (−log q). Add them up.
p: the truth / targetq: the model's probabilitiesH(p, q): the loss

If your belief is right (q = p), cross-entropy is just the entropy. Any other q costs more. So minimizing cross-entropy pushes q toward p: that's training.

The LLM case: one-hot targets

When an LLM reads “The capital of France is”, the training text says the next token is “Paris”. The target p puts probability 1 on “Paris” and 0 on everything else (a one-hot vector). Every term with p(x) = 0 vanishes, and the whole sum collapses to one term:

loss = −log q(correct token) “Minus the log of the probability the model gave the right answer.” That's the surprise from Lesson 6.1. Cross-entropy with a one-hot target is just the model's surprise at the truth.
💡 Big idea Cross-entropy = the average surprise of the truth under the model's beliefs. For a classifier or an LLM it's simply −ln q(correct answer), averaged over every example or token. Lowering it = giving the truth more probability.

The “uniform” preset gives each of 4 tokens 0.25, so the loss is ln 4 ≈ 1.386 nats. Scale that to 50,000 tokens and you get ln 50,000 ≈ 10.82: the hook's mystery number. A freshly initialized model is close to uniform, so that's where its loss starts.

🧠 Analogy: betting on horses

You have 100 chips to spread over the horses before a race. After the race, you only get to keep what you put on the winner, and your “pain” is −log(share on the winner). All-in on one horse and it wins: almost no pain. All-in and it loses: infinite pain. Spreading evenly: moderate pain, every time. Cross-entropy rewards betting in proportion to the real chances, which is exactly what we want a model to learn.

Perplexity: “how many tokens is it torn between?”

A loss in nats is hard to feel. So we undo the log: perplexity = eaverage loss. If the loss were ln 4 every time, the perplexity would be 4: the model is as unsure as if it were choosing uniformly among 4 tokens. And the hook's “loss of 2”? Perplexity e2 ≈ 7.4: on average the model is torn between about 7 equally likely next tokens, out of 50,000.

perplexity = exp( (1/N) Σt −ln q(tokent) ) “e to the power of the average per-token loss.” N is the number of tokens and the sum runs over every token t in the text. A perplexity of 20 means “on average, as torn as a fair 20-sided die”.
✏️ Worked example: a 4-token sentence

The model gave the true tokens of a sentence these probabilities: 0.6, 0.3, 0.05, 0.9.

  • Per-token losses: −ln 0.6 ≈ 0.511, −ln 0.3 ≈ 1.204, −ln 0.05 ≈ 2.996, −ln 0.9 ≈ 0.105 nats.
  • Average: (0.511 + 1.204 + 2.996 + 0.105) / 4 ≈ 1.204 nats per token. This is the number a training log prints.
  • Perplexity: e1.204 ≈ 3.33. On average the model was as torn as if picking among about 3 equally likely tokens.

One bad token (0.05) contributed more than half of the loss. Cross-entropy cares most about where the model was surprised.

Watch training push the loss down

Training adjusts the logits to lower the loss. For softmax + cross-entropy, the gradient (the “which way is uphill” arrow, Lesson 3.3) has a lovely simple form: q − p, the model's probabilities minus the target. So each step lowers the logits of tokens that got too much probability and raises the correct one's.

🎮 Playground · Mini training loop

Five candidate tokens, the target is “Paris”. All logits start at 0 (uniform). Each step does logits ← logits − η · (q − p). Turn on label smoothing and see where the loss stops.

Without smoothing, the loss heads toward 0 forever as q(Paris) → 1, which needs the logits to grow without limit. That's overconfidence. Label smoothing changes the target to 0.92 on Paris and 0.02 on each other token (ε = 0.1 spread over 5 tokens). Now the best possible loss is the entropy of that soft target (cross-entropy can't go below the target's own entropy, and equals it when q = p): 0.92·(−ln 0.92) + 4 × 0.02·(−ln 0.02) ≈ 0.077 + 4 × 0.078 ≈ 0.39 nats. The model stops pushing once it matches the soft target.

🐍 In code 
import numpy as np, torch, torch.nn.functional as F
p_true = np.array([0.6, 0.3, 0.05, 0.9])    # prob. the model gave each true token
loss = -np.log(p_true).mean()                   # 1.204 nats per token
np.exp(loss)                                    # perplexity 3.33

logits = torch.tensor([[2.0, 0.5, 0.1, -1.0]])  # 1 example, 4 classes: raw scores
target = torch.tensor([0])                        # index of the correct class
F.cross_entropy(logits, target)                  # softmax + (−log q[target]) in one stable call
F.cross_entropy(logits, target, label_smoothing=0.1)   # soft targets
🌍 Where it's used
Next-token cross-entropy = the pretraining loss 🧠 LLMs · 2020 Kaplan et al.: Scaling Laws

How: for every position in trillions of tokens of text, the target is the actual next token (one-hot) and the loss is −ln q(that token). The scaling-law paper studies how exactly this cross-entropy falls as a power law with model size, data and compute.

Why this method: minimizing cross-entropy is the same as maximum likelihood (Lesson 5.3): make the real text as probable as possible. It also needs no labels beyond the text itself.

Label smoothing for image classifiers 🖼️ Deep learning · 2015 Szegedy et al.: Rethinking the Inception Architecture

How: instead of a one-hot target over ImageNet's 1,000 classes, use (1 − ε) on the true class plus ε/1000 on every class, with ε = 0.1. The paper reports a consistent improvement of about 0.2% (absolute) in both top-1 and top-5 error.

Why this method: with one-hot targets the loss keeps rewarding ever-larger logits; a soft target gives the cross-entropy a finite best point, so the model stays less overconfident.

Knowledge distillation with soft targets 🏭 In production · 2015 Hinton, Vinyals & Dean: Distilling the Knowledge in a Neural Network

How: a small “student” model is trained with cross-entropy against the full probability list of a big “teacher” (softened with a higher softmax temperature), not just the one correct label. The paper used it to improve the acoustic model of a heavily used commercial speech system.

Why this method: a soft target carries much more information per example (“this 2 looks a bit like a 3”) than a one-hot label, so the student learns more from each example.

A good predictor is a good compressor 🧠 LLMs · 2023 Delétang et al.: Language Modeling Is Compression

How: feed a model's next-symbol probabilities to an arithmetic coder and each symbol costs about −log₂ q bits. So the compressed size is about the model's total cross-entropy on the data, in bits. Chinchilla 70B, trained mainly on text, compressed ImageNet image patches to 43.4% of their size, better than PNG's 58.5%.

Why this method: it turns “lower loss” into something concrete: every 0.1 nats less per token is a smaller file.

🤯 Fun fact · English is very predictable

Stored as plain text, each character costs 8 bits. But estimates of the true entropy of English text are only about 0.6 to 1.3 bits per character, because after “q” comes “u”, after “th” often comes “e”, and so on. A language model with low cross-entropy has learned exactly that predictability.

🌉 AI bridge · cross-entropy at every stage

LLMs: pretraining and supervised fine-tuning (SFT) both minimize next-token cross-entropy; SFT just uses curated example answers instead of the internet. The RL course shows how that fits the full recipe in 7.2: pretrain → SFT → RL.

RL: a policy-gradient update looks like a cross-entropy step on the action the agent took, multiplied by how good it turned out. Sums of token log-probabilities are the starting point of RL course 7.1: the LLM as a policy.

Next: cross-entropy minus entropy = the extra bits you pay for a wrong belief. That gap is the KL divergence (Lesson 6.4). The q − p gradient is derived in Lesson 8.2. Same gradient, new letters there: in this phase the target is p and the model q; from Lesson 8.1 on, the model is p and the target y, so it's written p − y.

Check yourself

1. A model gives the correct next token probability 0.25. What is its cross-entropy loss on that token, and what is the perplexity?
With a one-hot target the loss is −ln q(correct) = −ln 0.25 = ln 4 ≈ 1.386. Perplexity = e1.386 = 4: as torn as choosing among 4 equally likely tokens.
2. Model A's validation perplexity is 12, model B's is 20, on the same text and tokenizer. Which predicts better?
Lower perplexity = lower average cross-entropy = less surprise at the real text. (Comparing across different tokenizers is unfair, because the “per token” unit changes.)
3. Why does knowledge distillation train the student on the teacher's full probability list instead of only the correct label?
Cross-entropy works with any target distribution. A teacher saying “80% dog, 15% wolf, 5% cat” tells the student that dogs look like wolves, something a one-hot “dog” label never says.
📝 TL;DR
  • Cross-entropy H(p, q) = −Σ p log q: the average surprise when the truth is p but you believe q. It's never below H(p).
  • With a one-hot target it's just −ln q(correct): the LLM / classifier loss.
  • Perplexity = eaverage loss = “how many equally likely tokens the model is torn between”. Lower is better.
  • The gradient with respect to the logits is q − p. Label smoothing and distillation swap in soft targets.
