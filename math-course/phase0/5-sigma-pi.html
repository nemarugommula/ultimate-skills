Σ and Π: reading math like code

Σ means “add them all up” and Π means “multiply them all together”. Both are just for-loops, and they're in the loss function of every model you'll ever train.

🧰 You'll need (quick reminders)
  • Logs turn multiplying into adding: ln(a × b) = ln a + ln b (Lesson 0.3), and ln is the log with base e (Lesson 0.4).
  • The mean squared error = the average of the squared misses (Lesson 0.1).
  • A Python for-loop: for i in range(3): runs with i = 0, 1, 2.
🎯 Hook

OpenAI's first GPT paper (2018) states the whole training goal of its language model in one line:

L₁(U) = Σi log P(ui | ui−k, …, ui−1; Θ)

It looks like hieroglyphs. It's actually a for-loop with a running total, about 3 lines of Python. By the end of this lesson you'll read it out loud.

Subscripts: numbering the items in a list

Say you have the list of numbers [3, 1, 4, 1, 5]. Math names the items with small numbers written low, called subscripts:

x₁ = 3   x₂ = 1   x₃ = 4   x₄ = 1   x₅ = 5

Read x₂ as “x sub 2”: item number 2. When the subscript is a letter, xi (“x sub i”), it means “item number i”, where i is a counter that will run through 1, 2, 3, … just like a loop variable. One trap: math usually starts counting at 1, Python at 0. So x₁ in a paper is x[0] in code.

Σ: add them all up

Add the list: 3 + 1 + 4 + 1 + 5 = 14. Writing “+” between a million items is impossible, so math uses the Greek capital letter sigma (S for “sum”):

Σi=1n xi = x₁ + x₂ + … + xn “The sum, for i from 1 to n, of x sub i.” Bottom: where the counter starts (i = 1). Top: where it stops (n, the number of items). Right: what to add each time. For our list, n = 5 and the sum is 14.

In Python that's exactly:

total = 0                       # start the running total at 0
for i in range(1, n + 1):        # i = 1, 2, ..., n   (bottom and top of the Σ)
    total += x[i - 1]             # add item i  (Python counts from 0)

Sometimes the top and bottom are left off, as in Σi or just Σ. That means “over all the items”. The thing on the right can be any recipe: Σ xi² adds up the squares, 9 + 1 + 16 + 1 + 25 = 51.

Averages, hats and bars

The average (mean) is the sum divided by how many there are: 14 / 5 = 2.8.

x̄ = (1/n) Σi=1n xi “x bar equals one over n times the sum of the x's.” A bar on top means “the average of”.

A hat means “a prediction or estimate”: ŷ (“y hat”) is what the model guessed, y is the truth. Now the error from Lesson 0.1 fits on one line:

MSE = (1/n) Σi=1n (ŷi − yi)² “The mean squared error is one over n times the sum, over every example i, of (prediction minus truth) squared.” Loop over the examples, square each miss, add, divide by n.

Π: multiply them all together

Three independent things must all happen: chances 0.5, 0.2 and 0.1. The chance that all three happen is 0.5 × 0.2 × 0.1 = 0.01. For “multiply them all” math uses the Greek capital pi (P for “product”):

Πi=1n pi = p₁ × p₂ × … × pn “The product, for i from 1 to n, of p sub i.” Same loop as Σ, but the running total starts at 1 (not 0) and uses × instead of +. This Π has nothing to do with π = 3.14159…

And here's the payoff from Lesson 0.3: the log of a product is the sum of the logs. So ln Π pi = Σ ln pi. Every Π of probabilities in AI gets turned into a Σ of log-probabilities, so it never underflows.

💡 Big idea Σ is a loop that adds (start at 0), Π is a loop that multiplies (start at 1). The subscript is the loop counter. Once you see that, most formulas in AI papers become “loop over the data, compute something, add it up, maybe divide by n”.
🧠 Analogy: the receipt and the chain

Σ is a shopping receipt: one line per item, and the total at the bottom. Π is a chain: it holds only if every link holds, so one weak link (a probability near 0) drags the whole thing down, and a single 0 breaks it completely.

That last one is a preview: in matrix multiplication (Lesson 2.2), every entry of the answer is a Σ, and computing all of them is a loop inside a loop.

Read a real loss function

Back to the hook. A language model reads “The cat sat on the mat” and, at each position, gives some probability to the token that really came next. The training loss is the average surprise:

L = −(1/N) Σi=1N ln pi “L equals minus one over N times the sum, over each of the N tokens, of the log of the probability the model gave to the right token.” The minus sign makes it positive (logs of probabilities are negative), so smaller L = better model.
🎮 Playground · Compute a language model's loss

Each slider is the probability the model gave to the correct next token. Watch the Σ, the Π and the loss together. Try “one bad guess”: one confident mistake hurts a lot. (The sliders use a log scale, so tiny probabilities are reachable.)

Notice the three views agree: the Π is the probability of the whole sentence, the Σ of logs is its log, and the loss is that log divided by −N. GPT-1's formula from the hook is the same Σ: P(ui | ui−k, …, ui−1; Θ) reads “the probability of token i, given (the bar “|”) the k tokens before it, using the model's knobs Θ (“theta”)”. They maximize the sum of logs; we minimize minus its average. Same thing.

🐍 In code 
import numpy as np
x = np.array([3, 1, 4, 1, 5])
x.sum(), x.mean(), (x ** 2).sum()           # Σx = 14, x̄ = 2.8, Σx² = 51
p = np.array([0.5, 0.2, 0.1])
p.prod(), np.log(p).sum()                  # Π = 0.01, Σ ln p = -4.605
loss = -np.log(p).mean()                   # -(1/N) Σ ln p = 1.535

A, B = np.random.rand(2, 3), np.random.rand(3, 4)
C = [[sum(A[i, k] * B[k, j] for k in range(3)) for j in range(4)] for i in range(2)]
np.allclose(C, A @ B)                      # True: matrix multiply = nested Σ (Lesson 2.2)
🌍 Where it's used
Σ of log-probabilities: the GPT training goal 🧠 LLMs · 2018 Radford et al.: Improving Language Understanding by Generative Pre-Training (GPT-1)

How: equation 1 of the paper is L₁(U) = Σi log P(ui | previous k tokens; Θ): loop over every token in the training text, add the log of the probability the model gave it, and train Θ to make that sum as big as possible.

Why this method: the probability of the whole text is a Π over tokens; taking the log turns it into a Σ that doesn't underflow and splits neatly into one term per token, so it can be computed in parallel.

Π of word probabilities: spam filters 🤖 Machine learning · 2002 Paul Graham: A Plan for Spam

How: each word has a learned “spam probability”. For a new email, the 15 most telling words are combined with a product: Π pi / (Π pi + Π (1 − pi)). His code literally multiplies the list of probabilities.

Why this method: treating words as independent clues means their evidence multiplies, a simple version of Bayes' rule (Lesson 4.2) that worked very well in practice.

Σ with discounting: an agent's return 🎮 RL · 2013 DQN: Playing Atari with Deep Reinforcement Learning

How: the paper scores a game from now on by its discounted return: the next reward, plus γ (“gamma”, e.g. 0.9) times the one after, plus γ² times the one after that, and so on. Counting rewards from r₁, that's G = r₁ + γ·r₂ + γ²·r₃ + … = Σt γt−1 rt: loop over the time steps, shrink each reward by γ (Lesson 0.4) once per step of delay, add up. Try it with the Σ γi−1 xi button above.

Why this method: one number summarizes a whole future of rewards, so the agent can compare actions by comparing a single sum.

(1/n) Σ: scoring an image classifier 🖼️ Deep learning · 2012 AlexNet (Krizhevsky et al.)

How: an error rate is (1/n) Σ missi, where missi is 1 if picture i was classified wrongly and 0 if right. AlexNet's “top-5 error” on the ImageNet 2010 test set was 17.0%: the true label wasn't among its 5 best guesses for 17.0% of the test images.

Why this method: averaging (1/n) makes the score independent of how many pictures are tested, so results on test sets of different sizes can be compared with one number.

🤯 Fun fact · Σ is over 270 years old

The capital sigma for sums appears in a 1755 book by Leonhard Euler, and Joseph-Louis Lagrange picked it up in 1772. A handy way to remember the pair: Σ is the Greek capital S, as in “sum”, and Π is the Greek capital P, as in “product”.

🌉 AI bridge · loops in disguise

Deep learning & LLMs: every neuron is a Σ (the dot product, Lesson 1.3), every layer is a nested Σ (Lesson 2.2), the probability of a sentence is a Π over tokens (Lesson 4.5), and training maximizes a Σ of log-probabilities (Lessons 5.3 and 6.3).

RL: Monte Carlo methods estimate how good a situation is by playing it many times and averaging the returns, (1/n) Σ: see the RL course's Lesson 3.1: Monte Carlo.

Check yourself

1. What is Σi=14 2i?
Loop i = 1, 2, 3, 4 and add 2i each time: 2 + 4 + 6 + 8 = 20. (384 = 2 × 4 × 6 × 8 is what Π would give.)
2. What is Πi=13 xi for x = [2, 0, 5]?
2 × 0 × 5 = 0. One zero breaks the chain. That's why a model that gives the right token probability 0 gets an infinite loss: ln 0 doesn't exist.
3. Training losses are usually written with (1/N) Σ, an average, rather than a plain Σ. Why?
A plain Σ over 1,000 examples is about 10× bigger than over 100, even for the same model. Dividing by N gives a per-example score you can compare across batch sizes and datasets.
📝 TL;DR
  • xi = item i of a list (math counts from 1, Python from 0).
  • Σ = for-loop that adds (start 0). Π = for-loop that multiplies (start 1). ln Π = Σ ln.
  • Mean = (1/n) Σ; ŷ = prediction; MSE = (1/n) Σ (ŷi − yi)².
  • LLM loss = −(1/N) Σ ln pi; RL return = Σ γt−1 rt; nested Σ = matrix multiplication.
