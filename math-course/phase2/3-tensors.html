Tensors, shapes & broadcasting

Vectors and matrices grow into “tensors”: boxes of numbers with any number of sides. Reading their shapes is the everyday skill behind every line of PyTorch and NumPy.

🧰 You'll need (quick reminders)
  • A vector is a list of numbers, like [3, 1, 2] (Lesson 1.1).
  • A matrix is a grid with rows and columns; “2×3” means 2 rows, 3 columns (Lesson 2.1).
  • The shape rule: (m×n)·(n×p) → (m×p); the inside numbers must match (Lesson 2.2).
🎯 Hook

Every deep-learning programmer has seen this message:

RuntimeError: mat1 and mat2 shapes cannot be multiplied (64x784 and 512x10)

It isn't a bug in the math. It's a shape mistake: someone tried a (64×784)·(512×10) product, and 784 ≠ 512. After this lesson you'll read that line like a sentence, and predict shapes before you run the code.

Numbers first: the shape ladder

A tensor is just a box of numbers arranged along some number of directions, called axes. Its shape lists how many numbers there are along each axis. Climb the ladder:

🔢

A number

shape ()

7. Zero axes, called a scalar.

➡️

A vector

(3,)

[3, 1, 2]. One axis.

🔲

A matrix

(2, 3)

2 rows × 3 columns. Two axes.

🖼️

A color image

(3, 224, 224)

Red, green, blue layers, each 224×224 pixels.

📚

A batch of images

(32, 3, 224, 224)

32 photos at once. Four axes.

How many numbers are inside? Multiply the shape: 32 × 3 × 224 × 224 = 4,816,896. That's one batch going into an image classifier.

Text models use a three-axis shape: (batch, sequence, d_model). A batch of 8 texts, 1,024 tokens each, every token a vector of 768 numbers (the size used by GPT-2 small): shape (8, 1024, 768), which is 8 × 1024 × 768 = 6,291,456 numbers flowing between layers.

Naming trap: some libraries call the number of axes a tensor's “rank”. That's unrelated to the matrix rank of Lesson 2.4. In this course “rank” means the Lesson 2.4 idea; we say “number of axes” here.

💡 Big idea A tensor's shape is its job description: which axis is the batch, which is time, which is features. Most tensor operations are bookkeeping on the shape (reshape, transpose, sum over an axis), and the rest are matrix multiplications on the last two axes.

Four moves that change shapes

  • Reshape: same numbers, new arrangement. The product of the shape must stay the same. [1, 2, 3, 4, 5, 6] with shape (6,) → reshape(2, 3) → [[1, 2, 3], [4, 5, 6]] (filled row by row). Writing −1 means “work this one out for me”.
  • Transpose (written ᵀ or .T): swap two axes. A (3, 5) matrix becomes (5, 3): rows become columns.
  • Sum (or mean) over an axis: that axis disappears. (8, 1024, 768).sum(axis=1) adds up all 1,024 tokens → (8, 768).
  • Matmul on stacks: (32, 10, 64) @ (32, 64, 10) → (32, 10, 10). The first axis is a batch: 32 separate (10×64)·(64×10) products at once.

Broadcasting: let the small one stretch

Adding a bias to a whole batch: the batch has shape (4, 3) (4 inputs, 3 features each) and the bias has shape (3,). You want the same bias added to every row. NumPy and PyTorch do this automatically, by broadcasting:

Line the shapes up from the right. Each pair must be equal, or one of them must be 1 (or missing). A size-1 (or missing) axis is stretched by copying, so (4, 3) + (3,) → (4, 3), and (3, 1) + (1, 4) → (3, 4). But (4, 3) + (4,) is an error: lined up from the right, 3 meets 4.
✏️ Worked example: broadcasting by hand

[[1, 2, 3], [4, 5, 6]] has shape (2, 3). Add [10, 20, 30], shape (3,).

  • Line up from the right: 3 meets 3 ✓. The left axis (2) is missing in the bias, so the bias is copied onto both rows.
  • Row 1: [1 + 10, 2 + 20, 3 + 30] = [11, 22, 33]. Row 2: [4 + 10, 5 + 20, 6 + 30] = [14, 25, 36].
  • Now try [10, 20] (shape (2,)): 3 meets 2 ✗, error. To add one number per row, make it a column, shape (2, 1).

Broadcasting is why one line of code adds a bias to 32 images, normalizes every color channel of a batch with a (3, 1, 1) tensor, or builds a whole table from a column and a row. It's also why a mistake can silently broadcast into a shape you didn't want, so print shapes often.

🧠 Analogy: egg cartons and a rubber stamp

One egg is a scalar. A row of eggs is a vector. A carton (rows × columns) is a matrix. A stack of cartons is a 3-axis tensor, a pallet of stacks is 4 axes. The shape is the label on the box: “32 stacks × 3 cartons × 224 rows × 224 eggs”.

Broadcasting is a rubber stamp: you carve one row (the bias) and stamp it onto every row of the carton. You never carve 32 copies.

The transformer's favorite reshape: splitting heads

Attention (Lesson 8.4) runs several “heads” side by side, each looking at its own slice of each token vector. GPT-2 small has 768 numbers per token and 12 heads, so each head gets 768 / 12 = 64. The split is pure shape bookkeeping:

(8, 1024, 768)  → view → (8, 1024, 12, 64)  → transpose(1, 2) → (8, 12, 1024, 64)

Now the heads sit on their own axis, and one batched matmul handles all 8 × 12 = 96 (text, head) pairs at once. No numbers changed; only the label on the box.

🐍 In code 
import numpy as np, torch
imgs = np.zeros((32, 3, 224, 224))            # (batch, channels, height, width)
imgs.shape, imgs.size                        # ((32, 3, 224, 224), 4816896)
mean = np.array([0.5, 0.4, 0.3]).reshape(3, 1, 1)
(imgs - mean).shape                          # broadcasting: one mean per color channel

x = torch.randn(8, 1024, 768)                  # (batch, sequence, d_model)
heads = x.view(8, 1024, 12, 64).transpose(1, 2)
heads.shape                                  # torch.Size([8, 12, 1024, 64])
(heads @ heads.transpose(-2, -1)).shape        # [8, 12, 1024, 1024]: every token vs every token
🌍 Where it's used
Image batches as 4-axis tensors 🖼️ Deep learning · 2012 AlexNet

How: AlexNet's first layer reads a 224 × 224 × 3 input image. Today PyTorch's Conv2d expects inputs shaped (N, C, H, W): batch, channels, height, width. Lesson 8.3b shows what Conv2d does with them.

Why this method: one fixed layout means every layer knows which axis is which, and the batch axis lets the GPU process many photos in one go (Lesson 2.2).

Splitting attention heads with reshape 🧠 LLMs · 2017 Attention Is All You Need

How: the original transformer used d_model = 512 and h = 8 heads, so each head works on 512 / 8 = 64 numbers. In code this is the view + transpose above.

Why this method: the paper notes that because each head is smaller, the total cost is similar to one full-size attention, while each head can look for different things.

Broadcasting 📊 Data science · 2020 Array programming with NumPy (Harris et al., Nature)

How: the NumPy paper describes broadcasting as arrays being “virtually duplicated” to match shapes, without copying data in memory. Subtracting a column mean from a whole table is one line: X - X.mean(axis=0).

Why this method: no Python loops and no wasted copies, so data-science code is short and fast. PyTorch follows the same rules.

The (seq × seq) attention tensor 🧠 LLMs · 2022 FlashAttention

How: attention scores have shape (batch, heads, seq, seq), so doubling the text length quadruples them. FlashAttention computes the same exact result in small tiles, cutting reads and writes to the GPU's main memory.

Why this method: reading the shape tells you where the cost explodes. FlashAttention avoids ever storing that huge tensor in slow memory, instead of approximating attention.

A state made of stacked frames 🎮 RL · 2013 DQN: Playing Atari with Deep RL

How: the DQN network's input is an 84 × 84 × 4 tensor: the last 4 grayscale frames of the game stacked along one axis.

Why this method: one frame can't show which way the ball moves; stacking frames on a new axis gives the network motion at almost no extra cost.

🤯 Fun fact · half a billion scores per layer

Take a model with 32 heads reading 4,096 tokens. One layer's attention scores have shape (32, 4096, 4096): that's 32 × 4,096 × 4,096 = 536,870,912 numbers, for a single text. At 2 bytes per number, about 1.07 GB. That one shape is why long context windows are hard, and why tricks like FlashAttention exist.

Check yourself

1. x has shape (2, 3, 4). x.reshape(6, ?) works only if ? is…
x holds 2 × 3 × 4 = 24 numbers. A reshape keeps all of them, so 6 × ? = 24, and ? = 4. Writing reshape(6, −1) asks NumPy to work out that 4 for you.
2. What shape is (5, 1) + (1, 3)?
Line up from the right: 1 meets 3 (the 1 stretches to 3), 5 meets 1 (the 1 stretches to 5). Result (5, 3): every row value plus every column value, a full table.
3. Why does transformer code reshape (batch, seq, 768) into (batch, 12, seq, 64)?
12 × 64 = 768: nothing is lost, the numbers are just relabeled. Putting heads on their own axis turns “12 separate attentions” into one batch, which is exactly what GPUs are fast at.
📝 TL;DR
  • A tensor is a box of numbers; its shape lists the size of each axis. Number of entries = product of the shape.
  • Images: (N, C, H, W). Text: (batch, seq, d_model). Attention heads: (batch, heads, seq, d_head).
  • Reshape keeps the count; transpose swaps axes; summing over an axis removes it; matmul uses the last two axes.
  • Broadcasting: align from the right; sizes must match or be 1, and 1s stretch.
