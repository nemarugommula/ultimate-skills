Recap: Training a network

Losses, backprop, the PyTorch loop, initialization, optimizers, the learning rate and batch size: everything that happens between “here's a network” and “here's a trained network”. The phase on one page, a game where you diagnose real training runs from their loss curves, and a training recipe to design yourself.

🧾 Cheat sheet

🎯

1.1 Losses

Classes → cross-entropy on logits: push = p − y. Regression → MSE; outliers → Huber. Know-nothing loss = ln K.

MSE behind a sigmoid has a σ′ that vanishes when confidently wrong (25× weaker at p = 0.02). Label smoothing ε = 0.1 stops logits growing forever.

🧰 nn.CrossEntropyLoss(label_smoothing=…), nn.BCEWithLogitsLoss, nn.HuberLoss

🔁

1.2 Backprop & autograd

gradient = local derivative × upstream; add copies, multiply swaps, ReLU gates. All gradients ≈ 2–3 forward passes.

Reverse mode needs one sweep for one loss and a billion weights; nudging needs two passes per weight. The price is storing activations. .grad accumulates.

🧰 requires_grad, loss.backward(), torch.no_grad(), autograd.gradcheck

🔧

1.3 The PyTorch loop

forward → loss → zero_grad → backward → step. Linear(in, out) has in·out + out parameters.

Labels int64 (B,), logits (B, K); no softmax before CrossEntropyLoss; shuffle; train()/eval() and no_grad() are independent. Check loss at step 0.

🧰 nn.Module, nn.Sequential, DataLoader, torch.optim

🎲

1.4 Initialization

Random (symmetry!), with each layer's variance factor n·Var(w)·(½ for ReLU) ≈ 1. He: 2/nin. Xavier: 2/(nin + nout).

Factors raised to the depth explode or vanish. PyTorch's Linear default is uniform ±1/√nin, not He. Residual branches start small (GPT-2: 1/√N) or at zero.

🧰 nn.init.kaiming_normal_, xavier_uniform_, orthogonal_

🏃

1.5 Optimizers

AdamW: lr 3e-4 to 1e-3, β₂ 0.95 at scale, weight decay ≈ 0.1 (not on biases/norms). 16 bytes/param in fp32.

Momentum averages away the zig-zag; Adam divides by each weight's typical gradient; the W decouples decay so every weight shrinks by lr·λ. Muon for matrices is the 2026 challenger.

🧰 torch.optim.AdamW, SGD(momentum=0.9), torch.optim.Muon (2.9+)

📈

1.6 Learning rate

Search on a log scale (or a range test); the best sits just below the cliff. Warmup ~1–5% of steps, cosine to ~10% (or WSD).

Warmup protects the unsettled start (RAdam: loss 3 vs ~10 without it); decay lets noisy runs settle (20× in our replay). Llama 3: 8,000 warmup steps, cosine over 1.2M.

🧰 lr_scheduler.LambdaLR, CosineAnnealingLR, OneCycleLR

📦

1.7 Batch size

Noise ∝ 1/√B. SGD: batch × k → lr × k with gradual warmup. Critical batch ≈ noise scale tr(Σ)/|G|², and it grows.

ResNet-50 at batch 8,192: 1 hour on 256 GPUs at small-batch accuracy. Past the critical batch, more parallelism buys nothing. Accumulate micro-batches with loss ÷ k.

🧰 DataLoader(batch_size=…), loss / accum, model.no_sync()

🗣️ Teach it back

Answer out loud, like in an interview: “Walk me through exactly what happens in one training step of a classifier in PyTorch, from the batch coming out of the DataLoader to the weights changing. Then: the loss is flat at 0.693 for the first thousand steps. What are the first three things you check?”

A strong answer covers: a shuffled mini-batch; the forward pass recording a graph; logits into CrossEntropyLoss (log-softmax + negative log-likelihood, push p − y); zero_grad because .grad accumulates; backward as one reverse sweep of local derivative × upstream; the optimizer step (AdamW: momentum, per-weight scaling, decoupled decay) with the scheduled lr. For the flat 0.693 (ln 2: the model knows nothing): check the learning rate (too high kills ReLUs, too low crawls; run a range test), the initialization and activation statistics per layer (vanishing signal, dead units), and the plumbing (labels and shapes, shuffling, softmax before the loss, zero_grad placement), then try overfitting one small batch (Lesson 2.6).

🏗️ Build it yourself: a fraud detector's training recipe

✏️ The problem

A payments company has 2 million labelled card transactions, each with 40 numeric features (already standardized). About 1% are fraud. The rows are stored in time order. You'll train a small MLP on one GPU with 8 GB of memory.

Using only this phase's ideas, write down: the architecture and its parameter count, the output layer and loss, the initialization (including the final bias), the optimizer and its settings, the batch size and steps per epoch, the learning-rate schedule, the loss you expect at step 0, and the pitfalls you'll guard against. Then open the reveal.

Reveal: one good answer

Architecture and shapes

  • 40 → 256 → 256 → 1 with ReLU: Linear(40, 256) = 10,240 + 256 = 10,496; Linear(256, 256) = 65,536 + 256 = 65,792; Linear(256, 1) = 257. Total 76,545 parameters.
  • Memory with AdamW (16 bytes/param): about 1.2 MB. Activations for a batch of 1,024: 1,024 × 513 × 4 bytes ≈ 2.1 MB. Memory is not the constraint; the GPU is idle-cheap.
  • Shapes: x (B, 40) float32; logits (B, 1); targets (B, 1) float32, not (B,), or MSE-style broadcasting bites (Lesson 1.3).

Loss and initialization

  • One sigmoid output, nn.BCEWithLogitsLoss on raw logits (Lesson 1.1); no sigmoid layer in the model. Optionally pos_weight to up-weight the rare fraud class.
  • He (Kaiming) init for the ReLU layers (Lesson 1.4). Set the final bias to ln(0.01/0.99) ≈ −4.6 so the model starts out predicting the 1% base rate.
  • Expected loss at step 0: with that bias, about −(0.01 ln 0.01 + 0.99 ln 0.99) ≈ 0.056. With a zero bias it would be about ln 2 = 0.693, and the first hundreds of steps would only be learning the base rate.

Optimizer, batch and schedule

  • AdamW, peak lr 1e-3, weight decay 0.01 on the weight matrices only (Lesson 1.5); confirm the peak with a quick range test or a 3-point sweep (3e-4, 1e-3, 3e-3).
  • Batch 1,024 (each batch then holds ~10 frauds on average): 2,000,000 / 1,024 ≈ 1,953 steps per epoch; 10 epochs ≈ 19,531 steps.
  • Linear warmup over ~200 steps (1%), cosine decay to 10% of the peak (Lesson 1.6). If you later move to batch 8,192, scale the lr and lengthen the warmup (Lesson 1.7; re-tune, since this is Adam).

Pitfalls to guard against

  • Rows are in time order: split train/validation by time (validate on the latest weeks), then shuffle within the training set (Lesson 1.3).
  • Accuracy is useless here: predicting “never fraud” scores 99%. Track precision/recall or PR-AUC (math 5.6b).
  • The silent loop bugs: sigmoid before the loss, missing zero_grad, (B,) vs (B, 1), forgetting model.train() after evaluation.
  • Log the lr, the loss at step 0 and the per-layer activation stats in the first run.

What this recipe doesn't cover yet: regularization against overfitting (dropout, weight decay tuning, early stopping, Lesson 2.4), normalization layers (2.3), gradient clipping (2.1) and a systematic debugging routine (2.6). That's Phase 2. For tabular data, a gradient-boosted tree baseline is worth comparing against (math 8.1b).

🏆 Boss quiz

1. A 10-class classifier is freshly initialized and guesses uniformly. What cross-entropy loss should it print on step 0?
Uniform guessing gives the right class probability 1/10, so the loss is −ln(1/10) = ln 10 = 2.303 (Lesson 1.1). 0.69 = ln 2 is the two-class value. If your 10-class model starts far from 2.3, check the final layer's initialization and the loss wiring.
2. A ReLU layer has 2,048 inputs. What weight std does He initialization give, and what does PyTorch's nn.Linear default give?
He: Var = 2/n → std = √(2/2,048) = 0.03125. The default is uniform on ±1/√2,048, whose std is (1/√2,048)/√3 = 1/√6,144 ≈ 0.0128, about 2.4× smaller, so each ReLU layer multiplies the variance by about 1/6 (Lesson 1.4).
3. You move an SGD training run from batch 256 to batch 2,048 and multiply the lr by 8. The loss becomes NaN within the first 50 steps. What's the standard fix?
The linear scaling rule assumes consecutive gradients are similar, which fails early when the network changes fast. Goyal et al. fixed exactly this with a 5-epoch gradual warmup to the scaled lr; without it their batch-8k error was 24.84% vs 23.74% with it (Lessons 1.6 and 1.7).
4. How much memory do weights + gradients + AdamW state take for a 7-billion-parameter model in float32?
4 bytes each for the weight, its gradient, and AdamW's m and v: 16 bytes × 7 × 10⁹ = 112 GB, before activations (Lessons 1.3 and 1.5). That's why Phase 10 covers mixed precision and sharding the optimizer state across GPUs.
5. A loop runs loss.backward(), then opt.zero_grad(), then opt.step(). The loss never moves. Why?
zero_grad must come anywhere before backward. Between backward and step it wipes the fresh gradient (by default it sets .grad to None, so the optimizer skips those parameters entirely). No error, a flat loss: a perfect silent bug (Lesson 1.3).
