Phase 1 · Lesson 4

Initialization: why random, why Xavier and He

Before step 1, every weight needs a starting value. Start them all at zero and the network can never learn. Start them a little too big or a little too small and a 10-layer network is dead on arrival. The fix is one number: the right spread.

🧰 You'll need (quick reminders)
  • The gradient reaching layer 1 is a product of one factor per layer (Lessons 0.4 and 1.2).
  • Variance is the average squared distance from the mean; standard deviation (std) is its square root (math 4.4). For independent things, variances add.
  • tanh saturates for |z| > 2; ReLU outputs 0 for about half of its inputs (Lesson 0.4).
🎯 Hook

In 2015, Kaiming He and colleagues trained a 30-layer ReLU network for ImageNet twice. Same architecture, same data, same optimizer. With the then-standard “Xavier” initialization it completely stalled: they checked and its gradients were all diminishing, and more epochs didn't help. With their new initialization, which differs by essentially a factor of √2 in the weights' spread, it converged.

Who uses this: every nn.Linear and nn.Conv2d you create is initialized by one of these rules, and open LLM training code in 2026 still hand-picks how every residual layer starts. Why would the starting spread of random numbers decide whether a network can learn at all? You're about to kill a 10-layer network three different ways, then save it.

Numbers first: what one layer does to the spread

A unit adds up n inputs, each multiplied by a weight: z = w₁x₁ + w₂x₂ + … + wₙxₙ. If the inputs have variance 1 and the weights are random with variance Var(w), independent and centered on 0, then the variances add up:

Var(z) = n · Var(w) · Var(x)

So each layer multiplies the variance by n · Var(w). With n = 256 inputs:

The same multiplication happens to gradients on the way back. Deep networks are a long chain of multiplications, and any factor that isn't close to 1 gets raised to the power of the depth.

💡 Big idea Pick the weights' spread so that each layer keeps the signal's variance about the same, forward and backward: n · Var(w) ≈ 1, adjusted for what the activation throws away. Then a signal (and a gradient) can cross 10 or 100 layers without dying or exploding. Randomness itself is needed for a different reason: so that units start different from each other.

Why random at all? The symmetry trap

If two hidden units start with identical weights, they compute the same output, receive the same gradient, take the same step, and are identical again. Forever. A layer of 8 identical units is just one unit drawn 8 times.

🤔 Why this? Random initialization
  1. The problem before Zero (or any constant) weights make every unit in a layer compute the same thing and get the same update. The layer never becomes more than one unit; with zeros and tanh or ReLU, the hidden gradients are exactly 0 and nothing learns.
  2. What people tried Zeros (works for logistic regression, which has no hidden units, and fails for networks); hand-set values.
  3. Why this works Small random numbers make each unit start as a different feature detector, so they receive different gradients and specialize. Biases can start at 0, because the random weights already break the tie.
  4. What it costs, when it fails Randomness alone isn't enough: the scale of the random numbers decides whether signals survive depth (next). Runs become seed-dependent; fix torch.manual_seed for reproducibility.
  5. What refined it Scaled random inits: Xavier/Glorot (2010), He/Kaiming (2015), orthogonal (2013), and special small inits for residual layers (below).

✏️ Worked example: where Xavier and He come from

Keep the variance at 1 forward: nin · Var(w) = 1 → Var(w) = 1/nin (LeCun's rule). For a 256-wide layer: std = 1/16 = 0.0625.

Also keep the gradient's variance at 1 backward: going backwards each unit sums over nout paths, which wants Var(w) = 1/nout. Glorot & Bengio compromise: Var(w) = 2 / (nin + nout). For 256 → 256 that's the same 1/256.

ReLU throws away half: for inputs centered on 0, ReLU zeroes the negative half, so the signal's second moment (the mean of squares) halves at every layer: 0.5¹⁰ ≈ 0.001 after 10 layers. He et al. double the weights' variance to compensate: Var(w) = 2 / nin, std = √(2/256) ≈ 0.088. Check: 256 × (2/256) × ½ = 1 ✓.

PyTorch's nn.Linear default is uniform on ±1/√nin, whose variance is 1/(3nin): each ReLU layer multiplies the variance by 1/3 × ½ = 1/6. In a real 10-layer, 256-wide PyTorch ReLU stack (Tools box) the std falls from 0.34 at layer 1 to 0.022 at layer 10.

🤔 Why this? Xavier / Glorot initialization (2010)
  1. The problem before The common recipe was uniform on ±1/√n. Glorot & Bengio measured deep sigmoid and tanh networks with it and saw activations and back-propagated gradients shrink layer by layer, with saturation spreading through the layers.
  2. What people tried Unsupervised layer-by-layer pre-training to find a good starting point; hand-tuned per-layer scales.
  3. Why this works They derived the scale that keeps the variance steady both forward (needs 1/nin) and backward (needs 1/nout) and averaged: Var(w) = 2/(nin + nout), i.e. uniform on ±√6/√(nin + nout), their “normalized initialization”. In our playground, tanh + Xavier keeps every layer's std near 0.1 and trains.
  4. What it costs, when it fails The derivation assumes an activation that acts like the identity near 0 (tanh, not ReLU). With ReLU each layer still loses half the variance: in our ReLU playground Xavier's layer 10 std is about 5% of layer 1's, and in He's 30-layer experiment it stalled.
  5. What refined it He initialization for ReLU (next); normalization layers that re-standardize activations every layer (Lesson 2.3).
🤔 Why this? He / Kaiming initialization (2015)
  1. The problem before ReLU zeroes about half its inputs, so with Xavier each layer roughly halves the signal's power: 0.5³⁰ ≈ 10⁻⁹ over 30 layers. He et al.'s 30-layer ReLU network with Xavier completely stalled.
  2. What people tried Xavier; small constant std (they note 0.01 makes some deeper networks stall); training shallower networks first and stacking.
  3. Why this works Double the variance to pay back what ReLU throws away: Var(w) = 2/nin (std √(2/nin)), biases 0. Then n · Var(w) · ½ = 1 at every layer, so a 30-layer net starts with the signal intact, and their 30-layer model converged. Tiny worked number: n = 512 → std = √(2/512) = 0.0625.
  4. What it costs, when it fails It only fixes the start. During training the scales drift again; at 100+ layers small errors still compound. For leaky ReLU/PReLU the factor becomes 2/(1 + a²) (that's the a argument in PyTorch).
  5. What refined it BatchNorm/LayerNorm (Lesson 2.3) and residual connections (Lesson 2.2), which make networks much less sensitive to the exact init; zero-initializing the last layer of each residual block (below).

Beyond the formula: orthogonal and residual-aware init

  • Orthogonal init (Saxe, McClelland & Ganguli, 2013): use a random orthogonal matrix (a rotation, every singular value exactly 1) instead of independent random numbers. Every direction is preserved, not just the variance on average. They show it gives deep linear networks learning times that don't grow with depth. Common in RNNs and some RL code: nn.init.orthogonal_.
  • Small init on residual outputs: in a residual network each block adds to a running signal, so N blocks add N contributions and the variance grows with depth. GPT-2 scales the weights of residual layers at initialization by 1/√N, N = number of residual layers. Goyal et al. (2017) initialize the last BatchNorm scale γ of each ResNet block to 0, so every block starts as the identity; it improved all their models, especially with large batches.
  • Normalization layers (Lesson 2.3) re-standardize activations at every layer, so modern transformers are far more forgiving. Residual-aware init is still standard, though: nanoGPT starts its residual projections with std 0.02/√(2 · n_layer), and Karpathy's nanochat (checked November 2026) starts them at exactly zero. That doesn't trigger the symmetry trap, because the other weights in each block are random and the zeroed matrix still gets a non-zero gradient.
🧰 Tools you'll actually use

Initializers live in torch.nn.init and work in place (the trailing underscore). This snippet measures the std after 10 ReLU layers of width 256 for four choices:

import torch, torch.nn as nn

torch.manual_seed(0)
x = torch.randn(1024, 256)

def stack(init, act=nn.ReLU, depth=10, width=256):
    layers = []
    for _ in range(depth):
        lin = nn.Linear(width, width)
        if init is not None:
            init(lin.weight); nn.init.zeros_(lin.bias)
        layers += [lin, act()]
    return nn.Sequential(*layers)

inits = {
    "PyTorch default": None,
    "N(0, 1)": lambda w: nn.init.normal_(w, std=1.0),
    "Xavier normal": nn.init.xavier_normal_,
    "He (Kaiming) normal": lambda w: nn.init.kaiming_normal_(w, nonlinearity="relu"),
}
with torch.no_grad():
    for name, init in inits.items():
        h, stds = x, []
        for layer in stack(init):
            h = layer(h)
            if isinstance(layer, nn.ReLU):
                stds.append(h.std().item())
        print(f"{name:20s} layer 1 std {stds[0]:9.3g}   layer 10 std {stds[-1]:9.3g}")

# What we got (torch 2.8, CPU):
# PyTorch default      layer 1 std     0.339   layer 10 std     0.022
# N(0, 1)              layer 1 std      9.32   layer 10 std  2.42e+10
# Xavier normal        layer 1 std     0.587   layer 10 std    0.0276
# He (Kaiming) normal  layer 1 std     0.831   layer 10 std     0.815

What the default really is: nn.Linear.reset_parameters calls kaiming_uniform_(weight, a=√5); the source comments that this equals uniform(−1/√in, 1/√in), and biases are uniform on the same range. To apply your own init to a whole model: model.apply(fn) with an fn that checks isinstance(m, nn.Linear).

🎤 Interview angle

“Why not initialize weights to zero? Why He init for ReLU?” A strong answer:

  • Zero/constant init → symmetry: identical units get identical gradients forever.
  • Scale: each layer multiplies the variance by n · Var(w); raised to the depth, anything but ≈ 1 explodes or vanishes, forward and backward.
  • Xavier: Var = 2/(nin + nout) for tanh-like; He: Var = 2/nin because ReLU zeroes half the signal.
  • Modern practice: normalization + residuals reduce sensitivity; scale residual branches by 1/√N (GPT-2) or zero-init their last layer; check activation stats per layer when debugging.
🏭 In the real world
The normalized initialization 📜 History · 2010 Glorot & Bengio: Understanding the Difficulty of Training Deep Feedforward Neural Networks

How: watched activations and gradients layer by layer in deep sigmoid/tanh nets, then derived Var(w) = 2/(nin + nout).

Why this method: it kept activation and gradient variances steadier across layers than the standard ±1/√n init, which is exactly the histogram view of the playground.

He init for very deep ReLU nets 🧪 Research · 2015 He et al.: Delving Deep into Rectifiers

How: zero-mean Gaussian weights with std √(2/n), biases 0.

Why this method: their 30-layer ReLU model converged with it and completely stalled with Xavier; it became the default for CNNs.

Scaled residual init in a language model 🏢 OpenAI · 2019 Radford et al.: Language Models are Unsupervised Multitask Learners (GPT-2)

How: the weights of residual layers are scaled at initialization by 1/√N, where N is the number of residual layers.

Why this method: the paper says it “accounts for the accumulation on the residual path with model depth”: N blocks each add a contribution, so each must start smaller.

Zero-γ: every block starts as the identity 🏢 Facebook AI Research · 2017 Goyal et al.: Accurate, Large Minibatch SGD

How: the last BatchNorm γ of each residual block starts at 0, so the signal initially flows only through the shortcut.

Why this method: they found it eases optimization at the start of training and improves all their models, more so with large minibatches (Lesson 1.7).

🤯 Fun fact · the default is the “before” picture

The initialization Glorot & Bengio used as the bad baseline in 2010, uniform on ±1/√n, is essentially what nn.Linear still does by default (the source code even links a GitHub issue discussing it). It's fine in practice because modern networks add normalization and residuals, but for a plain deep ReLU MLP, call kaiming_normal_ yourself.

Check yourself

1. A ReLU layer has 1,024 inputs. What weight std does He initialization use?
He: Var(w) = 2/nin = 2/1,024, so std = √(2/1,024) = 0.0442. Check: n · Var(w) · ½ = 1,024 × (2/1,024) × ½ = 1, so the signal's power is preserved through the ReLU layer.
2. You initialize every weight of an MLP to 0.1 (not zero). Training runs, the loss drops a little, then plateaus well above a small model's loss. What's the likely cause?
Constant init makes all units in a layer compute the same value, get the same gradient and take the same step, so they stay identical forever. The network's effective width is 1 per layer. Use random init (He/Xavier); the playground's 0.5 start ended with 1 distinct unit after 1,000 steps.
3. A plain 20-layer ReLU MLP built with default nn.Linear layers trains very slowly; printing activation stds shows them shrinking layer by layer. Best first fix?
The default is uniform ±1/√n (variance 1/(3n)), so each ReLU layer multiplies the variance by about 1/6: over 20 layers the signal all but disappears. He init makes the per-layer factor 1. N(0, 1) would explode instead (factor n/2 per layer), and sigmoid adds its own vanishing slope.
📝 TL;DR
  • Random, not constant: identical starting units stay identical forever (symmetry). Biases can start at 0.
  • Each layer multiplies the variance by n · Var(w) (× ½ for ReLU); raised to the depth, only ≈ 1 survives, forward and backward.
  • Xavier/Glorot: Var(w) = 2/(nin + nout) for tanh-like activations. He/Kaiming: Var(w) = 2/nin for ReLU.
  • PyTorch's nn.Linear default is uniform ±1/√nin (via kaiming_uniform_ with a = √5), not He.
  • Modern nets: orthogonal init for some RNN/RL code; residual branches scaled by 1/√N (GPT-2) or zero-initialized (zero-γ); normalization layers (2.3) make init far less fragile.
