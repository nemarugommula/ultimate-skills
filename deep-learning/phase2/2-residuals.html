Phase 2 · Lesson 2

Residual connections: the gradient highway

In 2015 a deeper network was worse than a shallower one, even on its own training data. The fix was one plus sign, y = x + F(x), and it's now inside almost every deep network you'll ever use, from ResNets to GPT.

🧰 You'll need (quick reminders)
  • The gradient at an early layer is a product of one factor per layer; far from 1, it vanishes or explodes (Lesson 2.1).
  • He initialization sets the starting weight scale so that ReLU layers neither shrink nor grow the signal at step 0 (Lesson 1.4).
  • Training error is measured on the data the network learns from; test error on data it has never seen (math 5.6).
🎯 Hook

Kaiming He and colleagues at Microsoft Research trained two plain convolutional networks on CIFAR-10: one with 20 layers, one with 56. The 56-layer network had higher training error. Not higher test error, which would just be overfitting: it was worse at fitting the very images it trained on.

That's strange. The deep network could copy the shallow one and set its 36 extra layers to “do nothing”, so it should be at least as good. On ImageNet the same thing happened: the 34-layer plain net had higher training error “throughout the whole training procedure” than the 18-layer one, and 28.54% top-1 validation error vs 27.94%. Then they added skip connections, changing nothing else. ResNet-34 dropped to 25.03%, and a 152-layer version (in an ensemble) won the 2015 ImageNet challenge with 3.57% top-5 error.

Why couldn't 36 layers learn to do nothing, and why does a single “+ x” fix it? You'll race a plain network against a residual one, watch the plain one get stuck as you add layers, and count the 2ⁿ hidden paths that make residual networks so easy to train.

Numbers first: learning to do nothing is hard

Suppose the best thing a layer can do is pass its input through unchanged: output = input. A plain layer computes relu(Wx + b). To output exactly x it has to learn W = the identity matrix (1 on the diagonal, 0 everywhere else), starting from random numbers, and it can't even pass negative values through the ReLU.

A 64-wide layer has 64 × 64 = 4,096 weights that must land on exactly the right values. Random init puts them nowhere near: each starts as a random number of typical size √(2/64) ≈ 0.18, while the 64 diagonal ones should be exactly 1 and the other 4,032 exactly 0.

Now write the layer as x + F(x). To do nothing, F just has to output 0: push the weights toward zero, which is the easiest thing gradient descent and weight decay ever do. He et al. put it this way: it “would be easier to push the residual to zero than to fit an identity mapping by a stack of nonlinear layers”.

💡 Big idea A residual block computes y = x + F(x): the input skips around the layers and is added back. The block only has to learn the change (the residual) it wants to make. And on the way back, the gradient gets a path with factor exactly 1 through every block: the gradient highway.
🧠 Analogy: track changes on a document

A plain layer is an editor who must retype the whole document from memory and hopefully improve it. Thirty editors in a row, and the original is unrecognisable. A residual block is an editor with track changes on: the document passes through as-is, and each editor only adds their edits. An editor with nothing to say adds nothing, and the text survives. Feedback to the first editor also comes back through the untouched document, not through 29 rewrites.

The degradation problem, live

Here's that 2015 experiment in miniature. Two networks with identical layers, weights and data (the two-spiral set, plain gradient descent). Each block is one 12-unit ReLU layer. The plain block computes h ← W·relu(h) + b; the residual block computes h ← h + α(W·relu(h) + b). That's the only difference.

Why it works, reason 1: the gradient highway

Take the slope of y = x + F(x) with respect to x. The x term contributes exactly 1; the branch contributes F′(x). So each block multiplies the gradient by (1 + F′) instead of F′ alone. He et al.'s follow-up paper (2016) calls this “the additive term ‘1’” in backward propagation.

✏️ Worked example: three blocks, branch slope 0.1

Each branch F has slope F′ = 0.1 (small, like a freshly initialized branch). Gradient from the output = 1.

Per blockReaches block 1
Plain (y = F(x))× 0.10.1³ = 0.001
Residual (y = x + F(x))× (1 + 0.1)1.1³ = 1.331

Multiply out the residual product: (1 + 0.1)³ = 1 + 3 × 0.1 + 3 × 0.01 + 0.001 = 1 + 0.3 + 0.03 + 0.001. Read each term as a path: the “1” skips all three branches, the three 0.1s go through exactly one branch, the three 0.01s through two, and the 0.001 through all three. That last term is the only path a plain network has. 1 + 3 + 3 + 1 = 8 = 2³ paths.

Why it works, reason 2: a crowd of shallow paths

Veit, Wilber and Belongie (2016) unrolled residual networks exactly like that: with n blocks, every block is either taken or skipped, so there are 2ⁿ paths from input to output, of every length from 0 to n. Most of them are short. Their lesion test is striking: delete one block from a trained ResNet at test time and only half the paths break, so accuracy drops only modestly. Delete one layer from a plain network (such as VGG) and you cut its only path.

What you should see: 10 blocks give 1,024 paths, and the lengths pile up in the middle (252 paths go through exactly 5 blocks, only 1 goes through all 10). Delete 3 blocks: 2⁷ = 128 paths survive, 12.5%, and every surviving path still connects input to output. The plain network loses its only path the moment you delete anything. Veit et al. found the same shape in real nets: in a ResNet with 54 blocks, more than 95% of paths go through 19 to 35 blocks, and most of the gradient in a 110-layer ResNet comes from paths only 10 to 34 layers deep. A “very deep” ResNet trains like an ensemble of fairly shallow networks.

🤔 Why this? Residual connections y = x + F(x)
  1. The problem before With ReLU, He init and batch normalization, gradients no longer vanished at step 0, yet deeper plain networks trained worse: 56 layers had higher training error than 20 on CIFAR-10, and plain-34 was worse than plain-18 on ImageNet (28.54% vs 27.94% top-1). He et al. called it the degradation problem: an optimization failure, not overfitting.
  2. What people tried Careful init, normalization, auxiliary losses attached to middle layers (GoogLeNet), and highway networks (Srivastava, Greff & Schmidhuber, 2015), which mix a layer's output with its input using a learned gate: y = H(x)·T(x) + x·(1 − T(x)). Highways trained networks with hundreds of layers, inspired by LSTM gates.
  3. Why this works Drop the gate and always add: y = x + F(x). (1) Doing nothing is easy: F → 0. (2) Backward, each block multiplies the gradient by (1 + F′), so there's always a factor-1 path: in our worked example 1.331 instead of 0.001. (3) n blocks hide 2ⁿ paths, mostly short, so the network trains like an ensemble of shallower ones. The skip adds no parameters and one addition per value.
  4. What it costs, when it fails x and F(x) must have the same shape (otherwise a 1×1 projection adds parameters). Activations add up, so their size grows with depth unless branches are scaled or normalized (our α = 1/√depth; Lesson 2.3). The input of each block must be kept in memory for the backward pass. Depth alone isn't a free lunch: ResNet-1202 reached under 0.1% training error on CIFAR-10 but tested worse than ResNet-110 (7.93% vs 6.43%), which the authors attribute to overfitting.
  5. What refined it Pre-activation ResNets (He et al., 2016: normalization and ReLU inside the branch, a clean identity path; a 1001-layer ResNet hit 4.62% on CIFAR-10); bottleneck blocks (Lesson 3.4); DenseNet's concatenation; and the transformer block, x + Attention(Norm(x)), x + MLP(Norm(x)), where the skip is called the residual stream (Lesson 6.4, pre-norm vs post-norm).

Residuals everywhere

The original transformer (2017) wraps both of its sub-layers in residuals: the output of each is “LayerNorm(x + Sublayer(x))”. Modern LLMs such as LLaMA move the normalization inside the branch (pre-norm: x + Sublayer(Norm(x)), Lesson 6.4), which keeps a perfectly clean identity path from the first token embedding to the last layer. Interpretability researchers call that path the residual stream: every attention and MLP block reads from it and writes a small update back into it. That's the “track changes” picture, at the scale of a hundred layers.

🧰 Tools you'll actually use

A residual block in PyTorch is a module whose forward returns x + self.f(x). torchvision's resnet18/resnet50 build the classic image versions (pass weights=None for the architecture only; pretrained weights are Lesson 3.5). This snippet builds 30 blocks with and without the skip and measures the gradient at block 1.

import torch, torch.nn as nn

class Residual(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.f = nn.Sequential(nn.Linear(d, d), nn.ReLU(), nn.Linear(d, d))
    def forward(self, x):
        return x + self.f(x)              # y = x + F(x)

class Plain(Residual):
    def forward(self, x):
        return torch.relu(self.f(x))      # same layers, no skip

torch.manual_seed(0)
x = torch.randn(256, 64)
for Block in (Plain, Residual):
    net = nn.Sequential(*[Block(64) for _ in range(30)], nn.Linear(64, 1))
    net(x).pow(2).mean().backward()
    first = net[0].f[0].weight.grad.norm().item()
    last = net[29].f[0].weight.grad.norm().item()
    print(f"{Block.__name__:8s} block 1: {first:.1e}   block 30: {last:.1e}")

import torchvision
m = torchvision.models.resnet50(weights=None)   # architecture only, no download
print(f"ResNet-50 parameters: {sum(p.numel() for p in m.parameters()) / 1e6:.1f}M")

# What we got on a laptop CPU (torch 2.8, torchvision 0.23):
# Plain    block 1: 0.0e+00   block 30: 1.6e-03
# Residual block 1: 8.9e-01   block 30: 1.5e+00
# ResNet-50 parameters: 25.6M

The plain stack's first block gets a gradient of exactly 0.0 in float32: nothing arrives. Same layers with a skip: 0.89. Gotcha: write x = x + self.f(x), not x += self.f(x), when x is still needed by autograd; in-place ops on tensors saved for backward raise an error.

🎤 Interview angle

“What problem do residual connections solve, and why do they work?” A strong answer:

  • Names the degradation problem: deeper plain nets had higher training error (an optimization problem, not overfitting), even with good init and BatchNorm.
  • Gives the three reasons: identity is easy (F → 0); the gradient through each block is 1 + F′, so there's always a direct path; n blocks unroll into 2ⁿ paths that behave like an ensemble of shallow networks (Veit et al.).
  • Mentions the costs: matching shapes or a projection, activation growth (hence normalization and branch scaling), memory.
  • Connects to transformers: x + Sublayer(Norm(x)) and the residual stream; knows highway networks were the gated predecessor.
🏭 In the real world
ResNet wins ImageNet 2015 🧪 Research · 2015 He, Zhang, Ren & Sun: Deep Residual Learning for Image Recognition

How: stacks of 2- or 3-layer convolutional blocks with identity shortcuts, up to 152 layers on ImageNet (8× deeper than VGG) and 1,202 on CIFAR-10.

Why this method: it fixed the degradation problem at no parameter cost; an ensemble reached 3.57% top-5 error and first place in the ILSVRC 2015 classification task.

The gated predecessor 🧪 Research · 2015 Srivastava, Greff & Schmidhuber: Highway Networks

How: a transform gate T(x) decides how much of each block's output is new and how much is the carried input.

Why this method: borrowing LSTM-style gating let “highway networks with hundreds of layers” train directly with gradient descent, months before ResNet.

Every transformer layer 🧪 Research · 2017 Vaswani et al.: Attention Is All You Need

How: a residual connection around the attention sub-layer and around the feed-forward sub-layer, followed by layer normalization (Lesson 6.4).

Why this method: stacking many attention + MLP layers needs the same gradient highway; LLMs with dozens to over a hundred layers (Llama 3 405B has 126) keep it, usually with the normalization moved inside the branch.

Residual nets as ensembles 🧪 Research · 2016 Veit, Wilber & Belongie: Residual Networks Behave Like Ensembles of Relatively Shallow Networks

How: unrolled ResNets into 2ⁿ paths, deleted and reordered blocks at test time, and measured which path lengths carry the gradient.

Why this method: it explains the robustness and trainability: the effective depth is far smaller than the nominal depth.

🤯 Fun fact · you can delete layers from a trained ResNet

Veit et al. removed single blocks from trained residual networks at test time, no retraining, and found only “a modest and smooth impact on performance”. Do the same to VGG and it collapses, because you've cut its only path. In the unrolled view, deleting one block zeroes exactly half of the paths and leaves the other half working.

Check yourself

1. A 56-layer plain network has higher training error than a 20-layer one. What does that tell you?
Overfitting shows up as low training error with high test error. Here even training error is worse, so the network fails to fit. A residual design makes “extra layers do nothing” the easy default (F → 0), which is exactly what fixed it.
2. Four residual blocks, each branch with slope F′ = 0.5. Treating everything as numbers, what factor reaches the first block, and how many paths contribute?
Each block multiplies by (1 + F′) = 1.5, and 1.5⁴ = 5.0625. Expanded, it's a sum over 16 paths (each block taken or skipped): 1 + 4(0.5) + 6(0.25) + 4(0.125) + 0.0625. Note it can grow too: that's why branches are scaled at init and activations normalized (Lesson 2.3).
3. You're designing a block whose output must have 256 channels, but its input has 128. What happens to the residual connection?
Addition needs matching shapes. ResNet uses a projection (or zero-padding) only where the width or resolution changes; everywhere else the shortcut stays a pure identity. Concatenation is a different design (DenseNet).
📝 TL;DR
  • Degradation: deeper plain nets trained worse (56 vs 20 layers on CIFAR-10; plain-34 vs plain-18 on ImageNet). An optimization failure, not overfitting.
  • Residual block: y = x + F(x). It learns only the change, “do nothing” is F = 0, and it adds no parameters.
  • Backward, each block multiplies by 1 + F′: there's always a factor-1 path. n blocks = 2ⁿ paths, mostly short: an ensemble of shallow nets.
  • Costs: matching shapes (or projections), activations that grow with depth (scale branches, normalize: 2.3), memory.
  • Highway networks were the gated predecessor; today every ResNet, U-Net and transformer is built on residuals (the residual stream, 6.4).
