Phase 3 · Lesson 1

Why not an MLP for images?

A plain network that looks at a photo needs a hundred million weights and still gets confused when the cat moves a few pixels. Two simple ideas, borrowed from how eyes work, fix both problems at once.

🧰 You'll need (quick reminders)
  • A dense (fully connected) layer connects every input to every output: it has inputs × outputs weights plus one bias per output (Lesson 0.3). A stack of dense layers is an MLP (multi-layer perceptron).
  • To a computer an image is a grid of numbers: height × width × 3 colour channels (red, green, blue), each 0–255 or 0–1 (math 2.3 tensors).
🎯 Hook

Take a small colour photo, 224 × 224 pixels. That's 150,528 numbers. Feed it into one dense layer with 1,000 units and you need 150.5 million weights: two and a half times all of AlexNet, the 60-million-parameter network that won ImageNet in 2012. For one layer.

Now train it to spot cats. Then slide the same cat 10 pixels to the right. To your eyes nothing changed. To the network, almost every input number moved to a different slot: it's a brand-new input it has never seen.

The fix is the convolutional neural network (CNN). CNNs read millions of bank cheques a day in the late 1990s, won ImageNet in 2012, and still power phone cameras, medical scans and factory inspection today. How can one layer be 84,000× smaller and also not care where the cat is?

Numbers first: count the weights

A dense layer's weight count is just inputs × outputs. For images the input count is height × width × channels, and it grows with the square of the image side:

ImageInput numbersDense layer toWeights + biases
28 × 28 grey (handwritten digit)784100 units78,500
224 × 224 colour (ImageNet size)150,5281,000 units150,529,000
1024 × 1024 colour (a small phone photo)3,145,7281,000 units3,145,729,000

Three billion weights is 12.6 GB in 32-bit floats, for the first layer alone, before it has learned anything. And each of those weights has to be learned from data: with a million training photos, you'd have 3,000 weights per photo. That's a recipe for memorizing instead of learning (overfitting, Lesson 2.4).

Problem two: a cat moved 10 pixels is a new input

An MLP first flattens the image: row 1, then row 2, and so on, into one long list. Weight number 5,000 is wired to pixel number 5,000 and nothing else. So the network learns “a cat ear at pixel 5,000”, not “a cat ear”. Move the cat and the ear lands on pixels the network has never associated with ears.

What you should see: shifting the cross 2 pixels right changes 24 of the 144 input numbers and drops the cosine similarity between the old and new input vectors to 0.40 (1.00 would mean “same direction”). To a dense layer that's a very different input. The conv's feature map just slides along with the picture: same blobs, same strongest response, new place. That property has a name: the convolution is translation equivariant (shift the input, the output shifts the same way). Take the maximum over the whole map and you get a number that doesn't care where the cross is at all: translation invariant. Pooling does exactly that (Lesson 3.3).

💡 Big idea A convolution layer bakes two assumptions (priors) about images into the architecture. Locality: to understand a pixel, look at its neighbours first; an edge is a few pixels wide. Weight sharing: a pattern means the same thing wherever it appears, so use the same small detector everywhere. Locality cuts the wiring; sharing cuts the weights to a handful and makes “moved” the same as “same”.
🧠 Analogy: one wanted poster vs a guard per seat

You need to find a face in a stadium of 50,000 seats. The MLP way: hire one guard per seat, and each guard has to learn what the face looks like from their own seat. If the person sits somewhere new, that seat's guard has never learned the face. The CNN way: print one wanted poster (the filter) and walk it past every seat (the slide). One thing to learn, works in every seat, and a new seat is no problem.

The brain did it first

In 1959, David Hubel and Torsten Wiesel recorded single neurons in a cat's visual cortex. Each cell responded only to a small patch of the visual field (its receptive field), and many fired only for an edge or bar at one particular angle. Their 1962 paper described “simple” cells that want an edge in an exact spot and “complex” cells that respond to the same edge anywhere in a slightly bigger area. They shared the 1981 Nobel Prize for this work.

That is locality (small receptive fields), feature detectors (edges at an angle) and a step toward position tolerance (complex cells). In 1980 Kunihiko Fukushima built it into a model, the Neocognitron, whose title promised recognition “unaffected by shift in position”: layers of local feature detectors alternating with layers that tolerate small shifts. It wasn't trained with backpropagation. Yann LeCun's group combined the same layout with backprop, which led to LeNet-5 (1998): a small CNN that read handwritten digits. Lesson 3.4 walks the whole family tree.

🤔 Why this? Convolution as a layer (locality + weight sharing)
  1. The problem before Dense layers on images need inputs × outputs weights: 150.5 million for one 224 × 224 → 1,000 layer, and 3.1 billion at 1024 × 1024. And because weight i is tied to pixel i, a pattern learned in one spot is useless anywhere else: shift the picture 2 pixels and the input vector's cosine similarity drops to 0.40.
  2. What people tried Hand-made features (edge histograms, SIFT descriptors) fed into a simple classifier; shrinking images until dense layers fit; showing the MLP every shifted copy (data augmentation), which helps but means learning the same thing at every position separately (you'll measure this below).
  3. Why this works Each output looks only at a small k × k patch (locality), and the same k × k × channels weights are used at every position (sharing). 64 filters of 3 × 3 on a colour image: 64 × 27 + 64 = 1,792 parameters, at any image size. A pattern learned once is detected everywhere, and shifting the input just shifts the output map (equivariance).
  4. What it costs, when it fails One layer only sees a tiny patch, so you need many stacked layers (and pooling) to see a whole object (Lesson 3.3). Sharing assumes position doesn't matter, which is wrong for some data (in a face-ID crop the eyes are always at the top; in a chart, position is the meaning). Compute doesn't shrink like parameters do: those 1,792 weights are used at 50,176 positions.
  5. What refined it Padding, stride and channels (Lesson 3.2), pooling and deep stacks of 3 × 3 (3.3), residual connections for 100+ layers (2.2, 3.4), cheap depthwise-separable convs (3.4). Vision Transformers (Lesson 4.5) relax the locality prior and learn it from huge datasets instead.

🧰 Tools you'll actually use

PyTorch's nn.Conv2d(in_channels, out_channels, kernel_size) is the conv layer. Count parameters with one line, and check the equivariance claim yourself. The device="meta" trick builds a layer's shapes without allocating its 600 MB of weights.

import torch, torch.nn as nn

dense = nn.Linear(224 * 224 * 3, 1000, device="meta")   # "meta": shapes only, no memory used
conv = nn.Conv2d(3, 64, kernel_size=3, padding=1)
count = lambda m: sum(p.numel() for p in m.parameters())
print(f"dense: {count(dense):,} parameters")
print(f"conv:  {count(conv):,} parameters")

# Shift the picture 10 pixels right: the conv output shifts by exactly 10 pixels too.
torch.manual_seed(0)
img = torch.zeros(1, 3, 224, 224)
img[:, :, 80:140, 60:120] = torch.rand(1, 3, 60, 60)        # a random "object"
moved = torch.roll(img, shifts=10, dims=3)
out, out_moved = conv(img), conv(moved)
print("same map, just shifted:", torch.allclose(torch.roll(out, 10, dims=3), out_moved, atol=1e-6))
cos = torch.nn.functional.cosine_similarity(img.flatten(), moved.flatten(), dim=0)
print(f"cosine similarity of the two input vectors: {cos:.2f}")

# What we got on a laptop CPU (torch 2.8):
# dense: 150,529,000 parameters
# conv:  1,792 parameters
# same map, just shifted: True
# cosine similarity of the two input vectors: 0.62

Gotcha: PyTorch images are (batch, channels, height, width), “NCHW”. Libraries such as PIL and NumPy usually give you (height, width, channels); convert with torchvision.transforms.v2.ToImage() or x.permute(2, 0, 1).

🎤 Interview angle

“Why use a CNN instead of an MLP for images?” A strong answer:

  • Gives the parameter arithmetic: a dense layer is H·W·C × outputs (150M for 224 × 224 × 3 → 1,000); a conv layer is k·k·C_in × C_out + C_out, independent of image size.
  • Names the two priors: locality and weight sharing, and connects sharing to translation equivariance (and pooling to invariance).
  • Says what the priors cost: limited receptive field per layer (fixed by depth and pooling), and wrong assumptions when position matters.
  • Bonus: mentions that ViTs weaken these priors and need more data, which is why CNNs still win on small datasets and edge devices.
🏭 In the real world
Reading bank cheques 📜 History · 1998 LeCun, Bottou, Bengio & Haffner: Gradient-Based Learning Applied to Document Recognition

How: convolutional character recognizers inside a larger trained system that reads the amounts on business and personal cheques.

Why this method: the paper shows CNNs, “specifically designed to deal with the variability of 2D shapes”, beat every other method on handwritten digits; the system was deployed commercially and read several million cheques per day.

The ImageNet moment 📜 History · 2012 Krizhevsky, Sutskever & Hinton: AlexNet

How: five convolutional layers and three dense layers, 60 million parameters, trained on 1.2 million images on two GPUs.

Why this method: convolutions kept the parameter count trainable at 224 × 224; the dense layers at the end, which only see small feature maps, still hold most of the 60 million weights. It won with 15.3% top-5 error vs 26.2% for the runner-up (Lesson 3.4).

Skin-cancer screening from photos 🧪 Research · 2017 Esteva et al., Nature: Dermatologist-level classification of skin cancer

How: a deep CNN trained on 129,450 clinical images, tested against 21 board-certified dermatologists on biopsy-proven cases.

Why this method: a lesion can be anywhere in the photo, at any rotation; a CNN learns its visual patterns once and finds them anywhere.

Model zoos 🧰 Open source torchvision.models · timm

How: ResNets, EfficientNets, ConvNeXts and more, each one line of code, with optional pre-trained weights.

Why this method: in practice you rarely design a CNN from scratch; you pick a proven backbone and adapt it (Lessons 3.4 and 3.5).

🤯 Fun fact · the discovery was an accident

In his Nobel lecture, Hubel describes hours of getting nothing from a cell with their dot stimuli. Then, while they slid a glass slide into the projector, the cell “went off like a machine gun”. It wasn't the dot: the slide's edge was casting a faint straight line on the retina, at one particular angle. Orientation-selective edge detectors, the same thing a CNN's first layer learns (Lesson 3.6), were found because of a slide's edge.

Check yourself

1. A 64 × 64 colour image goes into a dense layer with 500 units. How many parameters (weights + biases)?
Inputs = 64 × 64 × 3 = 12,288. Weights = 12,288 × 500 = 6,144,000, plus 500 biases = 6,144,500. (2,048,500 forgets the 3 colour channels.) A 3 × 3 conv with 500 filters on the same image would have 500 × 27 + 500 = 14,000, at any image size.
2. Your MLP classifies products on a conveyor belt with 99% accuracy in testing. In the factory, the camera was mounted 3 cm further left and accuracy falls to 60%. What's the most likely explanation?
A dense layer's weights are wired to specific pixels, so a shift scrambles which weights see what (you saw the cosine similarity fall to 0.40 for a 2-pixel shift). A conv layer slides the same filters everywhere, so the feature maps simply shift; pooling then makes the decision position-tolerant.
3. Which pair of ideas does a convolution layer add compared with a dense layer?
Locality alone still costs 88 million parameters on a 224 × 224 image (one private filter per position). Sharing alone isn't meaningful without patches. Together they give a handful of weights that detect a pattern anywhere, and a shift of the input just shifts the output.
📝 TL;DR
  • A dense layer on an image needs H × W × C × outputs weights: 150.5M for 224 × 224 × 3 → 1,000, and it grows with the square of the image side.
  • An MLP ties each weight to one pixel, so a shifted object is a new input; it has to see every position to learn them all (35% → 95% in the playground).
  • Convolution adds two priors: locality and weight sharing. 64 filters of 3 × 3 × 3 = 1,792 parameters at any image size; shifting the input just shifts the feature map (equivariance).
  • The design comes from the visual cortex (Hubel & Wiesel 1959–62), the Neocognitron (1980) and LeNet (1998).
  • The costs: each layer sees only a small patch (stack layers, Lesson 3.3) and position is assumed not to matter.
