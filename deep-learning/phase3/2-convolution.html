Convolution: filters, stride, padding, channels

Nine numbers slid across a picture can blur it, sharpen it or find every edge in it. A CNN layer is just many of these little stencils, and a handful of knobs decide the shape of what comes out.

🧰 You'll need (quick reminders)
  • A dot product multiplies two lists number by number and adds the results: [1, 2, 3]·[4, 5, 6] = 4 + 10 + 18 = 32 (math 1.3).
  • A conv layer uses locality (small patches) and weight sharing (same filter everywhere), which is why it needs so few parameters (Lesson 3.1).
🎯 Hook

Here are nine numbers:

[ 0 −1 0 ] [ −1 5 −1 ] [ 0 −1 0 ]

Lay them on a 3 × 3 patch of a photo, multiply each pixel by the number on top of it, add the nine products, write the result down, slide over one pixel, repeat. The photo comes out sharper. Change the numbers to all 1/9 and it comes out blurred. Put −1, 0, +1 in each row and only the vertical edges survive.

Image editors have shipped this “convolution matrix” filter for decades. The trick of a CNN is that it doesn't use hand-picked numbers: it learns them, hundreds of filters per layer. What exactly happens at each position, and what decides how big the output is? By the end you'll design your own vertical-edge detector and predict any layer's output shape in your head.

Slide the window to all three places it fits and the output row is [0, 3, 3]: zero on the flat dark part, big where dark turns bright. That's the whole operation: at every position, a dot product between the kernel and the patch under it. The output grid is called a feature map (or activation map): it says “how much of this pattern is here?” for every position.

💡 Big idea A kernel is a little pattern, and the dot product measures how well each patch matches it. Positive weights say “I want brightness here”, negative weights say “I want darkness here”. A feature map is a map of where the pattern appears. A conv layer learns many such patterns at once.

What you should see: sharpen leaves flat areas alone (its weights sum to 1, so a flat patch of value v gives v) and makes the square's outline pop: 3 on the line itself (it was 1), −1 on the dark pixels right next to it. An edge kernel's weights sum to 0, so any flat patch, dark or bright, gives exactly 0: it only reacts to change. The horizontal-edge preset ignores the edge image completely. To win the vertical challenge, turn it on its side: −1, 0, +1 across each row. For the outline detector, try +8 in the middle and −1 all around (or +4 with −1 above, below, left, right).

In a CNN nobody types these in. Each kernel starts random and gradient descent adjusts its nine numbers to whatever helps the loss. Trained networks end up with edge and blob detectors in their first layer anyway (you'll see real ones in Lesson 3.6).

🧠 Analogy: a stencil and a flashlight

Cut a stencil of the pattern you're looking for. Slide it over the page, one step at a time. At each spot, shine a light through it and measure how much light comes out the other side (bright pixels where the stencil is open, dark where it's blocked). Write that brightness on a new sheet at the same spot. The new sheet is the feature map. Negative weights are like a filter that subtracts light where you want darkness.

Stride and padding: what decides the output size

Two knobs change how the kernel moves:

  • Stride s: how many pixels the window jumps each step. Stride 2 skips every other position, so the output is about half the size in each direction.
  • Padding p: a border of zeros added around the input before sliding. Without it, a 3 × 3 kernel can't be centered on edge pixels, so every layer shrinks the image by 2.

Count the positions that fit, and you get the formula every CNN engineer knows by heart. In words: the padded width, minus the kernel, divided by the stride, rounded down, plus one for the starting position:

output = ⌊(n + 2p − k) / s⌋ + 1

Two names you'll see everywhere: “valid” = no padding (output shrinks by k − 1), and “same” = enough padding that the output equals the input size at stride 1, which is p = (k − 1)/2 for odd k: p = 1 for 3 × 3, p = 2 for 5 × 5.

What you should see: n = 7, k = 3, s = 2, p = 0 gives ⌊(7 − 3)/2⌋ + 1 = 3 outputs per row (3 × 3 in all). Press “Make it same” with k = 3: p becomes 1, s becomes 1 and the output is 7 × 7. With k = 1 and s = 2, the kernel lands on every other pixel and three quarters of the input is never seen (on an 8 × 8 input: 48 of 64 pixels). When the stride doesn't divide evenly, the floor ⌊ ⌋ quietly drops the last column: try n = 8, k = 3, s = 2, p = 0.

🤔 Why this? Padding
  1. The problem before A valid 3 × 3 conv shrinks each side by 2. Ten layers turn a 32 × 32 image into 12 × 12, and border pixels are covered by fewer windows than central ones (a corner pixel takes part in 1 of the 900 output positions of a 3 × 3 valid conv on 32 × 32; a central pixel in 9).
  2. What people tried Using fewer layers; larger inputs; cropping the labels to match the shrinking output.
  3. Why this works Add a ring of p zeros: with p = (k − 1)/2 the output keeps the input's size (“same”), so you can stack as many layers as you like and the shape only changes where you decide (with stride or pooling). Edge pixels get a full window.
  4. What it costs, when it fails The zeros are made-up data: features near the border see a fake black frame, and networks can even learn to use it to tell where they are in the image. Even-sized kernels (2 × 2, 4 × 4) can't pad symmetrically.
  5. What refined it Other padding modes: reflect, replicate, circular (padding_mode= in PyTorch), often used in image generation to avoid border artifacts. Most classifiers simply use zero “same” padding.
🤔 Why this? Stride
  1. The problem before At stride 1, every layer has as many positions as pixels. Later layers want bigger, coarser views with more channels, and at full resolution that's expensive: a 3 × 3, 256 → 256 conv on 224 × 224 costs 224 · 224 · 256 · 2,304 ≈ 29.6 billion multiply-adds.
  2. What people tried A separate pooling layer after each block (Lesson 3.3); simply resizing images smaller.
  3. Why this works Stride 2 computes only every other position: the output has a quarter of the positions, so the next layers cost a quarter as much, and each output summarizes a wider area. The downsampling is learned, unlike fixed pooling. ResNet does most of its downsampling with stride-2 convolutions.
  4. What it costs, when it fails Information is thrown away; if stride exceeds kernel size, pixels are skipped entirely (you found them). Strided outputs are no longer perfectly shift-equivariant: a 1-pixel shift of the input can change the output, not just move it.
  5. What refined it Stride 2 at a few chosen points (each doubling channels), anti-aliased downsampling (blur before striding), and transposed convolutions to go back up (Lesson 4.3).

Channels: real images are 3 layers deep

A colour image is three grids stacked: red, green and blue. So a kernel is really k × k × C_in: one 3 × 3 slice for each input channel. At each position it does one big dot product across all 27 numbers and outputs one number. That's one output channel. Want 64 output channels (64 different patterns)? Use 64 kernels.

weights = k · k · C_in · C_out    parameters = k · k · C_in · C_out + C_out (one bias per output channel)
output shape = H_out × W_out × C_out    multiply-adds = H_out · W_out · C_out · k · k · C_in

The next layer's input channels are this layer's output channels. That's how depth builds up: layer 1 finds 64 kinds of edges and colours; layer 2's kernels are 3 × 3 × 64, mixing combinations of those edges into corners and textures.

The 1 × 1 convolution: a tiny dense layer at every pixel

A 1 × 1 kernel looks at one pixel only, so it can't see shapes. What it does see is all C_in channels of that pixel. It computes a weighted mix of them, the same mix at every pixel. Below, a 1 × 1 conv with three weights turns an RGB picture into one channel.

What you should see: k = 1, C_in = 256, C_out = 64 costs only 16,448 parameters, while the same channel change with a 3 × 3 kernel costs 147,520. In the mixer, the grey preset is a classic brightness formula; “red − green” makes the red square glow and pushes the green background negative. A learned 1 × 1 conv does this with dozens of channels at once.

🤔 Why this? 1 × 1 convolution
  1. The problem before Deep layers carry hundreds of channels, and a 3 × 3 conv's cost grows with C_in × C_out: 3 × 3 from 256 to 256 channels is 589,824 weights, and every one is used at every position.
  2. What people tried Fewer channels everywhere (less capacity), or bigger, slower networks.
  3. Why this works A 1 × 1 conv is a small dense layer applied to each pixel's channel vector: it mixes channels without looking at neighbours. Use it to squeeze 256 channels to 64 (16,448 parameters), do the expensive 3 × 3 work at 64 channels, then expand back. Network in Network (2013) introduced the idea, and GoogLeNet (2014) used 1 × 1 convolutions “mainly as dimension reduction modules” to remove computational bottlenecks.
  4. What it costs, when it fails It sees no spatial context at all, so it can't replace 3 × 3 layers, only sit between them. Squeezing too hard (256 → 8) throws information away.
  5. What refined it ResNet's bottleneck block (1 × 1 down, 3 × 3, 1 × 1 up) and MobileNet's depthwise-separable conv, which is a per-channel 3 × 3 followed by a 1 × 1 (both in Lesson 3.4).

Convolution or cross-correlation?

A pedantic but common interview question. In maths, a convolution flips the kernel before sliding it; sliding it without flipping is called cross-correlation. Deep-learning libraries all do cross-correlation and call it convolution: PyTorch's Conv2d documentation says exactly that. It doesn't matter for learning, because the kernel is learned: the network would just learn the flipped version. It matters only when you copy a hand-made kernel from a signal-processing textbook. The maths course works through both: math 8.3b.

🧰 Tools you'll actually use

nn.Conv2d(in_channels, out_channels, kernel_size, stride=1, padding=0) as a layer, F.conv2d(x, weight) as a function. Tensors are (batch, channels, height, width); the weight is (C_out, C_in, k, k). padding="same" works for stride 1 only.

import torch, torch.nn as nn, torch.nn.functional as F

x = torch.arange(25.).reshape(1, 1, 5, 5)            # (batch, channels, height, width)
k = torch.tensor([[-1., 0., 1.]] * 3).reshape(1, 1, 3, 3)   # vertical-edge kernel
print(F.conv2d(x, k).shape, F.conv2d(x, k, padding=1).shape, F.conv2d(x, k, stride=2).shape)
# one output by hand: the top-left 3×3 window times the kernel, summed
print(F.conv2d(x, k)[0, 0, 0, 0].item(), (x[0, 0, :3, :3] * k[0, 0]).sum().item())

conv = nn.Conv2d(3, 64, kernel_size=3, stride=1, padding="same")
print(conv.weight.shape, conv.bias.shape)              # one 3×3×3 kernel per output channel
print(conv(torch.randn(8, 3, 32, 32)).shape)

squeeze = nn.Conv2d(256, 64, kernel_size=1)            # 1×1 conv: mixes channels, keeps H×W
print(sum(p.numel() for p in squeeze.parameters()), squeeze(torch.randn(1, 256, 14, 14)).shape)

Gotcha: the general formula in the PyTorch docs also has dilation d (gaps inside the kernel, Lesson 3.3): ⌊(n + 2p − d·(k − 1) − 1)/s⌋ + 1. With d = 1 it's the formula above.

🎤 Interview angle

“A 3 × 3 conv with 128 filters, stride 2, padding 1, on a 56 × 56 × 64 input. Output shape and parameter count?” A strong answer, out loud:

  • Output side: ⌊(56 + 2 − 3)/2⌋ + 1 = 28 → 28 × 28 × 128.
  • Parameters: 3 · 3 · 64 · 128 + 128 = 73,856. Multiply-adds: 28 · 28 · 128 · 576 ≈ 57.8 million.
  • Knows that each kernel spans all 64 input channels, that the bias is per output channel, and that “same” padding with stride 2 halves the size.
  • Bonus: frameworks compute cross-correlation; a 1 × 1 conv is a per-pixel dense layer across channels.
🏭 In the real world
Hand-made kernels in image editors 🧰 Open source GIMP: Convolution Matrix filter

How: you type a kernel's numbers (sharpen, blur, edge detect, emboss) and the editor slides it over the photo.

Why this method: a convolution is the simplest local filter there is: one dot product per pixel, any effect you can describe as “combine each pixel with its neighbours”.

A big, strided first layer 📜 History · 2012 AlexNet

How: its first layer filters the 224 × 224 × 3 image with 96 kernels of size 11 × 11 × 3 at a stride of 4 pixels.

Why this method: stride 4 cuts the positions 16× right away, which made the rest of the network affordable on 2012 GPUs. Later networks replaced big kernels with stacks of 3 × 3 (Lesson 3.3).

1 × 1 bottlenecks 🧪 Research · 2014 Szegedy et al.: Going Deeper with Convolutions (GoogLeNet)

How: 1 × 1 convolutions shrink the channel count before each expensive 3 × 3 and 5 × 5 branch of the Inception module.

Why this method: it cut computation enough for a 22-layer network that, per the paper, used 12× fewer parameters than AlexNet while being significantly more accurate.

Downsampling by stride 🧪 Research · 2015 He et al.: Deep Residual Learning (ResNet)

How: ResNet downsamples “directly by convolutional layers that have a stride of 2”, doubling the channel count each time the resolution halves.

Why this method: learned downsampling, and the doubling keeps the compute per layer roughly constant as the maps shrink.

🤯 Fun fact · nobody actually convolves

The documentation of OpenCV's filter2D, one of the most used image-filtering functions anywhere, admits that it computes correlation, not convolution. PyTorch's Conv2d docs say the same: the operator is the “valid 2D cross-correlation”. The name “convolutional network” stuck anyway, because with learned kernels the flip makes no difference.

Check yourself

1. Input 64 × 64 × 32. Conv layer: 5 × 5 kernels, 48 filters, stride 1, padding 2. What's the output shape and the parameter count?
Side: ⌊(64 + 4 − 5)/1⌋ + 1 = 64 (p = 2 is “same” for 5 × 5). Depth = number of filters = 48. Parameters: 5 · 5 · 32 · 48 = 38,400 weights + 48 biases = 38,448. Each filter spans all 32 input channels; forgetting that gives 1,248.
2. A teammate's model crashes: the last conv's output is 3 × 3 but the classifier expects 4 × 4. The input is 32 × 32, and there are three 3 × 3 convs with stride 2 and no padding. What happened?
Valid convs lose k − 1 before the stride divides, and the floor drops leftovers: ⌊29/2⌋ + 1 = 15, ⌊12/2⌋ + 1 = 7, ⌊4/2⌋ + 1 = 3. Padding 1 gives ⌊31/2⌋ + 1 = 16, then 8, then 4. Always run the formula (or a dummy tensor) through every layer.
3. A block has 256 channels, and the 3 × 3 conv inside it is too expensive. What's the standard fix?
The 3 × 3 at 256 → 256 costs 589,824 weights. 1 × 1 (256 → 64) + 3 × 3 (64 → 64) + 1 × 1 (64 → 256) is 16,384 + 36,864 + 16,384 = 69,632 weights (biases aside), about 8.5× fewer. That's the ResNet bottleneck (Lesson 3.4). Removing padding barely changes the cost; a 7 × 7 makes it worse.
📝 TL;DR
  • A conv slides a k × k kernel over the input and takes a dot product at each position; the output is a feature map of “how much of this pattern is here”.
  • Kernels summing to 1 keep brightness (blur, sharpen); kernels summing to 0 react only to change (edges). CNNs learn their kernels.
  • Output size = ⌊(n + 2p − k)/s⌋ + 1. “Same” padding p = (k − 1)/2 keeps the size; stride 2 halves it.
  • A kernel is k × k × C_in, one per output channel: parameters = k·k·C_in·C_out + C_out; compute = H_out·W_out·C_out·k·k·C_in.
  • 1 × 1 convs mix channels per pixel (squeeze 256 → 64 for 16,448 parameters). Libraries compute cross-correlation; with learned kernels it doesn't matter.
