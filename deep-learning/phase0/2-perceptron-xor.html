Phase 0 · Lesson 2

The perceptron and the XOR problem

In 1958 a machine that learned from its mistakes made headlines. In 1969 a four-point puzzle helped knock neural networks out of fashion for over a decade. You'll run both, and then fix the puzzle in two minutes.

🧰 You'll need (quick reminders)
  • A neuron computes a weighted sum z = w₁x₁ + w₂x₂ + b and bends it; with a step bend it says 1 if z > 0, else 0 (Lesson 0.1).
  • The points where z = 0 form a straight line: one neuron separates classes with one line (Lesson 0.1).
🎯 Hook

July 1958. The U.S. Office of Naval Research shows reporters a room-sized IBM 704 that, after 50 trials, has taught itself to tell punch cards marked on the left from cards marked on the right. Its creator, Cornell psychologist Frank Rosenblatt, calls it the perceptron.

The next day the New York Times headline reads “New Navy Device Learns By Doing”. The story says the Navy expects the machine to “walk, talk, see, write, reproduce itself and be conscious of its existence.”

Eleven years later, a book by two MIT researchers showed what a perceptron can't learn, using a problem with just four points that a child can solve. What is that problem, why can no single perceptron ever solve it, and what's the fix that today's networks are built on?

The perceptron: a neuron that learns from mistakes

A perceptron is the step neuron from Lesson 0.1 plus a learning rule. Show it an example. If it's right, do nothing. If it's wrong, nudge the weights toward the right answer:

w ← w + η · (y − ŷ) · x     b ← b + η · (y − ŷ)

Read it in words. y − ŷ (truth minus prediction) is 0 when right, +1 when it said 0 but should have said 1, and −1 when it said 1 but should have said 0. So a missed “yes” adds the input to the weights (the score for that input goes up); a false alarm subtracts it. η (eta, the learning rate) is the step size; we'll use 1.

✏️ Worked example: one epoch of AND, by hand

AND outputs 1 only for (1, 1). Start with w = (0, 0), b = 0. One pass through all four examples is an epoch.

Input xTruth yz = w·x + bSays ŷUpdate
(0, 0)000 ✓none
(0, 1)000 ✓none
(1, 0)000 ✓none
(1, 1)100 ✗w = (0,0) + 1·(1−0)·(1,1) = (1, 1), b = 0 + 1 = 1

One mistake, one fix. But now z(0, 0) = 1 > 0: the next epoch it wrongly says “yes” for (0, 0) and subtracts. It wobbles for a few epochs, then settles on w = (2, 1), b = −2, a line that gets all four right. In the playground below you'll see it take 5 epochs.

🤔 Why this? The perceptron learning rule
  1. The problem before McCulloch–Pitts neurons (1943) could compute logic, but a person had to choose every weight. A machine that “sees” needs hundreds of weights; nobody can set those by hand.
  2. What people tried Hand-wiring; hand-written rules for each pattern.
  3. Why this works Each mistake moves the weights toward the input that was misjudged, so the score for that input rises (or falls) by η·|x|². Concretely: after the miss on (1, 1) above, its score went from 0 to 1 + 1 + 1 = 3. And there's a theorem (Novikoff, 1962): if some line separates the classes, the rule finds one after a finite number of mistakes. It's also tiny: no gradients, just add or subtract.
  4. What it costs, when it fails If no line separates the classes, it never stops: it keeps fixing one mistake by causing another (XOR, below). It only works for one layer of step neurons, since it needs to know the right answer for each neuron, and hidden neurons don't have one. And it stops at the first line that works, not the best one.
  5. What refined it Smooth activations plus gradient descent (Lesson 0.1's training, then backprop in Lesson 1.2), which can train hidden layers. The perceptron's “nudge toward the input” survives inside every gradient: for a sigmoid neuron the update is also error × input.

🔮 Predict: AND, OR and XOR each have four points. XOR says 1 when exactly one input is 1: (0,1) and (1,0) are “yes”, (0,0) and (1,1) are “no”. The perceptron learns AND in 5 epochs. How many for XOR: 2, 10, or never?

The hype, and the book

Rosenblatt built hardware too: the Mark I Perceptron (1958), now in the Smithsonian. Its middle layer was an array of potentiometers, literal adjustable knobs, in a cabinet labelled PERCEPTRON. Reporters loved it; the New Yorker called it “the first serious rival to the human brain ever devised.”

Marvin Minsky at MIT was the leading skeptic, and he and Rosenblatt debated in public. In 1969 Minsky and Seymour Papert published Perceptrons, a careful mathematical book showing what single-layer perceptrons can and cannot compute. Among the things they can't: XOR, and whether a picture is one connected shape.

⚠️ Careful with the legend

The story is often told as “one book killed neural networks”. The book is at the center of a long-running controversy, and it's fair to say it pushed many researchers and funders away from perceptrons toward symbolic AI. But the first broad “AI winter” (roughly the mid-1970s) also had other causes, such as the UK's 1973 Lighthill report and DARPA's cuts to academic AI research. Rosenblatt died in 1971, before neural networks came back. It was already known that networks with more layers of threshold units can compute XOR (McCulloch and Pitts had wired logic out of neurons in 1943); what was missing was a way to train the hidden layer. That arrived in 1986 with backpropagation.

Why one line can't do XOR

Draw it: the two “yes” points sit on one diagonal, the two “no” points on the other. Any straight line that puts both yes-points on one side puts at least one no-point there too. You can prove it with four inequalities. A step neuron needs:

InputNeedsInequality
(0, 0) → 0z ≤ 0b ≤ 0
(1, 0) → 1z > 0w₁ + b > 0
(0, 1) → 1z > 0w₂ + b > 0
(1, 1) → 0z ≤ 0w₁ + w₂ + b ≤ 0

Add the middle two rows: w₁ + w₂ + 2b > 0, so w₁ + w₂ + b > −b. And −b ≥ 0 by the first row. So w₁ + w₂ + b > 0, which breaks the last row. No weights can satisfy all four. Don't take the algebra's word for it, though:

What you should see: 75% comes easily: any line that cuts off one corner gets 3 of 4. Then you're stuck. Even 1,000 random lines never beat 75%. That's the inequality proof, made physical. A problem a single line can separate is called linearly separable; XOR isn't, and neither are most interesting problems (a cat photo, a spiral, a circle inside a ring).

The fix: a hidden layer

XOR is “OR, but not AND”. One line can do OR; another line can do AND. So use two neurons to draw two lines, then a third neuron to combine their answers. The first two form a hidden layer: their outputs aren't the final answer, they're new features the last neuron reads.

h₁ = step(x₁ + x₂ + b₁)    h₂ = step(x₁ + x₂ + b₂)    out = step(v₁h₁ + v₂h₂ + c)

What you should see: the defaults make both hidden neurons OR, so the network is just OR: 3 of 4. Slide b₂ to −1.5 and h₂ becomes AND (x₁ + x₂ must exceed 1.5). Now look at the right-hand picture: (0, 1) and (1, 0) both land on the same hidden point (1, 0), while (0, 0) → (0, 0) and (1, 1) → (1, 1). In the hidden space, XOR is linearly separable. Set v₂ = −2 (“AND counts against”) and all four turn green. The hidden layer didn't make the last neuron smarter; it moved the points so a line works.

💡 Big idea One neuron draws one line. A hidden layer draws several lines and turns each input into a new set of coordinates (“which side of each line am I on?”). Problems that are hopeless in the original coordinates can become a straight cut in the new ones. Learning those coordinates automatically is what deep learning is. How depth multiplies this power is Lesson 0.3.
🧠 Analogy: sorting socks in the dark

You can't tell matching pairs apart by any single measurement. So you ask two helper questions: “is at least one of them striped?” and “are both striped?”. Neither helper solves the task. But a pair where the first answer is yes and the second is no is exactly the mismatched pair. Hidden neurons are helpers that ask the right in-between questions; training (Phase 1) is how a network figures out which questions to ask.

Why couldn't the perceptron rule just learn the hidden layer? It needs the right answer for each neuron, and nobody tells you what h₁ “should” be. The step function makes it worse: its slope is 0, so there's no signal saying which hidden weight to nudge. The cure needed two pieces: a smooth bend with a usable slope (sigmoid, Lesson 0.4) and a way to pass blame backwards through layers (backpropagation, Lesson 1.2).

🧰 Tools you'll actually use

You'd never use the perceptron rule in practice, but it's ten lines with tensors, and the hand-wired XOR network is the same nn.Linear layers every real model uses:

import torch

X = torch.tensor([[0., 0], [0, 1], [1, 0], [1, 1]])
targets = {"AND": torch.tensor([0., 0, 0, 1]), "XOR": torch.tensor([0., 1, 1, 0])}

def perceptron(X, y, lr=1.0, epochs=10):
    w, b = torch.zeros(2), torch.tensor(0.)
    for epoch in range(1, epochs + 1):
        mistakes = 0
        for x, t in zip(X, y):
            pred = float(w @ x + b > 0)           # step activation
            if pred != t:                         # wrong → nudge toward the answer
                w += lr * (t - pred) * x
                b += lr * (t - pred)
                mistakes += 1
        if mistakes == 0:
            return f"learned in {epoch - 1} epochs: w={w.tolist()}, b={b.item()}"
    return f"still {mistakes} mistakes after {epochs} epochs"

for name, y in targets.items():
    print(name, "→", perceptron(X, y))

# The fix: a hidden layer (weights set by hand, like the playground)
hidden = torch.nn.Linear(2, 2)
out = torch.nn.Linear(2, 1)
with torch.no_grad():
    hidden.weight[:] = torch.tensor([[1., 1], [1, 1]])
    hidden.bias[:] = torch.tensor([-0.5, -1.5])     # h1 = OR, h2 = AND
    out.weight[:] = torch.tensor([[1., -2]])
    out.bias[:] = -0.5                               # OR and not AND = XOR
step = lambda z: (z > 0).float()
print("XOR net:", step(out(step(hidden(X)))).squeeze().tolist())

# What we got on a laptop CPU (torch 2.8):
# AND → learned in 5 epochs: w=[2.0, 1.0], b=-2.0
# XOR → still 4 mistakes after 10 epochs
# XOR net: [0.0, 1.0, 1.0, 0.0]

In real code you'd swap the step for a smooth activation and let an optimizer find the weights; Lab 0 trains exactly this XOR network with nn.Sequential. For a perceptron on tabular data, scikit-learn has sklearn.linear_model.Perceptron.

Approach✅ Gains❌ Costs
Single perceptronTiny, fast, guaranteed to converge when a line existsOnly straight-line boundaries; loops forever on XOR-like data

🎤 Interview angle

“Why can't a single-layer perceptron learn XOR, and how do you fix it?” A strong answer:

  • A single neuron's decision boundary is a line (hyperplane); XOR's classes sit on opposite diagonals, so it isn't linearly separable. The four inequalities contradict each other.
  • The perceptron rule converges if and only if the data is separable (Novikoff); on XOR it cycles forever.
  • Fix: a hidden layer (e.g. OR and AND neurons, then OR-and-not-AND), or a hand-made feature like x₁·x₂.
  • Training that hidden layer needs a differentiable activation and backpropagation, the 1986 breakthrough.
🏭 In the real world
The Mark I Perceptron 📜 History · 1958 Smithsonian National Museum of American History: Mark I Perceptron

How: built at the Cornell Aeronautical Laboratory with Office of Naval Research funding; sensory units, an array of potentiometers as the adjustable association layer, and response units.

Why this method: Rosenblatt wanted a physical model of how a brain might learn to perceive, not just a program. The museum got it from Cornell in 1967.

Hype, debate and the AI winter 📜 History · 1958–1971 Cornell Chronicle: Professor's perceptron paved the way for AI, 60 years too soon

How: the 1958 demo, the newspaper headlines, the Rosenblatt–Minsky debates and the 1969 book, told by people who were there.

Why this method: a single layer learned simple patterns, but nobody yet knew how to train more layers; as Thorsten Joachims puts it in the article, the functions were “too simple”.

The book that drew the limits 📜 History · 1969 Minsky & Papert: Perceptrons (MIT Press)

How: proved what single-layer perceptrons can't compute, including parity (XOR is its two-input case) and connectedness.

Why this method: careful math instead of demos; its limits are exactly the linear-separability limit you just hit.

Hidden units that learn features 🧪 Research · 1986 Rumelhart, Hinton & Williams: Learning representations by back-propagating errors

How: back-propagation adjusts every weight, including hidden ones, to shrink the output error (Lesson 1.2).

Why this method: in their words, the ability to create useful new features distinguishes it from the perceptron-convergence procedure: hidden units “come to represent important features of the task domain”.

Perceptrons inside a CPU 🧪 Research · 2001 Jiménez & Lin: Dynamic Branch Prediction with Perceptrons

How: a processor guesses whether each if will be taken using a perceptron per branch, fed by the history of recent branches, trained online with the perceptron rule.

Why this method: it's cheap enough for hardware and scales linearly with history length; with a 4 KB budget it cut misprediction rates on SPEC 2000 by 10.1% versus the gshare predictor.

🤯 Fun fact · one extra input dissolves XOR

Feed a single perceptron a third input, x₁·x₂ (1 only for (1, 1)). Now z = x₁ + x₂ − 2·x₁x₂ − 0.5 gets all four right: 0 → −0.5, (1,0) and (0,1) → 0.5, (1,1) → −0.5. The problem wasn't the neuron, it was the coordinates. A hidden layer is a machine for learning such features instead of guessing them.

Check yourself

1. A perceptron has w = (1, −1), b = 0, η = 1. It sees x = (0, 1) with truth y = 1. What are the weights after this example?
z = 1·0 + (−1)·1 + 0 = −1, so it says 0: a missed “yes”. Update: w ← w + 1·(1 − 0)·(0, 1) = (1, 0); b ← 0 + 1 = 1. Only the weight of the input that was present (x₂ = 1) changed. Now z(0, 1) = 0 + 0 + 1 = 1 > 0: fixed.
2. You run the perceptron rule on a 2-feature dataset for 1,000 epochs and it still makes mistakes every epoch, with weights that keep cycling. What's the most likely explanation?
The convergence theorem only promises an answer if a separating line exists. When it doesn't (XOR, overlapping classes, a few wrong labels), every fix breaks something else and the weights cycle. The learning rate only rescales the weights (from w = 0 it doesn't even change which line is found). Fixes: a hidden layer (0.3), extra features, or a smooth loss that accepts some errors (logistic regression, Lesson 0.1's training).
3. You may add one extra input to a single perceptron on XOR's four points. Which one makes it solvable?
x₁ + x₂ and x₁ − x₂ are weighted sums of inputs the neuron already has, so they can't change which lines are possible. The product x₁·x₂ is new information (1 only at (1, 1)): z = x₁ + x₂ − 2·x₁x₂ − 0.5 solves XOR. Non-linear features break the one-line limit; hidden layers learn them.
📝 TL;DR
  • Perceptron (Rosenblatt, 1958) = step neuron + rule: if wrong, w ← w + η(y − ŷ)x. Converges whenever a separating line exists; AND takes 5 epochs here.
  • XOR isn't linearly separable: the four inequalities contradict, the best single line gets 75%, and the rule cycles forever.
  • Minsky & Papert's Perceptrons (1969) proved these limits; it's linked (with other causes like funding cuts) to the 1970s AI winter.
  • Fix: a hidden layer. Two neurons (OR, AND) re-map the points so one more neuron can cut them with a line.
  • Training hidden layers needs a smooth activation and backprop (1986): Lessons 0.4 and 1.2.
