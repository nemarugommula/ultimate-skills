Multi-layer networks: why depth helps

One hidden layer can, in theory, draw any curve. So why does every modern model stack dozens of layers? Twenty ReLUs will answer it: in one layer they make 21 straight pieces, in ten layers 1,024.

🧰 You'll need (quick reminders)
  • A neuron is a weighted sum plus a bend: f(w·x + b) (Lesson 0.1).
  • A hidden layer re-maps the inputs so a line can separate them: two neurons (OR, AND) solved XOR (Lesson 0.2).
  • ReLU(z) = max(0, z): 0 for negative inputs, the input itself for positive ones. Lesson 0.4 explains why it's the default; here we only need its shape, a hinge.
🎯 Hook

You have exactly 20 ReLU units to draw a zig-zag line. Put all 20 in one hidden layer and the best you can make is 21 straight pieces: each unit adds at most one bend. Arrange the same 20 units as 10 layers of 2 and the network draws a sawtooth with 1,024 straight pieces. Same parts, about 50× more detail.

Meanwhile, a famous 1989 theorem says a network with just one hidden layer can approximate any reasonable function as closely as you like. ResNet went to 152 layers in 2015, and every large language model stacks dozens of blocks.

If one layer is enough in theory, what does depth actually buy? You'll fit curves with hinges, fold a line with layers, and race a wide network against deep ones with the same number of parameters.

Layers build features out of features

In Lesson 0.2 the hidden layer computed two features (“at least one input on”, “both on”) and the output neuron combined them. Stack more layers and each one builds on the last: in image networks, the first layers respond to edges and colour blobs, the next to textures and parts, later ones to whole objects (Zeiler and Fergus made famous pictures of this in 2013; Lesson 3.6 shows how). Nobody programs these features: training discovers whatever helps lower the loss.

🧠 Analogy: a factory line

A car factory doesn't turn raw steel into a car in one step. Station 1 cuts sheets, station 2 bends them into panels, station 3 welds panels into a body. Each station only needs to know what the previous one hands it. A deep network is a factory for features: every layer turns the last layer's output into something a bit more useful, and the final layer only has to make a simple decision.

Numbers first: one ReLU is a hinge

Look at one hidden unit with a single input: ReLU(x − 1). For x ≤ 1 it's flat at 0; after x = 1 it rises with slope 1. A hinge at x = 1. The weight sets how steep it rises (and which way it faces), the bias sets where the hinge is (at x = −b/w).

The output neuron adds hinges up with its own weights. Watch three hinges make a bump:

Formula, if you like it: ŷ(x) = c + s·x + Σᵢ aᵢ·ReLU(x − kᵢ). The kᵢ are your dots (hidden biases); aᵢ, s and c are the output layer, fitted by least squares (math 8.1). The slope term s·x is just one more hinge parked off the left edge.

🤔 Why this? Hidden layers
  1. The problem before One neuron draws one straight line (Lesson 0.1). XOR, circles, spirals, cat photos: most real boundaries are curved, and the best single line on XOR gets 75% (Lesson 0.2).
  2. What people tried Hand-made features (add x², x₁·x₂, edge detectors) feeding one trainable layer. It works when you can guess the features; for images and text nobody could.
  3. Why this works Each hidden unit contributes one bend (a hinge for ReLU, a soft step for sigmoid). The output adds them, so N units can trace a curve with N bends; three hinges already make a bump, and bumps can build anything. The hidden weights are learned, so the network invents its own features.
  4. What it costs, when it fails More parameters and compute; no closed-form answer, so you need gradient training (backprop, Lesson 1.2) which can land in so-so solutions; more capacity to memorise noise (overfitting, Lesson 2.4); harder to interpret.
  5. What refined it Going deeper instead of only wider (below), better bends (0.4, 0.5), and tricks that make deep stacks trainable: initialization (1.4), residual connections (2.2), normalization (2.3).

Universal approximation: the promise and the catch

In 1989 George Cybenko (for sigmoid units) and Kurt Hornik, Maxwell Stinchcombe and Halbert White (for a broad class of bends) proved a universal approximation theorem: a network with one hidden layer can approximate any continuous function on a bounded region as closely as you want, if it has enough hidden units. Your hinge playground is the 1-D version: enough bumps, any curve.

Read the fine print, though. The theorem says such a network exists. It doesn't say:

  • how many units. With one input you needed about one hinge per bend. With 2 inputs, a naive grid of bumps at 10 positions per input already needs 10² = 100; with 10 inputs, 10¹⁰. Real inputs have thousands of dimensions;
  • that training will find it, or that it will work on new data rather than just memorising the training set.
💡 Big idea One wide layer can represent anything, the way a lookup table can: by spending a unit on every little piece. Depth lets the network reuse pieces. A later layer applies the same computation to everything the earlier layers produced, so the number of pieces can multiply with each layer instead of adding.

Why depth wins: folding the line

Here is the cleanest example of “multiply, not add” (Telgarsky, 2016). Two ReLUs make a tent: on 0…1, t(x) = 2·ReLU(x) − 4·ReLU(x − 0.5) goes up from 0 to 1 and back down to 0. It folds the interval in half. Feed the tent's output into another tent and the interval is folded twice: 2 teeth. Every layer of 2 units doubles the number of straight pieces.

What you should see: each extra layer doubles the pieces: 2, 4, 8, … 256 at L = 8. The deep net spends 2 units per layer (16 units, 49 parameters at L = 8). A one-hidden-layer net gains at most one bend per unit, so it needs 255 units (766 parameters) for the same shape, and given only 16 units its best fit is nearly a flat line through the middle. That's the depth separation result: some functions that a deep net computes with a handful of units need exponentially many in a shallow one.

🧠 Analogy: folding paper before you cut

Fold a strip of paper in half 5 times and make one cut across it: you get dozens of pieces from a single snip. Each layer of a deep network is a fold; the next layer's simple cut is applied to every folded copy at once. A one-layer network can't fold: it has to make every cut separately.

Theory backs this up in several forms (careful: these are statements about what can be represented, not about what training finds):

  • Montúfar, Pascanu, Cho and Bengio (2014): deep ReLU networks can split their input space into a number of linear regions that grows exponentially with depth, by re-using pieces of computation.
  • Telgarsky (2016): there are functions computed by deep, narrow ReLU nets that shallower nets can only approximate with exponentially many units (your sawtooth is his example).
  • Eldan and Shamir (2016): a simple function computed by a small 3-layer net that any 2-layer net needs width exponential in the input dimension to approximate: even one extra layer can be worth exponentially much width.
🤔 Why this? Going deep instead of wide
  1. The problem before A single hidden layer can represent anything but may need absurd width: 255 units for a sawtooth that 16 deep units draw, and a count that explodes with the number of input dimensions.
  2. What people tried Very wide shallow networks, kernel methods and hand-designed features, which ruled the 2000s on many tasks.
  3. Why this works Composition: each layer applies its computation to all the pieces made by the layers before, so pieces multiply (2 × 2 × 2 …) instead of adding. Real data seems to be built this way too (edges → textures → parts → objects; letters → words → phrases), so a deep stack is a good fit for it.
  4. What it costs, when it fails Deep stacks are harder to train: the gradient is multiplied once per layer and can vanish or explode (Lessons 0.4 and 2.1); before 2010 networks deeper than a few layers often didn't train at all. Each layer also adds latency, because layers run one after another.
  5. What refined it ReLU (0.4), good initialization (1.4), residual connections (2.2) and normalization (2.3) made 100+ layers trainable: ResNet reached 152 layers in 2015. Today's networks are both deep and wide; how to balance them is an engineering question (scaling laws, Lesson 6.8).

✏️ Worked example: counting parameters by hand

A layer from nin to nout units has nin × nout weights (every input connects to every unit) plus nout biases. Add the layers up.

  • 2 → 8 → 8 → 1 (Lesson 0.4's style): (2·8 + 8) + (8·8 + 8) + (8·1 + 1) = 24 + 72 + 9 = 105.
  • 784 → 128 → 10 (a classic digit classifier on 28×28 images): (784·128 + 128) + (128·10 + 10) = 100,480 + 1,290 = 101,770. Almost all of it is the first layer: wide inputs are expensive (one reason Phase 3 uses convolutions for images).
  • One GPT-2 small MLP block, 768 → 3,072 → 768: (768·3,072 + 3,072) + (3,072·768 + 768) = 4,722,432. GPT-2 small has 12 such blocks: 56.7 million parameters in MLPs alone.

Rule of thumb: parameters ≈ sum of (width of layer × width of next layer). Doubling every width roughly quadruples the parameters; doubling the depth only doubles them.

🧰 Tools you'll actually use

In PyTorch an MLP (multi-layer perceptron: stacked fully connected layers with bends) is an nn.Sequential of nn.Linear and activation modules. Count parameters with sum(p.numel() for p in model.parameters()). And the folding trick really works with tensors:

import torch, torch.nn as nn

def mlp(sizes):                       # Linear → ReLU → Linear → … → Linear
    layers = []
    for n_in, n_out in zip(sizes, sizes[1:]):
        layers += [nn.Linear(n_in, n_out), nn.ReLU()]
    return nn.Sequential(*layers[:-1])  # no ReLU after the last layer

for sizes in ([2, 44, 1], [2, 12, 10, 1], [2, 8, 8, 8, 1]):
    n = sum(p.numel() for p in mlp(sizes).parameters())
    print(f"{str(sizes):16s} {n} parameters")

gpt2_mlp = nn.Sequential(nn.Linear(768, 3072), nn.GELU(), nn.Linear(3072, 768))
print("one GPT-2-small MLP block:", sum(p.numel() for p in gpt2_mlp.parameters()))

# Depth folds the line: compose a 2-ReLU "tent" L times and count the straight pieces
tent = lambda x: 2 * torch.relu(x) - 4 * torch.relu(x - 0.5)
x = torch.linspace(0, 1, 2**16 + 1, dtype=torch.float64)
y = x
for L in range(1, 11):
    y = tent(y)
    slope_sign = torch.sign(torch.diff(y))
    pieces = int((slope_sign[1:] != slope_sign[:-1]).sum()) + 1
    if L in (1, 5, 10):
        print(f"{L:2d} layers × 2 ReLUs = {2 * L:2d} units → {pieces} straight pieces")

🎤 Interview angle

“The universal approximation theorem says one hidden layer is enough. Why go deep?” A strong answer:

  • The theorem is about existence: it allows the width to be enormous and says nothing about training or generalization.
  • Composition: deep ReLU nets can produce a number of linear regions exponential in depth (Montúfar et al.); some functions need exponentially many units if shallow (Telgarsky; Eldan & Shamir). The sawtooth is the classic example.
  • Real data is hierarchical, so features of features are a natural fit, and depth reuses them.
  • The cost: optimization difficulty (vanishing/exploding gradients), handled by ReLU, He init, residuals and normalization. Can count parameters by hand: Σ (nin·nout + nout).
🏭 In the real world
One hidden layer is universal 🧪 Research · 1989 Hornik, Stinchcombe & White: Multilayer feedforward networks are universal approximators

How: proved that one hidden layer with a squashing activation can approximate a very broad class of functions, given enough hidden units (Cybenko proved a sigmoid version the same year).

Why this method: it settled that neural networks are expressive enough in principle, which is why the open questions moved to efficiency and training.

Depth multiplies linear regions 🧪 Research · 2014 Montúfar, Pascanu, Cho & Bengio: On the Number of Linear Regions of Deep Neural Networks

How: counted how many flat regions a ReLU (or maxout) network can carve the input space into.

Why this method: deep networks “re-use pieces of computation exponentially often” in depth, a precise version of the folding picture.

The sawtooth separation 🧪 Research · 2016 Telgarsky: Benefits of depth in neural networks

How: networks with Θ(k³) layers and constant width that any network with O(k) layers can only approximate with Ω(2ᵏ) nodes.

Why this method: composing a simple tent map is the cleanest way to show that shallow nets must pay exponentially for what depth gets cheaply.

152 layers, once depth became trainable 🧪 Research · 2015 He et al.: Deep Residual Learning for Image Recognition (ResNet)

How: residual connections let networks up to 152 layers (8× deeper than VGG) train well; an ensemble reached 3.57% error on the ImageNet test set and won ILSVRC 2015.

Why this method: depth helped only once the optimization problem was fixed; the paper opens with “deeper neural networks are more difficult to train” (Lesson 2.2).

An MLP inside every transformer block 🧰 Open source · 2019 OpenAI GPT-2 source code (model.py)

How: each of GPT-2 small's 12 blocks contains an MLP that widens 768 → 3,072 (4×) and back, with a GELU bend (Lesson 0.5).

Why this method: attention mixes information between tokens; the MLP is where each token's features get transformed, and it holds a large share of the parameters (Lesson 6.4).

🤯 Fun fact · one more layer can beat any width

Eldan and Shamir's 2016 result has a striking punchline: for one specific, simple function, adding just one layer (going from 2 layers to 3) saves an amount of width that grows exponentially with the number of inputs. A single extra fold can be worth more than any amount of extra units laid side by side.

Check yourself

1. How many parameters (weights + biases) does an MLP with layer sizes 3 → 16 → 16 → 2 have?
(3·16 + 16) + (16·16 + 16) + (16·2 + 2) = 64 + 272 + 34 = 370. 336 is the weights alone (48 + 256 + 32): it forgets the 16 + 16 + 2 = 34 biases. The safe habit: write each layer as nin·nout + nout, then add.
2. A teammate says: “The universal approximation theorem proves one hidden layer can fit anything, so let's use a single hidden layer with 50,000 units instead of a 6-layer network.” What's the best reply?
Universal approximation is an existence result: enough units can represent the function. It doesn't bound the width (it can be exponential), and it doesn't promise that gradient descent finds those weights or that they generalize. Composition lets depth multiply pieces, which is why practical models are deep (and wide).
3. You build a 5-layer network with nn.Linear layers but forget the activations between them. Trained on a circle-inside-a-ring dataset, it's stuck near 50% accuracy. Why?
A linear function of a linear function is linear (2·(3x + 1) − 1 = 6x + 1), so the stack collapses to one weighted sum plus bias: one line. A line through a disc can get about half right. Put a ReLU between the layers and the same network bends its boundary into a circle easily.
📝 TL;DR
  • Each hidden ReLU is a hinge; an output layer adds hinges up, so N units give up to N bends (three make a bump). Placement matters as much as count.
  • Universal approximation (1989): one hidden layer can approximate any continuous function, given enough units. It says nothing about how many, or whether training finds them.
  • Depth composes: each layer acts on everything before, so pieces multiply. 10 layers × 2 ReLUs = 1,024 pieces; one layer of 20 gives at most 21.
  • At an equal budget of 177 parameters, deeper nets trained faster on spiral and moons; on a circle it was a tie. Depth helps most on structured, repeated patterns.
  • Parameters per layer = nin·nout + nout. Deep stacks need good bends, init, residuals and normalization to train (0.4, 1.4, 2.2, 2.3).
