Recap: Neurons & networks

From one weighted sum to the SwiGLU block inside today's LLMs: the neuron, the perceptron and its XOR wall, why layers and depth help, the bends between layers, and what the output layer says. The phase on one page, a game, a network to design yourself, and Lab 0.

🧾 Cheat sheet

🔢

0.1 A neuron

z = w·x + b, output = f(z). Boundary: the line w·x + b = 0.

Weights = how much each input matters; bias = a threshold you slide. Scaling all knobs together moves nothing. Sigmoid neuron + log loss = logistic regression; gradient (p − y)·x.

🧰 nn.Linear, torch.sigmoid, nn.BCEWithLogitsLoss

🚧

0.2 Perceptron & XOR

If wrong: w ← w + η(y − ŷ)x. Converges iff a separating line exists. One line on XOR: 75% max.

1958 hype, 1969 limits (Minsky & Papert). The fix is a hidden layer (OR, AND → XOR); training it needed smooth bends and backprop (1986).

🧰 sklearn.linear_model.Perceptron, two nn.Linear layers

🏗️

0.3 Layers & depth

Params per layer = n_in·n_out + n_out. One layer of N ReLUs: ≤ N + 1 pieces; L layers of 2: 2ᴸ.

Hidden units are hinges; one wide layer can approximate anything (1989) but may need huge width. Depth composes and reuses features; it costs trainability.

🧰 nn.Sequential, sum(p.numel() for p in m.parameters())

〰️

0.4 Activations I

Gradient × slope at every layer: sigmoid ≤ 0.25 (0.25¹⁰ ≈ 10⁻⁶); ReLU slope = 1 for z > 0.

No bend = the stack collapses to one line. ReLU is the hidden-layer default; its price is dead units (high LR). Sigmoid/tanh live on in outputs and gates.

🧰 nn.ReLU, nn.LeakyReLU, kaiming_normal_

✨

0.5 Activations II

GELU = z·Φ(z), SiLU = z·σ(z); SwiGLU = (Swish(xW) ⊗ xV)W₂ with hidden ≈ 2/3·4d.

ELU: negative side, mean near 0. GELU/SiLU: smooth, never dead. Gates multiply a learned dial by a learned value. Gains are small and show at scale.

🧰 nn.GELU, nn.SiLU, nn.ELU, F.glu

🎯

0.6 Output layers

Yes/no → sigmoid; tags → sigmoid each; one-of-K → softmax; number → linear. softmax(z/T); subtract the max.

Logit gap 1 = ×2.72 in probability; shifts change nothing. Temperature never changes the ranking. e⁸⁹ = inf in float32. Confidence ≠ correctness.

🧰 F.cross_entropy (logits!), torch.logsumexp, torch.softmax

🗣️ Teach it back

Answer out loud, like in an interview: “Start from one neuron and build up to the feed-forward block of a modern LLM. At each step, tell me what the previous version couldn't do and why the new piece fixes it. Then tell me how the last layer turns the network's numbers into an answer.”

A strong answer covers: a weighted sum plus bias draws one line; the perceptron learns a line but loops forever on XOR; a hidden layer re-maps points so a line works, and stacking layers composes features (pieces multiply with depth, while one wide layer needs a unit per bend); a bend is needed or layers collapse; sigmoid's slope ≤ 0.25 makes gradients vanish, ReLU's slope 1 fixes that but units can die; GELU/SiLU smooth it; SwiGLU adds a multiplicative gate, with the hidden width cut to 2/3 to keep parameters equal. At the output: logits, then sigmoid/softmax/linear by the shape of the answer, stable softmax by subtracting the max, temperature for sharpness, pair with cross-entropy, and a reminder that softmax confidence isn't calibrated.

🏗️ Build it yourself: the support-ticket router

✏️ The problem

Each incoming support ticket has already been turned into a 512-number vector by an off-the-shelf text-embedding model (the AI Engineer course's embeddings lesson covers how). From that vector your network must output, at once:

  1. which of 8 teams should handle it (exactly one);
  2. any of 5 flags: billing, outage, security, legal, VIP (zero, one or several);
  3. the expected hours to resolve (from 0.1 to about 500).

Design the network: layers and sizes, hidden activation, each output head with its activation and loss, and the parameter count. Name three bugs you'd guard against. Then open the reveal.

Reveal: one good answer

Architecture

  • A shared trunk: 512 → 256 → 128 with ReLU (GELU works too; at this size the difference is small, Lesson 0.5). Two hidden layers so the heads can share features of features (Lesson 0.3).
  • Team head: Linear(128, 8) → 8 logits → softmax with cross-entropy (exactly one team; Lesson 0.6).
  • Flag head: Linear(128, 5) → 5 logits → an independent sigmoid each with binary cross-entropy (flags overlap and can all be off).
  • Hours head: Linear(128, 1), no activation, trained to predict log(hours) with mean squared error, since 0.1 to 500 spans more than three orders of magnitude; at prediction time, exp() it.

Parameters, by hand

  • Trunk: (512·256 + 256) + (256·128 + 128) = 131,328 + 32,896 = 164,224.
  • Heads: (128·8 + 8) + (128·5 + 5) + (128·1 + 1) = 1,032 + 645 + 129 = 1,806.
  • Total: 166,030. Tiny: it trains in seconds on a CPU. The first layer holds 79% of it (wide inputs are expensive).

Training recipe (preview of Phase 1)

  • Loss = CE(team) + BCE(flags) + λ·MSE(log hours), with λ chosen so no head dominates; He init for the ReLU layers; Adam; a validation set held out.
  • In PyTorch: F.cross_entropy(team_logits, team), F.binary_cross_entropy_with_logits(flag_logits, flags), F.mse_loss(hours_out, hours.log()), all fed raw outputs.

Bugs to guard against

  • Softmax on the flag head (can't say “security and outage”, can't say “no flags”).
  • Applying softmax/sigmoid before a loss that expects logits (double squashing: weak, wrong gradients).
  • Forgetting the activation between trunk layers (the trunk collapses to one linear map).
  • A sigmoid or ReLU on the hours head (caps the answer, or zero gradient below 0).
  • A hand-written softmax without the max subtraction (NaN once logits grow).
  • Trusting “97% sure it's billing”: check calibration on held-out tickets and fit a temperature if needed (Lesson 9.6).

What this design doesn't cover yet: how to train it well (Phase 1: losses, backprop, optimizers, learning rate), how to stop it memorising the training tickets (Lesson 2.4), and how to debug it when the loss won't go down (Lesson 2.6).

🏆 Boss quiz

1. How many parameters does an MLP with layer sizes 10 → 32 → 32 → 3 have?
(10·32 + 32) + (32·32 + 32) + (32·3 + 3) = 352 + 1,056 + 99 = 1,507. 1,440 is the weights alone; don't forget one bias per unit (Lesson 0.3).
2. The perceptron rule has run 500 epochs on a 2-feature dataset and still makes mistakes every epoch. Which change can actually fix it?
The rule converges whenever a separating line exists, so endless mistakes mean no line exists (XOR-like data, or noisy labels). From zero weights, the learning rate only rescales the same answer, and more epochs just loop. A hidden layer or a new feature changes what can be separated (Lesson 0.2).
3. A classic transformer MLP has d = 2,048 and hidden size 8,192 (two matrices). For a SwiGLU block with the same number of weights, the hidden size should be about…
SwiGLU has three d × h matrices instead of two, so h = 2/3 × 8,192 ≈ 5,461 keeps 2·d·8,192 = 3·d·h (Lesson 0.5). Real models round to a hardware-friendly multiple.
4. Two classes with logits [3, 1]. What is the probability of the first class at temperature T = 2?
Divide by T: [1.5, 0.5], a gap of 1. Softmax with a gap of 1 gives σ(1) = 1 / (1 + e−1) = 0.731. At T = 1 the gap is 2 and it would be σ(2) = 0.88. Higher temperature, flatter, same ranking (Lesson 0.6).
5. A 10-layer MLP with sigmoid hidden units trains, but the first layers' weights barely change, and the layer-1 gradient is 10⁻⁷ of the last layer's. Best first fix?
Each sigmoid layer multiplies the gradient by at most 0.25, so ten layers shrink it toward 10⁻⁶ or less: vanishing gradients. ReLU's slope is exactly 1 for active units; He init keeps the weights' part near 1 too (Lessons 0.4 and 1.4). The output layer isn't the problem, and more sigmoid layers make it worse.

📝 TL;DR
  • A neuron = weighted sum + bias + bend; one neuron draws one line, so XOR needs a hidden layer.
  • Layers build features; depth composes (pieces multiply), width adds. Count parameters as Σ n_in·n_out + n_out.
  • Hidden bends must pass gradients: ReLU (slope 1) beat sigmoid (≤ 0.25); GELU/SiLU smooth it; SwiGLU gates it and runs most open LLMs.
  • The output layer is a contract: sigmoid, sigmoids, softmax or linear. Softmax(z/T) with the max subtracted, fed to cross-entropy as logits, and never mistaken for calibrated certainty.
