LSTM and GRU: gates that remember

The vanilla RNN forgets because its memory is rewritten and squashed at every step. The fix, from 1997, is a memory lane where information rides along untouched unless a gate decides otherwise. It powered Google Translate, voice transcription and a decade of NLP.

🧰 You'll need (quick reminders)
  • An RNN updates ht = tanh(W ht−1 + U xt + b); the gradient from k steps back is a product of k factors W·tanh′, so it vanishes (Lesson 5.2).
  • Sigmoid outputs 0 to 1, a natural dial; tanh outputs −1 to 1, a signed value (Lesson 0.4).
  • Element-wise multiply ⊙: multiply two vectors slot by slot.
🎯 Hook

In 2016 Google described GNMT, its production neural machine translation system: a deep stack of LSTMs, 8 encoder and 8 decoder layers. In side-by-side human evaluation on simple sentences, it reduced translation errors by an average of 60% compared with the old production system. A year earlier, Google had rebuilt voicemail transcription with LSTMs and its error rate settled at roughly half the old system's.

The LSTM wasn't new. Hochreiter and Schmidhuber published it in 1997, claiming it could bridge time lags “in excess of 1000 discrete-time steps”, when the RNN you just measured struggles past 20.

What single design change buys a 50× longer memory? You'll operate an LSTM cell by hand with gate sliders, then race it against a vanilla RNN over 100 steps.

Numbers first: multiply vs add

A vanilla RNN's memory passes through W and tanh at every step, so the gradient from k steps back is a product of k factors, each usually below 1. What if the memory were updated by adding instead?

The new memory, the cell state c, is changed by multiplying with a number the network chooses (the forget gate) and then adding new information. No weight matrix, no squashing on the way through. If the network wants to remember, it sets f ≈ 1 and the gradient flows back almost untouched.

💡 Big idea Give the network a separate memory lane (the cell state) that is updated additively, and let it learn gates, 0-to-1 valves, that decide what to erase, what to write and what to show. The gradient along the lane is just the product of forget-gate values, which the network can hold near 1.
🧠 Analogy: a conveyor belt with three workers

The cell state is a conveyor belt running through time. At each step three workers stand by it. The forget worker decides how much of each item on the belt to throw away (0 = all of it, 1 = keep everything). The input worker decides how much of a newly proposed item to place on the belt. The output worker decides what part of the belt to show to the outside world right now. Items nobody touches ride along unchanged for as long as you like.

The four pieces, one at a time

Every piece reads the same two things, the new input xt and the previous output ht−1, each through its own weights:

PieceFormula (in words first)RangeJob
Forget gate f“how much old memory to keep”: σ(Wf[ht−1, xt] + bf)0–1Erase selectively
Input gate i“how much of the new proposal to write”: σ(Wi[…] + bi)0–1Protect memory from irrelevant inputs
Candidate g“what new value is proposed”: tanh(Wg[…] + bg)−1 to 1The content to write (signed)
Output gate o“how much of the memory to reveal”: σ(Wo[…] + bo)0–1Keep a memory private until it's needed
ct = f ⊙ ct−1 + i ⊙ g ht = o ⊙ tanh(ct)

Why sigmoid for gates and tanh for values? A gate is a valve: “keep 0%… 100%” is exactly sigmoid's 0–1 range, and its saturation is a feature here (a gate can snap fully open or shut). The candidate is content, which can be positive or negative, so it uses zero-centred tanh. This is where the sigmoid and tanh you met in Lesson 0.4 still earn their keep.

✏️ Worked example: one LSTM step by hand (1 unit)

Memory ct−1 = 0.8. This step the gates come out as f = 0.9, i = 0.1, o = 0.5, and the candidate is g = −0.5 (a distracting input).

  1. Keep: 0.9 × 0.8 = 0.72. Write: 0.1 × (−0.5) = −0.05. New memory ct = 0.67.
  2. Show: ht = 0.5 × tanh(0.67) = 0.5 × 0.585 = 0.292.
  3. Gradient along the belt: ∂ct/∂ct−1 = f = 0.9. No weight matrix, no tanh′. Ten such steps: 0.9¹⁰ = 0.35; the vanilla RNN at 0.5 per step had 0.001.

Parameters: each of the 4 pieces is an RNN-sized layer. With 128 hidden units and 300-number inputs, PyTorch's nn.RNN has 55,040 parameters, nn.GRU 165,120 (3×), nn.LSTM 220,160 (4×).

🤔 Why this? The LSTM cell state
  1. The problem before In a vanilla RNN the gradient from k steps back is a product of k factors W·tanh′; you measured 6 × 10⁻⁷ at 20 steps for w = 0.5, and only a knife-edge band of weights survived. Hochreiter's 1991 thesis had already analysed this “decaying error backflow”.
  2. What people tried Careful weight initialization, second-order optimizers, and gradient clipping (which only fixes the exploding side).
  3. Why this works Add a memory path with an additive update: ct = f·ct−1 + i·g. Along it the gradient is multiplied only by f, a number the network controls, not by a weight matrix and a squashing slope. The 1997 paper called this the “constant error carousel” and reported bridging lags of more than 1,000 steps on synthetic tasks.
  4. What it costs, when it fails 4× the parameters and compute of a vanilla RNN per step; still strictly sequential (step t waits for step t−1); and the memory is still a fixed-size vector, so very long or very detailed contexts get squeezed. Gradients through the gates' own paths can still vanish.
  5. What refined it The forget gate (2000, next), peephole connections, the simpler GRU (below), and then attention (Lesson 5.4) and transformers (Phase 6). The same “add, don't overwrite” idea reappears as residual connections (Lesson 2.2).

🤔 Why this? The forget gate
  1. The problem before The 1997 LSTM had no forget gate: its cell was ct = ct−1 + i·g (f fixed at 1). Perfect for remembering, but on a long continuous stream the state only accumulates and can grow without bound, with no way to reset when one “episode” ends and the next begins.
  2. What people tried Resetting the state by hand at sequence boundaries, which needs someone to know where the boundaries are.
  3. Why this works Gers, Schmidhuber and Cummins, Learning to Forget (2000), multiplied the old cell by a learned gate f, “enabling the LSTM to reset its own state” (as a later review puts it). Now the network learns when to keep (f ≈ 1) and when to wipe (f ≈ 0). A huge 2015 study of LSTM variants found the forget gate to be one of the two most critical components.
  4. What it costs, when it fails f < 1 reintroduces decay: f = 0.9 for 100 steps leaves 0.00003. If f starts near 0.5 (bias 0, the usual default), the gradient vanishes at first just like an RNN's (you'll see it in the race below).
  5. What refined it Initializing the forget-gate bias to 1 or more so the cell starts by remembering: Jozefowicz, Zaremba and Sutskever (2015) found that “adding a bias of 1 to the LSTM's forget gate closes the gap between the LSTM and the GRU”. The GRU (next) ties forgetting and writing into one gate.

The race: RNN vs LSTM over 100 steps

Same question as Lesson 5.2: how much does the state at the end depend on the state k steps back? The vanilla RNN gets its best setting (w = 1, light noise). The LSTM's forget gate is σ(bf + noise), so it hovers around σ(bf); we follow the gradient along the cell state (the belt).

GRU: the same idea with fewer parts

Cho and colleagues (2014) proposed a lighter cell, later named the gated recurrent unit (GRU). It drops the separate cell state and output gate and uses two gates:

  • Update gate z: how much of the old state to keep. The rest (1 − z) is filled with the new candidate. One dial for both “forget” and “write”.
  • Reset gate r: how much of the old state to use when proposing the candidate.
h̃ = tanh(W xt + U (r ⊙ ht−1)) ht = z ⊙ ht−1 + (1 − z) ⊙ h̃

(Cho et al. and PyTorch use this convention, z = keep. Some texts swap z and 1 − z.)

🤔 Why this? GRU (gated recurrent unit)
  1. The problem before The LSTM works but has 4 weight blocks, a separate cell and hidden state, and many design choices (peepholes, gate couplings). Is all of it needed?
  2. What people tried Variants that remove or couple LSTM parts. A 2015 study ran 5,400 experiments on eight variants and found none significantly better than the standard LSTM, but coupling input and forget gates didn't hurt much.
  3. Why this works The GRU builds that coupling in: “keep z, write 1 − z” is still an additive, gated update, so the gradient along ht → ht−1 includes a direct factor z that can sit near 1. Three weight blocks instead of four (165,120 vs 220,160 parameters at 128 units, 300 inputs). Chung et al. (2014) found the GRU “comparable to LSTM”.
  4. What it costs, when it fails No separate output gate, so the whole memory is always exposed; tying keep and write means it can't both keep everything and write something new in the same unit. On some tasks LSTM wins, on others GRU: no universal winner.
  5. What refined it Attention on top of either cell (Lesson 5.4), then transformers. Gated designs live on: GLU-style gates in transformer feed-forward layers (Lesson 0.5) and the input-dependent gates of Mamba (Lesson 9.3).

The 2017 transformer paper put the problem plainly: recurrence's “inherently sequential nature precludes parallelization within training examples”. A GPU can process 1,000 tokens at once in attention, but an LSTM must take 1,000 steps in order. Attention also reaches any earlier token in one hop instead of through a chain of gates. LSTMs remain a sensible choice for small streaming models where constant memory per step matters.

🧰 Tools you'll actually use

nn.LSTM and nn.GRU are drop-in replacements for nn.RNN (the LSTM also returns the cell state). Parameter counts, a forget-bias init, and the gradient race for real:

import torch, torch.nn as nn

torch.manual_seed(0)
H, X = 128, 300
for cls in (nn.RNN, nn.GRU, nn.LSTM):
    m = cls(X, H, batch_first=True)
    print(f"{cls.__name__:4s} params: {sum(p.numel() for p in m.parameters()):,}")

# PyTorch packs the LSTM gates as [input, forget, cell, output]: set the forget-gate bias to 1
lstm = nn.LSTM(16, 32, batch_first=True)
with torch.no_grad():
    for name, p in lstm.named_parameters():
        if "bias" in name:
            p[32:64].fill_(0.5)        # b_ih + b_hh = 1 for the forget gate

# gradient race: how much does the last output depend on the input k steps back?
x = torch.randn(1, 200, 16, requires_grad=True)
rnn = nn.RNN(16, 32, batch_first=True)
for name, net in [("RNN ", rnn), ("LSTM", lstm)]:
    x.grad = None
    out, _ = net(x)
    out[0, -1].sum().backward()
    g = x.grad[0].norm(dim=1)
    print(name, "  ".join(f"k={k}: {g[-1 - k].item():.0e}" for k in (10, 50, 100)))

# What we got (torch 2.8, CPU):
# RNN  params: 55,040
# GRU  params: 165,120
# LSTM params: 220,160
# RNN  k=10: 2e-03  k=50: 9e-16  k=100: 0e+00
# LSTM k=10: 3e-02  k=50: 2e-06  k=100: 3e-10

The RNN's gradient at 100 steps underflowed to exactly 0 in float32. The untrained LSTM is about 15× better at 10 steps and still non-zero at 100, but not magic: training is what pushes forget gates towards 1 where memory matters. PyTorch has two bias vectors per layer (bias_ih, bias_hh), so their sum is the effective bias. Use nn.LSTM(..., num_layers=2, dropout=0.2) for stacks; bidirectional=True reads the sequence both ways (only when the whole sequence is available up front).

🎤 Interview angle

“How does an LSTM solve the vanishing gradient problem?” A strong answer:

  • Names the cell state and its additive update ct = f⊙ct−1 + i⊙g, so ∂ct/∂ct−1 = f (element-wise), not W·tanh′. With f ≈ 1 the gradient survives many steps.
  • Explains each gate and why sigmoid (0–1 valve) vs tanh (signed content).
  • Knows the forget gate was added later (Gers 2000), that bias init ≈ 1 matters, and that the GRU merges gates (z keep, 1 − z write) with comparable results.
  • Is honest about limits: still sequential (why transformers won on GPUs), fixed-size memory, not infinite memory; gradients through gate paths can still vanish.
🏭 In the real world
Google Neural Machine Translation 🏢 Google · 2016 Wu et al.: Google's Neural Machine Translation System

How: a deep LSTM network with 8 encoder and 8 decoder layers, residual connections between layers and attention from decoder to encoder (Lesson 5.4).

Why this method: LSTMs could carry sentence context that phrase-based systems lacked; residuals made 8 layers trainable. Human side-by-side ratings showed 60% fewer translation errors than the phrase-based production system.

Voicemail transcription 🏢 Google · 2015 Google Research: The neural networks behind Google Voice transcription

How: rebuilt acoustic and language models with LSTM RNNs, plus an LSTM to insert punctuation.

Why this method: memory cells let the model interpret sounds based on what came before; the recognition error rate settled at roughly half the old system's.

Which LSTM parts matter? 🧪 Research · 2015 Greff et al.: LSTM: A Search Space Odyssey

How: compared eight LSTM variants on speech recognition, handwriting recognition and polyphonic music modeling, tuning each with random hyperparameter search.

Why this method: settled years of folklore: no variant significantly beat the standard LSTM, and the forget gate and output activation were the most critical parts.

The original LSTM 📜 History · 1997 Hochreiter & Schmidhuber: Long Short-Term Memory (Neural Computation)

How: memory cells with a self-connection of weight 1 (“constant error carousels”), guarded by multiplicative input and output gates.

Why this method: constant error flow through the carousel let it bridge lags of more than 1,000 steps on synthetic tasks where earlier recurrent methods failed.

🤯 Fun fact · 15 years of CPU time to confirm the default

Greff and colleagues ran 5,400 LSTM training runs, about 15 years of CPU time, testing eight variations of the cell. The headline result: none of them improved significantly on the standard LSTM. Sometimes the best research result is “the default was right, and here's which parts you can't remove”.

Check yourself

1. An LSTM unit's forget gate sits at 0.95 for 40 steps (and its input gate at 0). What fraction of the original cell value (and of the gradient along the belt) remains?
c is multiplied by f at every step: 0.95⁴⁰ = 0.129. The cell state avoids the weight matrix and tanh′, but f < 1 still decays it. That's why the forget-gate bias matters: f = 0.99 would leave 0.67.
2. Your LSTM language model learns short-range patterns but early in training ignores everything more than ~10 tokens back. Gates were initialized with all biases 0. What's a cheap, well-supported fix?
Bias 0 gives f ≈ 0.5, so the belt halves every step and the gradient vanishes like a vanilla RNN's. A positive forget bias (Gers et al. 2000; Jozefowicz et al. 2015) starts the cell in “remember” mode. ReLU gates would no longer be 0–1 valves; removing the forget gate loses the ability to reset.
3. Why did transformers replace LSTMs for large-scale NLP, even though LSTMs can remember hundreds of steps?
ht depends on ht−1, so training on a 1,000-token sequence is 1,000 sequential steps, while a GPU can run attention over all 1,000 at once. Direct access also beats passing information through hundreds of gate multiplications. The 2017 transformer paper makes exactly this argument.
📝 TL;DR
  • LSTM = a cell state (memory belt) updated additively, c = f⊙c + i⊙g, plus h = o⊙tanh(c). Along the belt the gradient is multiplied only by f.
  • Gates use sigmoid (0–1 valves); the candidate uses tanh (signed content). 4 weight blocks: 4× an RNN's parameters.
  • The forget gate (Gers 2000) lets the cell reset; init its bias ≈ 1 so it starts by remembering.
  • GRU: update gate z keeps, 1 − z writes; reset gate; 3 blocks, often as good as LSTM.
  • Still sequential and fixed-size: attention (5.4) and transformers (Phase 6) fix both.
