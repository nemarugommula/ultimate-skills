Phase 5 · Lesson 2

Recurrent networks and backprop through time

A network that reads one word at a time and carries a running memory forward. One tiny loop gives it the power to handle sentences of any length, and one tiny multiplication explains why it forgets.

🧰 You'll need (quick reminders)
  • Words become vectors via an embedding table (Lesson 5.1).
  • tanh squashes to (−1, 1); its slope is 1 at 0 and falls to 0.07 by z = 2 (Lesson 0.4).
  • Backprop multiplies local slopes along a path (the chain rule, math 3.2); a deep stack of slopes below 1 makes the gradient vanish (Lesson 2.1).
🎯 Hook

In 2015 Andrej Karpathy concatenated all of Shakespeare into one 4.4 MB text file and trained a 3-layer recurrent network with 512 hidden units per layer, for a few hours, to do one thing: predict the next character. It produced new “plays” with character names, line breaks and archaic spelling. He then trained on 474 MB of Linux source code and got C code that opens and closes brackets correctly, indents well and sprinkles in comments (it won't compile: it uses variables it never declared).

The network never saw a grammar, a play format or a C compiler. It reads one character, updates a small vector it carries along, reads the next one… That vector has to remember that a quote or a brace is still open, hundreds of characters later.

How does a fixed-size vector remember a whole sequence? And why does it remember the last 10 characters far better than the 100th one back? You'll step through a network's memory by hand, then measure exactly how fast it forgets.

The recurrent cell: one loop

A recurrent neural network (RNN) keeps a hidden state h, a vector of, say, 128 numbers that acts as its memory. At each step t it reads one input xt and updates the memory. In words: new memory = squash(old memory mixed by one weight matrix + new input mixed by another):

ht = tanh(W ht−1 + U xt + b)

W (hidden × hidden) decides how the old memory carries over, U (hidden × input) how the new word gets written in, and tanh keeps every number in (−1, 1) so the memory can't blow up on the forward pass. The same W, U, b are used at every step. Elman's 1990 paper “Finding Structure in Time” popularised this “simple recurrent network”.

Unrolled: one cell copied over time, all copies share the same W and U. Each step can also emit an output yt = Vht.

💡 Big idea An RNN is a for-loop with learned weights: h = 0; for x in sequence: h = tanh(W @ h + U @ x + b). The hidden state is a fixed-size summary of everything read so far, and the same weights handle step 1 and step 1,000.
🧠 Analogy: reading with a sticky note

You read a long email one word at a time, and you may keep only one sticky note of notes. After each word you rewrite the note: keep some of what was there, add something about the new word. At the end, the note is all you have to answer “who bit whom?”. The note has fixed size, so old details get crowded out. That's the RNN's whole life.

🤔 Why this? Recurrence (weight sharing over time)
  1. The problem before MLPs need a fixed input size and learn each position separately: a 100-word window with 300-number embeddings is 30,000 inputs, 7.7 million first-layer weights with 256 units, and “not good” at position 5 teaches nothing about position 50.
  2. What people tried Bags of words (order lost), fixed windows of n words (n-grams: order kept only within a few words), hand-built features.
  3. Why this works Apply the same small cell at every step and pass a state along. Parameters don't grow with length: a cell with 128 hidden units and 300-number inputs has 128 × (128 + 300) + 128 = 54,912 weights whether the text is 5 words or 5,000. A pattern learned at one position works at every position, just as a convolution filter works anywhere in an image (Lesson 3.2).
  4. What it costs, when it fails Steps must run one after another: ht needs ht−1, so a 1,000-word document is 1,000 sequential matrix multiplies (GPUs hate that). Everything must squeeze through one fixed-size vector. And the gradient through time is a long product, so it vanishes or explodes (below).
  5. What refined it Gated cells that keep memory longer (LSTM, GRU: Lesson 5.3), attention that looks back directly instead of relying on the state (5.4), and transformers that drop recurrence entirely for parallelism (Phase 6). Recurrence came back in state-space models like Mamba (Lesson 9.3), designed to be trained in parallel.

Backprop through time (BPTT)

How do W and U learn? Unroll the loop into a deep network, one layer per time step, all layers sharing weights, and run ordinary backprop on it. That's backpropagation through time. Because the weights are shared, each copy computes a gradient for W and the copies' gradients are added up.

The crucial path: how much does the final state care about an earlier one? By the chain rule, you multiply one factor per step back: the recurrent weight times tanh's slope at that step.

∂hT/∂hT−k = (W·tanh′(zT)) × (W·tanh′(zT−1)) × … × (W·tanh′(zT−k+1)) (k factors)
✏️ Worked example: a 1-number RNN, three steps, forward and back

Weights w = 0.5, u = 1, no bias. Input sequence x = [1, 0, 0] (a single “blip”, then silence). Start h₀ = 0.

Stepz = w·ht−1 + u·xtht = tanh(z)tanh′(z) = 1 − h²
10.5 × 0 + 1 × 1 = 1.0000.7620.420
20.5 × 0.762 = 0.3810.3630.868
30.5 × 0.363 = 0.1820.1800.968

The blip fades on the forward pass: 0.762 → 0.363 → 0.180. Now backwards: ∂h₃/∂h₂ = w × tanh′(z₃) = 0.5 × 0.968 = 0.484. ∂h₃/∂h₁ = 0.484 × (0.5 × 0.868) = 0.210. Each step back multiplies by roughly w × (a slope ≤ 1). With w = 0.5, twenty steps back is at most 0.5²⁰ ≈ 0.000001. The loss can't “see” the blip any more, so it can't teach the weights to remember it.

Why vanilla RNNs forget

That product is the whole story. If every factor is below 1, the gradient from far back vanishes: 0.9²⁰ = 0.12, 0.5²⁰ ≈ 10⁻⁶. If factors are above 1, it explodes: 1.3²⁰ = 190. Bengio, Simard and Frasconi's 1994 paper put it in its title: Learning long-term dependencies with gradient descent is difficult. For a full weight matrix the same holds with “the largest eigenvalue of W” in place of w: Pascanu, Mikolov and Bengio (2013) showed that for tanh, a largest eigenvalue below 1 is enough for long-term gradients to vanish, and above 1 is needed for them to explode.

And tanh makes the trap tighter: to remember strongly, the state must be big, but big states sit where tanh is flat (slope near 0), which kills the gradient anyway.

Truncated BPTT: don't backprop through the whole book

Full BPTT on a 1-million-character file would unroll a million steps and store every hidden state for the backward pass. Instead, cut the stream into chunks of K steps (say 25 to 100), carry the hidden state forward from chunk to chunk, but stop the gradient at chunk boundaries.

For 1,000 steps × batch 32 × 512 hidden units, full BPTT stores 16.4 million numbers (65.5 MB) per layer just for the states; K = 100 needs 6.6 MB, and gives 10 weight updates instead of 1. Karpathy's 112-line min-char-rnn uses a 100-unit hidden state and unrolls 25 steps; the Paul Graham essay model in his blog post used truncated BPTT of 100 characters.

🤔 Why this? Truncated BPTT
  1. The problem before Full BPTT over a sequence of length T stores T hidden states per layer (65.5 MB for T = 1,000 at batch 32, hidden 512) and makes one weight update per pass over the whole sequence. Over a whole book, that's absurd.
  2. What people tried Chopping data into short independent sentences (loses context across boundaries), or online updates after every step (noisy and expensive).
  3. Why this works Keep the forward state flowing across chunks (so context carries on) but cut the backward pass every K steps (in PyTorch: h = h.detach()). Memory and compute per update become O(K), and you get T/K updates per pass. Since vanilla RNN gradients rarely survive more than a few dozen steps anyway (you just measured it), little is lost.
  4. What it costs, when it fails The gradient can never teach a dependency longer than K steps, even if the model could in principle use one. Choose K too small and you blind it; too big and memory explodes. Chunk boundaries are arbitrary.
  5. What refined it Gated RNNs make longer K worthwhile (5.3). Transformers replace the whole idea with a fixed context window processed in parallel (Phase 6); “long context” (6.11) is the modern version of choosing K.
🧰 Tools you'll actually use

nn.RNN runs the loop for you (tanh by default); nn.RNNCell is one step. This snippet checks the formula by hand and then measures how much the last output depends on inputs k steps back:

import torch, torch.nn as nn

torch.manual_seed(0)
rnn = nn.RNN(input_size=8, hidden_size=16, batch_first=True)    # tanh by default
x = torch.randn(1, 50, 8)                                         # 1 sequence, 50 steps, 8 features
out, h_last = rnn(x)
print(out.shape, h_last.shape)                                    # every h_t, and the final one

# the same thing by hand: h_t = tanh(W_ih x_t + b_ih + W_hh h_{t-1} + b_hh)
h = torch.zeros(16)
for t in range(50):
    h = torch.tanh(rnn.weight_ih_l0 @ x[0, t] + rnn.bias_ih_l0 + rnn.weight_hh_l0 @ h + rnn.bias_hh_l0)
print(torch.allclose(h, h_last[0, 0], atol=1e-6))

# how much does the loss at the END care about the input k steps back?
x.requires_grad_(True)
out, _ = rnn(x)
out[0, -1].sum().backward()
g = x.grad[0].norm(dim=1)                                         # gradient size per time step
for k in [1, 5, 10, 20, 40]:
    print(f"{k:2d} steps back: {g[-1 - k].item():.1e}")

# What we got (torch 2.8, CPU):
# torch.Size([1, 50, 16]) torch.Size([1, 1, 16])
# True
#  1 steps back: 6.2e-01
#  5 steps back: 2.8e-02
# 10 steps back: 9.1e-04
# 20 steps back: 2.1e-07
# 40 steps back: 7.9e-15

Truncated BPTT in a training loop: keep h between chunks but call h = h.detach() before each chunk. Clip with torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0) before optimizer.step(). For batches of different lengths, nn.utils.rnn.pack_padded_sequence skips the padding.

🎤 Interview angle

“Why do vanilla RNNs struggle with long sequences?” A strong answer:

  • Writes the cell (ht = tanh(W ht−1 + U xt + b)) and explains BPTT: unroll, shared weights, gradients summed over steps.
  • The gradient from k steps back is a product of k Jacobians W·diag(tanh′): largest eigenvalue below 1 → vanishing, above 1 → can explode; tanh saturation makes it worse.
  • Fixes, matched to the problem: clipping for exploding; LSTM/GRU gates and attention for vanishing; truncated BPTT for memory, with its blind spot beyond K.
  • Bonus: the serial dependency (ht needs ht−1) is why transformers replaced RNNs for training on GPUs.
🏭 In the real world
Character-level language models 🧰 Open source · 2015 Karpathy: The Unreasonable Effectiveness of Recurrent Neural Networks

How: many-to-many RNNs (LSTMs, 2–3 layers, 512 units) predict the next character of Shakespeare, Wikipedia, LaTeX and Linux source, trained with truncated BPTT.

Why this method: characters avoid a vocabulary entirely, and recurrence handles any length; the post became many engineers' first “wow” moment with sequence models.

Why long-term dependencies are hard 🧪 Research · 2013 Pascanu, Mikolov & Bengio: On the difficulty of training recurrent neural networks

How: analysed the product of Jacobians through time (eigenvalue conditions for vanishing and exploding) and proposed norm clipping of gradients.

Why this method: clipping is one line, prevents the sudden loss spikes of exploding gradients, and is still standard in training today, including transformers (Lesson 2.1).

The simple recurrent network 📜 History · 1990 Elman: Finding Structure in Time (Cognitive Science)

How: hidden unit patterns are fed back to the network at the next step, giving it a dynamic memory; simulations ran from a temporal version of XOR to discovering syntactic and semantic features of words.

Why this method: time is represented implicitly, by its effect on the state, rather than as extra input positions; the learned representations reflected lexical categories of words.

Recurrence returns, trainable in parallel 🧪 Research · 2023 Gu & Dao: Mamba (selective state spaces)

How: a state carried along the sequence like an RNN's, but with a structure that allows parallel training (Lesson 9.3).

Why this method: constant memory per generated token like an RNN; the authors report 5× higher inference throughput than Transformers and linear scaling in sequence length.

🤯 Fun fact · a neuron that counts quotes

Looking inside his trained character model (an LSTM, Lesson 5.3), Karpathy found a single hidden unit that turned on inside quotation marks and off outside. Nobody programmed it: tracking “am I in a quote?” helped predict the next character, so one cell “gradually tuned itself during training to become a quote detection cell”.

🌉 How it connects

The product-of-slopes argument is the same one as for deep sigmoid stacks (Lesson 0.4) and the full vanishing/exploding story with clipping is Lesson 2.1; an unrolled RNN is just a very deep network with shared weights. The chain rule is math 3.2 and backprop math 3.5. Next, Lesson 5.3 adds gates and an additive “conveyor belt” so the gradient can survive hundreds of steps; 5.4 lets a decoder look back at every encoder state with attention; Phase 6 drops recurrence entirely. Check yourself

1. A 1-number RNN has recurrent weight w = 0.8 and stays where tanh′ ≈ 1. Roughly how much of the gradient survives from 10 steps back?
BPTT multiplies one factor w·tanh′ per step back: 0.8¹⁰ = 0.107. Weight sharing means the same factor appears ten times in the product, not once. At 20 steps it's 0.8²⁰ = 0.012, and any saturation makes it smaller.
2. Your RNN's training loss is smooth for 2,000 steps, then jumps to NaN. The gradient norm right before was 10⁶. What do you try first?
A sudden huge gradient is an explosion: factors above 1 multiplied over many steps. Norm clipping rescales such gradients to a threshold so one bad batch can't wreck the weights. A longer K would make it worse; sigmoid just vanishes more.
3. You train with truncated BPTT, K = 20, on a task where the answer depends on a token 50 steps earlier. Accuracy stays at chance. Why?
Truncated BPTT keeps the state flowing forward across chunks but stops the backward pass at chunk boundaries. A dependency longer than K produces no gradient signal at all. Increase K (memory permitting), or use a gated cell / attention that makes long dependencies easier (5.3, 5.4).
📝 TL;DR
  • Sequences need order and variable length; bags of words lose order, MLPs need fixed length.
  • An RNN is a learned for-loop: ht = tanh(W ht−1 + U xt + b), same weights every step, parameters independent of length.
  • BPTT = unroll and backprop; gradients from k steps back are a product of k factors W·tanh′. Below 1 → vanish (0.5²⁰ ≈ 10⁻⁶), above 1 → explode (1.3²⁰ = 190).
  • Clipping fixes explosions; nothing simple fixes vanishing in a vanilla RNN: that's what LSTMs (5.3) and attention (5.4) are for.
  • Truncated BPTT bounds memory to K steps and adds updates, but the gradient can't see past K.
