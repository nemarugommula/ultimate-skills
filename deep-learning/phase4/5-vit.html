Phase 4 · Lesson 5

Vision Transformers: ViT, DeiT, Swin, DINOv2

Cut a photo into 196 little squares, treat each square like a word, and run a language-model-style transformer over them. It sounds too naive to work. It became the image encoder behind SAM, CLIP, DINOv2 and most vision-language models.

🧰 You'll need (quick reminders)
  • A CNN's convolution looks only at a small neighbourhood and reuses the same weights everywhere (Lessons 3.1 and 3.2): built-in assumptions called inductive biases.
  • Self-attention: every token builds a query, compares it with every other token's key, and mixes their values (Lesson 6.1, math 8.4). Its cost grows with the square of the number of tokens.
  • Transfer learning: pretrain big, fine-tune small (Lesson 3.5).
🎯 Hook: the model that lost, then won

In 2020 a Google team trained a pure transformer on image patches, no convolutions at all. On ImageNet alone (1.3 million images) it scored “a few percentage points below ResNets of comparable size”, in the paper's own words. A loss.

Then they pretrained it on bigger datasets: ImageNet-21k (14 million images) and Google's internal JFT-300M (300 million). Now it matched or beat the best CNNs, reaching 88.55% on ImageNet. Their summary: “large scale training trumps inductive bias”. The paper's title: An Image is Worth 16×16 Words.

Today ViTs are the image encoders inside SAM (Lesson 4.4), CLIP (4.6), DINOv2 and DINOv3 (whose features power detectors like RF-DETR and depth models like Depth Anything 3), and the vision side of most multimodal LLMs (Lesson 8.5). Why would a model with fewer built-in assumptions need more data, and why is that a good trade?

Numbers first: an image as a sentence

Take a 224 × 224 color image. Cut it into 16 × 16 patches: 224 ÷ 16 = 14 per side, so 14 × 14 = 196 patches. Each patch is 16 × 16 × 3 = 768 numbers. Flatten each patch into a vector and you have a “sentence” of 196 “words”, each a 768-number vector.

224 × 224 × 3 pixels → 196 tokens × 768 numbers → (linear layer) → 196 tokens × D (D = 768 for ViT-Base) → + [CLS] = 197 tokens

Then it's a standard transformer encoder (12 layers for ViT-Base): every token attends to every other token in every layer. The cost of attention is the number of token pairs: 197² ≈ 38,800 per head per layer. Halve the patch size to 8 and you get 784 tokens and 16× the pairs. That's the central budget of every vision transformer.

🤔 Why this? Patches as tokens (and the patch embedding)
  1. The problem before Transformers were winning NLP, but attention over pixels is hopeless: a 224 × 224 image has 50,176 pixels, so 2.5 billion pairs per layer. Earlier vision attention was mixed into CNNs or applied to small local neighbourhoods.
  2. What people tried Attention on CNN feature maps, local attention windows on pixels, attention on very small images.
  3. Why this works A 16 × 16 patch is a sensible “word”: big enough that 196 of them cover the image (38,000 pairs, affordable), small enough to describe one piece. The patch embedding is one linear layer applied to every flattened patch, which is exactly a convolution with kernel = stride = 16 (the Tools box checks they're identical): 16 · 16 · 3 · 768 + 768 = 590,592 parameters. After that, the full transformer machinery (and its scaling behaviour) applies unchanged.
  4. What it costs, when it fails Detail below the patch size is squeezed into one vector; small objects suffer. Cost grows with the square of the token count, so high-resolution inputs (detection, segmentation) are expensive. Patches are a hard grid, cut wherever the boundaries fall.
  5. What refined it Smaller patches when compute allows (ViT-B/8, DINOv2's /14), hierarchical windows (Swin, below), token merging and pruning, and native-resolution patching (SigLIP 2's variants keep the aspect ratio, Lesson 4.6).

[CLS] and position: two things patches forget

Self-attention treats its input as a set: shuffle the 196 patches and every output is just shuffled the same way. So ViT adds two things:

  • Position embeddings: a learned 768-number vector per position (197 × 768 = 151,296 parameters), added to each patch token. Now “top-left sky patch” and “bottom-right sky patch” differ.
  • A [CLS] token: an extra learned vector prepended to the sequence (borrowed from BERT, Lesson 6.5). It isn't any patch; it attends to all of them in every layer, and its final state is the whole-image summary fed to the classifier head.

🤔 Why this? The [CLS] token (and learned position embeddings)
  1. The problem before A transformer outputs one vector per patch; a classifier needs one vector per image. And attention can't see order, so a ViT without positions is a “bag of patches”.
  2. What people tried Averaging all patch outputs (global average pooling, as CNNs do); fixed sinusoidal positions from NLP (Lesson 6.3).
  3. Why this works [CLS] is a learned “summary slot”: it has no content of its own, so each layer it gathers whatever the task needs from all patches by attention (your toy query does this by hand). It also keeps ViT identical to BERT, so NLP tricks transfer. Learned position embeddings let the model discover 2D structure itself; the ViT paper found 2D-aware variants gave little extra over plain learned 1D positions.
  4. What it costs, when it fails One more token (197 instead of 196). Learned positions are tied to the training grid: a different resolution means interpolating them. ViT's authors note averaging patches works about as well once the learning rate is tuned, so [CLS] isn't magic. Large ViTs also learn to dump attention onto a few uninformative “register-like” tokens, creating artifacts in attention maps.
  5. What refined it Rotary and relative position schemes (Lesson 6.3), extra “register” tokens to absorb those artifacts (used by DINOv2 variants and DINOv3), DeiT's second special token for distillation (below).

Why ViT needed more data

💡 Big idea A CNN is born knowing two things: nearby pixels matter together (locality), and a cat is a cat wherever it is (weights shared across positions). A ViT knows neither; it can attend from any patch to any other from layer 1. With little data, the CNN's built-in knowledge wins. With enough data, the ViT learns locality where it helps and long-range relations where they help, and its flexibility wins. Inductive bias is a prior: great when data is scarce, a ceiling when data is plentiful.

DeiT: making ViT work on ImageNet alone

DeiT (Data-efficient image Transformers, Touvron et al., Facebook AI, December 2020) showed the data hunger was partly a training recipe problem. With heavy augmentation and regularization (the ideas of Lesson 2.5), an 86 M-parameter ViT reached 83.1% top-1 on ImageNet with no external data, trained on a single computer in under 3 days. Then a trick: a second special token.

🤔 Why this? DeiT's distillation token
  1. The problem before ViT needed hundreds of millions of images and “expensive infrastructure” (DeiT's words) to beat CNNs; most teams only had ImageNet.
  2. What people tried Stronger augmentation and regularization (it helped a lot), and classic knowledge distillation: train the student to match a teacher's soft predictions (Hinton et al., 2015).
  3. Why this works Add a distillation token next to [CLS]. [CLS] learns from the true labels; the distillation token learns to match a teacher's predictions, through attention like everything else. A CNN teacher works best: the student absorbs the CNN's locality bias from its predictions, without having convolutions itself. DeiT reached up to 85.2% on ImageNet this way.
  4. What it costs, when it fails You need a good teacher trained first, and extra compute to run it during training; the student is at best roughly as good as the teacher on its strengths.
  5. What refined it Distillation became standard in vision: DINOv2's and DINOv3's small models are distilled from a giant teacher; self-distillation with no labels at all is DINO (below, and Lesson 9.1).

Swin: windows and a hierarchy

Detection and segmentation want high-resolution features at several scales, and global attention's n² cost explodes there. Swin Transformer (Liu et al., Microsoft, 2021) borrows two CNN habits:

  • Windows: attention only within non-overlapping 7 × 7 windows of patches (M = 7), so cost is linear in image size. In the next layer the windows shift by half a window, so information crosses window borders.
  • A hierarchy: start with tiny 4 × 4 patches, then merge neighbours stage by stage (1/4 → 1/8 → 1/16 → 1/32 of the image), like a CNN's feature pyramid, ready for detection heads.
✏️ Worked example: global vs windowed, with Swin's formula

Swin's first stage on a 224 image: 4 × 4 patches → a 56 × 56 grid (hw = 3,136 tokens), C = 96 channels, windows M = 7. The paper gives the attention cost as Ω(MSA) = 4hwC² + 2(hw)²C for global and Ω(W-MSA) = 4hwC² + 2M²hwC for windows. Compare the second terms (the attention itself):

global: 2 × 3,136² × 96 ≈ 1.89 billion · windowed: 2 × 49 × 3,136 × 96 ≈ 29.5 million · ratio = 3,136 ÷ 49 = 64×

Double the image side and global attention costs 16× more; windowed costs 4× more (linear in hw). That's what made transformers practical for 1,000-pixel detection inputs.

🤔 Why this? Swin's shifted windows and hierarchy
  1. The problem before Plain ViT has one coarse resolution (1/16) and quadratic cost, a poor fit for dense tasks that need fine, multi-scale features at high resolution.
  2. What people tried Plain ViT backbones with upsampling heads; sliding-window attention (expensive, awkward on GPUs).
  3. Why this works Non-overlapping windows are cheap and GPU-friendly; shifting them every other layer connects neighbouring windows, so the receptive field still grows with depth. Merging patches builds a pyramid that plugs into existing detectors (FPN, Mask R-CNN). Swin reported 87.3% top-1 on ImageNet-1K, 58.7 box AP on COCO and 53.5 mIoU on ADE20K, beating the previous state of the art by 2.7 box AP.
  4. What it costs, when it fails More complex than ViT (shift-and-mask logic, relative position biases); long-range relations take several layers to form; some of ViT's simplicity for scaling and for masked pretraining is lost.
  5. What refined it Swin V2 for larger models and resolutions; ConvNeXt (2022, Lesson 3.4) brought these design lessons back into a pure CNN; hierarchical ViTs like Hiera became SAM 2's encoder (Lesson 4.4).

DINOv2 and DINOv3: features without labels

Supervised ViTs learn what their labels ask for. DINO (2021) trained a ViT with no labels: a student network sees small crops of an image and must match a teacher (a slowly updated copy of itself) that sees larger crops. Its [CLS] attention maps turned out to outline objects, with no segmentation labels ever (Lesson 9.1 explains the method). DINOv2 (Meta, April 2023) scaled this up with a curated dataset of 142 M images (LVD-142M), a 1 B-parameter ViT distilled into smaller models, and produced “all-purpose” features that beat the strongest open image–text model (OpenCLIP) on most image- and pixel-level benchmarks without fine-tuning.

DINOv3 (Meta, August 2025) trained a 7 B-parameter ViT on about 1.7 billion curated images (LVD-1689M) and introduced Gram anchoring, which stops the per-patch (dense) features from degrading during long training, then distilled it into ViT-S/B/L and ConvNeXt models. Its dense features are strong enough that it outperforms specialized models across many tasks without fine-tuning.

🤔 Why this? DINOv2-style self-supervised features
  1. The problem before Labelled datasets are expensive and narrow: ImageNet's 1,000 classes teach “what class”, not “where are the parts” or “what's similar to what”. Text-supervised models (CLIP, Lesson 4.6) learn what captions mention and miss fine spatial detail.
  2. What people tried Supervised pretraining on ever-bigger labelled sets (JFT), weak supervision from captions, earlier self-supervised methods (SimCLR, MAE) trained on uncurated or small data.
  3. Why this works Matching a teacher across crops forces features that describe what's in the image regardless of viewpoint, scale or color: semantics and geometry, from pixels alone. Unlabelled images are nearly free, so the data and model can scale; curating the data for diversity keeps it from being dominated by a few kinds of photo. One frozen backbone then serves classification, retrieval, segmentation and depth with just a small head.
  4. What it costs, when it fails Pretraining is enormous (a 7 B teacher on 1.7 B images); the features know nothing about words, so for text queries you still need CLIP-style models; frozen features can miss domain specifics (medical, satellite) without fine-tuning (DINOv3 also released a satellite-image model).
  5. What refined it DINOv3's Gram anchoring and text alignment; DINOv2 backbones inside RF-DETR (Lesson 4.2) and Depth Anything (Lesson 4.8). The full self-supervised family is Lesson 9.1.

🧰 Tools you'll actually use

timm (PyTorch Image Models) has hundreds of ViT, DeiT and Swin variants; Hugging Face Transformers has ViT, DINOv2 and DINOv3. This script patchifies by hand, proves the patch embedding is a strided convolution, and builds a ViT-B/16 with random weights (nothing downloaded):

import torch, torch.nn as nn, timm

torch.manual_seed(0)
x = torch.rand(1, 3, 224, 224)

# 1. Patchify by hand: 16x16 patches -> 196 tokens of 16*16*3 = 768 numbers
p = 16
patches = x.unfold(2, p, p).unfold(3, p, p)                     # (1, 3, 14, 14, 16, 16)
tokens = patches.permute(0, 2, 3, 1, 4, 5).reshape(1, 14 * 14, 3 * p * p)
print("raw patch tokens", tuple(tokens.shape))

# 2. Patch embedding = a Conv2d with kernel = stride = patch size (same as a Linear on each patch)
embed = nn.Conv2d(3, 768, kernel_size=16, stride=16)
z = embed(x).flatten(2).transpose(1, 2)                         # (1, 196, 768)
lin = embed.weight.permute(0, 2, 3, 1).reshape(768, -1)         # same weights, as a Linear on (16, 16, 3) patches
z2 = tokens.reshape(1, 196, 3, p, p).permute(0, 1, 3, 4, 2).reshape(1, 196, -1) @ lin.T + embed.bias
print("conv == linear on patches:", torch.allclose(z, z2, atol=1e-5), f"{sum(q.numel() for q in embed.parameters()):,} params")

# 3. A full ViT-B/16 from timm, random weights (pretrained=False: nothing downloaded)
vit = timm.create_model("vit_base_patch16_224", pretrained=False).eval()
print(f"ViT-B/16: {sum(q.numel() for q in vit.parameters()):,} params")
print("cls token", tuple(vit.cls_token.shape), "position embeddings", tuple(vit.pos_embed.shape))
with torch.no_grad():
    feats = vit.forward_features(x)                             # (1, 197, 768): [CLS] + 196 patch tokens
print("features", tuple(feats.shape), "logits", tuple(vit.forward_head(feats).shape))

# What we got (torch 2.8, timm 1.0, CPU):
# raw patch tokens (1, 196, 768)
# conv == linear on patches: True 590,592 params
# ViT-B/16: 86,567,656 params
# cls token (1, 1, 768) position embeddings (1, 197, 768)
# features (1, 197, 768) logits (1, 1000)

Pretrained features (downloads weights; not run here): AutoModel.from_pretrained("facebook/dinov2-base") in Transformers, or timm.create_model("vit_base_patch16_224", pretrained=True). DINOv3 checkpoints such as facebook/dinov3-vitb16-pretrain-lvd1689m are on the Hugging Face Hub (you must accept a license first).

Gotcha: changing the input size of a pretrained ViT means resizing its position embeddings (timm does it with dynamic_img_size=True or when you pass a new img_size). Feed DINOv2 multiples of 14 pixels: its patch is 14.

🎤 Interview angle

“How does a Vision Transformer process an image, and when would you pick it over a CNN?” A strong answer:

  • Patchify (224/16 → 196 tokens of 768 numbers), linear patch embedding (= a strided conv), [CLS] token, learned position embeddings, standard transformer encoder, [CLS] → head.
  • Explains inductive bias: CNNs assume locality and translation equivariance and win on small data; ViTs need large pretraining or a DeiT-style recipe/distillation, then scale better.
  • Knows the cost: attention is quadratic in tokens (patch size and resolution matter), and Swin-style windows make it linear for dense tasks.
  • In practice: start from a pretrained backbone (DINOv2/v3 or CLIP/SigLIP for text-related tasks) and fine-tune; pick a CNN for tiny edge budgets.
🏭 In the real world
The paper that started it 🧪 Research · 2020 Dosovitskiy et al.: An Image is Worth 16x16 Words

How: a standard transformer encoder on 16 × 16 patches, pretrained on ImageNet-21k or JFT-300M and fine-tuned on smaller benchmarks.

Why this method: reuse the architecture that scaled in NLP; with enough data it matched or beat CNNs while needing “substantially fewer computational resources to train”.

Universal frozen features 🏢 Meta · 2025 Meta AI: DINOv3

How: a 7 B ViT trained self-supervised on ~1.7 B images, distilled into smaller ViTs and ConvNeXts; also a satellite-imagery variant.

Why this method: one backbone, no labels, strong dense features for detection, segmentation and depth with only light task heads.

A detection and segmentation backbone 🧪 Research · 2021 Liu et al.: Swin Transformer

How: shifted 7 × 7 windows and patch merging produce a feature pyramid that drops into Mask R-CNN-style detectors.

Why this method: linear cost in image size and multi-scale features; it beat the previous best COCO box AP by 2.7.

The model zoo everyone uses 🧰 Open source timm (PyTorch Image Models)

How: one create_model call for ViT, DeiT, Swin, ConvNeXt, EVA and more, with pretrained weights and training scripts.

Why this method: comparing backbones fairly on your data is the fastest way to choose one.

🤯 Fun fact · 768 = 768

A 16 × 16 RGB patch has 16 × 16 × 3 = 768 numbers, and ViT-Base's hidden size is also 768 (a size inherited from BERT-Base). So for ViT-B/16 the patch embedding maps 768 numbers to 768 numbers: a square 768 × 768 matrix (plus bias), the 590,592 parameters you counted. Pure coincidence, and a handy one to remember.

Check yourself

1. A ViT with patch size 14 runs on 518 × 518 images (as DINOv2 does). How many patch tokens, not counting [CLS]?
518 ÷ 14 = 37 patches per side, so 37² = 1,369 tokens. Compared with 196 tokens at 224/16, that's 7× the tokens and about 49× the attention pairs: why high-resolution ViTs are expensive.
2. Your team trains a ViT-Base from scratch on 50,000 labelled product photos. It overfits and scores worse than a ResNet-50 trained the same way. What's the best next step?
This is exactly the ViT paper's finding: without the CNN's built-in locality, a ViT on mid-sized data loses. Large pretraining (or a strong recipe with a CNN teacher) supplies what the architecture doesn't assume. Smaller patches multiply cost and don't add data.
3. You switch a detector's backbone from a plain ViT (global attention) to a Swin-style backbone and double the input side from 800 to 1,600 pixels. Roughly how does the attention cost change for each?
Doubling the side gives 4× the tokens. Global attention scales with tokens², so 16×; windowed attention scales with tokens × window size, so 4×. That's why hierarchical, windowed backbones dominate high-resolution dense prediction.
📝 TL;DR
  • ViT: 224² image → 196 patches of 16 × 16 × 3 = 768 numbers → linear patch embedding (= conv with kernel = stride = 16) + position embeddings + [CLS] → transformer → [CLS] → head.
  • Attention cost grows with tokens²: halve the patch and pay 16×. Swin's 7 × 7 shifted windows make it linear and add a CNN-like hierarchy for dense tasks.
  • Weak inductive bias: ViT loses to CNNs on mid-size data but wins with big pretraining (“large scale training trumps inductive bias”).
  • DeiT: ImageNet-only ViTs via a strong recipe and a distillation token learning from a CNN teacher (83.1%, under 3 days on one machine).
  • DINOv2 (2023) and DINOv3 (Aug 2025, 7 B teacher, ~1.7 B images, Gram anchoring): self-supervised features that work frozen for almost any vision task.
