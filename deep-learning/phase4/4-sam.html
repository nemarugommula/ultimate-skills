Segment Anything: promptable segmentation (SAM)

Click on anything, get its mask in a twentieth of a second, even for objects no one ever labelled for training. How Meta's SAM works, why it is split into a heavy part and a light part, how SAM 2 remembers objects through a video, and what SAM 3 added.

🧰 You'll need (quick reminders)
  • Instance masks, mask IoU, Dice and focal loss (Lessons 4.1 to 4.3).
  • A Vision Transformer (ViT) turns an image into a grid of patch tokens and runs a transformer over them (Lesson 4.5 explains it fully; here it's just “the heavy encoder”).
  • Attention lets a set of tokens look at another set and pull in what's relevant (Lesson 6.1).
🎯 Hook: a billion masks, and a click that answers in 50 ms

In April 2023 Meta released SAM together with SA-1B: 1.1 billion masks on 11 million images, 400× more masks than any segmentation dataset before it. Of those masks, 99.1% were made by the model itself.

Give SAM a click, a box or a rough mask on any photo and it returns a mask, even for things nobody labelled: a cell under a microscope, a crater, a sticker on a laptop. Once the photo is encoded, each new click takes about 50 ms in a web browser, on a CPU. Meta's November 2025 SAM 3 announcement says SAM 3 (with SAM 3D) powers Facebook Marketplace's “View in Room” feature and will power effects in Instagram's Edits app; labelling tools and robots use the SAM family every day.

How can one model segment “anything”, and why is each click so cheap when the network is huge?

The task: segment what I point at

Classic segmentation models have a fixed list of classes (Lesson 4.3). SAM's task is different: promptable segmentation. Input: an image plus a prompt (one or more points marked “object” or “not object”, a box, or a rough mask). Output: a valid mask for whatever the prompt points at. No class names: just “this thing”.

A single click is ambiguous. Click on a shirt's pocket: did you mean the pocket, the shirt, or the whole person? SAM doesn't guess one answer: it outputs three masks by default, because, in the paper's words, three layers (whole, part, and subpart) “are often enough to describe nested masks”, each with a predicted IoU score so the best can be picked. Add more clicks and the ambiguity disappears.

🤔 Why this? Promptable segmentation
  1. The problem before Every segmentation model was trained for a fixed list of classes on its own labelled data (Lesson 4.3). A new domain (cells, satellite roofs, a factory part) meant a new dataset and a new model. Interactive tools existed but needed many clicks per object.
  2. What people tried Class-specific models per domain; interactive segmentation trained on small datasets; edge-based tools like “magic wand” (the playground's cousin).
  3. Why this works Make the prompt the task, as language models did with text prompts. “Segment what I point at” is defined for any object, needs no class list, and lets one model be trained on masks of anything. It also composes: a detector's boxes or a text model's outputs can be the prompts (Lesson 4.6). The paper reports zero-shot performance “often competitive with or even superior to” fully supervised results.
  4. What it costs, when it fails SAM 1 and 2 return masks without names: “what is this?” needs another model. Ambiguous prompts need several masks or more clicks. Domains far from SA-1B's photos (medical scans, microscopy) can need fine-tuning. Fine detail (hair, thin wires) is soft at the 256 × 256 mask resolution before upsampling.
  5. What refined it SAM 2 (video), SAM 3 (prompts that are words or example images and return all matching objects with names), lighter variants (MobileSAM, FastSAM), and medical versions like MedSAM.

Heavy once, light many times

SAM has three parts:

  • Image encoder: a big ViT (pretrained as a masked autoencoder, MAE, Lesson 9.1) reads the 1024 × 1024 image and outputs an image embedding of 256 channels on a 64 × 64 grid. It runs once per image.
  • Prompt encoder: turns each click or box corner into a small vector (its position plus “positive / negative / corner” type).
  • Mask decoder: a tiny transformer where prompt tokens and image embedding attend to each other, then three output tokens become three masks and three IoU scores.
✏️ Worked example: we timed it on a laptop CPU

We built a SAM with Hugging Face's default configuration (a ViT-B-sized encoder) and random weights, so nothing was downloaded, and timed it on this course's laptop CPU (code in the Tools box):

The decoder is 22× smaller and 70× faster. Ten clicks on one photo cost 2.05 + 10 × 0.029 = 2.34 s with the split, versus 10 × (2.05 + 0.029) = 20.8 s if you reran the whole model per click: 8.9× faster, and every click after the first feels instant. (Your numbers will differ; the ratio is the point. The released SAM uses a bigger ViT-H encoder, which makes the split matter even more.)

🤔 Why this? SAM's heavy encoder / light decoder split
  1. The problem before Interactive segmentation reran a whole network after every click, so the network had to be small (weaker masks) or the tool felt slow. Annotating SA-1B meant millions of clicks; every second per mask mattered.
  2. What people tried Small networks for speed; caching some features in ad hoc ways.
  3. Why this works Put almost all the computation where it can be shared: the image doesn't change between clicks, only the prompt does. The paper: the image embedding “can be reused (and its cost amortized) with different prompts”, so they “can afford a high number of image encoder FLOPs because they are computed only once per image, not per prompt”. The decoder (about 4 M parameters) runs on a CPU in a browser in ~50 ms. Even the 3 masks come out of one decoder call.
  4. What it costs, when it fails The first click on a new image waits for the encoder (seconds on a CPU, a fraction of a second on a GPU). For video at 30 fps the encoder must run on every frame, so the split helps less. Storing embeddings (256 × 64 × 64 floats ≈ 4 MB each) adds up for big image sets.
  5. What refined it SAM 2 uses a faster hierarchical encoder (Hiera) and is 6× faster than SAM on images; MobileSAM and EfficientSAM shrink the encoder; SAM 3 shares one backbone between a detector and a video tracker.

The data engine: the model labels its own dataset

Segmentation masks aren't lying around on the internet like captions are, so Meta built them with SAM in the loop, in three stages:

StageWho does whatOutput
1. Assisted manualAnnotators click; SAM proposes masks; humans fix them. SAM is retrained 6 times as data grows, and the encoder grows from ViT-B to ViT-H.4.3 M masks on 120k images; time per mask falls from 34 s to 14 s
2. Semi-automaticSAM fills in the confident masks; humans label what it missedmore varied, less obvious objects
3. Fully automaticSAM is prompted with a grid of points on every image and keeps only confident, stable masks1.1 B masks on 11 M images
🤔 Why this? A model-in-the-loop data engine
  1. The problem before The largest segmentation datasets had a few million masks; at 30+ seconds of human time per mask, a billion was out of reach.
  2. What people tried Crowd-sourced polygons (COCO), coarse labels (Cityscapes' 20,000 coarse images), synthetic data.
  3. Why this works A flywheel: better model → faster labelling → more data → better model. Each stage moves humans from drawing to correcting to just checking quality, and the last stage costs only compute. The paper checks quality by comparing automatic masks with professional annotations.
  4. What it costs, when it fails The model's blind spots can be baked into its own data (it can't easily label what it can't see); quality depends on the filtering rules. Data collection still needed licensed, privacy-protected images (faces and plates blurred).
  5. What refined it SAM 2's video engine (SA-V: 50.9K videos, 642.6K masklets) and SAM 3's engine of 4 M unique concept labels with hard negatives; the same idea powers Depth Anything's pseudo-labels (Lesson 4.8).

SAM 2: segmenting through a video with memory

Video adds time. The object moves, turns, gets hidden behind someone, comes back. Running SAM per frame would need a click on every frame. SAM 2 (July 2024) treats an image as a one-frame video and adds a memory: after each frame, a memory encoder stores a compact summary of the frame and its predicted mask in a memory bank; on the next frame, memory attention lets the new frame's features look at those memories before the mask decoder runs. One click on frame 1 can follow the object for the whole clip, and a correction click on frame 40 is remembered from then on.

🧠 Analogy: a detective's photo wall

You're following one person through a crowd. You don't re-read their full description each second: you keep a few snapshots pinned up (“red jacket, from the side”, “same person, hood up”) and compare each new glimpse with the wall. When they vanish behind a bus you keep the wall; when they reappear, you recognize them. SAM 2's memory bank is the wall: a few recent frames plus every frame you clicked on.

🤔 Why this? SAM 2's streaming memory
  1. The problem before Image SAM has no notion of time: per-frame use needs per-frame prompts, and masks flicker or jump to other objects. Video object segmentation models existed but weren't promptable at this scale.
  2. What people tried SAM on each frame plus a separate tracker to carry the prompt forward; propagating masks with optical flow.
  3. Why this works Memory attention gives each frame direct access to how the object looked before, so appearance changes and occlusions are handled by comparison, not by a hand-made tracker. It's streaming: frames are processed one at a time with a fixed-size memory, so it works on live video. Prompts can come at any frame. The paper reports better accuracy with 3× fewer interactions than prior approaches on video, and on images it is more accurate and 6× faster than SAM.
  4. What it costs, when it fails Memory has a fixed size, so long occlusions or look-alike objects (identical twins, a flock of birds) can swap identities; cost grows with the number of objects tracked; the first frames depend on the first prompt being right.
  5. What refined it SAM 2.1 checkpoints (September 2024); SAM 3 (November 2025) adds concept prompts and a detector; SAM 3.1 (March 2026) “Object Multiplex” shares memory across objects to track many objects faster.

SAM 3: from “this thing” to “every yellow school bus”

SAM 3 (Meta, November 2025) changes what a prompt can be: a short noun phrase (the paper's example: “yellow school bus”), image exemplars (boxes around examples), or both. The task, “promptable concept segmentation”, returns masks and IDs for all matching objects in an image or video. It pairs an image-level detector with a SAM 2-style memory tracker on one shared backbone, and adds a “presence head” that first decides whether the concept is in the image at all. Meta reports it doubles the accuracy of existing systems on concept segmentation and runs in 30 ms for an image with more than 100 detected objects on an H200 GPU.

Where SAM helps, and where to be careful

  • Labelling: click-to-mask in annotation tools; auto-labelling by feeding a detector's boxes to SAM as prompts (Ultralytics ships an auto_annotate helper that does exactly this).
  • Robotics and AR: “segment the object under the gripper”, cut-outs for placing furniture in a room.
  • Video editing: one click to track and mask a person through a clip.
  • Medical images, with caveats: SA-1B is natural photos; scans look different. MedSAM fine-tuned SAM on 1,570,263 medical image-mask pairs across 10 modalities. Any clinical use needs validation on your own scanners and patients, and a human in the loop.
🧰 Tools you'll actually use

The timing experiment from the worked example: SAM from Hugging Face Transformers with its default config and random weights (no download), so the masks are garbage but the shapes and timings are real.

import time, torch
from transformers import SamConfig, SamModel

torch.manual_seed(0)
model = SamModel(SamConfig()).eval()            # default config = ViT-B sized encoder, random weights (no download)
pixels = torch.rand(1, 3, 1024, 1024)
with torch.no_grad():
    t = time.perf_counter()
    emb = model.get_image_embeddings(pixels)                    # run the heavy ViT once
    print("image embedding", tuple(emb.shape), f"{time.perf_counter() - t:.2f} s")
    pts = torch.tensor([[[[500., 400.]]]])                      # one click (x, y) in 1024-pixel coordinates
    lab = torch.tensor([[[1]]])                                 # 1 = positive click, 0 = negative
    t = time.perf_counter()
    for _ in range(10):
        out = model(image_embeddings=emb, input_points=pts, input_labels=lab, multimask_output=True)
    print("masks", tuple(out.pred_masks.shape), "scores", tuple(out.iou_scores.shape),
          f"{1000 * (time.perf_counter() - t) / 10:.0f} ms per prompt")

# masks (1, 1, 3, 256, 256) scores (1, 1, 3) 29 ms per prompt

🎤 Interview angle

“We need masks for 50,000 product photos of 300 product types. How would you use SAM?” A strong answer:

  • Auto-label: a detector (or an open-vocabulary detector, Lesson 4.6, or SAM 3 with text prompts) proposes boxes; SAM turns boxes into masks; humans review a sample and fix with clicks.
  • Explains the encoder/decoder split (encode each photo once, many prompts) and the 3-mask ambiguity output with predicted IoU scores.
  • Measures quality on a hand-labelled subset (mask IoU, Dice) before trusting the rest; then trains a small, fast model on the SAM-made labels for production.
  • Knows SAM gives masks without names, and that out-of-domain images (X-rays, microscopy) may need fine-tuning.
🏭 In the real world
Shopping and creative apps 🏢 Meta · 2025 Meta AI blog: Introducing SAM 3

How: SAM 3 and SAM 3D power Facebook Marketplace's “View in Room” (visualize a lamp or table in your space); SAM 3 effects are announced for Instagram's Edits app.

Why this method: users name or tap an object and get its exact cut-out, with no per-category model to train.

The original model and dataset 🧪 Research · 2023 Kirillov et al.: Segment Anything

How: a MAE-pretrained ViT encoder, a prompt encoder and a light mask decoder, trained with focal + Dice loss on SA-1B, built by the three-stage data engine.

Why this method: a promptable task plus a huge, diverse dataset gives zero-shot transfer to new image distributions.

Auto-annotation pipelines 🧰 Open source Ultralytics: SAM 2 docs

How: a detector's boxes are passed to SAM as prompts to create segmentation labels for a whole dataset (auto_annotate).

Why this method: boxes are cheap to get, masks are expensive; SAM converts one into the other.

Medical segmentation 🧪 Research · 2023 Ma et al.: Segment Anything in Medical Images (MedSAM)

How: SAM fine-tuned on 1,570,263 image-mask pairs from 10 imaging modalities and over 30 cancer types, prompted with boxes.

Why this method: one promptable model instead of a specialist per modality; the authors report better accuracy and robustness than modality-wise specialists on 86 internal and 60 external validation tasks.

🤯 Fun fact · 34 seconds → 14 seconds

In the first, human-driven stage of SAM's data engine, the model was retrained 6 times as the data grew, and the average time for a person to annotate one mask fell from 34 seconds to 14. By the last stage, people weren't drawing at all: 99.1% of the final billion masks were generated fully automatically.

Check yourself

1. On a GPU, the encoder takes 400 ms and the decoder 20 ms. A labelling job sends 20 box prompts per image. Roughly how much faster is “encode once” than rerunning the full model per prompt?
Rerun: 20 × (400 + 20) = 8,400 ms. Encode once: 400 + 20 × 20 = 800 ms. 8,400 ÷ 800 = 10.5×. It can never reach (400 + 20) ÷ 20 = 21× because every prompt still pays the decoder.
2. A user clicks once on a car's side mirror in SAM's demo and gets just the mirror, but wanted the whole car. What's the intended way to handle this?
One click is ambiguous (subpart, part, whole), so SAM outputs three masks with predicted IoU scores. Pick another one, or add a click: more prompts remove the ambiguity. No retraining needed.
3. You need to count and outline every “forklift” in hours of warehouse video, with no labelled data. Which tool fits best?
SAM 1 needs a prompt per object per frame and doesn't know names. SAM 3 takes a concept (a noun phrase) and returns every matching instance with identities through the video. A detector-plus-SAM 2 pipeline does the same in two steps. Semantic segmentation can't count instances.
📝 TL;DR
  • Promptable segmentation: image + clicks/box/mask → a mask for “this thing”, any object, no class list. One click is ambiguous, so SAM returns 3 masks with IoU scores.
  • Heavy ViT image encoder once per image (1024² → 256 × 64 × 64), tiny prompt encoder + mask decoder per prompt (~50 ms in a browser): cost amortized over many prompts.
  • SA-1B: 1.1 B masks on 11 M images from a model-in-the-loop data engine; 99.1% automatic.
  • SAM 2 (2024): streaming memory bank + memory attention for video; 6× faster than SAM on images, 3× fewer interactions on video.
  • SAM 3 (Nov 2025): text or exemplar prompts → all matching objects, tracked; SAM 3.1 (Mar 2026) speeds multi-object tracking. Validate before medical or safety use.
