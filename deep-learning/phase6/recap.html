Recap: Transformers

From one attention head to a million-token mixture of experts: the whole phase on one page, a game where you track down where an LLM's memory and time went, a small GPT to design yourself, and the boss quiz.

🧾 Cheat sheet

🔍

6.1 Self-attention

softmax(QKᵀ / √d) V. Divide by √d, or big dot products make softmax one-hot and gradients vanish.

Each token asks (query), advertises (key) and hands over (value). Any two tokens connect in one step, fully in parallel; the price is n² per head and layer. A causal mask hides the future.

🧰 F.scaled_dot_product_attention

🧩

6.2 Multi-head attention

h heads of size d/h: split → attend → concat → WO. Same 4d² parameters as one wide head.

One softmax per token blurs different relations; heads specialise (previous token, coreference). Typical head size 64–128 (GPT-3: 96 × 128). Many heads are prunable after training.

🧰 nn.MultiheadAttention, view + transpose

🧭

6.3 Positional encodings

RoPE: rotate q and k by position × frequency, so q·k depends only on the distance.

Attention is permutation-blind, so positions must be injected. Learned tables cap the length; sinusoids are clock hands; RoPE (Llama, Qwen) and ALiBi put distance into the score.

🧰 rotary embeddings in HF models, rope_theta

🧱

6.4 The transformer block

x + Attn(Norm(x)), then x + MLP(Norm(x)). Pre-norm trains deep stacks without warm-up.

Attention mixes across tokens (4d²), the MLP works per token (8d², or SwiGLU), the residual stream is a running sum with a slope-1 gradient path. GPT-2 small: 124M parameters.

🧰 nn.RMSNorm, nn.LayerNorm, SwiGLU

🔀

6.5 Encoder, decoder, both

Same block, three masks: full (BERT), causal (GPT), full + causal + cross-attention (T5, Whisper).

Encoders read (embeddings, classification); decoders write (chat, code). Decoder-only won for general LLMs: one objective, prompting for any task, simple serving.

🧰 AutoModel, AutoModelForCausalLM, AutoModelForSeq2SeqLM

✂️

6.6 Tokenization

BPE: start from bytes or characters, repeatedly merge the most frequent adjacent pair until the vocabulary is full.

Byte-level BPE (GPT-2) means no token is ever unknown. Bigger vocabularies mean fewer tokens per text: Llama 3's 128K vocabulary packs 3.94 English characters per token vs 3.17 for Llama 2's. Token counts drive cost, context use and odd failures (digits, spelling).

🧰 tiktoken, HF tokenizers, SentencePiece

🎓

6.7 Pretraining objectives

Next-token: predict t+1 from ≤ t, loss on every token. Perplexity = eloss.

MLM masks 15% (80/10/10) and sees both sides; span corruption (T5) rewrites missing spans. Teacher forcing + causal mask train all positions in one pass. SFT and RLHF/DPO turn the base model into an assistant.

🧰 F.cross_entropy with shifted labels, DataCollatorForLanguageModeling

📈

6.8 Scaling laws

C ≈ 6·N·D. Compute-optimal: N and D both ∝ √C, about 20 tokens per parameter.

Loss is a power law (Kaplan: 10× params → loss × 0.84). Chinchilla 70B beat Gopher 280B on the same budget. Over-train small models when serving dominates (Llama 3 8B: 15T tokens).

🧰 log-log fits, a ladder of small runs

⚡

6.9 Efficient attention

KV bytes = 2 · layers · kv_heads · head_dim · tokens · batch · bytes. Llama 3 8B: 128 KiB/token.

Decoding is memory-bound (~1 FLOP/byte). GQA/MQA/MLA shrink the cache; FlashAttention tiles attention in SRAM with an online softmax: exact, O(n) memory, far less HBM traffic.

🧰 SDPA (is_causal, enable_gqa), flash-attn, vLLM

🏥

6.10 Mixture of experts

Router picks top-k of E expert MLPs per token. Memory follows total params; compute follows active.

Mixtral 46.7B / 12.9B; DeepSeek-V3 671B / 37B. Without balancing, routing collapses: aux loss α·E·Σf·P (α = 0.01), capacity and dropped tokens, or DeepSeek-V3's bias nudging.

🧰 HF MoE models, vLLM / SGLang expert parallelism

📜

6.11 Long context

Prefill grows with n², the KV cache with n. Past training length, scale RoPE (PI, NTK, YaRN) and fine-tune.

Sliding windows cap cost (Mistral W = 4,096); attention sinks keep streams stable; ring attention spreads exact attention over GPUs. Models lose the middle; RULER beats needle tests.

🧰 rope_scaling, sliding_window, RULER

🗣️ Teach it back

Answer out loud, like in an interview: “I type ‘The capital of France is’ into a decoder-only LLM. Walk me through what happens to those characters, step by step, until the model outputs a probability for the next token. Then tell me what changes when it generates the second token, and what limits how long my prompt can be.”

texttokensembeddingspositionsblocks × Lfinal normlogitssoftmaxnext tokenKV cache

A strong answer covers: BPE turns text into token ids (6.6); an embedding table maps ids to vectors; RoPE rotates queries and keys by position (6.3); each pre-norm block runs causal multi-head attention and an MLP with residuals (6.1, 6.2, 6.4); a final norm and the unembedding matrix give one logit per vocabulary entry; softmax (with temperature) gives probabilities, trained by next-token cross-entropy (6.7). For the second token only the new token runs through the model, reusing cached keys and values (6.9); prompt length is limited by the trained positions, n² prefill and KV-cache memory (6.11).

🏗️ Build it yourself: a small code-completion GPT

✏️ The problem

Your company wants its own code-completion model. You get 8 H100 GPUs for 2 weeks (assume each sustains 400 TFLOP/s, about 40% of its ~989 dense bf16 peak), about 200 billion tokens of permissively licensed code, and a requirement: serve it on single 24 GiB GPUs with a 16k-token context to about 20 developers at once per GPU.

Using this phase's ideas: what's your compute budget, what would Chinchilla say, what size do you actually pick, what's the architecture and parameter count, how big is the KV cache, how many training tokens, and what can go wrong? Then open the reveal.

Reveal: one good answer

Budget

  • C = 8 GPUs × 14 days × 86,400 s × 4 × 10¹⁴ FLOP/s ≈ 3.9 × 10²¹ FLOPs.
  • Chinchilla (6.8): C = 6·N·20N = 120 N² → N ≈ √(3.9e21 / 120) ≈ 5.7B params on ~114B tokens. Training-optimal, but 5.7B in bf16 is 10.6 GiB, and serving 20 users at 16k would need far more KV cache than is left.
  • Serving dominates (thousands of completions a day for years), so over-train a smaller model: pick ~1.5B and spend the whole budget on tokens.

Architecture (decoder-only, 6.4 / 6.5)

  • d = 2,048, 32 layers, 16 query heads of size 128, 4 K/V heads (GQA, 6.9), SwiGLU MLP width 5,632, pre-RMSNorm, RoPE with a large base (6.3, 6.11), vocabulary 32,000 (BPE trained on code, 6.6), tied embeddings.
  • Per layer: attention 2·d² + 2·d·(4·128) = 10.5M, MLP 3 × 2,048 × 5,632 = 34.6M → 45.1M. × 32 = 1.44B, + 65.5M embeddings → ≈ 1.51B parameters.
  • Inference: ~2N ≈ 3 GFLOPs per token.

Data and training

  • Tokens = C ÷ 6N = 3.9e21 ÷ (6 × 1.51e9) ≈ 428B tokens (~283 tokens per parameter). That's about 2.1 epochs of the 200B-token corpus: fine, repeating up to ~4 epochs costs little (6.8).
  • Next-token loss with teacher forcing (6.7); also train fill-in-the-middle examples (move a span to the end) so the model can complete code between a prefix and a suffix.
  • Context: pretrain at 4k, then a short long-context stage at 16k with a bigger RoPE base or YaRN (6.11). FlashAttention via SDPA throughout (6.9).
  • Validate the plan first: a ladder of 4–5 small runs (20M–300M) to fit your own loss curve and catch bugs before the big run (6.8).

Serving numbers

  • KV cache: 2 × 32 × 4 × 128 × 2 bytes = 64 KiB per token → 1 GiB per 16k-token user.
  • Weights 2.8 GiB (bf16) + 1 GiB buffers → 20 GiB left → 20 users at full 16k context. With an fp8 cache, 40. Without GQA (16 K/V heads) it would be 4 GiB per user: only 5.

Classic mistakes

  • Training the Chinchilla-optimal 5.7B and discovering it can't serve 20 users at 16k on a 24 GiB GPU.
  • Forgetting the label shift or the causal mask: suspiciously low loss, useless generation (6.7).
  • Evaluating long context only with needle tests; test real repository-level completion (6.11).
  • Deduplicating poorly: repeated files act like many extra epochs and the model memorizes.

Not covered here: distributed training across the 8 GPUs (Phase 10), and post-training plus evals for code assistants (AI Engineer 7.1, RL 8.13).

🏆 Boss quiz

1. A model has 48 layers, 8 K/V heads of size 128 and an fp8 KV cache (1 byte per value). How much cache do 10 users at 32k tokens each need?
Per token: 2 × 48 × 8 × 128 × 1 byte = 98,304 bytes = 96 KiB. × 32,768 tokens × 10 users = 32,212,254,720 bytes = 30 GiB. (15 forgets the factor 2 for K and V; 60 uses bf16's 2 bytes.)
2. You have 2.4 × 10²³ FLOPs. What's the compute-optimal model by the ~20-tokens-per-parameter rule?
C = 6·N·D with D = 20N gives C = 120 N², so N = √(2.4e23 / 120) = √(2e21) ≈ 4.5 × 10¹⁰ = 45B and D = 20N ≈ 0.9T tokens. The 175B option is the GPT-3-era split (too big, too little data); the 10B one is over-trained, a valid choice only if serving cost dominates.
3. A colleague widens every attention head from 64 to 512 dimensions and training stalls: most attention rows are almost one-hot and the gradients into Q and K are tiny. What did they most likely break?
With unit-variance q and k, q·k has variance d. At d = 512, raw scores are ~22 in size, softmax picks one key almost surely, and its gradient vanishes. Dividing by √d keeps scores near unit variance whatever the head size (6.1).
4. A 48-layer post-norm transformer diverges in the first few hundred steps unless you use a long learning-rate warm-up. What change is the standard fix?
Post-norm normalizes the residual stream after each sublayer, which makes gradients near the output large early in training, so it needs warm-up. Pre-norm (GPT-2 onward) leaves the residual path untouched, so gradients flow evenly and deep stacks train stably (6.4).
5. Your deployed model (already trained, 32 K/V heads) runs out of memory on long chats. You can't retrain. Which change shrinks the KV cache right away?
Cache precision is a serving setting: fp8 halves the bytes with no retraining (check quality). GQA changes the architecture, so it needs training or at least uptraining (~5% of pretraining compute). FlashAttention speeds up attention and avoids the n × n matrix, but doesn't shrink the cached keys and values (6.9).
