Phase 6 · Lesson 4

The transformer block: pre-norm vs post-norm

Attention mixes information across tokens; an MLP thinks about each token alone; residuals and normalization keep 100 stacked blocks trainable. Moving one normalization layer is what let GPT-2 and every LLM since skip a fragile warm-up.

🧰 You'll need (quick reminders)
  • Multi-head self-attention (Lessons 6.1–6.2): every token gathers a blend of the others; 4d² weights.
  • Residual connections add a layer's input back to its output, y = x + f(x), giving gradients a highway (Lesson 2.2). LayerNorm / RMSNorm rescale each token's vector to a standard size (Lesson 2.3).
  • GELU and SwiGLU: the smooth activations transformers use (Lesson 0.5).
🎯 Hook

The original 2017 Transformer had a fragile habit: train it with a normal learning rate from step 1 and it could fall apart. Everyone used a warm-up, a period where the learning rate starts near zero and creeps up over thousands of steps.

In 2020, Xiong et al. showed why, and that the fix is moving one layer: put the normalization before each sublayer instead of after it, and the model trains well without the warm-up stage, with less tuning. GPT-2 (2019) had already made exactly that move, and today's open models (Llama 3, Qwen3) all use the “pre-norm” layout.

What's inside one block, and why does the position of a normalization matter so much? You'll stack 24 blocks in both layouts and watch the numbers.

Numbers first: where a model's parameters actually live

GPT-2 small has d = 768 and 12 blocks. Count what one block holds:

Two thirds of every block is the plain MLP, not the famous attention. Geva et al. (2020) open with the same observation: feed-forward layers are “two-thirds of a transformer model's parameters”.

💡 Big idea A transformer block does two jobs in turn: attention moves information between tokens (“communicate”), then an MLP processes each token on its own (“compute”). Both write their result into a running sum, the residual stream, rather than replacing it. Normalization keeps the numbers each sublayer reads at a sane size.
🧠 Analogy: a shared whiteboard per token

Each token has its own whiteboard (the residual stream). In every block, first a meeting happens: each token reads the others' boards and copies a few notes onto its own (attention). Then everyone goes back to their desk and thinks alone, adding conclusions to their own board (MLP). Nobody erases the board, they only add. Before reading a board, you put on glasses that make any handwriting the same size (normalization).

Inside the block

In words, a modern (pre-norm) block is two lines:

x = x + Attention( Norm(x) )     x = x + MLP( Norm(x) )

The MLP is the same small network from Phase 0, applied to each token separately: widen to 4d, bend with GELU, shrink back to d. The original 2017 Transformer used ReLU with d = 512 and a hidden width of 2,048 (4×); GPT-2 and BERT use GELU; Llama-style models use SwiGLU (Lesson 0.5).

🤔 Why this? The MLP sublayer
  1. The problem before Attention only averages value vectors (weights are positive and add to 1). Stack attention alone and each token is a blend of blends: almost linear, with no per-token “thinking” step.
  2. What people tried Attention-only models: great for studying (Anthropic's circuits work uses them), noticeably weaker as language models.
  3. Why this works A wide two-layer MLP with a bend is a universal function-builder (Phase 0). Running it per token after attention lets the model transform what it just gathered: Geva et al. found MLP units act like key–value memories, where a unit fires on a text pattern and pushes up likely next tokens. 4× width gives it room: 8d² weights per block.
  4. What it costs, when it fails Two thirds of the parameters and most of the per-token compute. Every token pays the full MLP even if it's an easy one.
  5. What refined it Gated MLPs (SwiGLU, Shazeer 2020) with the hidden width cut to ⅔ to keep the cost equal, now standard; and mixture-of-experts, where each token visits only a few of many MLPs (Lesson 6.10).

The residual stream

Read the two lines again: nothing ever overwrites x. The token embedding goes in at the bottom, and each of the 2N sublayers adds a correction on top. At the end, the sum is normalized and turned into next-token scores. Anthropic's 2021 “mathematical framework” paper describes it this way: every component communicates “by reading and writing to different subspaces of the residual stream”.

🤔 Why this? The residual stream (x + f(x) around every sublayer)
  1. The problem before Deep plain stacks lose the gradient on the way back (Lesson 2.1); a 24-block transformer is 48 sublayers deep.
  2. What people tried Careful initialization and shallower models.
  3. Why this works With y = x + f(x), the gradient of y with respect to x is 1 + f′: there is always a direct path of slope 1 back to the embedding (Lesson 2.2's highway). Each sublayer only has to learn a small edit, and any sublayer can read what any earlier one wrote.
  4. What it costs, when it fails The stream is a sum of 2N contributions, so its size grows with depth unless something reins it in. That's exactly where the normalization placement matters (next).
  5. What refined it Scaling the residual branches at initialization (GPT-2 scales them by 1/√N), and the pre-norm layout.

What you should see (seed 3, 24 blocks): in post-norm the stream stays at exactly 5.7 (that's √32: every Norm resets it), but the gradient piles up toward the output: the last block's weights get about 5× the gradient of the first block's. That's the effect Xiong et al. proved: at initialization post-norm's gradients are largest near the output, so a full learning rate on step 1 makes big, destabilizing updates there, hence the warm-up. In pre-norm the gradients are spread evenly (the last block even gets a bit less, about 0.5×), but the stream grows from 5.6 to 32: nothing resets it until the final Norm. Averaged over seeds 1–5 the pattern holds (post-norm's last/first ratio about 2.3×; pre-norm's below 1). PyTorch with real attention + MLP blocks shows the same split (snippet below).

🤔 Why this? Pre-norm (normalize the input of each sublayer)
  1. The problem before Post-norm puts a Norm on the residual path after every sublayer, so the highway isn't clean, and at initialization gradients are much bigger near the output (5× in the toy). Training needed a careful learning-rate warm-up, which Xiong et al. call “crucial to the final performance” yet slow and fiddly.
  2. What people tried Warm-up schedules and tuning; careful initialization.
  3. Why this works Pre-norm normalizes only what each sublayer reads, leaving the residual sum untouched: a clean identity path from top to bottom, gradients of similar size in every layer, and Xiong et al. trained it without warm-up to comparable results with less tuning. GPT-2 moved its LayerNorms “to the input of each sub-block” and added one after the last block.
  4. What it costs, when it fails The stream grows with depth (5.6 → 32 in the toy), so late sublayers' contributions are relatively small, and you must add a final norm before the output. Post-norm can be the better model when it trains: in Liu et al.'s (2020) grid of 15 settings, pre-norm always converged and post-norm diverged in 7, but where post-norm converged it beat pre-norm in 7 of 8. A 2025 study (“The Curse of Depth”) also ties pre-norm to deep layers in Llama- and Qwen-family models contributing less than expected.
  5. What refined it RMSNorm instead of LayerNorm (cheaper, no mean subtraction, Lesson 2.3) in Llama-style models; Gemma 3 uses RMSNorm both before and after sublayers; QK-norm inside attention (Lesson 6.1).

Stack it: from token to next-token scores

A full decoder model (the GPT shape) is: token embedding (a table of V × d) → N blocks → final norm → unembedding (a d × V matrix that scores every vocabulary entry; often the same table as the embedding, “tied”). Positions come in via a position table (GPT-2) or RoPE inside attention (Llama, Lesson 6.3).

✏️ Worked example: counting GPT-2 small to the last parameter
  • Token embedding: 50,257 × 768 = 38,597,376 (tied: the unembedding reuses it).
  • Position table: 1,024 × 768 = 786,432.
  • One block: 12 × 768² + 13 × 768 = 7,077,888 + 9,984 = 7,087,872 (the 13d is biases and LayerNorm scales). × 12 blocks = 85,054,464.
  • Final LayerNorm: 2 × 768 = 1,536.

Total: 38,597,376 + 786,432 + 85,054,464 + 1,536 = 124,439,808, the famous “124M”. Notice 31% of it is the embedding table: in small models, vocabulary is expensive (Lesson 6.6).

🧰 Tools you'll actually use

A complete GPT-style block from scratch, in both layouts. It checks the 12d² + 13d count and then stacks 24 random blocks to measure the residual stream's size, like the playground but with real attention:

import torch, torch.nn as nn, torch.nn.functional as F
torch.manual_seed(0)

class Block(nn.Module):
    def __init__(self, d, h, pre=True):
        super().__init__()
        self.pre, self.h = pre, h
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.qkv, self.proj = nn.Linear(d, 3 * d), nn.Linear(d, d)       # attention: 4d^2 + 4d
        self.mlp = nn.Sequential(nn.Linear(d, 4 * d), nn.GELU(), nn.Linear(4 * d, d))  # MLP: 8d^2 + 5d

    def attn(self, x):
        B, n, d = x.shape
        q, k, v = (t.view(B, n, self.h, d // self.h).transpose(1, 2) for t in self.qkv(x).split(d, -1))
        return self.proj(F.scaled_dot_product_attention(q, k, v, is_causal=True).transpose(1, 2).reshape(B, n, d))

    def forward(self, x):
        if self.pre:                                   # GPT-2 onward: x + f(norm(x))
            x = x + self.attn(self.ln1(x))
            return x + self.mlp(self.ln2(x))
        x = self.ln1(x + self.attn(x))                 # original 2017: norm(x + f(x))
        return self.ln2(x + self.mlp(x))

d, h = 768, 12
print(sum(p.numel() for p in Block(d, h).parameters()), 12 * d * d + 13 * d)

x = torch.randn(1, 16, 64)
for pre in (True, False):
    stack, z, sizes = [Block(64, 4, pre) for _ in range(24)], x, []
    with torch.no_grad():
        for blk in stack:
            z = blk(z); sizes.append(z.norm(dim=-1).mean().item())
    print("pre " if pre else "post", [round(sizes[i], 1) for i in (0, 5, 11, 23)])

PyTorch also ships nn.TransformerEncoderLayer(d, h, norm_first=True) (pre-norm; the default norm_first=False is post-norm) and nn.RMSNorm. For a readable full GPT, see nanoGPT. Gotcha: in a pre-norm model, forgetting the final norm leaves the unembedding reading a stream whose size depends on depth.

🎤 Interview angle

“Draw a transformer block. Pre-norm or post-norm, and why?” A strong answer:

  • x = x + Attn(Norm(x)); x = x + MLP(Norm(x)); attention mixes across tokens, the MLP (4× width, GELU/SwiGLU) works per token.
  • Parameters: about 4d² attention + 8d² MLP = 12d² per block; GPT-2 small = 124M with a 50,257 × 768 embedding.
  • Post-norm puts the norm on the residual path, giving large near-output gradients at init (Xiong et al. 2020) and needing warm-up; pre-norm keeps a clean identity path and trains stably; add a final norm.
  • Modern details: RMSNorm, SwiGLU, RoPE, GQA, and the residual-stream view.
🏭 In the real world
Moving LayerNorm to the input 🏢 OpenAI · 2019 Radford et al.: GPT-2

How: LayerNorm moved “to the input of each sub-block”, one extra LayerNorm after the final block, residual weights scaled by 1/√N at init.

Why this method: the paper doesn't say; the layout trained a 48-block, 1.5B-parameter model and became the template later GPT-style models kept (Xiong et al. explained why a year later).

Why warm-up was needed 🧪 Research · 2020 Xiong et al.: On Layer Normalization in the Transformer Architecture

How: mean-field analysis plus measured gradients per layer in post-norm and pre-norm models at initialization.

Why this method: post-norm's gradients grow with layer index; pre-norm's stay about the same, and pre-norm trained without warm-up reached comparable results in less time.

Today's open-model recipe 🏢 Alibaba · 2025 Qwen3 Technical Report

How: grouped-query attention, SwiGLU, RoPE, and RMSNorm with pre-normalization, plus QK-norm.

Why this method: each piece is the refinement of a block you met here: cheaper norm, gated MLP, relative positions, smaller KV cache.

MLPs as memories 🧪 Research · 2020 Geva et al.: Transformer Feed-Forward Layers Are Key-Value Memories

How: looked at which training texts make each MLP unit fire, and which output tokens it promotes.

Why this method: lower layers' units catch shallow patterns, upper layers more semantic ones, and each unit's output pushes probability toward likely next tokens.

🤯 Fun fact · “divine benevolence”

Noam Shazeer's 2020 paper that introduced SwiGLU, the MLP inside most of today's open LLMs, admits it doesn't know why it works. The conclusion says: “we attribute their success, as all else, to divine benevolence.” Deep learning is still partly an experimental science.

Check yourself

1. A GPT-style block has d = 2,048 and a GELU MLP with 4× width. Ignoring biases and norms, how many weights does one block have, and how many of them are in the MLP?
Attention: WQ, WK, WV, WO = 4d² = 16.8 M. MLP: d × 4d plus 4d × d = 8d² = 33.6 M. Total 12d² = 50.3 M, with two thirds in the MLP.
2. You implement the original post-norm Transformer and train a 24-layer version with your usual learning rate from step 1. The loss explodes within a few hundred steps. Without changing the learning rate's peak value, what are the two standard fixes?
Post-norm has large gradients near the output at initialization (Xiong et al. 2020), so early full-size steps are destabilizing. Warm-up starts with tiny steps until things settle; pre-norm removes the cause by keeping the residual path clean, and trains without warm-up. Removing residuals would make it far worse.
3. A teammate converts a model to pre-norm but deletes the final LayerNorm “because every sublayer already normalizes its input”. Outputs are badly scaled, and worse in deeper versions. Why?
Pre-norm normalizes only what each sublayer reads; the stream keeps summing contributions and grows with depth (5.6 → 32 over 24 blocks in the playground). Without the final norm, the output layer sees a vector whose size depends on how deep the model is. GPT-2 added exactly this extra LayerNorm after the last block.
📝 TL;DR
  • Block = attention (mix across tokens, 4d²) + MLP (per token, 4× width, GELU/SwiGLU, 8d²), each wrapped in a residual and a norm.
  • The residual stream is a running sum every sublayer writes into; it gives gradients a slope-1 path.
  • Post-norm (2017) normalizes the stream after each sublayer: bounded size, but gradients pile up near the output → warm-up needed.
  • Pre-norm (GPT-2 →) normalizes each sublayer's input: clean path, even gradients, no warm-up needed (Xiong et al. 2020); add a final norm.
  • GPT-2 small = 124,439,808 parameters; modern open models: pre-RMSNorm, SwiGLU, RoPE, GQA.
