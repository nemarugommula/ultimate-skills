Phase 9 · Lesson 2

Graph neural networks

Molecules, road networks, social networks and 3D meshes aren't grids or sequences. Graph neural networks learn on them by letting every node listen to its neighbours, round after round.

🧰 You'll need (quick reminders)
  • A layer is a matrix multiply plus a bend: h′ = ReLU(W h) (Lessons 0.3 and 0.4).
  • A CNN slides the same small filter over every pixel and looks only at its neighbours (Lesson 3.2). Keep that idea: GNNs do the same on graphs.
  • Attention computes a weighted average of other tokens with weights from a softmax (Lesson 6.1).
🎯 Hook

Every time Google Maps tells you “arrive 9:42”, a graph neural network may be behind it. Google and DeepMind modelled roads as a graph (road segments connected where they meet) and deployed a GNN to predict travel times. They report it cut bad ETA predictions by over 40% in cities like Sydney compared with the previous production system.

In 2023, DeepMind's GraphCast, a GNN on a mesh wrapped around the globe, made 10-day weather forecasts in under a minute on one TPU and beat the European Centre's flagship forecast (HRES) on 90% of 1,380 test targets. Pinterest recommends pins with a GNN running on a graph of 3 billion nodes.

But a road map has no pixels and no word order. How do you feed it to a neural network at all? You'll find out by spreading colours through a graph by hand, solving a challenge in two rounds, and then watching too many rounds ruin everything.

Numbers first: why an MLP or a CNN can't take a graph

A graph is a set of nodes (atoms, people, road segments) and edges between them (bonds, friendships, junctions). Each node has a feature vector x (atom type, age, speed limit). Try the obvious approaches:

IdeaWhat goes wrong
Flatten the adjacency matrix into an MLPA molecule with 20 atoms gives 400 inputs, one with 21 gives 441: the input size changes. And numbering the atoms differently gives a different input for the same molecule: 20 atoms can be numbered 20! ≈ 2.4 × 1018 ways.
A CNNA filter needs a fixed grid: “the pixel to the left”. A node has no left, and might have 1 neighbour or 1,000.
An RNN over the nodesIt needs an order. A graph doesn't have one.

So we need a network that (1) works for any number of nodes and neighbours, and (2) gives the same answer however you number the nodes. That second property is called permutation invariance (for a whole-graph answer) or equivariance (for per-node answers: relabel the nodes and the answers get relabelled the same way).

💡 Big idea Message passing: in each round, every node collects its neighbours' vectors, combines them with an order-free operation (sum, mean or max), and updates its own vector with a small shared network. After k rounds, each node knows about everything within k hops. The same weights are used at every node, exactly like a CNN filter is reused at every pixel.
🧠 Analogy: gossip in a village

On day 1 each villager knows only their own news. Every evening, everyone chats with their direct neighbours and updates their opinion: a bit of their own view, a bit of the neighbours'. After two evenings you've heard news from friends of friends. After a month everyone in the village holds the same blended opinion, and nobody remembers who started what. Both halves of that story matter in this lesson.

Message passing, one round at a time

For node v with vector hv, one round (one GNN layer) is:

message = AGGREGATE { hu for every neighbour u }  →  hv′ = ReLU( Wself hv + Wnbr · message )

AGGREGATE must not care about order (sum, mean, max), so relabelling nodes can't change anything. The weights W are shared by every node, so the number of parameters doesn't depend on the size of the graph.

🤔 Why this? Message passing
  1. The problem before Graphs have no fixed size, no grid and no node order. Flattening a 20-node adjacency matrix gives 400 inputs that change with every relabelling (20! ≈ 2.4 × 1018 numberings of the same molecule).
  2. What people tried Hand-made graph features (counts of rings, degrees, fingerprints of molecules) fed to classical models; “spectral” graph convolutions defined through the graph's eigenvectors, which were expensive and tied to one fixed graph.
  3. Why this works Each node does the same local computation with the same weights: gather neighbours with an order-free operation, then update. That is a CNN filter generalized from “the 8 pixels around me” to “whoever I'm connected to”. Any graph size works, relabelling can't change the result, and k layers see k hops. Gilmer et al. (2017) showed that many earlier models were all instances of this one recipe and named it the message passing neural network.
  4. What it costs, when it fails Information moves one hop per layer, so far-apart nodes need many layers, and many layers over-smooth (you just saw it). Plain message passing also can't tell apart some different graphs (for example, two triangles versus one hexagon look the same to every node: each has 2 neighbours). Many messages funnel through a few bridge nodes (“over-squashing”).
  5. What refined it GCN (normalized averaging), GraphSAGE (sampled neighbours), GAT (learned attention weights), residual connections and normalization for depth (Lessons 2.2, 2.3), and graph transformers that let every node attend to every other.

Sum, mean or max? The aggregator matters

🤔 Why this? Neighbour aggregation: sum, mean, max
  1. The problem before A node may have 2 neighbours or 2 million, and they come in no particular order. You need one fixed-size vector out of a set of any size.
  2. What people tried Sorting neighbours by some score and running an RNN over them (GraphSAGE tested an LSTM aggregator on random orderings): it works but depends on an arbitrary order.
  3. Why this works Sum, mean and max all ignore order. Sum can count (a carbon with 4 bonds differs from one with 2): useful for molecules. Mean keeps values on the same scale whatever the degree: a celebrity with a million followers doesn't explode. Max picks out “is any neighbour like X?”, robust to how many there are. Tiny example: neighbours with values 1, 1, 1, 1 give sum 4, mean 1, max 1; a node with a single neighbour of value 1 gives sum 1, mean 1, max 1. Only sum tells them apart.
  4. What it costs, when it fails Sum blows up with degree and depth (98,930 after 10 rounds in the playground) unless normalized. Mean and max can't count neighbours. Every choice throws some information away.
  5. What refined it GCN's symmetric normalization (divide by √degu · √degv), combining several aggregators at once (“principal neighbourhood aggregation”), and attention-weighted averages (GAT, below).

GCN: the averaging layer that started the boom

Kipf and Welling's Graph Convolutional Network (2016) is message passing with one specific, cheap normalization. Add a self-loop to every node (so you keep your own features), then average neighbours weighted by 1 ÷ √(degu · degv), then apply a shared weight matrix and ReLU. As a matrix formula, with Â = A + I:

H′ = ReLU( D̂−½ Â D̂−½ H W )

That's one matrix multiply by a normalized adjacency matrix, then a normal linear layer (matrix multiplication: math 2.2). Real graphs are stored as sparse edge lists, so the cost is proportional to the number of edges.

✏️ Worked example: one GCN layer on a 3-node path

Graph A — B — C, one feature each: x = [3, 0, 1]. With self-loops, degrees are A: 2, B: 3, C: 2. Weight W = 1.

B had nothing (0) and now holds a blend of its neighbours. Parameters: on the Cora citation graph (2,708 papers, 1,433 word features each, 7 topics), the paper's first layer maps 1,433 → 16 hidden units: 1,433 × 16 + 16 = 22,944 weights, the same whether the graph has 2,708 nodes or 2 million. Two such layers scored 81.5% on Cora's topic labels using only 20 labelled papers per topic (140 in all).

GraphSAGE: when the graph is too big

GCN, as first written, multiplies by the whole adjacency matrix at once and assumes you know the whole graph at training time. Pinterest and Reddit have billions of nodes, and new ones arrive every second. GraphSAGE (Hamilton, Ying and Leskovec, 2017) fixes both:

  • Sample a fixed number of neighbours per node instead of all of them: the paper used 25 at the first hop and 10 at the second, so each node's computation touches at most 25 × 10 = 250 nodes, whatever its real degree.
  • Learn an aggregation function instead of one embedding per node, so it can produce embeddings for new nodes never seen in training (“inductive” learning).

PinSage, Pinterest's version, runs on a graph of 3 billion nodes and 18 billion edges, trained on 7.5 billion examples.

GAT: not all neighbours are equal

Mean aggregation treats your best friend and a random acquaintance alike. A Graph Attention Network (Veličković et al., 2017) learns a score for each edge and turns the scores into weights with a softmax over the neighbours, exactly the attention of Lesson 6.1, but only over a node's neighbours.

🤔 Why this? Graph attention (GAT)
  1. The problem before GCN's weights 1 ÷ √(degu · degv) are fixed by the graph's shape. A spammy or mislabelled neighbour counts as much as a reliable one.
  2. What people tried Hand-made edge weights (interaction counts, distances), and separate learned weights per edge type.
  3. Why this works For each edge, a tiny network scores “how useful is u's message to v?” from both nodes' features; a softmax over v's neighbours turns scores into weights that sum to 1. Example: three neighbours scored 2, 0, 0 get weights 0.79, 0.11, 0.11 (mean would give 0.33 each), so one relevant neighbour can dominate. Several heads look for different things, as in a transformer (Lesson 6.2). GAT reported 83.0% on Cora versus GCN's 81.5%.
  4. What it costs, when it fails A score per edge per head: more compute and memory than GCN on dense graphs. Gains over a well-tuned GCN are often small on simple benchmarks. It still over-smooths with depth.
  5. What refined it GATv2 (a more expressive scoring function), and graph transformers that attend over all nodes with positional encodings that describe graph structure.
✏️ Worked example: a transformer is a GNN on a complete graph

Take a sentence of 6 tokens. Connect every token to every other one (and itself): 6 × 6 = 36 edges. Run GAT on that graph: each token scores every other token, softmaxes the scores and averages their vectors. That is self-attention (Lesson 6.1). The order of words, which a complete graph forgets, comes back through positional encodings (Lesson 6.3). So a transformer is message passing on a fully connected graph, and a GNN is attention restricted to the edges you already know. The cost difference: a 1,000-node graph with 5,000 edges needs 5,000 messages per layer; a complete graph on 1,000 nodes needs 1,000,000.

Over-smoothing: why GNNs stay shallow

You watched it happen: averaging again and again makes every node the same. Li, Han and Wu (2018) showed GCN's layer is a form of “Laplacian smoothing”: that's exactly why it works (nodes in a cluster become similar) and why deep GCNs fail (nodes from different clusters become indistinguishable). In practice most GNNs use 2 to 4 layers; deep ones need residual connections, normalization or other tricks. The torch snippet below measures it: after 50 rounds of averaging, every node vector points the same way (mean cosine 1.000).

🧰 Tools you'll actually use

For real work, use PyTorch Geometric (torch_geometric.nn.GCNConv, SAGEConv, GATConv, neighbour-sampling loaders) or DGL. Under the hood a GCN layer is a few lines of plain PyTorch, which this snippet runs (dense adjacency, fine for small graphs):

import torch, torch.nn as nn

class GCNLayer(nn.Module):
    """H' = Â H W with Â = D^-1/2 (A + I) D^-1/2 (Kipf & Welling)."""
    def __init__(self, d_in, d_out):
        super().__init__()
        self.lin = nn.Linear(d_in, d_out, bias=False)
    def forward(self, H, A):
        A_hat = A + torch.eye(A.shape[0])                   # self-loops: keep your own features
        d = A_hat.sum(1).rsqrt()                            # 1 / sqrt(degree)
        A_norm = d[:, None] * A_hat * d[None, :]            # symmetric normalization
        return A_norm @ self.lin(H)                         # aggregate neighbours, then mix features

# a 6-node graph: two triangles joined by one edge
edges = [(0, 1), (1, 2), (2, 0), (3, 4), (4, 5), (5, 3), (2, 3)]
A = torch.zeros(6, 6)
for i, j in edges:
    A[i, j] = A[j, i] = 1.0

torch.manual_seed(0)
H = torch.randn(6, 4)                                       # 4 features per node
layer = GCNLayer(4, 2)
out = layer(H, A)
print("output shape:", tuple(out.shape), "| parameters:", sum(p.numel() for p in layer.parameters()))

perm = torch.randperm(6)                                    # relabel the nodes
out_p = layer(H[perm], A[perm][:, perm])
print("same answers after relabelling:", torch.allclose(out_p, out[perm], atol=1e-6))

# over-smoothing: apply the averaging 50 times and watch the nodes become identical
A_hat = A + torch.eye(6); d = A_hat.sum(1).rsqrt(); A_norm = d[:, None] * A_hat * d[None, :]
X = H.clone()
for k in range(1, 51):
    X = A_norm @ X
    if k in (1, 5, 50):
        Xn = X / X.norm(dim=1, keepdim=True)
        print(f"after {k:2d} rounds, mean cosine between nodes = {(Xn @ Xn.T).mean().item():.3f}")

# after  5 rounds, mean cosine between nodes = 0.945

🎤 Interview angle

“Why can't you use an MLP on a graph, and what does a GNN layer do?” A strong answer:

  • Graphs vary in size and have no node order; an MLP on a flattened adjacency matrix isn't permutation invariant (24 outputs for 24 numberings of 4 nodes).
  • Message passing: aggregate neighbours with an order-free function (sum/mean/max), update with shared weights; k layers = k-hop receptive field; parameters independent of graph size.
  • GCN (normalized averaging), GraphSAGE (sampling, inductive), GAT (attention over neighbours); a transformer is attention on a complete graph.
  • Limits: over-smoothing with depth, over-squashing through bottlenecks, and limited power to distinguish some graphs; typical depth 2–4.
🏭 In the real world
Travel times on the road graph 🏢 Google / DeepMind · 2021 Derrow-Pinion et al.: ETA Prediction with Graph Neural Networks in Google Maps

How: the road network is split into “supersegments” (sequences of connected road segments on typical routes); a GNN passes messages between the segments and predicts each supersegment's travel time.

Why this method: traffic spreads along roads, which is exactly what message passing models; deployed, it reduced negative ETA outcomes by over 40% in cities like Sydney.

Weather forecasting on a mesh around the Earth 🧪 DeepMind · 2023 Lam et al.: GraphCast

How: an encoder maps the 0.25° weather grid onto a multi-scale icosahedral mesh, a processor runs learned message passing on the mesh, and a decoder maps back to the grid.

Why this method: a sphere has no clean grid, and the multi-scale mesh carries information far in few rounds; it beat ECMWF's HRES on 90% of 1,380 targets and runs a 10-day forecast in under a minute on one TPU v4.

Recommendations on a 3-billion-node graph 🏢 Pinterest · 2018 Ying et al.: Graph Convolutional Neural Networks for Web-Scale Recommender Systems (PinSage)

How: GraphSAGE-style sampled convolutions over a pin–board graph (3 billion nodes, 18 billion edges), with neighbours chosen by random walks.

Why this method: a pin's meaning comes from the boards people save it to; sampling keeps the cost per pin fixed at that scale.

Protein structure as graph reasoning 🧪 DeepMind · 2021 Jumper et al.: Highly accurate protein structure prediction with AlphaFold

How: AlphaFold 2's Evoformer keeps a representation for every pair of amino-acid residues and updates it with attention and “triangle” updates.

Why this method: the authors describe the Evoformer as viewing structure prediction “as a graph inference problem in 3D space” whose edges are residues in proximity; the pair representation is read as edges of that graph.

🤯 Fun fact · two-hop power

GraphCast's mesh is built by refining an icosahedron 6 times, giving 40,962 nodes spread evenly over the globe. Its trick against slow, one-hop-per-round spreading: it keeps the long edges from the coarse early meshes too, so its 16 message-passing layers carry information both locally and over long distances (the paper's words: “long-range information propagation with few message-passing steps”). Same idea you used when you seeded the hubs: put information where it travels far fast.

🌉 How it connects

Message passing reuses a CNN's two ideas, locality and shared weights (3.2), on any graph. GAT is attention (6.1, 6.2) restricted to edges; a transformer is a GNN on a complete graph, with positional encodings (6.3) restoring order and an n² cost (6.9). Residual connections (2.2) and normalization (2.3) help deeper GNNs. In the AI Engineer course, knowledge graphs for retrieval are GraphRAG (AI Eng 4.3); that's graphs as data for an LLM, not a GNN. Next: state-space models (9.3), another way to beat attention's n² cost.

Check yourself

1. A GCN layer maps 1,433 input features to 16 hidden units. How many parameters does it have on a graph with 2 million nodes (weights plus one bias per output)?
The same weight matrix is shared by every node, like a CNN filter shared by every pixel. The graph's size changes the compute (one message per edge), not the parameter count.
2. Your 12-layer GCN classifies nodes worse than your 2-layer one, and you find all node embeddings in the last layer have cosine similarity above 0.99 with each other. Diagnosis?
Each GCN layer is a smoothing step. A few steps make each cluster consistent (helpful); many steps blend clusters together until every node holds the same vector. More layers make it worse. Shallow GNNs, skip connections, or methods that keep each node's original features in the mix are the usual fixes.
3. You need to predict a property of molecules, where it matters whether a carbon atom has 2 or 4 bonded neighbours. Which aggregator is the safest choice?
Mean of four identical neighbours equals the mean of two, and so does max: both lose the count. Sum keeps it. Molecules have small, bounded degrees, so sum's tendency to explode on high-degree nodes isn't a problem here (it would be for a social network).
📝 TL;DR
  • Graphs have any size and no order, so MLPs and CNNs don't fit. A GNN must be permutation invariant/equivariant.
  • Message passing: aggregate neighbours (sum/mean/max), update with shared weights. k layers = k hops; parameters don't depend on graph size.
  • GCN = normalized averaging; GraphSAGE = sampled neighbours, works on new nodes and billion-node graphs; GAT = learned attention over neighbours.
  • Too many layers over-smooth: nodes become identical. Typical GNNs use 2–4 layers.
  • A transformer is attention on a complete graph. GNNs power Google Maps ETAs, GraphCast weather and Pinterest recommendations.
